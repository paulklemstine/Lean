                                                   Abstract. Hittmeir recently presented a deterministic algorithm that prov-
                                                   ably computes the prime factorisation of a positive integer N in N 2/9+o(1)
                                                   bit operations. Prior to this breakthrough, the best known complexity bound
                                                   for this problem was N 1/4+o(1) , a result going back to the 1970s. In this pa-
                                                   per we push Hittmeir’s techniques further, obtaining a rigorous, deterministic
                                                   factoring algorithm with complexity N 1/5+o(1) .




                                                                               1. Introduction
                                              Let F(N ) denote the time required to compute the prime factorisation of an
                                           integer N ⩾ 2. By “time” we mean “number of bit operations”, or more precisely,
                                           the number of steps performed by a deterministic Turing machine with a fixed,
                                           finite number of linear tapes [Pap94]. All integers are assumed to be encoded in
                                           the usual binary representation.
                                              In this paper we prove the following result:

                                           Theorem 1.1. There is an integer factorisation algorithm achieving

                                                                          F(N ) = O(N 1/5 log16/5 N ).

                                              One may show that the space complexity of this algorithm is O(N 1/5 log11/5 N ),
                                           but we will not give the details of this analysis.
                                              We emphasise that the new algorithm is deterministic, the complexity bound
                                           is rigorously established, and the algorithm runs on a classical computer. If one is
                                           willing to relax these conditions, better complexity bounds are known:
                                              – The class group relations method of Lenstra and Pomerance [LP92] provably
                                                 runs in expected time

                                                                  exp (1 + o(1))(log N )1/2 (log log N )1/2 .
                                                                                                           

                                               This is the best known rigorous bound for a probabilistic factoring algorithm.
                                             – The general number field sieve is conjectured to run in time

                                                            exp ((64/9)1/3 + o(1))(log N )1/3 (log log N )2/3 .

                                               This algorithm is responsible for all recent record-breaking factorisations, such
                                               as the factorisation of the 250-digit challenge number RSA-250 [BGG+ 20].
                                             – Shor’s factoring algorithm runs in polynomial time, specifically (log N )2+o(1) ,

   It is also worth mentioning the deterministic algorithm of Shanks [Sha71], which

mann Hypothesis. According to [CP05, §5.6.4], the complexity of this algorithm is
actually N 1/5 log4+o(1) N , which is slightly worse than our bound in Theorem 1.1.
   The literature on integer factorisation is vast. For further pointers, see [CP05].
For the rest of the paper, we focus on algorithms that are deterministic, rigorous,
and classical.
   The naive trial division method, i.e., checking all possible divisors up to N 1/2 ,
runs in time N 1/2+o(1) . The first algorithm faster than this was that of Lehman
[Leh74], who obtained F(N ) = N 1/3+o(1) . Lehman’s main theorem shows that if N
is a semiprime, i.e., N = pq for distinct primes p and q, then there exists a pair of
“small” integers a and b such that aq + bp lies in a certain short interval (depending
on a and b). His algorithm examines every integer in this interval, for every a and
b in a suitable range, and succeeds in factoring N as soon as it encounters aq + bp.
   Shortly after Lehman’s work appeared, Pollard [Pol74] and Strassen [Str77] in-
dependently published two closely related algorithms achieving F(N ) = N 1/4+o(1) .
Both of these algorithms depend heavily on the FFT (fast Fourier transform).
Strassen’s method was revisited by Bostan, Gaudry and Schost [BGS07], and then
again by Costa and the present author [CH14], who achieved

   More recently, in a spectacular preprint [Hit20], Hittmeir presented an algorithm

has many features in common with [Hit18], but instead of searching for p + q, it

replacement for (1.3) in this context is the congruence
                             αaq+bp ≡ αaN +b    (mod p),
which follows from Fermat’s little theorem. His algorithm actually examines many
more candidates than Lehman’s algorithm, but the complexity is drastically reduced
thanks to the use of the BSGS search.
   The algorithm described in the present paper achieves a further exponential
speedup, from N 2/9+o(1) to N 1/5+o(1) = N 0.2+o(1) . It is based largely on Hittmeir’s
algorithm from [Hit20]. The main difference, and the source of the exponential
speedup, is that we apply the BSGS search technique much more aggressively.
Whereas Hittmeir breaks up the search space into chunks and applies the BSGS
search to each chunk separately, we show how to sweep through the entire space
with a single BSGS search. For a more quantitative discussion of the relationship
between the two algorithms, see Remark 3.4.
   We also make one other small improvement to Hittmeir’s algorithm: we replace
a certain multipoint evaluation step with an invocation of Bluestein’s algorithm
[Blu70] (see Algorithm 4.1). This saves a further factor of (log N )O(1) overall.

                                 2. Preliminaries
   In this section we introduce various notation and terminology, and recall several
ingredients from the literature that will be needed later. All results stated in this
section without specific references may be found in standard textbooks on computer
algebra, such as [vzGG13] or [BZ11].
   For n a positive integer, we define lg n := ⌈log n/ log 2⌉ if n ⩾ 2, and lg 1 := 1.
Clearly lg n = Θ(log n) as n → ∞.
   Given a list of n ⩾ 1 elements of bit size β ⩾ 1, we may sort the list using
the “merge sort” algorithm in time O(nβ lg n) [Knu98]. Here we assume that the
elements belong to some totally ordered set, and that we may compare a pair of
elements in time O(β).

2.1. Integer arithmetic. Let n ⩾ 1, and assume that we are given integers x and
y such that |x|, |y| ⩽ 2n .
      • We may compute x + y and x − y in time O(n).
      • We write M(n) for the cost of computing the product xy. As mentioned in
        the Introduction, we may take M(n) = O(n lg n) [HvdH19].
      • If y > 0, we may compute the quotients ⌊x/y⌋ and ⌈x/y⌉ in time O(M(n)).
        We may therefore also compute the residue of x modulo y in the interval
        [0, y) in time O(M(n)).
4                                   DAVID HARVEY


      • More generally, for a fixed positive rational number u/v, and assuming that
        x, y > 0, we may compute ⌊(x/y)u/v ⌋ and ⌈(x/y)u/v ⌉ in time O(M(n)).
      • Using the “half-GCD” algorithm, we may compute g := gcd(x, y), and if
        desired find integers u and v such that ux + vy = g, in time O(M(n) lg n) =
        O(n lg2 n). In particular, if gcd(x, y) = 1, we may compute the inverse of
        x modulo y in time O(M(n) lg n).
   Let N ⩾ 2. We write ZN for the ring Z/N Z of integers modulo N . Elements of
ZN will always be represented by their residues in the interval [0, N ). In particular,
an element of ZN occupies at most lg N bits of storage. We write Z∗N for the group
of units of ZN , i.e., the subset of those x ∈ ZN for which gcd(x, N ) = 1.
      • Given x, y ∈ ZN , we may compute x ± y ∈ ZN in time O(lg N ), and we
         may compute xy ∈ ZN in time O(M(lg N )) = O(lg N lg lg N ).
      • Given x ∈ ZN and an integer m ⩾ 0, we may compute xm ∈ ZN in time
         O(M(lg N ) lg m), using the “repeated squaring” algorithm.
      • Given x ∈ ZN , we may test whether x ∈ Z∗N in time O(M(lg N ) lg lg N ),
         by computing gcd(x, N ). If this GCD is not 1 or N , and if N = pq is a
         semiprime, then we immediately recover p and q in time O(M(lg N )).

2.3. Strassen’s method. The following result, which goes back to Strassen [Str77],
may be used to quickly rule out “small” factors of a given integer N .
Proposition 2.5. Given as input a positive integer M = O(N ), we may test if N
has a prime divisor p ⩽ M , and if so find the smallest such divisor, in time
                                            O(M 1/2 lg3 N ).
Proof. We give only a sketch; for details (and improvements) see [Str77], [BGS07]
or [CH14]. Let d := ⌈M 1/2 ⌉ and compute f (x) = (x + 1) · · · (x + d) ∈ ZN [x] using
Lemma 2.3. Then evaluate f (x) simultaneously at x = 0, d, . . . , (d − 1)d, using
a fast multipoint evaluation algorithm. If any f (jd) = (jd + 1) · · · (jd + d) has
non-trivial GCD with N , then one of its constituents jd + i must have non-trivial
GCD with N , and this observation may be used to locate any prime divisors of N
such that p ⩽ d2 (using a similar procedure to the closely related Algorithm 4.1 of
the present paper).                                                                 

Remark 2.6. Taking M := ⌊N 1/2 ⌋ in the above result leads directly to Strassen’s
N 1/4+o(1) integer factorisation algorithm.
2.4. Finding elements of large order. The following result, which allows us to
find elements of large order in Z∗N , is due to Hittmeir. Of course in practice this is
easy, because almost every element of Z∗N has large order. The point of Hittmeir’s
result is that the algorithm is deterministic and gives provably correct output.
Proposition 2.7 ([Hit18, Theorem 6.3]). There is an algorithm with the following
properties. It takes as input integers N ⩾ 2 and D such that N 2/5 ⩽ D ⩽ N . It
returns either some α ∈ Z∗N such that ordN (α) > D, or a nontrivial factor of N ,
or “N is prime”. Its running time is
                                                O(D1/2 lg2 N ).
6                                 DAVID HARVEY


   The algorithm is somewhat involved, and we give only a brief summary here.
The idea is to try to compute the orders in ZN of candidates α = 2, 3, and so
on, using a BSGS search up to some bound. If for some candidate α we fail
to compute the order, then the order must be large and we are done. On the
other hand, if we succeed in computing the order of a candidate, then this reveals
valuable information about the possible prime divisors of N . Continuing in this
way, Hittmeir shows that eventually we recover enough information about these
divisors that it becomes feasible to search for them directly using a variant of the
algorithm of Proposition 2.5. For details, see [Hit18].

Remark 2.8. According to [Hit18, Remark 6.4], the assumption D ⩾ N 2/5 is not
the sharpest possible; the same result may be proved under the weaker hypothesis
D = Ω(N 1/3+o(1) ) for suitable o(1). Luckily for us, the N 2/5 bound as stated is
good enough for our application (but only just).


                             3. Lehman’s strategy
   Given an integer N that is either prime or a semiprime pq, the main algorithm
in Section 4 will attempt to factor N by searching for integers of the form aq + bp
for various small values of a and b. Before considering Lehman’s theorem in detail,
we show (following [Hit20, Lem. 4.1]) that it is easy to recover p and q once we
have guessed the correct value of aq + bp.

Lemma 3.1. Given as input an integer N ⩾ 2 such that N is either a prime or a
semiprime pq, and positive integers a, b, u = O(N ), we may test if u is of the form
aq + bp, and if so recover p and q, in time O(M(lg N )).

Proof. If N = pq and u = aq + bp, then aq and bp are roots of the polynomial
Q(y) := y 2 − uy + abN . We first check if Q(y) has rational roots, by testing
whether u2 − 4abN is a square, and if so, compute the roots via the quadratic
formula. It is then straightforward to recover p and q, if they exist.       

Remark 3.2. In fact, as is implicit in Lehman’s paper, we may still recover p
and q without knowing a and b, provided that we know the product ab and that
gcd(ab, N ) = 1. This requires one additional GCD operation, so the cost rises to
O(M(lg N ) lg lg N ).

                              4. The main algorithm
  Before discussing the main search algorithm, we first consider Algorithm 4.1,
which finds collisions modulo p or q between two subsets of ZN . This subroutine is
almost identical to Algorithm 3.2 of [Hit20]. However, whereas Hittmeir allows both
subsets to be essentially arbitrary, we specialise to the case that one of the subsets
consists entirely of powers of some fixed α ∈ Z∗N . This allows us to improve the
complexity from O((n + m) lg 3 N ) (see [Hit20, Lem. 3.3]) to O(n lg3 N + m lg2 N ).

Algorithm 4.1 – finding collisions modulo p or q
Input:
  – A positive integer N , either prime or semiprime.
  – A positive integer m, and an element α ∈ Z∗N with ordN (α) ⩾ m.
  – Elements v1 , . . . , vn ∈ ZN for some positive integer n, such that vh 6= αi for
    all h ∈ {1, . . . , n} and i ∈ {0, . . . , m − 1}.
Output:
  – If N = pq is a semiprime, and if there exists h ∈ {1, . . . , n} such that vh ≡ αi
    (mod p) or vh ≡ αi (mod q) for some i ∈ {0, . . . , m − 1}, returns p and q.
  – Otherwise returns “no factors found”.
 1) Using Lemma 2.3 (product tree), compute the polynomial
                        f (x) := (x − v1 ) · · · (x − vn ) ∈ ZN [x].
    2) Using Lemma 2.4 (Bluestein’s algorithm), compute the values f (αi ) ∈ ZN for

         c) If γi = N , then for h = 1, . . . , n:

    4) Return “no factors found”.


Proposition 4.1. Algorithm 4.1 is correct. For m, n = O(N ), its running time is
                                 O(n lg3 N + m lg2 N ).
Proof. We first prove correctness. Suppose that N = pq is a semiprime, and that
vh0 ≡ αi0 modulo p or modulo q for some h0 and i0 . Then f (αi0 ) includes the factor
vh0 − αi0 , so we have γi0 6= 1 in Step (3a). If additionally γi0 6= N , then p and q
are successfully recovered in Step (3b). Suppose however that γi0 = N . Then the
                  EXPONENT ONE-FIFTH INTEGER FACTORISATION                             9


factors will be recovered in Step (3ci) when we reach h = h0 , as the preconditions
ensure that gcd(N, vh0 − αi0 ) 6= N .
   Now we analyse the complexity. By Lemma 2.3 and Lemma 2.4, Steps (1)–(2)
run in time O(n lg3 N + m lg2 N ). Step (3a) executes at most m times. Step (3ci)
executes at most n times, because as soon as we find γi = N in Step (3c), we know
that (v1 − αi ) · · · (vn − αi ) = 0 in ZN , so one of the factors vh − αi must fail to
be invertible modulo N and thus reveal the factors p and q (here again we use the
hypothesis that vh 6= αi in ZN ). Therefore the total number of GCDs computed is
at most m + n, contributing O((m + n) lg N lg2 lg N ) to the complexity.             
