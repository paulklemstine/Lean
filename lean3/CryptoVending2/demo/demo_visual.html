System Overview

CryptoVend is built from three components: a seller HTML page (runs locally), a buyer HTML page (hosted on IPFS), and a smart contract (deployed on Layer 2).

💻 Seller SAP seller.html (local)
📜 Smart Contract CryptoVendL2.sol (L2 chain)
🛒 Buyer Page index.html (IPFS)
🌐 IPFS Encrypted file + buyer page

The Big Idea

A seller encrypts a file, deploys a contract, and pins everything to IPFS — all from a single HTML page in their browser. A buyer visits an IPFS-hosted page, pays via MetaMask, and receives the decrypted file — in under 30 seconds. The smart contract on Layer 2 enforces the rules: payment ≥ price, key delivery, and automatic refunds.

No server. No intermediary. No trust. Just math.

Phase 1: Seller Setup

The seller opens seller.html, selects a file, and deploys the vending machine.

  • Open seller.html in browser
  • Connect MetaMask wallet
  • Select file to sell
  • Choose L2 network (Arbitrum/Base)
  • Set price (e.g., 0.001 ETH)
  • Click "Deploy" →
  • Generate AES-256 encryption key
  • Encrypt file with AES-GCM
  • Upload encrypted file to IPFS
  • Deploy smart contract to L2
  • Generate buyer page HTML
  • Pin buyer page to IPFS
  • Share buyer page IPFS link
// What happens when you click "Deploy": // 1. Generate random 256-bit key const aesKey = crypto.getRandomValues( new Uint8Array(32) ); // 2. Compute key commitment const commitment = ethers.keccak256(aesKey); // 3. Encrypt file (browser SubtleCrypto) const iv = crypto.getRandomValues( new Uint8Array(12) ); const ciphertext = await crypto.subtle .encrypt({name: 'AES-GCM', iv}, key, file); // 4. Upload to IPFS const fileCID = await uploadToIPFS(ciphertext); // 5. Deploy contract const contract = await factory.deploy( price, commitment, fileCID, ... );

All cryptography runs in the browser using the Web Cryptography API — no external tools needed.

✓ After this phase: The encrypted file and buyer page are on IPFS. The contract is on L2. The seller shares one link.

Phase 2: Buyer Purchases

The buyer visits the IPFS link, connects MetaMask, and pays.

  • Visit IPFS buyer page
  • See file info and price
  • Connect MetaMask
  • Generate ECIES keypair
  • Send payment + public key to contract
  • Wait for key delivery
// Buyer's browser generates fresh keys: // Private key (32 bytes, never leaves browser) const privKey = crypto.getRandomValues( new Uint8Array(32) ); // Public key (65 bytes, sent to contract) const pubKey = secp256k1.getPublicKey( privKey, false // uncompressed ); // Send payment + public key await contract.purchase(pubKey, { value: ethers.parseEther("0.001") });

The public key is like a padlock the buyer sends to the seller. Only the buyer has the key to open it.

⏳ After payment: The contract holds the buyer's ETH and emits a PurchaseRequested event. The seller's watcher picks it up.

Phase 3: Automated Key Delivery

The seller's browser detects the purchase and delivers the encryption key, locked inside the buyer's public key.

💻 Seller Watcher ● online
📜 Contract deliverKey(id, encKey)
🛒 Buyer polling for key...
ECIES(pubKey, aesKey) →
← KeyDelivered event
// Seller's watcher (runs automatically in seller.html): contract.on('PurchaseRequested', async (id, buyer, pubKey) => { // Encrypt AES key with buyer's public key (ECIES) const encryptedKey = await eciesEncrypt(pubKey, aesKey); // Deliver on-chain await contract.deliverKey(id, encryptedKey); console.log(`✓ Key delivered to ${buyer}`); }); // This loop runs forever — every new buyer triggers a delivery // The seller just keeps the browser tab open
🔑 Key insight: The AES key is encrypted specifically for each buyer. Even if someone intercepts the on-chain data, they can't decrypt it without the buyer's private key.

Phase 4: Download & Decrypt

The buyer receives the encrypted key, decrypts it, downloads the encrypted file from IPFS, and decrypts it locally.

  • Detect KeyDelivered event from contract
  • Decrypt ECIES ciphertext → recover AES key
  • Verify: keccak256(key) == on-chain commitment ✓
  • Fetch encrypted file from IPFS
  • Decrypt file with AES-256-GCM
  • ✓ File downloaded! Sale complete.
// In buyer's browser: // 1. Decrypt the AES key const aesKey = await eciesDecrypt(myPrivateKey, encryptedKey); // 2. Total time: ~25 seconds
  • MetaMask approval: ~3s
  • Transaction confirm: ~5s
  • Key delivery: ~10s
  • IPFS download: ~5s
  • Decryption: <1s
If seller is offline:
  • Buyer waits for key delivery
  • After 1 hour: refund available
  • Buyer calls refund() → gets ETH back
  • No money lost, just time
