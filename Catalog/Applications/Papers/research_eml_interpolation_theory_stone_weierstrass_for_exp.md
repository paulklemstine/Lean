# EML Stone-Weierstrass Theory: Density and Complexity of Exp-Log Networks

## Abstract

We introduce the **EML algebra** — the algebra of functions generated by exponential, logarithm, addition, and multiplication — and prove that it is dense in C(K, ℝ) for compact K ⊂ (0, ∞) via the Stone-Weierstrass theorem. The key observation is that the identity function x ↦ x = exp(log(x)) lies in the EML algebra, providing point separation. We define **EML complexity** — the minimum size of an EML expression that ε-approximates a function — and establish structural results: constants have complexity 1, the identity has complexity 3, and degree-d polynomials have linear EML complexity O(d). We prove a strict depth hierarchy: exp(exp(x)) cannot be computed by any depth-1 EML expression, demonstrating that deeper networks are provably more expressive. Finally, we establish a Lipschitz transfer theorem connecting approximation error to function regularity. All results are machine-verified in Lean 4 using Mathlib.

**Keywords**: Stone-Weierstrass theorem, universal approximation, exp-log networks, computational complexity, depth hierarchy, Lipschitz transfer

## 1. Introduction

The Stone-Weierstrass theorem [Stone 1937, Weierstrass 1885] is one of the most powerful tools in approximation theory, guaranteeing that subalgebras of continuous functions satisfying mild conditions are dense in C(K, ℝ). While the theorem is typically applied to polynomial algebras, its scope extends to any subalgebra that separates points and contains constants.

We study the **EML algebra**: the algebra generated by compositions of the exponential function, the natural logarithm, addition, and multiplication. This algebra arises naturally in several contexts:

1. **Neural networks**: Networks with exp/log activation functions, including attention mechanisms and energy-based models.
2. **Approximation theory**: The identity x = exp(log(x)) shows that EML networks subsume polynomial approximation on positive domains.
3. **Complexity theory**: The EML framework provides a continuous analog of circuit complexity where gates compute exp and log.

Our main contributions are:
- A formal proof that the EML algebra is dense in C([a,b], ℝ) for 0 < a < b (Theorem 4.1).
- The introduction of **EML complexity** as a function complexity measure (Definition 7.1).
- A proof that depth-1 EML networks cannot compute exp(exp(x)), establishing a strict depth hierarchy (Theorem 10.1).
- A Lipschitz transfer theorem connecting approximation error to regularity (Theorem 8.1).
- A polynomial compression result showing degree-d polynomials have O(d) EML complexity (Theorem 9.1).

## 2. Definitions

### 2.1 EML Expressions

**Definition 2.1** (EML Expression). An *EML expression* is a term in the following grammar:
```
e ::= c | x | exp(e) | log(e) | e + e | e · e
```
where c ∈ ℝ is a constant and x is the input variable.

Formally, we define EML expressions as an inductive type:

```
inductive EMLExpr
  | const : ℝ → EMLExpr
  | var : EMLExpr
  | exp : EMLExpr → EMLExpr
  | log : EMLExpr → EMLExpr
  | add : EMLExpr → EMLExpr → EMLExpr
  | mul : EMLExpr → EMLExpr → EMLExpr
```

**Definition 2.2** (Evaluation). The evaluation `eval(e, x)` of an EML expression e at input x ∈ ℝ is defined recursively:
- eval(c, x) = c
- eval(var, x) = x
- eval(exp(e), x) = exp(eval(e, x))
- eval(log(e), x) = log(eval(e, x))
- eval(e₁ + e₂, x) = eval(e₁, x) + eval(e₂, x)
- eval(e₁ · e₂, x) = eval(e₁, x) · eval(e₂, x)

Note: We use Real.log, which returns 0 for non-positive inputs, ensuring eval is total.

### 2.2 Complexity Measures

**Definition 2.3** (Depth). The *depth* of an EML expression:
- depth(c) = depth(x) = 0
- depth(exp(e)) = depth(log(e)) = depth(e) + 1
- depth(e₁ ⊕ e₂) = max(depth(e₁), depth(e₂)) + 1

**Definition 2.4** (Size). The *size* of an EML expression:
- size(c) = size(x) = 1
- size(exp(e)) = size(log(e)) = size(e) + 1
- size(e₁ ⊕ e₂) = size(e₁) + size(e₂) + 1

### 2.3 EML Complexity

**Definition 2.5** (EML Approximation). An EML expression e *ε-approximates* a function f on [a,b] if for all x ∈ [a,b]: |f(x) - eval(e, x)| < ε.

**Definition 2.6** (EML Complexity). A function f has *EML complexity at most n at scale ε* if there exists an EML expression e with size(e) ≤ n that ε-approximates f.

**Definition 2.7** (Polynomial EML Complexity). A function f has *polynomial EML complexity* if there exist C, p > 0 such that f has EML complexity ⌈C · ε^{-p}⌉ at scale ε for all ε > 0.

## 3. Point Separation

The fundamental observation enabling density is:

**Lemma 3.1**. For x > 0: exp(log(x)) = x.

*Proof*. Direct from the inverse function theorem for exp and log. □

**Theorem 3.2** (EML Separation). The EML algebra separates points on any subset of (0, ∞). That is, for x ≠ y with x, y > 0, there exists an EML expression e such that eval(e, x) ≠ eval(e, y).

*Proof*. Take e = exp(log(var)). Then eval(e, x) = x ≠ y = eval(e, y). □

**Theorem 3.3** (EML Contains Constants). For any c ∈ ℝ, the constant function x ↦ c is in the EML algebra (via the expression const(c)).

## 4. Main Density Theorem

**Theorem 4.1** (EML Stone-Weierstrass). For 0 < a < b, the EML algebra is dense in C([a,b], ℝ) with respect to the uniform topology. Equivalently, for any continuous f : [a,b] → ℝ and ε > 0, there exists an EML expression e such that sup_{x ∈ [a,b]} |f(x) - eval(e, x)| < ε.

*Proof sketch*. The subalgebra A = Algebra.adjoin ℝ {id} ⊂ C([a,b], ℝ) generated by the identity function separates points (Theorem 3.2) and contains constants (as ℝ-scalar multiples of the unit). By Stone-Weierstrass (Mathlib: `ContinuousMap.subalgebra_topologicalClosure_eq_top_of_separatesPoints`), A is dense. Since the identity function id(x) = exp(log(x)) is EML-representable, A is contained in the EML algebra, hence the EML algebra is also dense. □

**Corollary 4.2**. For any f ∈ C([a,b], ℝ) and ε > 0, there exists a polynomial g in the subalgebra generated by the identity (hence an EML function) with dist(f, g) < ε in the sup-norm.

## 5. Depth-0 Classification

**Theorem 5.1**. Every depth-0 EML expression computes either a constant function or the identity function.

*Proof*. By case analysis: the only depth-0 expressions are const(c) and var. □

## 6. Depth-Size Tradeoff

**Theorem 6.1**. For any EML expression e: depth(e) + 1 ≤ size(e).

*Proof*. By structural induction on e.
- Base: depth(c) + 1 = 1 = size(c), depth(x) + 1 = 1 = size(x).
- Unary: depth(exp(e)) + 1 = depth(e) + 2. By IH, depth(e) + 1 ≤ size(e), so depth(e) + 2 ≤ size(e) + 1 = size(exp(e)).
- Binary: depth(e₁ ⊕ e₂) + 1 = max(depth(e₁), depth(e₂)) + 2. By IH and the fact that max(a,b) + 1 ≤ a + 1 + b ≤ size(e₁) + size(e₂) = size(e₁ ⊕ e₂) - 1 + 1. □

## 7. EML Complexity Results

**Theorem 7.1**. Constants have EML complexity 1 at any scale ε > 0.

*Proof*. The expression const(c) has size 1 and exactly computes the constant function c. □

**Theorem 7.2**. The identity function has EML complexity at most 3 on [a,b] with a > 0.

*Proof*. The expression exp(log(var)) has size 3 and exactly computes the identity on positive reals. □

## 8. Lipschitz Transfer

**Theorem 8.1** (Lipschitz Transfer). If f is K-Lipschitz on [a,b] and g is an ε-approximation to f, then for all x, y ∈ [a,b]:

|g(x) - g(y)| ≤ K|x - y| + 2ε

*Proof*. By the triangle inequality:
|g(x) - g(y)| ≤ |g(x) - f(x)| + |f(x) - f(y)| + |f(y) - g(y)| < ε + K|x-y| + ε = K|x-y| + 2ε. □

This result connects EML approximation to the Lipschitz error bounds established in the project catalog (cf. `lipschitz_cellwise_error_bound` in Bridges/ContinuousDiscreteTransfer.lean).

## 9. Polynomial Compression

**Theorem 9.1** (Polynomial Compression). For any degree d, there exists a constant C = 11 such that any polynomial of degree d can be represented by an EML expression of size at most C · (d + 1).

*Proof*. The key identity is x^n = exp(n · log(x)) for x > 0. The expression emlPower(n) := exp(const(n) · log(var)) has size 5 (constant, independent of n). Each term aᵢ · x^i requires const(aᵢ) · emlPower(i), which has size 7. Summing d + 1 terms with addition nodes gives total size ≤ 7(d+1) + d ≤ 11(d+1). □

**Theorem 9.2**. emlPower(n) has size exactly 5 for all n ∈ ℕ.

**Theorem 9.3**. For x > 0 and n ∈ ℕ: eval(emlPower(n), x) = x^n.

## 10. Depth Hierarchy

**Theorem 10.1** (Depth Separation). The function exp(exp(x)) cannot be computed by any depth-1 EML expression.

*Proof*. Suppose e has depth ≤ 1 and eval(e, x) = exp(exp(x)) for all x ∈ ℝ. By depth-0 classification and depth-1 structure analysis, every depth-≤1 expression has one of finitely many forms:
- const(c): contradicts exp(exp(0)) ≠ exp(exp(1))
- var: contradicts eval(var, 0) = 0 ≠ e ≈ 2.718
- exp(const(c)): constant, contradiction
- exp(var): eval(e, 0) = 1 ≠ e ≈ 2.718
- log(const(c)): constant, contradiction
- log(var): eval(e, 1) = 0 ≠ exp(e)
- Arithmetic combinations of depth-0 subexpressions

Each form is ruled out by evaluating at x = 0 and x = 1, showing numerical contradictions with the doubly-exponential growth of exp(exp(x)). □

**Corollary 10.2**. The EML depth hierarchy is strict: depth d+1 is provably more expressive than depth d (at least for d = 0, 1).

## 11. Monotonicity and Structural Properties

**Theorem 11.1**. The composition exp ∘ log is strictly monotone on (0, ∞).

*Proof*. Since exp(log(x)) = x on (0, ∞), this reduces to strict monotonicity of the identity. □

**Theorem 11.2**. exp is strictly monotone on ℝ (from Mathlib).

**Theorem 11.3**. log is strictly monotone on (0, ∞) (from Mathlib).

## 12. Discussion

### 12.1 Comparison with Neural Network Approximation

The universal approximation theorem for neural networks [Cybenko 1989, Hornik 1991] shows that shallow networks with sigmoidal activations are dense in C(K, ℝ). Our result provides an analogous guarantee for EML networks, with the advantage of explicit size bounds through the polynomial compression theorem.

### 12.2 Connection to the Catalog

Our Lipschitz transfer theorem (Theorem 8.1) directly extends the `lipschitz_cellwise_error_bound` results in the project catalog. The depth hierarchy (Theorem 10.1) relates to `not_exists_uniform_exp_depth_bound` in Bridges/ArrowDepthComplexity.lean, providing a concrete instance of depth separation in the EML setting.

### 12.3 Open Questions

1. **Full depth hierarchy**: Does the hierarchy extend to all depths? Is there a function computable at depth d+1 but not depth d, for every d?

2. **Tight EML complexity bounds**: What is the optimal constant in the polynomial compression theorem? Is C = 11 tight?

3. **Non-positive domains**: Our density result requires K ⊂ (0, ∞). Can the EML algebra be extended to handle functions on all of ℝ?

4. **Quantitative rates**: For f ∈ Lip_α(K), what is the precise EML complexity in terms of α and ε?
