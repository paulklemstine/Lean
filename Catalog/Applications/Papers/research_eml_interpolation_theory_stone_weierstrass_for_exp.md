# EML Stone-Weierstrass: Density and Depth Complexity of Exp-Log Networks

## Abstract

We introduce the **EML algebra** — the subalgebra of C(K, ℝ) generated by the exponential function, the logarithm, and the coordinate projection, on compact subsets K ⊂ (0, ∞). We prove the **EML Density Theorem**: this subalgebra is dense in C(K, ℝ), establishing that any continuous function on a positive compact set can be uniformly approximated by finite compositions of exp, log, addition, and multiplication. The proof applies the Stone-Weierstrass theorem, using the coordinate function for point separation.

We also introduce the **EML term language**, an inductive syntax for exp-log networks with a natural **depth measure**, and prove the **Monomial Depth Theorem**: the monomial x^n can be represented by the EML term exp(n · log(x)) at depth exactly 3, independent of the degree n. This demonstrates that exp-log circuits achieve exponential compression over arithmetic circuits for monomial evaluation.

We formalize these results in Lean 4 with complete, machine-verified proofs, building on the Mathlib library's formalization of the Stone-Weierstrass theorem.

**Keywords**: Stone-Weierstrass theorem, exp-log networks, universal approximation, circuit depth, EML algebra, formal verification

## 1. Introduction

### 1.1 Background

The Stone-Weierstrass theorem is a cornerstone of functional analysis, generalizing Weierstrass's classical polynomial approximation theorem. In its algebraic form, it states: if X is a compact Hausdorff space and A is a subalgebra of C(X, ℝ) that separates points of X and contains constants, then A is dense in C(X, ℝ) in the uniform topology.

The theorem's power lies in its generality: to prove density, one need only verify the algebraic closure and separation properties. This has been applied to prove universal approximation results for various function classes, including polynomials, trigonometric polynomials, and neural network architectures.

### 1.2 Motivation: Exp-Log Networks

The class of functions computable by finite compositions of {exp, log, +, ×} — which we call **EML functions** (Exponential-Multiply-Logarithm) — is of interest in several areas:

1. **Neural networks**: Networks with exponential and logarithmic activation functions appear naturally in multiplicative architectures and attention mechanisms.

2. **Circuit complexity**: The depth of an EML circuit measures sequential computation cost, and the exp-log trick (x^n = exp(n log x)) provides exponential depth compression for monomials.

3. **Numerical analysis**: EML functions include all elementary transcendental functions and are the natural building blocks for many numerical algorithms.

### 1.3 Contributions

We make four contributions:

1. **EML Density Theorem** (Theorem 4.1): On compact K ⊂ (0, ∞), the EML algebra is dense in C(K, ℝ).

2. **EML Separation Theorem** (Theorem 3.1): The EML algebra separates points via the coordinate function.

3. **Monomial Depth Theorem** (Theorem 5.1): The monomial x^n has EML depth exactly 3, independent of n.

4. **Depth Filtration** (Section 6): The depth measure induces a monotone filtration of the EML term space, with a complete characterization at depth 0.

All results are formalized in Lean 4 with complete proofs, using the Mathlib library.

## 2. Definitions

### 2.1 EML Terms

**Definition 2.1** (EML Term). An EML term is an element of the inductive type:
```
Term ::= const(c) | var | exp(t) | log(t) | add(t₁, t₂) | mul(t₁, t₂)
```
where c ∈ ℝ and t, t₁, t₂ are EML terms.

**Definition 2.2** (Evaluation). The evaluation function eval : Term → ℝ → ℝ is defined recursively:
- eval(const(c), x) = c
- eval(var, x) = x
- eval(exp(t), x) = exp(eval(t, x))
- eval(log(t), x) = log(eval(t, x))
- eval(add(t₁, t₂), x) = eval(t₁, x) + eval(t₂, x)
- eval(mul(t₁, t₂), x) = eval(t₁, x) · eval(t₂, x)

**Definition 2.3** (Depth). The depth of an EML term:
- depth(const(c)) = depth(var) = 0
- depth(exp(t)) = depth(log(t)) = depth(t) + 1
- depth(add(t₁, t₂)) = depth(mul(t₁, t₂)) = max(depth(t₁), depth(t₂)) + 1

**Definition 2.4** (Size). The size of an EML term counts the total number of nodes in the abstract syntax tree.

### 2.2 The EML Subalgebra

**Definition 2.5** (EML Subalgebra). For a compact interval [a, b] ⊂ (0, ∞), the EML subalgebra is:
```
A_EML = Algebra.adjoin ℝ {coord, exp|_K, log|_K}
```
where:
- coord : K → ℝ is the coordinate projection x ↦ x
- exp|_K : K → ℝ is exp restricted to K
- log|_K : K → ℝ is log restricted to K (continuous since K ⊂ (0, ∞))

This is the smallest ℝ-subalgebra of C(K, ℝ) containing these three generators.

## 3. Separation Property

**Theorem 3.1** (EML Separation). The EML subalgebra A_EML separates points of K = [a, b].

*Proof sketch.* The coordinate function coord ∈ A_EML (as a generator) is injective on K: if x ≠ y then coord(x) = x.val ≠ y.val = coord(y) by the injectivity of Subtype.val. Since coord belongs to A_EML and separates any pair of distinct points, A_EML separates points. □

*PEGB Analysis:*
- **Proof**: Complete formal proof via Subtype.val injectivity.
- **Example**: On [1, 2], coord(1) = 1 ≠ 2 = coord(2).
- **Generalization**: Any subalgebra containing an injective continuous function separates points.
- **Boundary**: On a singleton {a}, separation is vacuously true (no distinct points exist).

## 4. Density Theorem

**Theorem 4.1** (EML Density). For 0 < a ≤ b, the EML subalgebra A_EML on [a, b] satisfies:
```
closure(A_EML) = C([a, b], ℝ)
```

*Proof.* By Theorem 3.1, A_EML separates points. As a subalgebra over ℝ, it contains constants (algebraic constants are in any subalgebra). By the Stone-Weierstrass theorem (Mathlib's `ContinuousMap.subalgebra_topologicalClosure_eq_top_of_separatesPoints`), the topological closure of A_EML equals ⊤ = C(K, ℝ). □

**Corollary 4.2** (Quantitative Approximation). For any f ∈ C([a, b], ℝ) and ε > 0, there exists g ∈ A_EML with dist(f, g) < ε.

*PEGB Analysis:*
- **Proof**: Direct application of Stone-Weierstrass.
- **Example**: x² on [1, 2] is approximated exactly by exp(2 log(x)) ∈ A_EML.
- **Generalization**: The theorem extends to any compact K ⊂ (0, ∞), not just intervals. It also extends to higher dimensions via multivariate EML terms.
- **Boundary**: At a = 0, log is discontinuous, and the theorem fails. The restriction to (0, ∞) is necessary for log to be a continuous generator.

## 5. Monomial Depth Theorem

**Definition 5.1**. The monomial term for degree n is:
```
M_n = exp(mul(const(n), log(var)))
```

**Theorem 5.1** (Monomial Depth). For all n ∈ ℕ:
1. depth(M_n) = 3
2. size(M_n) = 5
3. For x > 0: eval(M_n, x) = x^n

*Proof of (3).* We have eval(M_n, x) = exp(n · log(x)). By the identity exp(n · log(x)) = (exp(log(x)))^n = x^n (using exp ∘ log = id on (0, ∞) and the exponential law). Formally, this uses `Real.exp_nat_mul` and `Real.exp_log`. □

*PEGB Analysis:*
- **Proof**: Complete formal proof using exp_nat_mul and exp_log.
- **Example**: M_2 evaluates to x² on (0, ∞). At x = 3: exp(2 · log(3)) = exp(log(9)) = 9 = 3².
- **Generalization**: For real exponents α, exp(α · log(x)) = x^α, giving constant-depth EML representation of arbitrary real powers.
- **Boundary**: At x = 0, log(0) is undefined (returns 0 in Mathlib's convention), so exp(n · log(0)) = exp(0) = 1 ≠ 0^n for n ≥ 1. The restriction to positive reals is essential.

**Remark 5.2** (Depth compression). In a purely arithmetic circuit (using only +, ×), computing x^n requires depth Ω(log n) — this is a classical result of Brent (1974). The EML monomial term achieves depth 3 for any n, demonstrating that exp and log provide *exponential depth compression*.

---

## 6. Depth Filtration

**Definition 6.1**. The depth-d term set is:
```
A_d = {t : Term | depth(t) ≤ d}
```

**Theorem 6.1** (Monotonicity). The filtration is monotone: d₁ ≤ d₂ ⟹ A_{d₁} ⊆ A_{d₂}.

**Theorem 6.2** (Depth 0 characterization). A₀ = {const(c) | c ∈ ℝ} ∪ {var}.

**Theorem 6.3** (Depth bounds). For any term t:
- depth(t) ≤ size(t) - 1
- size(t) ≥ 1

---

## 7. Exp-Log Identities

**Theorem 7.1**. For all x ∈ ℝ: eval(log(exp(var)), x) = x.

**Theorem 7.2**. For x > 0: eval(exp(log(var)), x) = x.

**Theorem 7.3** (Depth non-uniqueness). The identity function has EML representations at depth 0 (as var) and depth 2 (as log(exp(var))). Thus the minimum depth of a function is not determined by any single representation.

## 8. Discussion

### 8.1 Comparison with Polynomial Approximation

The classical Weierstrass theorem shows that polynomials are dense in C(K, ℝ). The EML Density Theorem shows the same for EML functions. The advantage of EML is the depth structure: monomials of degree n require polynomial circuit depth Ω(log n) but EML circuit depth only 3.

### 8.2 Relation to Neural Network Theory

The universal approximation theorem for neural networks (Cybenko, Hornik) is structurally similar to our EML Density Theorem. Both use variants of Stone-Weierstrass. The EML framework offers a more refined complexity measure (depth) that better reflects the sequential computation cost.

### 8.3 The Role of Positivity

Our density theorem requires K ⊂ (0, ∞) because log is only continuous on positive reals. For K containing 0, one would need a modified EML algebra — for instance, replacing log with a regularized version log(|x| + ε). Whether such modifications preserve density is an open question.

### 8.4 Open Problems

1. **Jackson-type rates**: Can we prove quantitative approximation rates relating the depth/size of an EML term to the smoothness of the target function?

2. **Depth hierarchy**: Is the depth filtration strictly increasing beyond depth 3? That is, are there continuous functions requiring EML depth d for every d?

3. **Multivariate extension**: Extend the EML framework to functions of several variables, with coordinate projections as generators.

## 9. Algorithms

### 9.1 EML Evaluation

Given an EML term t and input x > 0, evaluation proceeds by recursive descent:
```
EVALUATE(t, x):
  match t:
    const(c) → return c
    var → return x
    exp(s) → return exp(EVALUATE(s, x))
    log(s) → return log(EVALUATE(s, x))
    add(s₁, s₂) → return EVALUATE(s₁, x) + EVALUATE(s₂, x)
    mul(s₁, s₂) → return EVALUATE(s₁, x) × EVALUATE(s₂, x)
```

Time complexity: O(size(t)). Space complexity: O(depth(t)) for the recursion stack.

### 9.2 Monomial Construction

Given degree n, construct the EML term for x^n:
```
MONOMIAL(n):
  return exp(mul(const(n), log(var)))
```
Time: O(1). Resulting term has depth 3, size 5.
