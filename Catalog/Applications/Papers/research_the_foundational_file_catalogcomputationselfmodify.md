# Discrete Dynamics of Self-Modifying Computation

## Abstract

A *self-modifying machine* is a computational device whose program may be
rewritten at every step of execution. We study such machines through the lens of
discrete dynamical systems. Building on the behavioural simulation theorem —
that a self-modifying machine over program space `P` and state space `S` is
equivalent to a fixed-program machine over the product `P × S`, so its halting
problem is Turing-equivalent to the classical one — we move from *behaviour* to
*dynamics*. A machine that never halts is, on its configuration space, a
self-map `dyn : P × S → P × S`, and running it for `n` steps is exactly
iterating `dyn` `n` times. Transporting the elementary theory of finite
dynamical systems across this bridge, we establish three structural facts about
**finite** self-modifiers, two of them in tension. (1) *Finiteness makes
prediction trivial:* every orbit is confined to the first `card(P × S)`
iterates, so any infinite-horizon orbit property reduces to a bounded search of
length `card(P × S)`. (2) *Finiteness forces self-reproduction:* every total
finite machine re-enters a previously visited configuration within
`card(P × S)` steps — a finitary Kleene/quine fixed point. (3) *Reachability,
not step complexity, is where control fails:* under strong connectivity a single
bad configuration admits no nonempty forward-invariant region of safe states, so
no state-based monitor can keep the machine aligned, and every start reaches a
bad state. All results are formally verified; the entire theory is generated by
a single pigeonhole collision among the first `card(P × S) + 1` iterates.

**Keywords:** self-modifying computation, discrete dynamical systems, finite
self-maps, eventual periodicity, halting problem, quines, AI alignment,
forward-invariant sets, reachability.

## 1. Introduction

### 1.1 Motivation

Self-modifying code — programs that alter their own instructions during
execution — appears across computing: just-in-time compilers, genetic
programming, reflective and metacircular interpreters, polymorphic malware, and,
abstractly, any learning agent that updates the policy governing its own
behaviour. A persistent folk belief holds that self-modification makes
termination and safety analysis *fundamentally harder* than for fixed programs.

The behavioural picture refutes the first half of this belief. If we model one
step of a self-modifier as a partial function
`step : P → S → Option (P × S)` — taking the current program `p` and state `s`
to either `none` (halt) or a *new* pair `(p', s')` — then encoding the program
as part of the state yields a standard fixed-program machine over `P × S`, and
the two halt on exactly the same inputs. Self-modification is, behaviourally, a
matter of bookkeeping: the program is just data. Consequently the self-modifying
halting problem is Turing-equivalent to the classical one — no harder, no
easier.

This paper asks the *dynamical* question that behavioural equivalence leaves
open: what is the structure of the **orbit** of a configuration under repeated
self-modification, particularly when memory is finite? Finite configuration
spaces are the natural setting for any physically realizable agent, and the
answer turns out to cleanly separate two notions that are often conflated:
*predictability* and *controllability*.

### 1.2 Contributions

We work in two layers.

- **An abstract finite-dynamics layer** (`FiniteDynamics`), developed for an
  arbitrary self-map `f : A → A` on a finite type `A`. From a single pigeonhole
  collision we derive eventual periodicity, orbit confinement, and an
  all-or-nothing dichotomy for forward-invariant sets under strong connectivity,
  yielding an abstract *alignment obstruction*.

- **A self-modifying-machine layer**, where a never-halting (*total*) machine is
  realized as a self-map `dyn` via the bridge lemma `run = dyn^[·]`, and each
  abstract fact specializes to a statement about machines: a *quine cycle*
  theorem, a *bounded-search* characterization of orbit safety, and a
  *machine-level alignment obstruction*.

The conceptual payload is that, on finite memory, prediction is trivial while
control may be impossible, and the impossibility is governed entirely by the
**reachability relation**, never by the complexity of the step map.

## 2. The Computational Model

### 2.1 Self-modifying machines

**Definition 2.1 (Self-modifying machine).** A self-modifying machine over
program type `P` and state type `S` is a step function
`step : P → S → Option (P × S)`. A *configuration* is a pair `(p, s) ∈ P × S`.

**Definition 2.2 (Run).** The `n`-step run is defined by
`run (p, s) 0 = some (p, s)` and
`run (p, s) (n+1) = ` (if `step p s = none` then `none` else
`run (p', s') n` where `step p s = some (p', s')`).

**Definition 2.3 (Halting).** The machine *halts* from `(p, s)` if
`∃ n, run (p, s) n = none`.

**Definition 2.4 (Standard simulation).** The standard simulation `toStd` is the
fixed-program machine over `P × S` with step
`(p, s) ↦ step p s` (interpreted as `Option (P × S)`).

**Theorem 2.5 (Behavioural equivalence — foundational).** The machine halts from
`(p, s)` iff `toStd` halts from `(p, s)`.

*Proof sketch.* A step-indexed induction shows that `run (p, s) n`, mapped to its
program–state pair, equals `toStd.run (p, s) n` for all `n`; halting is
"`∃ n, · = none`", which the map preserves. ∎

Theorem 2.5 yields the many-one equivalence of the two halting problems and
their shared undecidability (via abstract diagonalization), but says nothing
about orbit structure. We now turn to dynamics.

### 2.2 Total machines as self-maps

**Definition 2.6 (Total machine).** A machine is *total* if `step p s ≠ none`
for all `(p, s)`; equivalently it never halts.

**Definition 2.7 (The dynamics map).** For a total machine, define
`dyn : P × S → P × S` by `dyn (p, s) = (p', s')` where `step p s = some (p', s')`
(well defined by totality).

**Lemma 2.8 (Run equals iterate, `run_eq_iter`).** For a total machine and every
`n`, running for `n` steps equals iterating `dyn`:
`run (p, s) n = some (dyn^[n] (p, s))`.

*Proof sketch.* Induction on `n`. The base case is `run (p,s) 0 = some (p,s) =
some (dyn^[0] (p,s))`. In the step case, totality means `step p s = some (dyn
(p,s))`, so `run (p,s) (n+1) = run (dyn (p,s)) n`, which by the inductive
hypothesis equals `some (dyn^[n] (dyn (p,s))) = some (dyn^[n+1] (p,s))`. ∎

Lemma 2.8 is the bridge: every dynamical fact about iterating `dyn` becomes a
fact about the machine.

## 3. The Finite-Dynamics Layer

Throughout this section `A` is a type, `f : A → A` a self-map, and where stated
`A` is a finite type with `N := card A`.

### 3.1 Basic relations

**Definition 3.1 (Reaches).** `Reaches f x y :⇔ ∃ n, f^[n] x = y`. We say `y`
lies on the forward orbit of `x`.

**Definition 3.2 (Strong connectivity).** `StronglyConnected f :⇔ ∀ x y,
Reaches f x y`: every configuration reaches every other.

**Definition 3.3 (Forward invariance).** A set `R ⊆ A` is *forward-invariant*
if `∀ x ∈ R, f x ∈ R`.

### 3.2 The generating collision

**Theorem 3.4 (Iterate collision, `iterate_collision`).** For finite `A`,
every `f` and `x`, there exist `i < j ≤ N` with `f^[i] x = f^[j] x`.

*Proof sketch.* Consider the map `k ↦ f^[k] x` on the index set
`{0, 1, …, N}`, which has `N + 1 > N = card A` elements. By pigeonhole
(`Fintype.exists_ne_map_eq_of_card_lt`) two distinct indices `a ≠ b` have
`f^[a] x = f^[b] x`; order them to obtain `i < j`, and `j ≤ N` since indices lie
in `{0, …, N}`. ∎

This is the *only* nontrivial combinatorial input; everything below is a
deduction from it.

### 3.3 Eventual periodicity and orbit confinement

**Theorem 3.5 (Eventual periodicity, `dyn_eventually_periodic`).** For finite
`A`, every `f` and `x`, there exist `k ≤ N` and `p` with `0 < p ≤ N` and
`f^[p] (f^[k] x) = f^[k] x`. Thus every point reaches a periodic point within
`N` steps, with positive period at most `N`.

*Proof sketch.* Take the collision `i < j ≤ N`. Set `k = i` and `p = j - i`.
Then `0 < p ≤ N`, and
`f^[p] (f^[i] x) = f^[(j-i)+i] x = f^[j] x = f^[i] x`,
using `iterate_add_apply` and `(j - i) + i = j`. ∎

**Theorem 3.6 (Orbit confinement, `orbit_mem_initial_segment`).** For finite
`A`, every `f`, `x`, and `n`, there is `k ≤ N` with `f^[n] x = f^[k] x`.

*Proof sketch.* From the collision `i < j` with `p = j - i`, the orbit is
`p`-periodic from index `i` onward: `f^[m+p] x = f^[m] x` for all `m ≥ i` (proved
by rewriting `m + p = (m - i) + (i + p)` and `i + p = j`, then folding through
the collision). Now induct on `n` by strong induction. If `n ≤ N` take `k = n`.
If `n > N` then `n > p` and `n - p ≥ i`, so `f^[n] x = f^[n-p] x` by the
periodicity identity; the inductive hypothesis applied to `n - p < n` supplies a
`k ≤ N` with `f^[n-p] x = f^[k] x`, hence `f^[n] x = f^[k] x`. ∎

Theorem 3.6 is the crux: *the entire infinite forward orbit is contained in its
first `N + 1` points.*

### 3.4 Invariant sets and the alignment obstruction

**Lemma 3.7 (Invariance is iteration-stable, `iterate_mem_of_forwardInvariant`).**
If `R` is forward-invariant and `x ∈ R`, then `f^[n] x ∈ R` for all `n`.

*Proof sketch.* Induction on `n`: the base case is `x ∈ R`; the step case uses
`f^[n+1] x = f (f^[n] x)` and forward invariance. ∎

**Theorem 3.8 (All-or-nothing dichotomy,
`forwardInvariant_eq_univ_of_stronglyConnected`).** If `f` is strongly connected
and `R` is nonempty and forward-invariant, then `R = A` (the whole space).

*Proof sketch.* Fix `x ∈ R`. For arbitrary `y`, strong connectivity gives `n`
with `f^[n] x = y`; Lemma 3.7 gives `f^[n] x ∈ R`; hence `y ∈ R`. ∎

**Theorem 3.9 (Abstract alignment obstruction, `alignment_obstruction`).** If
`f` is strongly connected and the predicate `bad : A → Prop` holds of at least
one element, then there is *no* set `R` that is simultaneously nonempty,
forward-invariant, and entirely safe (`∀ x ∈ R, ¬ bad x`).

*Proof sketch.* Suppose such `R` exists. By Theorem 3.8, `R = A`. Let `b` be a
bad element; then `b ∈ R`, contradicting safety of `R`. ∎

**Theorem 3.10 (Bad states are universally reachable,
`reaches_bad_of_stronglyConnected`).** If `f` is strongly connected and `bad b`
holds, then for every `x` there is `n` with `bad (f^[n] x)`.

*Proof sketch.* Strong connectivity gives `n` with `f^[n] x = b`; substitute. ∎

These two are complementary readings of the same fact: no safe trap exists
(3.9), and indeed every trajectory hits the bad set (3.10).

## 4. The Machine Layer

We now specialize the finite-dynamics layer to a total self-modifying machine on
a finite configuration space `P × S`, writing `N := card (P × S)` and using the
bridge Lemma 2.8.

### 4.1 Quine cycles

**Theorem 4.1 (Quine cycle, `selfmod_quine_cycle`).** Let `m` be a total
self-modifying machine on a finite `P × S`, and let `c₀ = (p, s)`. Then there
exist `i < j ≤ N` such that `run c₀ i = run c₀ j` (the configuration reached
after `i` steps equals that reached after `j` steps), and the machine runs
forever (never returns `none`). In particular some configuration on the orbit is
revisited within `N` steps and is periodic.

*Proof sketch.* Totality gives, via Lemma 2.8, `run c₀ n = some (dyn^[n] c₀)`,
so the machine never halts. Apply Theorem 3.4 to `dyn` and `c₀`: there are
`i < j ≤ N` with `dyn^[i] c₀ = dyn^[j] c₀`; transporting along `run_eq_iter`
gives `run c₀ i = run c₀ j`. By Theorem 3.5 the revisited configuration is
periodic with period `≤ N`. ∎

This is a finitary analogue of Kleene's recursion theorem: on finite memory,
self-reproduction is not constructed but *forced*. An immortal finite
self-modifier must eventually become a quine.

### 4.2 Bounded-search safety

**Theorem 4.2 (Bounded search, `selfmod_reaches_bad_iff_bounded`).** Let `m` be
a total machine on a finite `P × S`, and let `R` be any set of configurations
("bad" states). Then the machine *ever* reaches `R` from `c₀` if and only if it
reaches `R` within the first `N` steps:
`(∃ n, dyn^[n] c₀ ∈ R) ↔ (∃ n ≤ N, dyn^[n] c₀ ∈ R)`.

*Proof sketch.* The `(⇐)` direction is immediate. For `(⇒)`, suppose
`dyn^[n] c₀ ∈ R`. By Theorem 3.6 there is `k ≤ N` with `dyn^[n] c₀ = dyn^[k] c₀`,
so `dyn^[k] c₀ ∈ R` with `k ≤ N`. ∎

An infinite-horizon orbit property is therefore decidable by simulating exactly
`N` steps. On bounded memory self-modification adds **no** analytic difficulty —
a sharp counterpoint to the undecidability of the unbounded case.

### 4.3 Machine alignment obstruction

**Theorem 4.3 (Machine alignment obstruction,
`selfmod_alignment_obstruction`).** Let `m` be a total machine on a finite
`P × S` whose dynamics `dyn` is strongly connected, and suppose at least one
configuration is bad. Then there is no nonempty, forward-invariant region of
exclusively safe configurations; equivalently, from every starting configuration
the machine reaches a bad configuration.

*Proof sketch.* Apply the abstract Theorems 3.9 and 3.10 to `f = dyn`, and
translate "orbit point" to "configuration reached by `run`" via Lemma 2.8. ∎

No state-based monitor — a rule inspecting the current configuration to permit
or forbid it — can confine such a machine to safety, because the only nonempty
forward-invariant region is the whole space, which contains the bad state.

## 5. Discussion

### 5.1 Predictability versus controllability

The results split cleanly along a fault line:

- **Predictability is trivial on finite memory.** Orbit confinement (3.6) and
  its machine form (4.2) reduce any infinite-horizon question to an `N`-step
  search. Whatever a finite self-modifier will *ever* do, it does within `N`
  steps; the rest is repetition (4.1).
- **Controllability can be impossible on finite memory.** The alignment
  obstruction (3.9 / 4.3) shows that strong connectivity plus a single bad state
  forecloses every nontrivial safe invariant region.

Crucially, the obstruction is insensitive to the step map's complexity. One may
take the simplest imaginable `dyn` (e.g. a single directed cycle through all
configurations); strong connectivity alone, together with one bad state, kills
safety. The locus of difficulty is the **reachability relation**, not
computational complexity.

### 5.2 Design implication

The practical reading inverts the usual concern. The worry about self-modifiers
is typically framed as runaway *power* or *unpredictability*; on finite memory
that worry is misplaced, since everything recurs within `N` steps. The genuine
obstacle to safety is *connectivity*. To make a state-based monitor possible one
must *engineer the reachability graph* so that a nontrivial forward-invariant
safe region exists — i.e. so that the unsafe set is genuinely walled off and
cannot be reached from the operating region. This is a structural, topological
design goal about the orbit graph, not a constraint on per-step logic.

### 5.3 Relation to classical results

Theorem 2.5 places self-modifying halting at the classical Turing degree
(Σ⁰₁). The quine cycle (4.1) is the finitary shadow of Kleene's recursion
theorem. The bounded-search theorem (4.2) is the dynamical counterpart of the
decidability of bounded halting. The alignment obstruction (3.9) is a
dynamical-systems statement — about forward-invariant sets of a strongly
connected map — repurposed as a safety/control theorem.

## 6. Algorithms

The constructive content of the finite-dynamics layer yields directly executable
procedures on any finite configuration space.

**Algorithm A — Orbit Confinement & Cycle Detection.** Iterate `dyn` from `c₀`,
recording the first occurrence index of each configuration in a table. The first
repeated configuration witnesses the collision `i < j ≤ N` of Theorem 3.4: `i`
is the recorded index of the repeat (the *preperiod tail length*) and `j - i` is
the *period*. Halts within `N + 1` iterations. Complexity: `O(N · cost(step))`
time, `O(N)` space (or `O(1)` extra space via Floyd's two-pointer variant).

**Algorithm B — Bounded Safety Search.** To decide whether a total machine ever
enters bad region `R`, simulate at most `N` steps and test membership in `R` at
each (Theorem 4.2). Returns the first witnessing step, or reports safety.
Complexity: `O(N · (cost(step) + cost(R)))`.

**Algorithm C — Strong-Connectivity / Alignment Audit.** Build the functional
graph of `dyn` (`N` nodes, one out-edge each), compute its strongly connected
components, and inspect the unique terminal component (the eventual cycle).
The machine is "unavoidably unsafe from every start" exactly when every start's
terminal cycle intersects `R`; under full strong connectivity (single terminal
SCC equal to the whole graph) a single bad state suffices (Theorem 4.3).
Complexity: `O(N · cost(step))` to build the graph plus linear SCC analysis.

## 7. Worked Examples

We make the theory concrete on three families of finite machines; all numbers
below are reproducible by direct iteration.

### 7.1 A single directed cycle

Let `P × S = {0, 1, …, 5}` (so `N = 6`) and `dyn(c) = (c + 1) mod 6`. This map
is total (every state has a successor) and strongly connected (following the
arrow long enough reaches any target). Starting at `c₀ = 0` the orbit is
`0, 1, 2, 3, 4, 5, 0, …`. The iterate collision (Theorem 3.4) fires at `i = 0`,
`j = 6`: `dyn^[0](0) = dyn^[6](0) = 0`. Hence the preperiod is `0` and the period
is `6` — the maximal possible — and the quine cycle (Theorem 4.1) is the entire
space. Orbit confinement (Theorem 3.6) is visible because there are only six
distinct values. Flagging `bad = {3}`, strong connectivity makes every start
reach `3` (Theorem 4.3): from `0` in three steps, from `4` in five steps, and so
on. The maximal safe forward-invariant region is empty.

### 7.2 A rho-shaped machine (genuine preperiod)

Let `N = 6` and define `dyn` by the successor table
`0↦1, 1↦2, 2↦3, 3↦4, 4↦2, 5↦0`. The orbit of `0` is
`0, 1, 2, 3, 4, 2, 3, 4, 2, …`: a tail `0 → 1 → 2` feeding a 3-cycle
`2 → 3 → 4 → 2`. The collision is `i = 2`, `j = 5`, giving preperiod `k = 2`
(≤ N) and period `p = 3` (0 < p ≤ N), exactly as Theorem 3.5 predicts; one
checks `dyn^[k+p](0) = dyn^[5](0) = 2 = dyn^[2](0) = dyn^[k](0)`. Orbit
confinement is non-vacuous here: `dyn^[1000000](0)` is *not* literally one of the
first points by index, but it equals `dyn^[4](0) = 4`, with witness `k = 4 ≤ N`.
This machine is *not* strongly connected (nothing reaches `5` except `5`
itself), so the alignment obstruction does not apply; indeed for `bad = {5}` the
maximal safe invariant region is `{0, 1, 2, 3, 4}`, a nonempty forward-invariant
safe set, and control is possible.

### 7.3 Affine self-modification on ℤ/n

Let `dyn(c) = (a·c + b) mod n`, a one-line model of linear code rewriting. For
`n = 7`, `b = 0`, and varying multiplier `a`, the cycle length through `c = 1`
tracks the multiplicative order of `a` in `(ℤ/7)^*`: `a = 1` gives period `1`,
`a = 2` and `a = 4` give period `3`, `a = 6` gives period `2`, and the primitive
roots `a = 3, 5` give the full period `6`. This is the empirical seed of Future
Direction #1: the generic quine-cycle bound `N` is rarely tight, and for affine
dynamics the realized period is an *order* computation rather than a search. The
contrast with §7.1 is instructive: the additive map `a = 1, b = 1` realizes the
worst-case period `N`, while multiplicative maps realize exponentially shorter
cycles.

### 7.4 Reading the examples

The three families exhibit the full qualitative range. The pure cycle (§7.1) is
the worst case for prediction horizon yet the cleanest illustration of the
obstruction. The rho machine (§7.2) shows that preperiods are real and that
breaking strong connectivity restores controllability. The affine family (§7.3)
shows that cycle length is a refined invariant governed by algebra, pointing to
sharper quantitative theory. In every case the *step map* is trivial; what
varies — and what determines safety — is the *shape of the reachability graph*.

## 8. Applications

The abstraction is deliberately spare, which makes it broadly instantiable.

- **Self-monitoring agents.** Model an agent's policy as the program component
  `P` and its working memory as `S`; a policy-updating agent is literally a
  self-modifying machine. On bounded memory, Theorem 4.2 says a safety monitor
  need only look ahead `N` steps, while Theorem 4.3 warns that if the policy
  space is reachability-rich, a single unsafe configuration cannot be excluded
  by any state-based guard. The engineering response is structural: design the
  update operator so that the reachability graph has a bad-free terminal region.
- **Self-patching software.** Just-in-time compilers and hot-patching runtimes
  rewrite executable code at run time. Theorem 2.5 certifies that reasoning
  about such systems is no harder than reasoning about a fixed program over the
  expanded state; Theorem 4.1 certifies that a non-terminating self-patcher on
  finite memory must enter a repeating configuration, which is the basis for
  loop/leak detection.
- **Malware analysis.** Polymorphic and metamorphic malware mutate their own
  code to evade signatures. The quine-cycle theorem implies that any such sample
  confined to finite memory and never halting eventually repeats a full
  configuration; cycle detection (Algorithm A) is then a principled detector,
  and bounded-search safety (Algorithm B) bounds the cost of deciding whether a
  flagged behaviour is ever exhibited.
- **Cellular automata and finite digital dynamics.** Any deterministic finite
  automaton with output feedback is a self-map of its configuration space; the
  results give immediate eventual-periodicity and confinement statements,
  recovering classical facts as instances of a single pigeonhole argument.

## 10. Conclusion

Self-modification, so often treated as a source of intractable complexity, is on
finite memory a tame and classical object: a self-map whose every orbit is
visible in its first `card(P × S)` iterates. From the single pigeonhole
collision among those iterates flow eventual periodicity, forced
self-reproduction (quine cycles), and bounded-search decidability of orbit
safety. Yet the same finiteness that trivializes *prediction* is powerless
against the *control* problem: under strong connectivity one bad configuration
poisons the whole space. The decisive variable is reachability, not step
complexity — which tells designers of self-modifying agents exactly what to
shape.
