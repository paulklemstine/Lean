## Core Mathematical Vision

Let
\[
p(x_1,\dots,x_n)=\sum_{|\alpha|=d} c_\alpha x^\alpha
\]
be a homogeneous polynomial with nonnegative coefficients, and suppose \(p\) admits a recursive Lorentzian certificate. Interpret the normalized coefficient vector
\[
\psi_p := \frac{1}{\sqrt{\sum_\alpha c_\alpha^2}} (c_\alpha)_\alpha
\]
as a pure quantum state in the occupation-number basis. The conjectural principle is:

> **Recursive Lorentzian structure induces recursively preparable amplitude structure.**

This is plausible because Lorentzianity is not just a sign condition: it enforces strong log-concavity, controlled Hessian signatures, and recursive derivative stability. Those are exactly the kinds of constraints that make hierarchical normalization and branching procedures stable. The certificate tree should therefore encode a sequence of conditional amplitude splits, and hence a circuit skeleton.

The key conceptual leap: do **not** try to formalize full quantum mechanics first. Formalize the preparation theorem as a theorem about **normalized coefficient distributions and recursive branching kernels**. Then derive a finite algorithm that compiles certificates into a preparation tree. The “quantum circuit” can initially be represented by an abstract gate tree or branching program with a proved correctness theorem for the produced amplitude vector. That is already scientifically meaningful and Lean-friendly.

## Main theorem statement with Lean-oriented signature

You should aim for a theorem of the following shape. Adapt names to actual available catalog definitions, but keep the mathematical content precise.

### Theorem 1: Certificate compilation correctness
If a homogeneous polynomial has a recursive Lorentzian certificate, then its normalized coefficient distribution is generated by a recursively defined preparation tree compiled from the certificate.

Suggested Lean-style signature:
```lean
theorem exists_preparation_from_recursiveLorentzian
  {n d : ℕ}
  (p : MvPolynomial (Fin n) ℝ)
  (hp_hom : p.IsHomogeneous d)
  (hp_nonneg : ∀ s, 0 ≤ p.coeff s)
  (hcert : RecursiveLorentzianCertificate p) :
  ∃ T : CertificatePreparation (Fin (Nat.choose (n + d - 1) d)),
    T.depth ≤ d - 1 ∧
    preparesCoeffState T p
```

Here `preparesCoeffState T p` should mean that the output probability distribution or amplitude vector encoded by `T` agrees with the normalized coefficient state of `p`.

**Why this matters:** this is the first theorem converting Lorentzian recognition into a constructive preparation mechanism. It changes certificates from passive witnesses into active algorithms.

### Theorem 2: Depth recurrence / asymptotic bound
Prove that the preparation depth is bounded by the certificate depth plus logarithmic normalization overhead; in the first formal pass, even a polynomial upper bound derived from the recursive tree is valuable.

Suggested Lean-style signature:
```lean
theorem preparation_depth_bound
  {n d : ℕ}
  (p : MvPolynomial (Fin n) ℝ)
  (hp_hom : p.IsHomogeneous d)
  (hp_nonneg : ∀ s, 0 ≤ p.coeff s)
  (hcert : RecursiveLorentzianCertificate p) :
  let T := Classical.choose
    (exists_preparation_from_recursiveLorentzian p hp_hom hp_nonneg hcert)
  in
  T.depth ≤ certificateDepth hcert + (Nat.log2 (n + 1) + 1)
```

If `certificateDepth` already exists, use it. If not, define it from the recursive certificate.

A stronger asymptotic theorem is encouraged if feasible:
```lean
theorem preparation_size_poly_bound
  ...
  : preparationSize T ≤ C * n^d
```
for an explicit recursively defined `C`, or a theorem with `∃ C, ...`.

**Why this matters:** this is where the algorithmic content becomes credible. Without a complexity theorem, the bridge to quantum computing is metaphorical. With it, it becomes a blueprint.

## Most promising proof architecture

You must give the file a genuine proof plan with 2–3 strategies, and then execute the strongest one.

### Strategy A: Induction on certificate depth via derivative branching
**Most promising.**

1. `rcases` on `RecursiveLorentzianCertificate p` into its recursive children.
2. Show each child polynomial yields a compilable sub-preparation object by induction.
3. Prove a **branching composition lemma**: if a parent coefficient family decomposes into certified derivative slices with positive weights, then one can normalize and combine the child preparations into a parent preparation.
4. Use `field_simp` and `calc` to verify normalization identities.
5. Deduce the depth recurrence by adding one branching layer.

Why this is best: it matches the recursive structure already present in the catalog. It uses the theorem as the certificate wants to be used, instead of forcing an external spectral argument.

### Strategy B: Hessian-signature route via local quadratic splitting
1. Use Lorentzian Hessian signature: one positive eigenvalue, the rest nonpositive.
2. Convert this into a rank-1-dominant decomposition of local curvature.
3. Show that this decomposition yields a contractive normalization map whose fixed point is the coefficient distribution.
4. Iterate recursively down the certificate tree.

Why it is interesting: this is closer to the physics narrative. Why it is less promising for Lean first: spectral decomposition and fixed-point channel formalization are heavier than needed.

### Strategy C: Sampling-first, then amplitudes
1. Use `certificate_sampling_efficiency` to obtain an efficient exact or approximate sampler from the coefficient-square distribution.
2. Formalize a reversible branching program corresponding to that sampler.
3. Upgrade the sampler tree into an amplitude-preparation tree.

Why this matters: it leverages existing catalog theorems directly. Why it is probably second-best: the sampler-to-amplitude upgrade may require additional abstractions, but it is a strong fallback and may produce the cleanest verified algorithm.

**Recommendation:** implement Strategy A as the main proof, while borrowing local lemmas from Strategy C if the sampling theorems already provide exactly the branching structure you need.

## Mathematical insight you should exploit

The certificate tree should be understood as a **hierarchical disintegration of mass**. For a nonnegative homogeneous Lorentzian polynomial, directional derivatives preserve strong log-concavity and positivity in a way that organizes coefficients into recursively normalized slices. This is not accidental; it is the combinatorial shadow of a one-positive-direction geometry.

A preparation tree is therefore not arbitrary. It should encode:
- a choice of variable or derivative branch,
- a positive splitting weight,
- recursively prepared child distributions,
- a normalization identity proving the parent distribution is recovered.

This is mathematically cleaner than speaking immediately about unitary circuits. The latter can be deferred to the demo and paper. In Lean, prove correctness for **abstract preparation trees**, then explain in `RESEARCH_PAPER.md` how each branch corresponds to a controlled rotation / multiplexor layer in a quantum circuit.
