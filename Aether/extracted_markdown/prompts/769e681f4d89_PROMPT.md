# Assignment: Graph Coloring Beyond Enumeration — Chromatic Polynomials as a Bridge Between Structural Graph Theory, Matroidal Recursion, and Statistical Physics

You should not treat this as a routine formalization task. The real target is to build a Lean 4 chromatic-polynomial engine powerful enough to make structural graph coloring theorems computable, recursive, and transferable to other domains. The breakthrough is not “define χ_G.” The breakthrough is to create a certified recursive calculus for graph colorings that links:

- structural graph theory: deletion–contraction, Brooks-type bounds, planar coloring formulations,
- algebraic combinatorics: coefficients, positivity phenomena, Whitney-style expansions,

The most promising direction is to formalize chromatic polynomials for finite simple graphs in Mathlib, prove deletion–contraction in a reusable form, and then leverage that infrastructure toward nontrivial coefficient or positivity results for graph classes where recursive decomposition is available.

## Precise Theorem Targets

### Target A. Existence and counting specification of the chromatic polynomial

Define a polynomial over `ℤ` characterized by counting proper colorings on finite palettes.

A suitable specification theorem is:

```lean
noncomputable def SimpleGraph.chromaticPolynomial
  {V : Type*} [Fintype V] [DecidableEq V] :
  SimpleGraph V → Polynomial ℤ
```

with the intended correctness statement:

```lean
theorem SimpleGraph.eval_chromaticPolynomial
  {V α : Type*} [Fintype V] [DecidableEq V] [Fintype α] :
  ∀ (G : SimpleGraph V),
    Polynomial.eval (Fintype.card α : ℤ) (G.chromaticPolynomial) =
      Fintype.card { c : V → α // G.IsProperColoring c }
```

If `IsProperColoring` does not exist in exactly this form, define:

```lean
def SimpleGraph.IsProperColoring (G : SimpleGraph V) (c : V → α) : Prop :=
  ∀ ⦃u v : V⦄, G.Adj u v → c u ≠ c v
```

This theorem is the gateway result. Once certified, the polynomial becomes a universal counting invariant.

A sharper theorem, if convenient, is uniqueness:

```lean
theorem SimpleGraph.exists_unique_chromaticPolynomial
  {V : Type*} [Fintype V] [DecidableEq V] :
  ∃! P : Polynomial ℤ,
    ∀ n : ℕ,
      Polynomial.eval (n : ℤ) P =
        Fintype.card { c : V → Fin n // G.IsProperColoring c }
```

This is more foundational and mathematically cleaner, but the direct definitional route via deletion–contraction may be easier to formalize.

### Target B. Deletion–contraction for nonloop edges in simple graphs

This is the central theorem. Since simple graphs do not literally support loops and edge contraction changes the vertex type, you will likely need a carefully designed contraction construction, perhaps via quotienting by the relation identifying the endpoints of an edge.

Precise theorem statement:

```lean
theorem SimpleGraph.chromaticPolynomial_delete_contract
  {V : Type*} [Fintype V] [DecidableEq V]
  (G : SimpleGraph V) {u v : V} (h : G.Adj u v) :
  G.chromaticPolynomial
    =
  (G.deleteEdges {Sym2.mk (u, v)}).chromaticPolynomial
    -
  (G.contractEdge h).chromaticPolynomial
```

This exact API may need adaptation depending on available graph operations. If single-edge deletion is awkward, define a dedicated operation:

```lean
def SimpleGraph.deleteEdge (G : SimpleGraph V) (u v : V) : SimpleGraph V := ...
def SimpleGraph.contractEdge (G : SimpleGraph V) (h : G.Adj u v) : SimpleGraph (EdgeContractionType G u v) := ...
```

Then state:

```lean
theorem SimpleGraph.chromaticPolynomial_deleteEdge_contractEdge
  {V : Type*} [Fintype V] [DecidableEq V]
  (G : SimpleGraph V) {u v : V} (h : G.Adj u v) :
  G.chromaticPolynomial
    =
  (G.deleteEdge u v).chromaticPolynomial
    -
  (G.contractEdge h).chromaticPolynomial
```

This is revolutionary because it turns graph coloring into a certified recursive algebra. Once this theorem is in place, every recursively decomposable graph class becomes amenable to exact symbolic treatment in Lean.

theorem SimpleGraph.natDegree_chromaticPolynomial

These results are nontrivial but standard, and they make the object mathematically rigid. They also support coefficient extraction and asymptotic arguments.

### Target D. Closed forms for fundamental graph classes

These are ideal proving grounds and testbeds for recursion.

For complete graphs:

```lean
theorem SimpleGraph.chromaticPolynomial_completeGraph
  (n : ℕ) :
  (SimpleGraph.completeGraph (Fin n)).chromaticPolynomial
    =
  ∏ i in Finset.range n, (Polynomial.X - Polynomial.C (i : ℤ))
```

For trees:

```lean
theorem SimpleGraph.chromaticPolynomial_tree
  {V : Type*} [Fintype V] [DecidableEq V]
  (G : SimpleGraph V) [Fact G.Connected]
  (hT : G.IsTree) :
  G.chromaticPolynomial
    =
  Polynomial.X * (Polynomial.X - 1) ^ (Fintype.card V - 1)
```

For cycles:

```lean
theorem SimpleGraph.chromaticPolynomial_cycle
  (n : ℕ) (h : 3 ≤ n) :
  (cycleGraph (Fin n)).chromaticPolynomial
    =
  (Polynomial.X - 1)^n + (-1 : ℤ)^n * (Polynomial.X - 1)
```

These formulas build confidence, provide benchmark examples, and connect immediately to statistical mechanics.

### Target E. Four-color equivalence as a formal reduction theorem

Do not overpromise a full proof of the four-color theorem from scratch in this cycle unless Mathlib already contains the necessary planar infrastructure. The right target is an equivalence theorem between the standard graph-coloring formulation and a statement about existence of proper colorings with palette `Fin 4`.

```lean
theorem four_color_statement_iff
  :
  (∀ {V : Type*} [Fintype V] [DecidableEq V],
      ∀ G : SimpleGraph V, G.IsPlanar → G.Colorable 4)
    ↔
  (∀ {V : Type*} [Fintype V] [DecidableEq V],
      ∀ G : SimpleGraph V, G.IsPlanar →
        Nonempty { c : V → Fin 4 // G.IsProperColoring c })
```

If `Colorable 4` already exists, prove equivalence with your coloring predicate. This is not deep by itself, but it creates the exact formal interface needed for later import of a planar reducibility proof or external certification pipeline.

A stronger polynomial reformulation, if possible:

```lean
theorem four_color_statement_iff_eval_pos
  :
  (∀ {V : Type*} [Fintype V] [DecidableEq V],
      ∀ G : SimpleGraph V, G.IsPlanar → G.Colorable 4)
    ↔
  (∀ {V : Type*} [Fintype V] [DecidableEq V],
      ∀ G : SimpleGraph V, G.IsPlanar →
        0 < Polynomial.eval (4 : ℤ) G.chromaticPolynomial)
```

This turns four-coloring into positivity of a graph polynomial at a specific point, which is conceptually powerful and links coloring to partition-function positivity.

### Target F. Brooks’ theorem: formal statement and realistic staging

Brooks’ theorem is a major structural result. If full proof is too large for one cycle, still formalize the exact statement and prove key reduction lemmas. The desired theorem:

```lean
theorem SimpleGraph.colorable_card_le_maxDegree
  {V : Type*} [Fintype V] [DecidableEq V]
  (G : SimpleGraph V)
  (h_complete : ¬ Nonempty (G ≃g SimpleGraph.completeGraph V))
  (h_odd_cycle : ¬ G.IsOddCycle) :
  G.Colorable (G.maxDegree + 1) ∧ G.Colorable G.maxDegree
```

More standard form:

```lean
theorem SimpleGraph.brooks
  {V : Type*} [Fintype V] [DecidableEq V]
  (G : SimpleGraph V)
  (h_conn : G.Connected)
  (h_not_complete : ¬ IsCompleteGraph G)
  (h_not_odd_cycle : ¬ IsOddCycleGraph G) :
  G.chromaticNumber ≤ G.maxDegree
```

You may need to define `chromaticNumber`, `maxDegree`, `IsOddCycleGraph`, `IsCompleteGraph` if absent or differently named.

A powerful intermediate theorem more likely to be completed this cycle is the greedy bound:

```lean
theorem SimpleGraph.chromaticNumber_le_succ_maxDegree
  {V : Type*} [Fintype V] [DecidableEq V] (G : SimpleGraph V) :
  G.chromaticNumber ≤ G.maxDegree + 1
```

Then Brooks becomes the exceptional-improvement theorem. This staged approach is mathematically honest and formalization-friendly.

### Target G. Replace the vague “T-positivity for claw-free graphs” by a precise and defensible positivity theorem

The phrase “T-positive” is ambiguous. You must define it precisely before proving anything. There are at least three viable interpretations:

1. positivity in the falling-factorial basis,
2. positivity after a shift `X ↦ X+1`,
3. positivity in the basis induced by the Tutte polynomial / independence structures.

The most mathematically credible and Lean-accessible target is the falling-factorial expansion:

```lean
def fallingFactorialPoly (k : ℕ) : Polynomial ℤ := ∏ i in Finset.range k, (Polynomial.X - Polynomial.C i)

def TPositive (P : Polynomial ℤ) : Prop :=
  ∃ a : ℕ →₀ ℕ, P = ∑ k in a.support, Polynomial.C (a k : ℤ) * fallingFactorialPoly k
```

Then ask for:

```lean
theorem SimpleGraph.chromaticPolynomial_fallingFactorial_positive
  {V : Type*} [Fintype V] [DecidableEq V] (G : SimpleGraph V) :
  TPositive G.chromaticPolynomial
```

In fact this may hold for all finite graphs, not just claw-free graphs, via partition-count interpretations of coefficients. If so, that is better: it upgrades the assignment from a class-specific conjecture to a universal structural theorem. Then claw-free graphs become a testing ground for stronger positivity or unimodality phenomena.

If you want a truly class-specific breakthrough, target coefficient inequalities or real-rootedness-adjacent phenomena for claw-free graphs, but be careful: these are deep and may not currently be feasible in Lean without substantial infrastructure.

## Most Promising Proof Strategies

### Strategy A: Recursive deletion–contraction construction
This is the most promising overall route.

1. Define the chromatic polynomial recursively on the number of edges:
   - edgeless graph on `n` vertices gets `X^n`,
   - if `e = uv` is an edge, define
     `χ_G = χ_{G\e} - χ_{G/e}`.
2. Prove well-definedness by showing recursive evaluation agrees with the actual counting function on finite palettes.
3. Deduce uniqueness, degree, monicity, and closed forms from recursion.

Why this is best:
- It aligns with the universal combinatorial proof.
- It makes later Tutte polynomial formalization almost automatic.
- It converts graph coloring into a recursive certified algorithm.

The main technical obstacle is contraction. Solve this once carefully and the whole project opens.

---

### Strategy B: Direct polynomial interpolation from counting functions
A second route for existence.

1. For each finite graph `G`, define `f_G(n)` as the number of proper colorings with `n` colors.
2. Prove `f_G` satisfies deletion–contraction and hence is eventually polynomial, or directly prove finite-difference vanishing of order `|V|+1`.
3. define the unique polynomial of degree at most `|V|` agreeing with `f_G` on sufficiently many integers.

Why it is attractive:
- It avoids recursive dependence on graph contraction in the definition itself.
- It may be easier to characterize coefficients in the falling-factorial basis.

Why it is less promising:
- formal interpolation over `ℤ` with exact counting compatibility is often more cumbersome in Lean than recursive definitions;
- proving polynomiality from scratch is itself substantial.

Still, this strategy is excellent for proving universal falling-factorial positivity.

---

### Strategy C: Potts-model / partition-function route
This is the visionary bridge.

1. Define the zero-temperature antiferromagnetic Potts partition function:
   `Z_G(q, v)` specialized at `v = -1`.
2. Prove
   `χ_G(q) = Z_G(q, -1)`.
3. Obtain deletion–contraction from the Fortuin–Kasteleyn expansion.

This is the most conceptually revolutionary route because it links graph coloring to statistical mechanics and opens transfer to phase-transition methods, Lee–Yang style questions, and Tutte universality.

Why it may be harder now:
- it requires a partition-function formalization layer;
- more algebraic bookkeeping is needed.

Best use:
- after Target B is complete, introduce this as an alternative characterization theorem rather than the first construction.

## Cross-Domain Connections You Should Explicitly Exploit

### 1. Statistical physics
Chromatic polynomial = zero-temperature Potts partition function.
This means every formal theorem about `χ_G` is also a theorem about a physical partition function. Deletion–contraction is then a renormalization-like identity. This is not cosmetic: it opens a path to formalized phase-transition combinatorics and certified symbolic physics.

### 2. Matroid theory and Tutte polynomial
Deletion–contraction is the universal recursion of the Tutte world. Once chromatic polynomials are formalized in this style, the next leap is:
- graphic matroids,
- Whitney numbers,
- Tutte specialization
  `χ_G(q) = (-1)^{|V|-c(G)} q^{c(G)} T_G(1-q, 0)`.

Even if you do not prove this now, structure your API so this theorem becomes natural.

### 3. Computational complexity
Evaluation of chromatic polynomials at fixed integers connects to counting complexity (#P phenomena), while colorability statements connect to decision complexity. A formal recursive evaluator extracted from Lean could become a certified exact coloring counter for small graphs. This is a direct bridge to verified algorithms.

### 4. Algebraic combinatorics
Falling-factorial expansions, Stirling transforms, coefficient sign alternation, and acyclic orientation counts all live here. Once `χ_G` is in place, there is a realistic path to proving:
- alternating-sign coefficient theorem,
- interpretation of coefficients via broken circuits,
- `|χ_G(-1)| = number of acyclic orientations`.

That last theorem would be a major field-opening target for future cycles.
