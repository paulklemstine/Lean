# Assignment: Tropical Monotone Circuits as a Formal Bridge Between Boolean Logic, Dynamic Programming, and Tropical Geometry

You are not being asked to merely define another circuit model. You are being asked to formalize a new computational object in Lean 4 that sits simultaneously in three worlds:

1. **Boolean monotone computation** via `and`/`or`,
2. **Tropical algebra** via `+`/`min`,
3. **Optimization/DP semantics** via path aggregation on DAGs.

The breakthrough target is to show that tropical monotone circuits are not just syntax, but a mathematically robust semantics-preserving bridge between logical computation and tropical optimization. This opens a path toward formal lower bounds, tropical complexity measures, certified optimization semantics, and eventually a tropical complexity theory inside Lean.

## Core Vision

Define **tropical monotone circuits** as finite DAG-based expressions whose internal gates are:
- binary `min` gates,
- binary `+` gates,
- leaves carrying variables or constants.

Then prove that:
- these circuits evaluate to tropical polynomials / piecewise-linear monotone functions,
- Boolean monotone circuits embed into them via a `{0,1}`-valued semantics,
- DAG semantics and recursive syntax semantics coincide,
- the resulting functions are monotone and stable under composition,
- and a path-based normal form exists for a substantial subclass.

This is the first step toward a formal tropical circuit complexity theory.

# Breakthrough Theorems to Prove

## Theorem 1: Monotonicity of tropical monotone circuits

This is the foundational theorem. It says tropical monotone circuits genuinely compute monotone functions in the coordinatewise order.

### Mathematical statement
For every circuit `C : TropCircuit n`, if `x i ≤ y i` for all inputs `i`, then
`C.eval x ≤ C.eval y`.

### Lean 4 type signature
```lean
theorem TropCircuit.eval_monotone
    {n : ℕ} (C : TropCircuit n) :
    Monotone (TropCircuit.eval C) := by
```

If `Monotone` over functions `Fin n → ℝ` is awkward due to function-order instances, use:

```lean
theorem TropCircuit.eval_mono_pointwise
    {n : ℕ} (C : TropCircuit n) {x y : Fin n → ℝ}
    (hxy : ∀ i, x i ≤ y i) :
    TropCircuit.eval C x ≤ TropCircuit.eval C y := by
```

### Why this matters
This theorem certifies that the syntax really deserves the word *monotone*. It is the basis for order-theoretic semantics, optimization interpretations, and complexity measures based on monotone formula depth/size.

## Theorem 2: Boolean monotone logic embeds into tropical circuits

This should be the first serious bridge theorem. Use the catalog facts:
- `trop_min_is_and`
- `bool_or_as_tropical_min`
- `tropical_and_bound`
- `min_max_duality`

You likely need to define a Boolean monotone formula language:

```lean
inductive BoolMonoFormula (n : ℕ) : Type
| var : Fin n → BoolMonoFormula n
| top : BoolMonoFormula n
| bot : BoolMonoFormula n
| and : BoolMonoFormula n → BoolMonoFormula n → BoolMonoFormula n
| or  : BoolMonoFormula n → BoolMonoFormula n → BoolMonoFormula n
```

Then define a translation into tropical circuits.

### Candidate statement
There exists a translation `translate : BoolMonoFormula n → TropCircuit n` and a Boolean-to-tropical valuation encoding such that the translated circuit computes the Boolean formula semantics after decoding.

Because `+` is not literally Boolean `and` on raw `{0,1}` values unless decoded appropriately, the cleanest theorem may involve a threshold decoder:

```lean
def tropToBool (r : ℝ) : Bool := r ≤ 0
```

or a stricter restricted codomain.

### Lean 4 style statement
```lean
def encodeBool : Bool → ℝ
| false => 1
| true  => 0

def decodeBool (r : ℝ) : Bool :=
  r ≤ 0

theorem boolean_formula_tropical_sound
    {n : ℕ} (φ : BoolMonoFormula n) (σ : Fin n → Bool) :
    decodeBool (TropCircuit.eval (translate φ) (fun i => encodeBool (σ i)))
      = BoolMonoFormula.eval φ σ := by
```

If exact soundness with both `and` and `or` is technically messy, prove a two-stage theorem:
1. exact correspondence for `or` via `min`,
2. sound correspondence for `and` via additive thresholding,
3. then combine into a semantic preservation theorem for formulas in negation-free normal form.

### Why this is a breakthrough
This creates a certified logical-to-tropical compilation theorem. It means tropical circuits can be used as optimization-valued relaxations of monotone logic, opening formal links to SAT relaxations, shortest-path semantics, energy models, and tropical proof complexity.

## Theorem 3: Formula semantics equals DAG/path semantics for a series-parallel subclass

This is the theorem with the highest upside. For a restricted class of tropical circuits—say circuits generated by serial composition (`+`) and parallel composition (`min`) from leaves—show evaluation equals the minimum over path weights of a suitable combinatorial object.

This is the tropical analogue of “every series-parallel circuit computes a shortest-path cost”.

### Suggested mathematical statement
Define a subclass `SPTropCircuit n`. Associate to each circuit a finite family of affine forms (or weighted source-sink paths). Then prove:

\[
\mathrm{eval}(C,x) = \min_{p \in \mathrm{Paths}(C)} \left( w(p) + \sum_i m_{p,i} x_i \right).
\]

### Lean-oriented theorem signature
You may encode affine forms as finite-support coefficient maps into `ℕ` plus a constant.

```lean
structure TropAffine (n : ℕ) where
  coeff : Fin n → ℕ
  const : ℝ

def TropAffine.eval {n : ℕ} (a : TropAffine n) (x : Fin n → ℝ) : ℝ :=
  a.const + ∑ i, (a.coeff i : ℝ) * x i
```

Then define `normalForms : TropCircuit n → Finset (TropAffine n)` for the formula subclass, and prove:

```lean
theorem eval_eq_min_normalForms
    {n : ℕ} (C : TropCircuit n) (hform : isFormulaLike C) (x : Fin n → ℝ) :
    TropCircuit.eval C x =
      Finset.inf' (normalForms C) (by simpa using normalForms_nonempty C hform)
        (fun a => TropAffine.eval a x) := by
```

If `Finset.inf'` over `ℝ` becomes unpleasant, formulate using existence of a realizing element and lower-bound characterization.

### Why this matters
This is the first true structural theorem. It shows tropical circuits are not opaque recursive programs: they compute minima of affine families. That makes them legible to convexity, optimization, and geometry. It opens the door to tropical Newton polytopes, complexity via number of affine pieces, and certified dynamic-programming equivalences.

## Theorem 4: Dual max-plus semantics via `min_max_duality`

Use the catalog theorem `min_max_duality` to derive a semantic involution turning min-plus circuits into max-plus circuits under negation.

### Lean statement
Define a dual transform on circuits:
- constants negated,
- variables mapped to negated inputs,
- `min` exchanged with `max` after pushing negation through,
- `+` preserved up to negation rules.

At function level, the key theorem should be:

```lean
theorem eval_duality
    {n : ℕ} (C : TropCircuit n) (x : Fin n → ℝ) :
    TropCircuit.eval C x
      = - (MaxTropCircuit.eval (dual C) (fun i => - x i)) := by
```

or more modestly, a recursive theorem for a syntactic dual.

### Why this matters
This imports the entire min-plus/max-plus duality into the circuit setting. Suddenly tropical monotone circuits become a portal to game theory, control, Bellman equations, and idempotent functional analysis.

# Proof Strategy Architecture

## Strategy A: Structural induction on syntax
This is the most reliable route for Theorems 1 and 2.

### Steps
1. Define syntax and recursive evaluation.
2. Prove helper lemmas:
   - monotonicity of `fun z => z + c`,
   - monotonicity of binary `min`,
   - coordinatewise monotonicity preserved by composition.
3. Induct on the circuit/formula structure.

### Why promising
Lean handles inductives and recursion extremely well. This should minimize sorry and establish a clean foundation fast.

---

## Strategy B: Normal-form extraction into finite affine families
This is the most mathematically powerful route for Theorem 3.

### Steps
1. Define a normal form `NF(C)` as a finite set of affine forms.
   - variable gives singleton affine form,
   - constant gives singleton constant affine form,
   - `min` becomes union,
   - `+` becomes tropical convolution / pairwise sum of affine forms.
2. Prove by induction that evaluation equals min over `NF(C)`.
3. Derive monotonicity, piecewise-linearity, and perhaps Lipschitz-style corollaries from the normal form.

### Why promising
This turns syntax into geometry. It is the route most likely to produce a field-opening theorem, because it reveals the hidden polyhedral structure of tropical circuits.

---

## Strategy C: Graph semantics first, syntax second
This is riskier but visionary.

### Steps
1. Define a finite DAG with node labels `var`, `const`, `add`, `min`.
2. Give semantics by topological evaluation.
3. Prove every formula-like circuit embeds into a DAG and preserves evaluation.
4. For acyclic DAGs, extract path semantics or dynamic-programming semantics.

### Why promising
This aligns with actual circuit complexity and optimization. It will be harder in Lean because of finite graph infrastructure and acyclicity bookkeeping, but if successful it opens genuine tropical circuit complexity.

### Recommendation
Start with **Strategy A**, then push hard into **Strategy B**. Strategy C should be a future-direction theorem unless the graph library support is already favorable in your environment.

# Cross-Domain Connections You Should Explicitly Develop

## 1. Dynamic Programming / Shortest Paths
A min-plus circuit is a formal dynamic program:
- `+` = concatenate costs,
- `min` = choose the best branch.

This is not analogy; it should become theorem. Even proving it for a series-parallel subclass would be a major bridge.

## 2. Tropical Geometry
The normal-form theorem identifies circuit functions as minima of finitely many affine forms. These are tropical polynomials / concave piecewise-linear objects in min-plus convention. This connects circuit size/depth to polyhedral complexity.

## 3. Monotone Complexity Theory
Boolean monotone formulas embedding into tropical circuits suggests a semantic relaxation of monotone computation. This could eventually support formal lower bounds via number of affine pieces, Newton polytope complexity, or path-family explosion.

## 4. Control Theory / Bellman Semantics
Min-plus algebra is the algebra of deterministic optimal control and shortest path Bellman operators. Tropical circuits could become a compositional language for certified Bellman expressions.

## 5. Formal Verification / Neural Surrogates
Tropical circuits are piecewise-linear and monotone. This makes them plausible certifiable surrogates for monotone systems, robust decision rules, and certain classes of energy-based models.
