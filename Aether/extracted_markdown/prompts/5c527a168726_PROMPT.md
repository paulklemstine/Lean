## Title
Aether Quality Control: Formal Stress-Testing of Conjectures via Finite Counterexample Search and Monotone Risk Reduction

## Core Vision

Do **not** interpret “automated counterexample generation” as a vague meta-level slogan. Make it mathematically sharp inside Lean: formalize a class of conjectures for which a finite, adversarial search over the negation is sound, then prove that passing such a search strictly shrinks the space of surviving false conjectures. The breakthrough is to convert “quality control for theorem discovery” into a theorem **about theorem discovery**.

The right target is not an impossible semantic statement about all Lean propositions. The right target is a **certified finite-model stress test** for parameterized conjecture families, together with a monotonicity theorem saying that every added counterexample generator decreases false-positive mass. This opens a new field: **formal epistemics of automated mathematics**, where theorem-proving pipelines themselves become objects of proof.

## Precise Theorem Targets

### Target 1: Soundness of finite counterexample stress testing

Formalize a family of conjectures indexed by a finite parameter space `α`, with a decidable predicate `good : α → Prop`. A stress test is a finite set `T : Finset α` of adversarial candidates checked against `good`. A conjecture “survives” iff it holds on every candidate in `T`.

Prove that if some `a ∈ T` falsifies `good`, then the conjecture is false; equivalently, survival means exactly “no tested counterexample exists.” This sounds tautological, but the nontrivial content is to package it in a reusable framework for generated tests and then prove risk bounds below.

This is the atomic correctness theorem for the stress test.

### Target 2: Monotonicity — stronger stress tests can only reduce false positives

Let `Universe : Finset α` be the finite search universe of candidate instances for a conjecture family. False conjectures are those with at least one bad witness in `Universe`. Surviving false conjectures are those that are false globally on `Universe` but happen to evade the tested set `T`.

Define:

```lean
def FalseOn (good : α → Prop) (U : Finset α) : Prop :=
  ∃ a ∈ U, ¬ good a

def FalsePositive (good : α → Prop) [DecidablePred good]
    (U T : Finset α) : Prop :=
  FalseOn good U ∧ Survives good T
```

Now prove the structural theorem:

```lean
theorem falsePositive_antitone
    (good : α → Prop) [DecidablePred good]
    {T₁ T₂ U : Finset α}
    (hsub : T₁ ⊆ T₂) :
    FalsePositive good U T₂ → FalsePositive good U T₁ := by
  ...
```

Equivalently, in set-theoretic language: enlarging the stress-test set cannot create new surviving false conjectures.

A stronger cardinality version is the real breakthrough. Define the family of all predicates on a finite type `α`, or more realistically all predicates represented by a finite hypothesis class `H : Finset (α → Bool)`. For each hypothesis `h ∈ H`, interpret `good_h a := h a = true`. Then prove that the number of false positives after testing with `T₂` is bounded above by the number after testing with `T₁` whenever `T₁ ⊆ T₂`.

Suggested statement:

```lean
def SurvivesBool (h : α → Bool) (T : Finset α) : Bool :=
  T.all h

def IsFalseBool (h : α → Bool) (U : Finset α) : Bool :=
  U.any (fun a => !(h a))

def falsePositiveCount (H : Finset (α → Bool)) (U T : Finset α) : Nat :=
  ((H.filter (fun h => IsFalseBool h U && SurvivesBool h T))).card

theorem falsePositiveCount_antitone
    [Fintype α] [DecidableEq α]
    (H : Finset (α → Bool)) {T₁ T₂ U : Finset α}
    (hsub : T₁ ⊆ T₂) :
    falsePositiveCount H U T₂ ≤ falsePositiveCount H U T₁ := by
  ...
```

This theorem is the formal version of “surviving a harder stress test yields a lower false-positive rate.”

### Target 3: Optimality of adversarial generators via hitting false hypotheses

The genuinely new theorem is not just monotonicity, but **maximal elimination**. Define a generator `G : Finset α` to be optimal relative to a finite hypothesis class `H` and search budget `k` if `G.card ≤ k` and it maximizes the number of false hypotheses it kills.

A more Lean-friendly theorem is a greedy upper bound: if `T₂` hits every false hypothesis hit by `T₁`, then `T₂` is at least as strong.

Define “kills”:

```lean
def Kills (good : α → Prop) [DecidablePred good] (T : Finset α) : Prop :=
  ∃ a ∈ T, ¬ good a
```

For a finite family `H : Finset (α → Bool)`, define the killed subset:
```lean
def killedBy (H : Finset (α → Bool)) (T : Finset α) : Finset (α → Bool) :=
  H.filter (fun h => T.any (fun a => !(h a)))
```

Then prove:

```lean
theorem killedBy_mono
    [DecidableEq α]
    (H : Finset (α → Bool)) {T₁ T₂ : Finset α}
    (hsub : T₁ ⊆ T₂) :
    killedBy H T₁ ⊆ killedBy H T₂ := by
  ...
```

and therefore

```lean
theorem falsePositiveCount_decreases_by_kills
    [DecidableEq α]
    (H : Finset (α → Bool)) {U T₁ T₂ : Finset α}
    (hallfalse : ∀ h ∈ H, IsFalseBool h U = true)
    (hkills : killedBy H T₁ ⊆ killedBy H T₂) :
    falsePositiveCount H U T₂ ≤ falsePositiveCount H U T₁ := by
  ...
```

This captures “maximally difficult candidates” in a finite adversarial sense: a better generator is one whose test set kills more false hypotheses.

## 2–3 Proof Strategy Paths

### Strategy A: Finset/Boolean combinatorics on finite hypothesis classes
This is the most promising route.

1. Represent conjecture families by finite indices `ι`, with `eval : ι → α → Bool`.
2. Express “survives,” “false,” and “killed” using `Finset.all`, `Finset.any`, and `Finset.filter`.
3. Prove monotonicity by showing filter predicates strengthen under `T₁ ⊆ T₂`, then use `Finset.card_le_card` on subset inclusions.

Why this is strongest: it avoids impossible semantic quantification over arbitrary `Prop`, keeps everything computable, and gives exact finite false-positive counts.

---

### Strategy B: Set-theoretic abstraction first, then specialize to finite counts
Build a clean lattice-theoretic layer:

1. Define the set of surviving hypotheses `S(T)` and the set of false hypotheses `F(U)`.
2. Prove `T₁ ⊆ T₂ → S(T₂) ⊆ S(T₁)`.
3. Intersect with `F(U)` to get false-positive antitonicity, then specialize to finite sets to derive cardinal inequalities.

Why this matters: it reveals the theorem as a Galois-style monotonicity principle, not just a coding fact. It may connect beautifully to order theory in Mathlib.

---

### Strategy C: Adversarial optimization / hitting-set viewpoint
Treat each false hypothesis as carrying a witness set of counterexamples:
`W_h := {a | h a = false}`.

1. A test set `T` kills `h` iff `T ∩ W_h ≠ ∅`.
2. Thus stress testing becomes a finite hitting-set problem.
3. Prove that larger hitting sets eliminate weak hypotheses monotonically; if you can, define and prove existence of a maximal killer under cardinal budget using finite argmax over `Finset.powersetLen`.

Why this is revolutionary: it bridges theorem discovery with combinatorial optimization and active learning. This is the route toward “generate maximally difficult candidates.”

## Cross-Domain Connections

1. **Statistical learning theory**  
   Surviving hypotheses after stress testing are a version of a version-space. Your antitonicity theorem is a formal analog of empirical risk reduction under added adversarial samples.

2. **Property testing and active learning**  
   Counterexample generation becomes query design. “Maximally difficult candidates” correspond to points that split the hypothesis class most efficiently.

3. **Model checking and falsification**  
   This is theorem proving’s analog of bounded model checking: finite adversarial search can refute quickly, and passing deeper bounded search certifiably reduces residual error classes.

4. **Proof complexity / automated reasoning**  
   The generator is not proving the theorem; it is compressing the space of plausible falsehoods. This is epistemic preconditioning for proof search.

5. **Reliability engineering / formal methods**  
   Aether’s research pipeline becomes a verified safety filter: every additional stress-test stage is a proven reduction in downstream wasted effort on false conjectures.

## What Would Count as a Breakthrough

A theorem of the form

> For every finite hypothesis class and every extension of the adversarial test suite, the set/count of surviving false conjectures is monotone decreasing.

is already a serious foundational result for automated mathematics. But the real breakthrough is:

> There exists a finite-budget adversarial test suite maximizing eliminated false conjectures, and any conjecture surviving this suite is minimax-certified relative to the hypothesis class.

That statement turns conjecture screening into a formal optimization problem with correctness guarantees. If you can even partially formalize this, you open a path to **certified theorem-discovery pipelines**.
