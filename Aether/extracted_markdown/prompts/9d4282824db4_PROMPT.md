## Assignment: 3. Cryptographic Closure Hulls

**Mode:** prove

Prove a genuinely new structural theorem at the interface of lattice cryptography, closure systems, and certified security invariants. The point is not merely that intersections are easy; the point is to formalize a *cryptographic hull operator* whose fixed points are “secure key spaces,” and to identify exactly when cryptographic generation procedures preserve boundedness. This creates a reusable abstract language for security-by-closure, with immediate relevance to key derivation, reduction-invariant search spaces, and certified pruning of lattice attack surfaces.

### Research Direction

Let `V` be a normed additive commutative group (or a concrete lattice such as `Fin n → ℤ` with Euclidean norm / an available norm surrogate), let `red : V → V` be a reduction operator, and let `B : ℝ` be a security radius.

Define the predicate
- `0 ∈ S`,
- `S` is invariant under `red`, i.e. `∀ v ∈ S, red v ∈ S`,
- every element of `S` satisfies the norm bound `‖v‖ ≤ B`.

Call such a set a `SecureKeySpace red B S`.

The real theorem is not just that this predicate is intersection-stable. The real theorem is:

1. `SecureKeySpace red B` forms a Moore family on `Set V`.
2. Therefore there is a canonical closure operator `secureClosure red B : Set V → Set V`.
3. This closure is the **least** secure key space containing a seed set `A`.
4. The closure preserves the norm bound **if and only if** the seed is already pointwise bounded by `B`, provided `red` itself is norm-nonincreasing (or at least preserves the bound region).

This “if and only if” is the decisive statement: cryptographic closure does not magically repair oversized keys; it only propagates certified boundedness through reduction dynamics.

### Precise Theorem Statements

Work at a level Lean can support cleanly. A strong target is:

```lean
import Mathlib

open Set

variable {V : Type*} [NormedAddCommGroup V]

def SecureKeySpace (red : V → V) (B : ℝ) (S : Set V) : Prop :=
  (0 : V) ∈ S ∧
  (∀ ⦃v : V⦄, v ∈ S → red v ∈ S) ∧
  ∀ ⦃v : V⦄, v ∈ S → ‖v‖ ≤ B
```

Then prove the following.

#### Theorem 1: Intersection closure / Moore-family kernel
```lean
theorem secureKeySpace_sInter
    (red : V → V) (B : ℝ) (C : Set (Set V))
    (hC : ∀ S ∈ C, SecureKeySpace red B S) :
    SecureKeySpace red B (sInter C)
```

A finite-intersection variant may be easier first:
```lean
theorem secureKeySpace_inter
    (red : V → V) (B : ℝ) {S T : Set V}
    (hS : SecureKeySpace red B S) (hT : SecureKeySpace red B T) :
    SecureKeySpace red B (S ∩ T)
```

#### Theorem 2: Definition of the closure hull
```lean
def secureClosure (red : V → V) (B : ℝ) (A : Set V) : Set V :=
  sInter {S : Set V | A ⊆ S ∧ SecureKeySpace red B S}
```

#### Theorem 3: Least fixed-point theorem
```lean
theorem subset_secureClosure
    (red : V → V) (B : ℝ) (A : Set V) :
    A ⊆ secureClosure red B A
```

```lean
theorem secureClosure_is_secure
    (red : V → V) (B : ℝ) (A : Set V)
    (hex : ∃ S : Set V, A ⊆ S ∧ SecureKeySpace red B S) :
    SecureKeySpace red B (secureClosure red B A)
```

```lean
theorem secureClosure_least
    (red : V → V) (B : ℝ) (A S : Set V)
    (hS : A ⊆ S) (hsec : SecureKeySpace red B S) :
    secureClosure red B A ⊆ S
```

The existential side condition `hex` is mathematically essential unless you separately assume the whole space is secure, which generally fails because of the norm bound. This is exactly where the theory becomes nontrivial.

#### Theorem 4: Existence criterion for bounded secure supersets
A breakthrough-level characterization is:
```lean
theorem exists_secureKeySpace_iff
    (red : V → V) (B : ℝ) (A : Set V)
    (hred0 : red 0 = 0)
    (hred_bound : ∀ v, ‖v‖ ≤ B → ‖red v‖ ≤ B) :
    (∃ S : Set V, A ⊆ S ∧ SecureKeySpace red B S) ↔
    (∀ v ∈ A, ‖v‖ ≤ B)
```

This theorem says: under a bound-preserving reduction action fixing zero, a seed admits a bounded secure closure exactly when the seed is already bounded. This is the conceptual heart of the project.

#### Theorem 5: Closure preserves boundedness exactly under bounded seeds
```lean
theorem secureClosure_preserves_bound_iff
    (red : V → V) (B : ℝ) (A : Set V)
    (hred0 : red 0 = 0)
    (hred_bound : ∀ v, ‖v‖ ≤ B → ‖red v‖ ≤ B) :
    (∃ S : Set V, A ⊆ S ∧ SecureKeySpace red B S) ↔
    (∀ v ∈ A, ‖v‖ ≤ B)
```

If you want a more computational closure theorem, define the bounded reduction orbit hull:
```lean
inductive RedOrbitClosure (red : V → V) : Set V → V → Prop
| base {v} : v ∈ A → RedOrbitClosure red A v
| zero : RedOrbitClosure red A 0
| step {v} : RedOrbitClosure red A v → RedOrbitClosure red A (red v)
```
and prove that under `hred0` and `hred_bound`, the set `{v | RedOrbitClosure red A v}` is the least secure key space containing `A` whenever `A` is bounded. This gives a constructive alternative to the impredicative `sInter` definition.

### Proof Strategy

#### Strategy A: Pure closure-system route via `sInter` and least upper bounds
This is the most promising route for a first complete formalization.

1. Prove `secureKeySpace_inter` and then `secureKeySpace_sInter` directly from membership in `sInter`.
   - Zero: use `show (0 : V) ∈ sInter C` by intro `S hS`; exact `(hC S hS).1`.
   - Reduction stability: if `v ∈ sInter C`, then `v ∈ S` for every `S ∈ C`; apply each secure-space stability clause.
   - Norm bound: similarly inherited pointwise from every containing secure set.

2. Define `secureClosure` as the intersection of all secure supersets of `A`.

3. Prove leastness and containment abstractly:
   - `A ⊆ secureClosure red B A` by unfolding `sInter`.
   - `secureClosure red B A ⊆ S` for any secure superset `S` because `S` is one of the intersected sets.

4. For existence/characterization:
   - `(→)` is immediate since any secure superset bounds all elements of `A`.
   - `(←)` construct the candidate
     ```lean
     T := {v | ‖v‖ ≤ B}
     ```
     if `red` preserves the bound and `0` is bounded (`norm_zero`), then `T` is secure and contains `A`.

Why this is promising: it minimizes algebraic overhead, uses standard `Set.sInter` idioms, and isolates the subtle point—existence of at least one bounded secure superset.

#### Strategy B: Constructive inductive hull via reduction orbits
This is more ambitious and more cryptographically meaningful.

1. Define the closure generated by:
   - base seed membership,
   - zero,
   - repeated application of `red`.

2. Show every element in this inductive hull satisfies the norm bound if the seed is bounded and `red` is bound-preserving. This is an induction on derivations.

3. Show this hull is the least secure key space:
   - secure by induction,
   - least by proving any secure key space containing `A` contains every generated element.

Why this matters: it turns the abstract Moore closure into an executable derivation system, closer to how key spaces are generated in cryptographic protocols and reduction pipelines.

#### Strategy C: Specialize to lattice files and import certified inequalities from the catalog
Use this if you want stronger crypto authenticity.

1. Instantiate `V` with a lattice type already used in the repository, likely `Fin n → ℤ`.
2. Use `norm_cut_lower_bound`, `factor_vector_norm_bound'`, or `tropMatMul_norm_bound` to show specific reduction maps or cryptographic transforms preserve explicit bounds.
3. Derive a domain-specific theorem: e.g. tropical matrix key-update or factoring-derived reductions generate secure closures within certified norm radii.

Why this is powerful: it upgrades the abstract theorem into a bridge result connecting closure theory with concrete cryptographic primitives already verified in the catalog.

### Cross-Domain Connections

This project is bigger than lattices.

- **Universal algebra / order theory:** `SecureKeySpace` is a closure system; `secureClosure` is a nucleus-like operator on `Set V`. This imports the language of Moore families into cryptographic invariants.
- **Abstract interpretation / static analysis:** bounded secure closure is a safety invariant. The least secure hull is the abstract domain generated by a seed under a transition system (`red`).
- **Dynamical systems:** reduction iteration defines a discrete dynamical system; bounded secure key spaces are invariant bounded attractor regions.
- **Tropical cryptography:** if tropical matrix actions preserve a max-plus or min-plus norm surrogate, then tropical key evolution spaces become secure closure systems.
- **Proof-theoretic security certification:** the closure hull acts as a certified envelope around admissible keys, suggesting machine-checked attack-surface truncation.
- **Entropy extraction:** boundedness plus closure under derivation suggests a synthesis between geometric and information-theoretic security predicates.

This is exactly the kind of theorem that opens a field: **closure-theoretic cryptography**. Once formalized, one can ask about Galois connections between attack operators and secure hulls, fixed-point logics for key derivation, and abstract certification of cryptographic state spaces.

### Suggested Corollaries

Aim for at least one or two of these after the main theorem:

1. **Monotonicity**
```lean
theorem secureClosure_mono
    (red : V → V) (B : ℝ) {A₁ A₂ : Set V}
    (h : A₁ ⊆ A₂) :
    secureClosure red B A₁ ⊆ secureClosure red B A₂
```

2. **Idempotence**
```lean
theorem secureClosure_idem
    (red : V → V) (B : ℝ) (A : Set V)
    (hex : ∃ S : Set V, A ⊆ S ∧ SecureKeySpace red B S) :
    secureClosure red B (secureClosure red B A) = secureClosure red B A
```

3. **Fixed-point characterization**
```lean
theorem secureClosure_eq_iff
    (red : V → V) (B : ℝ) (S : Set V)
    (hex : ∃ T : Set V, S ⊆ T ∧ SecureKeySpace red B T) :
    secureClosure red B S = S ↔ SecureKeySpace red B S
```

4. **Impossibility corollary**
If `∃ v ∈ A, B < ‖v‖`, then no secure bounded closure exists.
