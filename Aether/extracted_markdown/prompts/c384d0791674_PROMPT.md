**Mode:** prove

Prove a genuinely new theorem package turning tropical canonicalization from an existence-level normalization into an **executable, complexity-certified algorithm** in Lean 4. The goal is not merely to show that canonical forms exist, but to certify that they can be computed by an extracted program with asymptotically optimal structure and exact semantic preservation. This is the bridge from formal tropical algebra to verified compilation and verified optimization.

You should target a theorem suite showing that canonicalization of finite tropical polynomials over `ℕ` or `ℝ` can be implemented by a sorting-plus-scan algorithm, and that this implementation is extensionally equal to the specification-level canonicalizer `NatCanonical p` (or its real/envelope analogue), while admitting a formal operation-count bound.

This would be a breakthrough because it upgrades tropical normalization from a declarative mathematical object into a **verified algorithmic primitive**. Once this exists, every future tropical compiler pass, shortest-path simplifier, min-plus hardware pipeline, and certified scheduling optimizer can use canonicalization as a trusted kernel.

## Precise Theorem Targets

You should define a concrete executable canonicalizer on finite lists of monomials. A monomial should be represented explicitly, e.g. as a pair `(exp, coeff)` or a structure with fields `e : ℕ` and `c : ℕ` / `ℝ`, depending on the ambient development.

A natural target is:

```lean
structure NatMono where
  exp   : ℕ
  coeff : ℕ
deriving DecidableEq, Repr
```

with polynomial data as:

```lean
abbrev NatPoly := List NatMono
```

Assuming `NatCanonical : NatPoly → NatPoly` already exists as the specification-level notion, define an executable algorithm:

```lean
def canonicalizeFast : NatPoly → NatPoly
```

based on sorting by exponent, merging equal exponents by coefficient-minimization, then scanning to remove dominated monomials.

### Core correctness theorem
```lean
theorem canonicalizeFast_correct (p : NatPoly) :
  canonicalizeFast p = NatCanonical p
```

If definitional equality to the existing canonicalizer is too rigid, prove setwise/extensional equality first:

```lean
theorem canonicalizeFast_spec (p : NatPoly) :
  CanonicalRepRel (canonicalizeFast p) (NatCanonical p)
```

and then derive equality under a uniqueness theorem for canonical representatives:

```lean
theorem canonicalizeFast_correct_of_unique
    (p : NatPoly)
    (huniq : CanonicalUnique) :
    canonicalizeFast p = NatCanonical p
```

### Semantic preservation theorem
Define evaluation:

```lean
def evalNatPoly : NatPoly → ℕ → ℕ
```

Then prove:

```lean
theorem eval_canonicalizeFast (p : NatPoly) (x : ℕ) :
  evalNatPoly (canonicalizeFast p) x = evalNatPoly p x
```

This is the theorem that matters for compiler extraction: the optimized representation computes the same tropical function.

### Minimality / optimality theorem
You should formalize that the output contains no redundant monomials and is minimal among equivalent canonical representatives:

```lean
theorem canonicalizeFast_irredundant (p : NatPoly) :
  Irredundant (canonicalizeFast p)

theorem canonicalizeFast_minimal
    (p q : NatPoly)
    (hq : Irredundant q)
    (heq : TropicallyEquivalent q p) :
    length (canonicalizeFast p) ≤ length q
```

This is stronger than correctness: it says the algorithm computes an **optimal compressed representation**.

### Complexity-bound theorem
Since Lean does not natively prove asymptotics by runtime introspection, formalize a cost model:

```lean
def canonCost : NatPoly → ℕ
```

or a step-indexed version of sort/scan costs. Then prove a quadratic upper bound first, with a pathway to `O(n log n)` later:

```lean
theorem canonicalizeFast_cost_quadratic (p : NatPoly) :
  canonCost p ≤ C * (p.length ^ 2) + C
```

for some explicit constant `C : ℕ`.

If you can isolate sorting separately, also target:

```lean
theorem canonicalizeFast_cost_split (p : NatPoly) :
  canonCost p ≤ sortCost p.length + scanCost p.length
```

with

```lean
theorem scanCost_linear (n : ℕ) :
  scanCost n ≤ C1 * n + C2
```

and, if using a verified mergesort from Mathlib or a locally defined one with comparison count:

```lean
theorem sortCost_nlogn (n : ℕ) :
  sortCost n ≤ C3 * n * Nat.log2 (n + 1) + C4 * n + C5
```

If the full `n log n` theorem is too infrastructure-heavy for one cycle, the mathematically decisive result is:

1. executable algorithm,
2. exact correctness,
3. irredundancy/minimality,
4. explicit quadratic bound.

That already changes the landscape.

## Proof Architecture: 3 Viable Strategies

### Strategy A: Specification-refinement pipeline
This is likely the most promising.

1. **Refine the spec into phases.**
   Show that `NatCanonical p` can be decomposed conceptually into:
   - permutation-invariant sorting,
   - same-exponent consolidation,
   - dominated-term elimination.

2. **Prove semantic invariance phase-by-phase.**
   Each phase preserves tropical evaluation. Use permutation invariance for sorting, direct coefficient-min arguments for merging equal exponents, and a geometric domination lemma for scan-based elimination.

3. **Invoke uniqueness of canonical form.**
   Once the fast output is sorted, irredundant, and semantically equivalent to `p`, identify it with `NatCanonical p`.

Why this is best: it mirrors compiler verification practice and isolates proof obligations cleanly. It also gives reusable lemmas for future verified optimization passes.

---

### Strategy B: Convex-geometric lower-envelope characterization
This is deeper and potentially more revolutionary, especially for the envelope version over `ℝ`.

1. Interpret each monomial `(e, c)` as the affine function `x ↦ c + e*x`.
2. Show canonicalization is exactly extraction of the lower envelope / nondominated frontier.
3. Prove that sorting by slope (`e`) followed by a monotone hull scan computes that frontier.

This connects tropical polynomial normalization to the same mathematics behind convex hull algorithms, Legendre–Fenchel transforms, and computational geometry. For the `ℝ` envelope theorem, this may be the cleanest route. The catalog theorem

- `tropical_interior_convex` from `Tropical/Core/TropicalDeepResearch.lean`

should be used as a geometric seed: it certifies convexity behavior that can support lower-envelope arguments and monotonicity of breakpoints.

Why this matters: it turns canonicalization into a theorem in **certified computational convexity**, not just list processing.

---

### Strategy C: Dominance as a tropical order / decision procedure
This is more algebraic.

1. Define a tropical preorder on monomials induced by pointwise domination.
2. Show canonicalization computes the antichain of minimal elements after quotienting equal exponents.
3. Extract a verified decision procedure for equivalence and irredundancy.

This approach is ideal if you want to generalize later to multivariate tropical polynomials, Pareto front computation, and tropical Gröbner-style reductions. It is also the right route if the existing `NatCanonical` is already framed order-theoretically.

## Deeper Mathematical Insight: What the Algorithm Is Really Computing

Do not frame this as “remove duplicates and dominated terms.” That is too shallow.

The true mathematical content is:

- A tropical polynomial is a finite family of affine cost functions.
- Canonicalization computes the **lower-envelope support** of that family.
- This support is the tropical analogue of:
  - the set of exposed points of a Newton polygon,
  - the active constraints in linear optimization,
  - the Pareto frontier in multicriteria optimization,
  - the alive branches in shortest-path dynamic programming.

So the theorem is not merely algorithm extraction. It is a certified equivalence between:

1. **syntax**: finite list of monomials,
2. **semantics**: pointwise min of affine functions,
3. **geometry**: lower convex envelope / hull frontier,
4. **algorithms**: sort-and-scan frontier extraction.

That four-way equivalence is the field-opening contribution.

### 5. Complexity theory / proof-producing algorithms
By certifying both correctness and cost bounds, you move toward a theory of **proof-carrying optimization algorithms** in tropical mathematics.

### 6. Convex analysis and Legendre duality
The lower-envelope viewpoint suggests future formalization of tropical dual transforms and Newton polytope semantics. This could become a bridge from tropical algebra to certified convex optimization.
