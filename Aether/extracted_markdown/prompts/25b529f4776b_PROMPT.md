## Precise Theorem Targets

You should define the objects so these statements become realistic Lean milestones.

### Theorem A: Monotone Karchmer–Wigderson upper bound from formulas

For a monotone Boolean formula computing a monotone function `f`, there is a deterministic monotone KW protocol whose communication cost is bounded by the formula depth.

Mathematical statement:

> For every `n : ℕ`, every monotone Boolean function `f : (Fin n → Bool) → Bool`, and every monotone formula `φ` computing `f`,  
> if `x,y : Fin n → Bool` satisfy `f x = true` and `f y = false`, then there exists an index `i : Fin n` such that `x i = true` and `y i = false`; moreover there is a deterministic protocol solving this search problem with cost at most `depth φ`.

Suggested Lean 4 type signature:
```lean
theorem monotone_formula_gives_KW_protocol
  {n : ℕ}
  (f : (Fin n → Bool) → Bool)
  (hf_mono : MonotoneBool f)
  (φ : MonoFormula n)
  (hφ : φ.eval = f) :
  ∃ P : KWProtocol n f,
    P.cost ≤ φ.depth
```

You will need supporting definitions like:
```lean
def MonotoneBool (f : (Fin n → Bool) → Bool) : Prop := ...
def MonoFormula (n : ℕ) := ...
def KWProtocol (n : ℕ) (f : (Fin n → Bool) → Bool) := ...
```

This is not yet the full equality, but it is the forward half that turns syntax into communication.

### Theorem B: Monotone Karchmer–Wigderson lower bound to formulas

If there is a deterministic monotone KW protocol of cost `d`, then there exists a monotone formula computing `f` of depth at most `d`.

Mathematical statement:

> For every monotone Boolean function `f`, any deterministic protocol solving the monotone KW relation for `f` with cost `d` induces a monotone formula computing `f` of depth at most `d`.

Suggested Lean 4 type signature:
```lean
theorem KW_protocol_gives_monotone_formula
  {n : ℕ}
  (f : (Fin n → Bool) → Bool)
  (hf_mono : MonotoneBool f) :
  ∀ P : KWProtocol n f,
    ∃ φ : MonoFormula n,
      φ.eval = f ∧ φ.depth ≤ P.cost
```

Combined with Theorem A, this yields the formal equivalence:
```lean
theorem monotone_formula_depth_eq_KW_cost
  {n : ℕ}
  (f : (Fin n → Bool) → Bool)
  (hf_mono : MonotoneBool f) :
  minMonoFormulaDepth f = minKWCost f
```

This is a major formal milestone. It gives Lean a certified version of one of the foundational correspondences in complexity theory.

### Theorem C: Rectangle lower bound implies monotone formula depth lower bound

You need an actual lower-bound extraction theorem that can later be instantiated for CLIQUE-like functions.

Mathematical statement:

> If every deterministic protocol solving the monotone KW relation of `f` requires communication cost at least `c`, then every monotone formula computing `f` has depth at least `c`.

Suggested Lean 4 type signature:
```lean
theorem KW_lower_bound_implies_formula_depth_lower_bound
  {n : ℕ}
  (f : (Fin n → Bool) → Bool)
  (hf_mono : MonotoneBool f)
  (c : ℕ)
  (hc : ∀ P : KWProtocol n f, c ≤ P.cost) :
  c ≤ minMonoFormulaDepth f
```

This theorem is the transfer mechanism from communication lower bounds to circuit lower bounds. It should be easy once A/B are done, but conceptually it is essential.

## Proof Strategy Architecture

### Strategy 1: Structural KW equivalence by recursion on formulas/protocol trees
Most promising for immediate success.

Steps:
1. **Define monotone formulas and their semantics**
   - variables, constants, `and`, `or`
   - `depth`, `size`
   - monotonicity proof by structural induction
2. **Define monotone KW relation**
   - on inputs `x,y` with `f x = true`, `f y = false`
   - output an index `i` with `x i = true ∧ y i = false`
3. **Prove formula → protocol**
   - recurse on formula root
   - `and`: both subformulas true on `x`, at least one false on `y`; Alice/Bob choose a child preserving the invariant
   - `or`: dual child-selection argument
4. **Prove protocol → formula**
   - recurse on protocol tree
   - leaf labeled by index `i` becomes variable `X_i`
   - Alice nodes become `or`, Bob nodes become `and` in the monotone setting
5. **Minimization corollaries**
   - derive depth equality and lower-bound transfer theorem

Why most promising: it is discrete, exact, and structurally aligned with Lean induction. No measure theory, no asymptotics first.

---

### Strategy 2: Rectangle/partition lower bounds for a concrete monotone relation
Most promising for obtaining the first nontrivial lower bound theorem after KW infrastructure.

Steps:
1. Define deterministic communication protocols and the induced partition into monochromatic rectangles.
2. Prove a generic lower bound:
   - if every monochromatic rectangle has density at most `δ`,
   - but the valid input space has density `μ`,
   - then cost is at least `⌈log₂ (μ / δ)⌉`.
3. Instantiate this for a monotone relation:
   - threshold separator,
   - disjointness-like monotone search relation,
   - or a restricted clique witness relation.
4. Transfer via KW to formula depth lower bounds.

Cross-domain hook: use entropy to formalize the partition counting argument. This is where catalog theorems become active ingredients.

---

### Strategy 3: Approximation-method scaffold for Razborov-type lower bounds
Most visionary, but technically hardest.

Steps:
1. Define monotone circuits/formulas and random approximators:
   - random “test” subsets / sunflowers / low-support approximants
2. Formalize an approximation lemma:
   - each small monotone circuit is close to a simple approximator under a chosen distribution on graphs
3. Prove a distinguishability theorem:
   - the target clique function differs significantly from every such approximator on positive/negative instances
4. Conclude a size lower bound by contradiction.

This is the route to genuine Razborov-style theorems. Even if the full endpoint is not finished, formalizing the approximation lemma and the “simple approximators cannot separate distributions” theorem would already be a major result.

## Cross-domain connections you must exploit

### 1. Information theory ↔ communication complexity
A protocol transcript is a code. A low-cost protocol compresses combinatorial witnesses. This makes the following catalog results operational:
- `compressor_gives_complexity_bound`

### 2. Order theory ↔ monotone computation
Monotone Boolean functions are order-preserving maps on a finite distributive lattice. This lets you use lattice-theoretic structure in place of ad hoc bit manipulations.

### 3. Proof complexity ↔ KW games
The KW correspondence is the communication shadow of formula complexity. Once formalized, it positions Lean for feasible interpolation and monotone proof lower bounds.

### 4. Extremal combinatorics ↔ approximation method
Razborov’s method is not “just complexity”; it is a probabilistic extremal combinatorics theorem about set systems and random restrictions/approximants. Formalize it that way.

### 5. Compression/Kolmogorov themes ↔ lower bounds
The theorem `compressor_gives_complexity_bound` suggests a broader doctrine: every small computational object yields compressibility. Lower bounds emerge from certifying incompressibility. This can become a reusable meta-pattern across complexity classes.

## Lean design advice

Use concrete finite types. Recommended encodings:

```lean
abbrev BitVec (n : ℕ) := Fin n → Bool
```

For order:
```lean
instance : LE (BitVec n) := ⟨fun x y => ∀ i, x i ≤ y i⟩
```
or simply define:
```lean
def BitwiseLE (x y : BitVec n) : Prop := ∀ i, x i = true → y i = true
```

Monotonicity:
```lean
def MonotoneBool {n : ℕ} (f : BitVec n → Bool) : Prop :=
  ∀ ⦃x y⦄, BitwiseLE x y → f x = true → f y = true
```

Formula syntax:
```lean
inductive MonoFormula (n : ℕ)
| var : Fin n → MonoFormula n
| bot : MonoFormula n
| top : MonoFormula n
| and : MonoFormula n → MonoFormula n → MonoFormula n
| or  : MonoFormula n → MonoFormula n → MonoFormula n
```

Then define:
- `eval`
- `depth`
- `size`

Protocols can be trees with alternating Alice/Bob moves, but for first formalization you may define a recursive object that already carries whose turn it is and the transcript cost.

For graph predicates:
```lean
abbrev Edge (m : ℕ) := Sym2 (Fin m)
abbrev Graph (m : ℕ) := Edge m → Bool
```
This is much better than matrices if you want undirected simple graphs without diagonal clutter.
