## Primary Theorem Target

Define tropical matrix multiplication on `Matrix (Fin n) (Fin n) ℝ` by replacing `+` with `max` and `*` with `+`. Interpret a weighted directed graph on `Fin n` as a matrix `W : Matrix (Fin n) (Fin n) ℝ`, where `W i j` is the weight of edge `i → j`.

Then prove the exact path-composition theorem:

### Mathematical statement
For every `n : ℕ`, every weighted adjacency matrices
`A B : Matrix (Fin n) (Fin n) ℝ`, and every vertices `i j : Fin n`,
the `(i,j)` entry of the tropical product `A ⊗ B` equals the maximum weight of all length-2 directed paths `i → k → j`:
\[
(A ⊗ B)_{ij} = \max_{k \in \mathrm{Fin}\, n} (A_{ik} + B_{kj}).
\]
This should then be lifted to `k`-fold tropical powers:
\[
(W^{⊗ m})_{ij} = \max \{ \text{weight}(p) : p \text{ is a directed path of length } m \text{ from } i \text{ to } j \}.
\]

This is the first genuinely structural theorem here: it turns tropical algebra into certified graph semantics.

## Lean 4 formalization target

You will likely need to introduce a finite tropical matrix product and a path-weight notion.

A plausible core signature is:

```lean
def tropMul {n : ℕ} (A B : Matrix (Fin n) (Fin n) ℝ) :
    Matrix (Fin n) (Fin n) ℝ :=
  fun i j => Finset.univ.sup fun k => A i k + B k j
```

Because `Finset.sup` over `ℝ` requires order infrastructure and a default/nonempty handling, it may be cleaner to use `sSup` over a finite set image or define first for `n.succ`. Another practical version is:

```lean
def tropMul {n : ℕ} [Fact (0 < n)] (A B : Matrix (Fin n) (Fin n) ℝ) :
    Matrix (Fin n) (Fin n) ℝ :=
  fun i j => Finset.univ.sup' Finset.univ_nonempty (fun k => A i k + B k j)
```

Then the first theorem should be literally definitional or one-line after unfolding:

```lean
theorem tropMul_entry {n : ℕ} [Fact (0 < n)]
    (A B : Matrix (Fin n) (Fin n) ℝ) (i j : Fin n) :
    tropMul A B i j = Finset.univ.sup' Finset.univ_nonempty (fun k => A i k + B k j) := by
  rfl
```

But the real theorem should connect this to graph paths. One robust path theorem target is:

```lean
def Path2Weight {n : ℕ} (W₁ W₂ : Matrix (Fin n) (Fin n) ℝ)
    (i j k : Fin n) : ℝ :=
  W₁ i k + W₂ k j

theorem tropMul_eq_max_path2_weight
    {n : ℕ} [Fact (0 < n)]
    (W₁ W₂ : Matrix (Fin n) (Fin n) ℝ) (i j : Fin n) :
    tropMul W₁ W₂ i j =
      Finset.univ.sup' Finset.univ_nonempty (fun k => Path2Weight W₁ W₂ i j k) := by
  rfl
```

Then define tropical powers and path weights recursively:

```lean
def tropPow {n : ℕ} [Fact (0 < n)] :
    ℕ → Matrix (Fin n) (Fin n) ℝ → Matrix (Fin n) (Fin n) ℝ
| 0, W => tropId
| m+1, W => tropMul (tropPow m W) W
```

and a recursive path-weight semantics for length `m`. The flagship theorem is:

```lean
theorem tropPow_eq_max_pathWeight
    {n : ℕ} [Fact (0 < n)]
    (W : Matrix (Fin n) (Fin n) ℝ) :
    ∀ (m : ℕ) (i j : Fin n),
      tropPow m W i j =
        sSup {w : ℝ | ∃ p, IsPathOfLength m i j p ∧ PathWeight W p = w}
```

You may need to replace `sSup` with a finite `Finset.sup'` over a finite encoding of length-`m` paths. That is likely the better Lean route.

## Third theorem target: associativity of tropical matrix multiplication

This is infrastructure, but nontrivial and essential.

### Statement
For all finite square matrices over `ℝ` (or better `LinearOrderedAddCommMonoid` if abstraction is manageable),
\[
(A ⊗ B) ⊗ C = A ⊗ (B ⊗ C).
\]

Lean target:

```lean
theorem tropMul_assoc {n : ℕ} [Fact (0 < n)]
    (A B C : Matrix (Fin n) (Fin n) ℝ) :
    tropMul (tropMul A B) C = tropMul A (tropMul B C) := by
```

This theorem is the algebraic engine behind path concatenation. Once proved, `tropPow` becomes mathematically legitimate rather than ad hoc.

## Proof strategy options

### Strategy A: Finite-sup direct algebra on matrices
1. Define `tropMul` using `Finset.sup'`.
2. Prove entrywise formulas by `rfl`/unfolding.
3. For associativity, show both sides equal
   \[
   \sup_{j}\sup_{k}(A_{ij}+B_{jk}+C_{k\ell})
   \]
   and commute/reassociate finite suprema plus real addition.
4. Then derive path semantics by induction on path length.

Why promising: this is the most canonical route in Lean because finite index types and `Finset` are manageable. It also gives reusable infrastructure.

### Strategy B: Work in `WithBot ℝ` or a max-plus semiring abstraction
1. Define a tropical semiring instance or use an existing order-theoretic structure if Mathlib supports enough of it.
2. Reinterpret tropical matrix multiplication as ordinary matrix multiplication over that semiring.
3. Path semantics then follows from standard matrix-power combinatorics.

Why promising: conceptually elegant and scalable. Why risky: semiring instance engineering may become a time sink unless Mathlib already has suitable max-plus machinery.

### Strategy C: Encode paths first, algebra second
1. Define finite path objects `Fin m → Fin n` with endpoint constraints.
2. Define path weight recursively.
3. Show tropical multiplication computes one-step extension of optimal path weight.
4. Derive associativity as a corollary of path concatenation semantics.

Why promising: strongest semantic story. Why risky: path encodings can become cumbersome before algebraic lemmas are available.

Most promising overall: Strategy A first, then import semantic content from Strategy C. Do not start by over-abstracting. Get the finite real-valued matrix theory working concretely on `Fin n`.
