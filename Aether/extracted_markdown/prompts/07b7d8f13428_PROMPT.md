Prove new, non-trivial theorems around the Hadamard matrix conjecture, but do not stop at restating folklore. The target is not “formalize a few examples.” The target is to make Lean certify a new mathematical interface for **Hadamard existence by algebraic generation**, and to connect it to **balanced designs, binary codes, spectral energy, and signal processing** in a way that makes future attacks on the full conjecture structurally possible.

## Core Vision

The classical conjecture says:

> For every positive integer `n`, if `4 ∣ n`, then there exists an `n × n` Hadamard matrix.

This is still open in full generality. So you must not pretend to solve the full conjecture. Instead, formalize and prove a **deep existence calculus** that strictly enlarges the certified universe of Hadamard orders and explains why the known constructions behave as a semiring of existence certificates.

The real breakthrough would be:

1. a precise formal notion of **Hadamard order generation**;
2. closure theorems proving that known constructions generate large infinite families;
3. a bridge theorem to **symmetric balanced incomplete block designs**, **Walsh codes**, or **optimal correlation sequences**;
4. a verified algorithm that, given `n`, either constructs a Hadamard matrix from certified generators or returns a mathematically meaningful obstruction/report.

This turns a century-old existence problem into a machine-checkable theory of constructive evidence.

## Theorem Program

You must prove **at least 3 substantial theorems**, all with real proof structure. Use induction, `rcases`, contradiction, matrix algebra, `field_simp` where relevant, and multi-step `calc`. No trivial proofs by enumeration.

### Theorem 1: Tensor closure of Hadamard existence

**Mathematical statement**

For all positive integers `m, n`, if Hadamard matrices exist of orders `m` and `n`, then one exists of order `m*n`.

**Lean-style target**
```lean
theorem hadamardOrder_mul
    {m n : ℕ} (hm : HadamardOrder m) (hn : HadamardOrder n) :
    HadamardOrder (m * n)
```

**Breakthrough significance**

This theorem turns isolated constructions into an algebra of existence. It is the formal core of “Hadamard orders form a multiplicative semigroup.” Once certified, every new sporadic order immediately explodes into infinitely many others. This is the right abstraction layer for attacking density questions.

**Proof strategy paths**

- **Strategy A: Kronecker/tensor matrix proof**
  1. Unpack `hm`, `hn` into matrices `H₁`, `H₂`.
  2. Define the Kronecker product `H := H₁ ⊗ₖ H₂` on product index types.
  3. Prove entrywise sign preservation and compute
     `H ⬝ H.transpose = (m*n) • 1`
     using mixed-product rules for Kronecker products.
  This is the most promising strategy if Mathlib’s matrix tensor/Kronecker API is adequate.

- **Strategy B: Row dot-product proof**
  1. Represent rows of the tensor product as pointwise products of row pairs.
  2. Show row inner products factor:
     `<r₁⊗s₁, r₂⊗s₂> = <r₁,r₂> * <s₁,s₂>`.
  3. Conclude orthogonality and norm.
  This is often easier than wrestling with matrix extensionality and may be more Lean-friendly.

- **Strategy C: Certified existence semigroup**
  1. Define a constructor on `HadamardOrder`.
  2. Prove a separate lemma that the matrix-level tensor constructor preserves `IsHadamard`.
  3. Package the result as a closure theorem.
  This gives the cleanest API for future growth.

### Theorem 2: Sylvester family gives infinite powers-of-two existence

**Mathematical statement**

For every `k : ℕ`, there exists a Hadamard matrix of order `2^k`.

**Lean-style target**
```lean
theorem hadamardOrder_pow_two (k : ℕ) :
    HadamardOrder (2 ^ k)
```

Optionally strengthen to:
```lean
theorem hadamardOrder_four_mul_pow_two (k : ℕ) :
    HadamardOrder (4 * 2 ^ k)
```

**Breakthrough significance**

This gives a fully verified infinite family and serves as the induction testbed for your existence calculus. It should not be a toy theorem: prove it through the new compositional framework, not by ad hoc matrices at each size.

**Proof strategy paths**

- **Strategy A: Induction via Sylvester doubling**
  1. Construct the `2 × 2` seed matrix.
  2. Define the Sylvester doubling operator
     `H ↦ [[H, H], [H, -H]]`.
  3. Prove preservation of the Hadamard property and conclude by induction on `k`.
  This is the canonical route and should be implemented cleanly.

- **Strategy B: Deduce from tensor closure**
  1. Prove `HadamardOrder 2`.
  2. Use repeated multiplication / powers:
     `2^k` is generated by the multiplicative semigroup theorem.
  3. Package as a semigroup-power lemma.
  This is elegant if your `HadamardOrder` API is strong.

- **Strategy C: Explicit Walsh recursion**
  1. Define Walsh matrices recursively.
  2. Show they are Hadamard by recursive orthogonality.
  3. Relate recursion to powers of two.
  This is strongest if you want immediate applications to signal processing.

### Theorem 3: Hadamard matrices induce balanced block designs

This is your required cross-domain bridge theorem.

**Mathematical statement**

If `H` is a normalized Hadamard matrix of order `4t`, then deleting the first row and column and converting `-1/1` to `0/1` yields the incidence matrix of a symmetric `2-(4t-1, 2t-1, t-1)` design.

**Lean-style target, schematic**
```lean
def NormalizedHadamard {n : Type*} [Fintype n] [DecidableEq n]
    (H : Matrix n n ℤ) : Prop :=
  IsHadamard H ∧ (∀ i, H i default = 1) ∧ (∀ j, H default j = 1)

theorem normalized_hadamard_gives_symmetric_design
    {t : ℕ} {α : Type*} [Fintype α] [DecidableEq α]
    (hcard : Fintype.card α = 4 * t)
    {H : Matrix α α ℤ}
    (hH : NormalizedHadamard H) :
    ∃ β : Type*, ∃ _ : Fintype β, ∃ _ : DecidableEq β,
      Fintype.card β = 4 * t - 1 ∧
      -- incidence structure with design parameters
      SymmetricBIBD β (2 * t - 1) (t - 1)
```

If `SymmetricBIBD` does not exist in the catalog, define it yourself as a novel structure:

```lean
structure SymmetricBIBD (V : Type*) [Fintype V] [DecidableEq V]
    (k λ : ℕ) : Prop := 
  (blocks : Type*)
  [blocks_fintype : Fintype blocks]
  [blocks_decidableEq : DecidableEq blocks]
  (inc : V → blocks → Prop)
  (v_eq_b : Fintype.card V = Fintype.card blocks)
  (block_size : ∀ B, Fintype.card {x : V // inc x B} = k)
  (pair_count : ∀ x y, x ≠ y →
      Fintype.card {B : blocks // inc x B ∧ inc y B} = λ)
```

**Breakthrough significance**

This theorem is where the project stops being isolated linear algebra and becomes combinatorics. It formally certifies the classical bridge:
**Hadamard matrices ↔ symmetric designs ↔ codes ↔ communication structures**.
Once this bridge exists, every existence theorem for Hadamard matrices automatically yields a design theorem and vice versa.

**Proof strategy paths**

- **Strategy A: Direct row-intersection counting**
  1. Normalize the matrix so first row/column are all `1`.
  2. Delete the first row/column and map `1 ↦ 1`, `-1 ↦ 0`.
  3. Use orthogonality to compute row sums and pairwise intersections exactly.
  This is conceptually clean and mathematically important.

- **Strategy B: Inner-product-to-incidence translation**
  1. Express binary incidence vectors in terms of sign vectors:
     `x_bin = (x_sign + 1)/2`.
  2. Translate orthogonality identities into cardinality identities.
  3. Package them into `SymmetricBIBD`.
  This is algebraically elegant; expect `field_simp` and parity lemmas.

- **Strategy C: Build a reusable sign-to-binary equivalence API**
  1. Define a conversion from sign matrices to incidence matrices.
  2. Prove generic lemmas relating dot products to Hamming weights/intersections.
  3. Apply to normalized Hadamard matrices.
  This gives maximum downstream value for coding theory.

### Theorem 4: Hadamard rows produce optimal binary codes / Walsh spectra

You need at least one theorem linking to coding theory or signal processing.

**Mathematical statement**

Rows of a normalized Hadamard matrix, after sign-to-bit conversion, form a binary code with pairwise Hamming distance exactly `n/2`.

**Lean-style target**
```lean
def signRowToBitVector {n : Type*} [Fintype n] [DecidableEq n]
    (r : n → ℤ) : n → Bool := ...

theorem hadamard_rows_equidistant_code
    {α : Type*} [Fintype α] [DecidableEq α]
    {H : Matrix α α ℤ}
    (hH : IsHadamard H) :
    ∀ i j, i ≠ j →
      hammingDist (signRowToBitVector (fun k => H i k))
                  (signRowToBitVector (fun k => H j k))
      = Fintype.card α / 2
```

If `hammingDist` is unavailable, define it.

**Breakthrough significance**

This is the coding-theory and communications bridge. It says Hadamard matrices certify **maximally separated codewords**, foundational for error correction, CDMA/Walsh coding, compressed sensing heuristics, and low-correlation signaling.

**Proof strategy paths**

- **Strategy A: Dot product vs Hamming distance identity**
  1. Prove for sign vectors `x,y ∈ {±1}^n`:
     `dot x y = n - 2 * d_H(x,y)`.
  2. Apply orthogonality to conclude `d_H = n/2`.
  This is the cleanest route.

- **Strategy B: Count equal and unequal coordinates**
  1. Partition coordinates into agreement/disagreement sets.
  2. Translate dot product into cardinality difference.
  3. Use orthogonality.
  More combinatorial, often easier to formalize than algebra over booleans.

- **Strategy C: Fourier/Walsh transform interpretation**
  1. View rows as characters of a Walsh system in the Sylvester case.
  2. Deduce flat cross-correlation and equidistance.
  3. Then abstract to arbitrary Hadamard matrices.
  This is the most conceptually ambitious and opens signal-processing narratives.

## Precise Arithmetic / Obstruction Theorem

You should also prove a nontrivial necessary condition.

### Theorem 5: Order divisibility obstruction

**Mathematical statement**

If a Hadamard matrix of order `n > 2` exists, then `4 ∣ n`.

**Lean-style target**
```lean
theorem hadamard_order_mod_four
    {n : ℕ} (hn : 2 < n) (hH : HadamardOrder n) :
    4 ∣ n
```

**Breakthrough significance**

This theorem turns the folklore congruence obstruction into a certified gateway lemma. It is essential for any existence-search algorithm because it rules out impossible orders before search begins.

**Proof strategy paths**

- **Strategy A: Normalize and parity count**
  1. Normalize the matrix.
  2. Compare two non-first rows: each has equally many agreements/disagreements.
  3. Deduce the row length beyond the first coordinate is even, hence `n ≡ 0 mod 4`.
  This is the standard and likely best path.

- **Strategy B: Sum-of-row argument**
  1. Show non-first rows have zero sum.
  2. Hence `n` is even.
  3. Use pairwise intersections in the binary reduction to get one more factor of 2.
  Good if your design bridge is already established.

- **Strategy C: Hamming distance route**
  1. Convert rows to binary vectors.
  2. Distances are `n/2`, so `n` must be even.
  3. Normalize and count weights to force `n/2` odd/even constraints leading to `4 ∣ n`.
  This beautifully links coding and arithmetic.
