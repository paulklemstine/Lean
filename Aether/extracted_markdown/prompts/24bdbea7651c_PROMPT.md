## Assignment: Emergent Computation in Pythagorean Orbit Lattices

Do not treat this as “another encoding theorem.” The breakthrough target is to turn the Berggren dynamics of primitive Pythagorean triples into a formally verified computational medium. The point is not merely that one can Gödel-encode Turing machines into naturals; the point is to prove that the *native orbit geometry* generated by Berggren transformations already carries enough local combinatorial structure to realize universal computation with controlled overhead. If achieved cleanly, this opens a new field: arithmetic dynamics as a substrate for intrinsic computation.

You should aim for a theorem package with one main universality theorem and 2–4 supporting structural theorems that are actually provable in Lean 4 with Mathlib and the catalog results.

### Core Vision

Primitive Pythagorean triples form a rooted ternary orbit under the classical Berggren matrices. The catalog already gives:

- `berggren_preserves_pythagorean`
- `berggren_lattice_automorphism`
- `berggren_entry_growth_bound`
- `exists_fixed_point_on_orbit_with_bound`
- `post_quantum_lattice_orbit_repeat_bound`

The key conceptual move is this:

1. formalize the Berggren orbit as a directed lattice/tree-like state graph,
2. define a finite-local update rule on configurations over that graph,
3. prove a simulation theorem for a known universal model,
4. derive polynomial overhead from the growth bound.

If the strongest “Turing-complete cellular automaton on the full Berggren orbit lattice” is too ambitious in one cycle, prove the finite-support simulation theorem first. But keep the universality statement explicit and central.

## Precise Theorem Targets

### Target A: Berggren orbit admits a computable rooted branching structure

Define a type of primitive triples and a one-step successor relation induced by the three Berggren generators. Then prove that every reachable state has exactly three canonical children and finite ancestry from the root `(3,4,5)`.

A useful Lean-facing skeleton:

```lean
structure PrimTriple where
  v : Fin 3 → ℤ
  primitive : Int.gcd (v 0) (Int.gcd (v 1) (v 2)) = 1
  pythagorean : (v 0)^2 + (v 1)^2 = (v 2)^2
  positive : 0 < v 0 ∧ 0 < v 1 ∧ 0 < v 2
```

Define:

```lean
inductive BDir where
  | A | B | C
deriving DecidableEq, Repr

def berggrenStep : BDir → PrimTriple → PrimTriple := ...
```

Then prove a structural theorem of the form:

```lean
theorem berggren_children_injective :
  ∀ d₁ d₂ : BDir, ∀ t₁ t₂ : PrimTriple,
    berggrenStep d₁ t₁ = berggrenStep d₂ t₂ →
    d₁ = d₂ ∧ t₁ = t₂
```

and a reachability/word realization theorem:

```lean
def reachableFromRoot (t : PrimTriple) : Prop := ∃ w : List BDir, applyWord w rootTriple = t

theorem reachable_has_word :
  ∀ t : PrimTriple, reachableFromRoot t → ∃ w : List BDir, applyWord w rootTriple = t
```

This may look tautological, so sharpen it into a normal form / uniqueness statement if possible:

```lean
theorem berggren_word_normal_form :
  ∀ t : PrimTriple, reachableFromRoot t →
    ∃! w : List BDir, applyWord w rootTriple = t
```

This uniqueness statement is the real structural lever: it turns the orbit into a canonical address space, analogous to binary strings on a tape tree.

### Target B: Local cylinder sets on Berggren words support shift-like dynamics

Define finitely supported configurations over orbit addresses:

```lean
def OrbitAddr := List BDir
def CellState := Fin k
def Config := OrbitAddr → CellState
```

Introduce a local rule depending only on a bounded neighborhood in the prefix/tree metric. For example, a radius-`r` rule:

```lean
def isLocalRule (r : ℕ) (F : Config → Config) : Prop := ...
```

Then prove existence of a nontrivial local rule that simulates a one-dimensional cellular automaton on a designated embedded geodesic, e.g. the `A`-ray.

A theorem target:

```lean
theorem exists_shift_embedding :
  ∃ φ : ℤ → OrbitAddr,
    Function.Injective φ ∧
    ∃ c : ℕ, ∀ m n : ℤ,
      distAddr (φ m) (φ n) ≤ c * Int.natAbs (m - n) + c
```

and then:

```lean
theorem exists_local_rule_simulating_line_CA :
  ∃ (k : ℕ) (F : Config → Config),
    isLocalRule 1 F ∧
    simulatesRule110AlongEmbedding F
```

You do not need to insist on Rule 110 specifically if Lean formalization becomes painful. A cyclic tag system, 2-counter machine, or a nearest-neighbor universal CA is equally acceptable. What matters is a *precise simulation theorem*.

### Target C: Universality theorem with polynomial overhead

This is the flagship theorem. Phrase it in a way that isolates the difficult computational content from the graph geometry.

A Lean-oriented statement:

```lean
theorem berggren_orbit_universal_with_poly_overhead :
  ∃ (k : ℕ) (F : Config → Config) (encode : TM2.Config Σ Γ → Config)
    (decode : Config → TM2.Config Σ Γ),
    isLocalRule 1 F ∧
    (∀ M x T,
      ∃ p : Polynomial ℕ,
        let c₀ := encode (TM2.init M x)
        let cT := (Nat.iterate F T) c₀
        simulates_upto_halt M x T cT ∧
        configuration_size cT ≤ p.eval (input_size x + T))
```

If formalizing `TM2` directly is too heavy, replace it with a simpler universal machine model already available or easy to define, e.g. a 2-counter machine or a finite string rewriting system.

A weaker but still major theorem is:

```lean
theorem berggren_orbit_simulates_two_counter_machine :
  ∃ (k : ℕ) (F : Config → Config),
    isLocalRule 1 F ∧
    ∀ P : TwoCounterProgram, ∃ encode,
      faithful_simulation F encode P
```

Then derive undecidability of reachability or eventual periodicity:

```lean
theorem berggren_CA_reachability_undecidable :
  ¬ Decidable (∀ (F : Config → Config) (c₀ ct : Config), ∃ n, (Nat.iterate F n) c₀ = ct)
```

Even if the final undecidability theorem is only sketched informally, the simulation theorem is the breakthrough formal core.

### Target D: Polynomial overhead from entry growth

Use `berggren_entry_growth_bound` to prove that address length and arithmetic bit-size remain polynomially coupled. This is where the arithmetic geometry becomes essential rather than cosmetic.

A theorem target:

```lean
theorem orbit_address_bitlength_polynomial_bound :
  ∃ p : Polynomial ℕ,
    ∀ w : BerggrenWord,
      bitSizeTriple (applyWord w rootTriple) ≤ p.eval w.length
```

and ideally a converse coarse bound:

```lean
theorem word_length_bounded_by_bitlength :
  ∃ C D : ℕ,
    ∀ w : BerggrenWord,
      w.length ≤ C * bitSizeTriple (applyWord w rootTriple) + D
```

This converts computational time on the orbit into ordinary complexity-theoretic resources.

## Proof Strategy Architecture

### Strategy 1: Embed a 1D universal cellular automaton along a canonical geodesic
Most promising.

**Step 1.** Prove the orbit has a canonical infinite ray, e.g. repeated application of one generator:
`[]`, `[A]`, `[A,A]`, `[A,A,A]`, ...
This gives an embedded copy of `ℕ`, and with a bi-infinite coding trick using two rays meeting at the root, you can simulate `ℤ`.

**Step 2.** Extend a 1D CA local rule to the whole Berggren tree by making off-ray cells quiescent or act as signal routers. Prove the update on the designated ray is unaffected by the rest of the graph.

**Step 3.** Import universality from a known universal 1D CA or cyclic tag system simulation. Then use `berggren_entry_growth_bound` to control the arithmetic size of cells used up to time `T`, yielding polynomial overhead.

Why this is promising: it minimizes graph-theoretic complexity. You only need enough orbit structure to host a line and enough locality to preserve the simulation.

### Strategy 2: Use the full ternary tree structure to implement a reversible branching machine
Potentially deeper, but harder.

**Step 1.** Prove the Berggren orbit is isomorphic, or almost isomorphic, to a rooted ternary tree on primitive triples via unique normal forms.

**Step 2.** Encode machine configurations as finite labeled subtrees. Use branching to represent tape segments, stacks, or counter values.

**Step 3.** Define a local tree automaton whose update realizes machine transitions via parent/child communication.

Why this is exciting: it makes universality intrinsic to the Berggren orbit, not imported from a line. Why it is harder: local tree automata are more subtle, and proving faithful simulation may require significant bespoke infrastructure.

### Strategy 3: Counter-machine simulation via arithmetic addresses
Most likely easiest to formalize if direct CA universality gets bogged down.

**Step 1.** Use Berggren word addresses as canonical codes for naturals or pairs of naturals.

**Step 2.** Define a local or near-local update system that implements increment/decrement/branch on address-coded counters.

**Step 3.** Prove simulation of Minsky 2-counter machines, then deduce universality/undecidability.

Why this is valuable: two-counter machines are much simpler to formalize than Turing machines, and universality is still genuine.

Recommendation: begin with Strategy 1, keep Strategy 3 as fallback, and treat Strategy 2 as the conceptual north star.

## How to Build on the Catalog Theorems

### `berggren_preserves_pythagorean`
Use this to ensure `berggrenStep` is closed on the carrier of Pythagorean triples. If positivity or primitiveness are missing, prove auxiliary lemmas that the classical Berggren matrices preserve those too on the intended domain.

### `berggren_lattice_automorphism`
This is crucial for turning orbit transitions into structure-preserving graph moves. Use it to justify that the local neighborhood relation is stable under address translation and that your CA rule respects the lattice symmetry.

### `berggren_entry_growth_bound`
This is the engine for complexity control. Every simulation theorem should culminate in a size-vs-time bound that explicitly invokes this theorem. Without it, “polynomial overhead” is just rhetoric.

### `exists_fixed_point_on_orbit_with_bound`
This can be used to construct quiescent or marker configurations, or to prove existence of bounded anchor states needed for initialization and synchronization.

### `post_quantum_lattice_orbit_repeat_bound`
This suggests a route to proving eventual periodicity bounds for restricted finite-state dynamics on bounded orbit regions. Even if universality makes global periodicity undecidable, local finite truncations can still satisfy effective repeat bounds. This gives a beautiful tension: finite truncations are controlled, while the infinite orbit supports universality.

## Cross-Domain Connections You Must Exploit

1. **Symbolic dynamics / cellular automata**  
   The orbit lattice should be treated as a non-Euclidean shift space. This connects arithmetic group actions with CA universality and undecidability.

2. **Geometric group theory**  
   Unique Berggren word normal forms turn primitive triples into a geometric coding space. If formalized cleanly, this is a small-scale arithmetic analogue of automatic structures and Cayley graph computation.

3. **Complexity theory**  
   The polynomial overhead theorem is not decorative; it upgrades existence of encoding to an efficient simulation result. This positions the work near implicit computational complexity and machine-independent models.

4. **Arithmetic dynamics / Diophantine geometry**  
   Primitive triples become not just number-theoretic objects but dynamically addressable computational states. This is the field-opening angle.

5. **Reversible / conservative computation**  
   Since Berggren maps are lattice automorphisms, there may be a path to reversible computational primitives. Even a partial result here would be striking.

Application keywords: **arithmetic dynamics, cellular automata, symbolic dynamics, Turing universality, complexity bounds, Diophantine computation, geometric group theory, reversible computation, undecidability, orbit coding**.

- This is where the arithmetic substrate becomes mathematically meaningful.

## Risk Management / If Direct Proof Fails

- If unique normal forms fail globally, restrict to a clean reachable suborbit where they hold.
- If full bi-infinite line embedding is awkward, simulate one-sided machines on `ℕ`.
- If CA locality on the full orbit is too technical, prove universality for finite-support configurations with a guarded update rule.
- If TM formalization is too expensive, switch to 2-counter machines.
- If polynomial overhead in exact bit complexity is too hard, first prove an explicit exponential upper bound, then sharpen using `berggren_entry_growth_bound`.
