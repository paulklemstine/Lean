## Precise theorem targets

You should sharpen the current informal targets into statements with explicit state vectors, layer operators, and endpoint extraction. The most useful formulation is via a tropical state vector after `i` layers.

### Core semantic theorem
```lean
theorem bp_layer_state_eq_transfer_fold
    (w d : ℕ) (P : TropicalBP w d) :
    ∀ i, i ≤ d →
      layerState P i =
        (transferProductUpTo P i).mulVec startVec
```

Here:
- `layerState P i : Fin w → TropicalWeight` is the minimum cost to reach each node at layer `i`,
- `transferProductUpTo P i` is the tropical product of the first `i` transfer matrices,
- `mulVec` is tropical matrix-vector multiplication,
- `startVec` is `0` at the start node and `∞` elsewhere.

This is the true induction invariant. The final theorem should be derived from it.

### Endpoint / min-cost extraction theorem
```lean
theorem bp_eval_eq_transfer_matrix_product
    (w d : ℕ) (P : TropicalBP w d) :
    P.minCost =
      (transferProductUpTo P d).mulVec startVec P.accept
```

If your library design prefers row vectors instead of column vectors, transpose accordingly, but keep the semantics exact.

### Path-sum / partition-function formulation
If `P.minCost` is currently defined via minimization over paths, prove the transfer form as an equivalence:
```lean
theorem transfer_product_entry_eq_min_path_weight
    (w d : ℕ) (P : TropicalBP w d) (v : Fin w) :
    (transferProductUpTo P d).mulVec startVec v =
      ⨅ p : P.PathsTo v d, pathWeight P p
```
or the closest available finite-minimum formulation in Mathlib.

This is mathematically deeper than the endpoint theorem and makes the transfer-operator semantics canonical.

### Circuit unrolling theorem
```lean
theorem circuit_unrolls_transfer
    (w d : ℕ) (P : TropicalBP w d) :
    tropBPToCircuit P =
      unfoldTransferProduct (transferMatrices P) startVec P.accept
```

If literal definitional equality is too strong, replace with semantic equality:
```lean
theorem circuit_eval_eq_transfer_unroll
    (w d : ℕ) (P : TropicalBP w d) :
    evalCircuit (tropBPToCircuit P) =
      evalUnrolledTransfer (transferMatrices P) startVec P.accept
```

In practice, the semantic version is often the correct theorem; if definitional equality becomes brittle, prove semantic equality first and then derive a stronger extensional statement if possible.

## 2–3 proof strategies

### Strategy A: Dynamic-program induction on layers
**Most promising.**

1. Define `layerState P 0 = startVec` and `layerState P (i+1)` by one tropical Bellman update:
   ```lean
   layerState P (i+1) v = ⨅ u, layerState P i u ⊗ transferMatrix P i u v
   ```
   where `⊗` is tropical addition of costs.

2. Prove by induction on `i` that
   ```lean
   layerState P i = (transferProductUpTo P i).mulVec startVec
   ```
   The induction step should reduce to associativity of tropical matrix multiplication and the definition of tropical matrix-vector action.

3. Conclude
   ```lean
   P.minCost = layerState P d P.accept
   ```
   by unfolding the definition of `minCost`.

**Why this is promising:** it aligns exactly with how both branching programs and transfer operators evolve. It avoids difficult path combinatorics until the semantic backbone is established.

---

### Strategy B: Path decomposition / finite-infimum theorem
1. Define paths of length `i` ending at `v`.
2. Show every such path uniquely decomposes into:
   - a path of length `i` ending at some `u`,
   - followed by one edge from `u` to `v` in layer `i`.
3. Use this decomposition to prove the Bellman recursion for path minima, then identify that recursion with tropical matrix multiplication.

This is stronger than Strategy A because it proves the **partition-function semantics** directly: transfer products compute minima over all paths. It may be technically heavier due to finite path indexing, but it opens the door to later weighted-automata and thermodynamic formalizations.

---

### Strategy C: Circuit compilation correctness by structural recursion
1. Inspect `tropBPToCircuit` and define `unfoldTransferProduct` recursively over layers.
2. Show both constructions produce the same gate DAG shape modulo extensional evaluation.
3. Prove semantic equality by induction on depth, using the already-established transfer recursion.

This is likely the right route for `circuit_unrolls_transfer`. Do **not** insist on syntactic equality unless the compiler is definitionally built by the same recursion. Semantic equivalence is the mathematically meaningful theorem.

## Which strategy to prioritize

1. **First:** Strategy A for `bp_layer_state_eq_transfer_fold` and `bp_eval_eq_transfer_matrix_product`.  
2. **Second:** Strategy C for the circuit theorem, built on the state recursion theorem.  
3. **Third:** Strategy B if time permits, because it upgrades the result from “algorithmic equivalence” to “path-integral semantics.”

This order minimizes sorrys while maximizing theorem depth.

## Mathematical framing and deeper insight

This project should be presented as a tropical analogue of the transfer-matrix formalism from statistical mechanics.

A depth-`d` branching program with layer matrices `M₀, …, M_{d-1}` computes:
- in ordinary thermodynamics: a partition function via matrix products,
- in tropical thermodynamics: a **zero-temperature free energy**, i.e. a minimum action / minimum path cost.

Thus:
- **partition function** ↔ weighted path sum,
- **zero-temperature limit** ↔ tropicalization,
- **transfer operator** ↔ Bellman propagation,
- **compiled circuit** ↔ time-unrolled evolution.

This is not cosmetic analogy. It suggests a general formal program:
- tropical automata as semiring dynamical systems,
- complexity measures as operator ranks / widths,
- circuit lower bounds via transfer compressibility,
- and eventually tropical spectral theory for computational models.

## Expected obstacles and how to neutralize them

### Obstacle 1: Matrix infrastructure over tropical weights
If `Matrix` multiplication requires semiring instances not yet aligned with your tropical weight type, either:
- instantiate the needed algebraic structure cleanly, or
- temporarily define bespoke tropical matrix multiplication and later bridge to `Matrix`.

Do not get trapped for hours in typeclass engineering if a lightweight bespoke representation gets the theorem proved.

### Obstacle 2: Indexing with `Fin d`
Products over prefixes often become awkward with `Fin`. It may be simpler to define `transferProductUpTo` recursively on `ℕ` with a proof argument `i ≤ d`, then access layer matrices via `⟨i, h⟩`.

### Obstacle 3: Syntactic equality of circuits
Prefer semantic equality first. Exact AST equality is fragile and usually not the true mathematical content.
