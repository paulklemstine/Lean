## Precise Formal Targets

### Definitions to introduce

Work in base `b ≥ 2`. Define:

- `digitsBase : Nat → Nat → List Nat`  
  digits of `n` in base `b`, least-significant-first or most-significant-first, but fix one convention and prove conversion lemmas.

- `ofDigitsBase : Nat → List Nat → Nat`

- `reverseDigits : Nat → Nat → Nat`  
  `reverseDigits b n := ofDigitsBase b (List.reverse (digitsBase b n))`

- `isPalindromeBase : Nat → Nat → Prop`  
  `isPalindromeBase b n := digitsBase b n = List.reverse (digitsBase b n)`

- `revAddStep : Nat → Nat → Nat`  
  `revAddStep b n := n + reverseDigits b n`

- `revAddIter : Nat → Nat → Nat → Nat`  
  `revAddIter b k n := Nat.iterate (revAddStep b) k n`

- `LychrelCandidateBase : Nat → Nat → Prop`  
  `LychrelCandidateBase b n := ∀ k : Nat, ¬ isPalindromeBase b (revAddIter b k n)`

This last notion is the formal candidate notion; avoid claiming actual truth for 196 unless proved.

## Exact Theorem Targets

### Theorem A: digit-reversal arithmetic is well-defined and involutive on normalized expansions
This is foundational and should be proved cleanly.

**Statement:**
For every base `b ≥ 2` and every natural number `n`, if `digitsBase b n` is normalized (no trailing leading-zero artifact in your chosen convention), then reversing twice returns the original number.

**Lean 4 target signature:**
```lean
theorem reverseDigits_involutive
    (b n : Nat) (hb : 2 ≤ b) :
    reverseDigits b (reverseDigits b n) = n
```
You may need a refined statement with a normalization hypothesis if your digit encoding admits leading zeros after reversal:
```lean
theorem reverseDigits_involutive_of_nonzero_last
    (b n : Nat) (hb : 2 ≤ b)
    (hnorm : normalizedDigits b n) :
    reverseDigits b (reverseDigits b n) = n
```

**Why it matters:**  
This identifies reverse-and-add as a genuine arithmetic dynamical system rather than an ad hoc decimal trick.

---

### Theorem B: palindromicity is equivalent to fixed-point behavior under digit reversal
**Statement:**
For every base `b ≥ 2`, a number is a palindrome iff it is fixed by `reverseDigits`.

**Lean 4 target signature:**
```lean
theorem isPalindromeBase_iff_reverseDigits_eq
    (b n : Nat) (hb : 2 ≤ b) :
    isPalindromeBase b n ↔ reverseDigits b n = n
```

**Why it matters:**  
This turns “eventually reaches a palindrome” into “eventually reaches a fixed point of an involution after applying `n ↦ n + rev(n)` repeatedly.” That reframes the problem in dynamical systems language.

### Theorem C: every reverse-and-add step yields an even number in base 10
This is simple but not trivial in a formal digit setting and is a useful invariant for pruning search.

**Statement:**
For every `n`, `revAddStep 10 n` is even.

**Lean 4 target signature:**
```lean
theorem revAddStep_base10_even (n : Nat) :
    Even (revAddStep 10 n)
```

**Reason:**  
Because `n + reverseDigits 10 n` has the same parity as `2 * lastDigitSymmetry`, but formalizing this through digits creates a useful invariant library.

**Breakthrough use:**  
This is the first example of a general modular invariant theorem. Generalize later to congruence classes mod `b-1`, mod `2`, mod `11`, etc.

### Theorem D: congruence mod `b - 1` is doubled under reverse-and-add
This is the first truly structural theorem.

**Statement:**
Since digit reversal preserves digit sum, and digit sum controls congruence mod `b-1`, one gets
\[
\operatorname{revAddStep}(b,n) \equiv 2n \pmod{b-1}.
\]

**Lean 4 target signature:**
```lean
theorem revAddStep_mod_pred_base
    (b n : Nat) (hb : 2 ≤ b) :
    revAddStep b n % (b - 1) = (2 * n) % (b - 1)
```
You may need a modular equivalence formulation:
```lean
theorem revAddStep_congr_mod_base_pred
    (b n : Nat) (hb : 2 ≤ b) :
    revAddStep b n ≡ 2 * n [MOD (b - 1)]
```

**Why it matters:**  
This gives a rigorous algebraic invariant for every iterate:
\[
\operatorname{revAddIter}(b,k,n) \equiv 2^k n \pmod{b-1}.
\]
That is a real theorem with consequences for excluding palindromic targets in residue classes.

### Theorem E: iterate congruence law
**Statement:**
For all `k`,
\[
\operatorname{revAddIter}(b,k,n) \equiv 2^k n \pmod{b-1}.
\]

**Lean 4 target signature:**
```lean
theorem revAddIter_congr_mod_base_pred
    (b n k : Nat) (hb : 2 ≤ b) :
    revAddIter b k n ≡ (2^k * n) [MOD (b - 1)]
```

**Why it matters:**  
This converts the nonlinear digit algorithm into a linear congruence dynamic. This is the first major bridge theorem.

### Theorem F: no palindrome can occur in a finite horizon if all reachable palindrome residues are excluded
This is the first theorem that directly targets 196 without pretending to solve the open problem.

Define the set of residues modulo `m` that are realized by base-10 palindromes up to some digit length bound `L`, then prove a finite obstruction principle.

**Statement:**
If for every `k ≤ K`, the residue of `revAddIter 10 k 196` modulo `m` is not among the residues of any base-10 palindrome with length at most `L_k`, and if one has an a priori theorem that `revAddIter 10 k 196` has length at most `L_k`, then the `k`th iterate is not a palindrome.

This can be made computational and certified.

**Lean 4 schematic signature:**
```lean
theorem finite_horizon_nonpalindrome_of_residue_exclusion
    (m : Nat) (hm : 0 < m) (K : Nat)
    (L : Nat → Nat)
    (hres :
      ∀ k ≤ K,
        revAddIter 10 k 196 % m ∉ palindromeResiduesUpToLength 10 m (L k))
    (hlen :
      ∀ k ≤ K,
        numDigits 10 (revAddIter 10 k 196) ≤ L k) :
    ∀ k ≤ K, ¬ isPalindromeBase 10 (revAddIter 10 k 196)
```

**Why it matters:**  
This creates a **formal certificate architecture** for long verified non-palindrome runs. Even if the infinite conjecture remains open, a theorem of this type lets Aristotle produce machine-checked finite obstructions at scale.

### Theorem G: carry-automaton simulation theorem
Define digitwise reverse-add with carry as a finite-state transducer on digit pairs.

**Statement:**
Arithmetic `revAddStep b n` agrees with the digitwise automaton computation from the digit sequence of `n` and its reverse.

**Lean 4 target signature:**
```lean
theorem revAddStep_eq_carryAutomaton_eval
    (b n : Nat) (hb : 2 ≤ b) :
    revAddStep b n =
      carryAutomatonEval b (digitsBase b n)
```

**Why it matters:**  
This is the portal to automata theory, symbolic dynamics, and eventually SAT/SMT-assisted obstruction theorems.

## Proof Strategy Architecture

### Strategy 1: Digit-sum / modular arithmetic route
Most promising for immediate theorem production.

**Step 1.** Formalize `digitsBase` and prove:
- `ofDigitsBase_digitsBase`
- `digit_sum_congr_mod_base_pred`
- reversal preserves digit sum.

**Step 2.** Deduce:
- `reverseDigits b n ≡ n [MOD (b - 1)]`
- therefore `revAddStep b n ≡ 2*n [MOD (b - 1)]`
- then iterate by induction to get Theorem E.

**Step 3.** Build residue-exclusion criteria for palindromes modulo carefully chosen moduli (`9`, `11`, `99`, `109`, etc.), then combine with length bounds to certify non-palindromicity over large horizons.

**Why most promising:**  
This path uses standard number theory, is Lean-friendly, and produces genuinely new formal theorems quickly.

---

### Strategy 2: Carry automaton / symbolic dynamics route
Higher risk, much higher ceiling.

**Step 1.** Define a digitwise reverse-add transducer whose state is the carry and position index.

**Step 2.** Prove equivalence with arithmetic addition of `n` and `reverseDigits b n`.

**Step 3.** Characterize palindrome output as a synchronization condition on left/right emitted digits; derive impossible carry patterns for broad input classes, ideally including a family containing 196 iterates.

**Why revolutionary:**  
This reframes Lychrel behavior as a finite-state reachability problem, opening the door to automata-theoretic undecidability/decidability questions and certified exhaustive search.

---

### Strategy 3: Growth and interval exclusion route
Useful for finite-horizon certification.

**Step 1.** Prove upper and lower bounds on `numDigits 10 (revAddIter 10 k n)`.

**Step 2.** Enumerate all palindrome residues of a given digit length modulo selected `m`.

**Step 3.** Combine growth bounds with residue exclusion to show no palindrome can occur before horizon `K`.

**Why useful:**  
This gives publishable certified computation: “196 is formally verified non-palindromic through horizon `K` with proof object.”

## Cross-Domain Connections

### 1. Automata theory and formal languages
Reverse-and-add is a digit transducer with carry memory. Palindromes form a highly constrained regular/context-sensitive pattern depending on encoding. Formalizing this builds a bridge between arithmetic dynamics and automata reachability.

### 2. Symbolic dynamics
The orbit `n, T(n), T²(n), ...` under `T(n)=n+rev(n)` can be studied as a nonlocal symbolic dynamical system. Fixed points correspond to palindromes; non-termination becomes avoidance of a special subshift.

### 3. Additive number theory / modular dynamics
The theorem
\[
T(n)\equiv 2n \pmod{b-1}
\]
shows the digit algorithm hides a linear modular skeleton. This is exactly the kind of “chaotic-looking process with rigid algebraic shadow” that can generate breakthrough structure.

### 4. Certified computation / proof-producing search
Finite-horizon non-palindrome certificates are ideal for Lean extraction, reflection, or externally generated proof witnesses. This connects to formal verification and theorem-guided experimental mathematics.

### 5. Complexity theory
If the carry-automaton model is developed, one can ask whether palindrome reachability for reverse-and-add in fixed base is decidable, semidecidable, or computationally intractable for restricted digit classes. That is a stunning direction.
