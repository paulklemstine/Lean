## Proof Architecture: 3 Strategic Routes

You must not rely on trivial automation. The file must contain at least 3 substantial theorems using induction, `rcases`, `by_contra`, `field_simp` where relevant, and multi-step `calc`. Here are the proof routes.

### Strategy A: Structural induction + monotone closure of majorants
**Most promising for the upper bound.**

1. Prove closure lemmas for `HasPolyTowerMajorant` under inverse-free constructors:
   - constants/variable,
   - addition/multiplication preserve same or max level up to polynomial slack,
   - exponentiation raises level by exactly one.
2. Use induction on syntax to prove:
   ```lean
   HasPolyTowerMajorant (growthRank e) e
   ```
3. Extract exactness by pairing with a lower-bound induction.

Why promising: this should build directly on `growthRank_le_emlDepth` and any existing recursion principles in the catalog.

### Strategy B: Lower-bound separation via eventual domination contradiction
**Most promising for the hard direction.**

1. Define or reuse an eventual domination relation:
   ```lean
   EventualLE (f g : ℝ → ℝ) : Prop := ∀ᶠ x in Filter.atTop, f x ≤ g x
   ```
2. Prove a tower-separation lemma:
   ```lean
   ¬ EventualLE (fun x => iterExp (k+1) x) (fun x => iterExp k (C * x^N))
   ```
   for any fixed `C, N`.
3. Use structural decomposition of `e` to show that if `growthRank e = k`, then `eval e` eventually dominates every lower tower class.

This will likely require:
- positivity/eventual monotonicity lemmas,
- repeated use of `by_contra`,
- asymptotic comparison by taking logs or iterated logs if available,
- `calc` chains comparing `exp (iterExp k ...)` against `iterExp k (...)`.

Why promising: it attacks the exact semantic issue head-on and turns the conjecture into a formal asymptotic separation theorem.

### Strategy C: Canonical normal forms and witness extraction
**Best for theorem families and computational verification.**

1. Define `towerExpr k` and prove it has growth rank `k`.
2. Prove every inverse-free expression of rank `k` admits a semantic sandwich:
   ```lean
   iterExp k (a*x^m) ≤ eval e x ≤ iterExp k (b*x^n)
   ```
   eventually, for suitable parameters.
3. Deduce exactness and strictness from the witness family.

Why promising: this route creates an algorithmic classification procedure and makes the demo/computational test natural.
