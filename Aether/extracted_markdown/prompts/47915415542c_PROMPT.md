## Theorem 1 — Witness-level separation for coproducts

### Mathematical statement

If `P` separates `F` and `Q` separates `G`, and both are topology-compatible, then the union `P ∪ Q` separates the coproduct presheaf `F ⊕ G` and remains topology-compatible.

The key case split is across the two coproduct summands:
- two left sections are separated by a probe from `P`,
- two right sections are separated by a probe from `Q`,
- a left section and a right section are already distinguished by the coproduct tag, or by a canonical probe construction if the notion of separation is probe-only and ignores tags.

### Lean target signature

Adapt to the actual presheaf coproduct notation in Mathlib/catalog (`F ⊞ G`, `Limits.binaryCofan`, etc.):

```lean
theorem separates_union_of_separates_coprod
  {C : Type u} [Category C]
  (J : GrothendieckTopology C)
  (F G : Cᵒᵖ ⥤ Type v)
  (P Q : Finset Probe) :
  Separates J F P →
  Separates J G Q →
  TopologyCompatible J F P →
  TopologyCompatible J G Q →
  Separates J (F ⊞ G) (P ∪ Q) ∧
  TopologyCompatible J (F ⊞ G) (P ∪ Q)
```

If your notion of topology-compatibility is monotone in the probe family, isolate that as a lemma and use it here.

### Why this is nontrivial

This is not just set union. You must carefully transport the separation property through the coproduct semantics of sections. The proof should expose the geometry of probes: a probe family for a disjoint union of data types is the union of probe families for the summands.

### Proof strategy options

**Strategy A: direct section case split via coproduct constructors**  
Most promising if sections of `F ⊞ G` are definitionally `Sum (F.obj X) (G.obj X)` or equivalent.
1. Unfold `Separates` for the coproduct.
2. `rcases` two arbitrary distinct coproduct sections into the four `Sum` cases.
3. In same-summand cases, invoke the corresponding separating family.
4. In mixed-summand cases, derive separation from injectivity/disjointness of coproduct constructors, or from how probes evaluate through inclusions.

**Strategy B: factor through universal property of categorical coproduct**  
Most promising if the catalog defines coproduct abstractly, not as `Sum`.
1. Build probe evaluation maps into a profile object.
2. Show the profile map for `F ⊞ G` factors through the product/sum of profile maps of `F` and `G`.
3. Use injectivity of the induced map assembled from the witness families.

**Strategy C: prove a stronger monotone profile-capacity lemma first**  
If `Theorems.lean` has a profile capacity theorem, strengthen it to unions of probe families.
1. Prove profile cardinality under union is at most multiplicative/additive as appropriate.
2. Derive separation of coproduct from profile injectivity.

## Theorem 2 — Subadditivity of compression number

### Mathematical statement

The witness-level theorem should descend immediately to the numeric invariant:

\[
\kappa_{\mathrm{sh}}(J, F \oplus G) \le \kappa_{\mathrm{sh}}(J,F) + \kappa_{\mathrm{sh}}(J,G).
\]

This is the headline theorem. It should be stated with full quantifiers and proved by constructing an admissible witness for the coproduct from near-optimal witnesses for the summands.

### Lean target signature

```lean
theorem kappa_sh_coprod_le
  {C : Type u} [Category C]
  [FiniteSiteData C J] -- replace with actual finiteness assumptions
  (J : GrothendieckTopology C)
  (F G : Cᵒᵖ ⥤ Type v) :
  κ_sh J (F ⊞ G) ≤ κ_sh J F + κ_sh J G
```

If `κ_sh` is defined as an infimum/minimum over cardinalities of finite separating compatible families, then the proof should explicitly choose minimizers using finite-ness/existence lemmas from the catalog.

### Proof strategy options

**Strategy A: minimizer extraction + witness union**  
Most promising if `κ_sh` is already a natural number minimum.
1. Obtain optimal witnesses `P` and `Q` for `F` and `G`.
2. Apply Theorem 1 to get a witness `P ∪ Q` for `F ⊞ G`.
3. Bound `|(P ∪ Q)| ≤ |P| + |Q|`.
4. Conclude by minimality of `κ_sh`.

**Strategy B: prove a general “compression number from witness constructor” lemma**  
1. Abstract a lemma: any constructor sending witnesses for `F`,`G` to a witness for `H` with cardinality bound `≤ m+n` yields `κ_sh J H ≤ κ_sh J F + κ_sh J G`.
2. Instantiate with `H = F ⊞ G`.
This is architecturally cleaner and may support later tensor/product/subobject inequalities.

**Strategy C: use profile capacity theorem from `Theorems.lean`**  
1. Translate `κ_sh` into a profile cardinality/capacity upper bound.
2. Show capacities add under coproduct profile assembly.
3. Recover the numeric inequality.
Use this if the catalog theorem is strong enough to avoid low-level witness extraction.

## Theorem 3 — Capacity/entropy bridge for coproducts

This is the cross-domain theorem. Connect probe complexity to information theory using the profile capacity bound from the catalog.

### Mathematical statement

Assume the catalog contains a theorem bounding the number of distinguishable sections by probe profiles. Then prove a logarithmic corollary of the subadditivity theorem, e.g.:

\[
\log_2 N_{F \oplus G}(X)
\le \kappa_{\mathrm{sh}}(J,F) + \kappa_{\mathrm{sh}}(J,G)
\]

for an appropriate notion `N_F(X)` of distinguishable section count/profile capacity at object `X`, or more generally

\[
\mathrm{capacity}(F \oplus G) \le \mathrm{capacity}(F)+\mathrm{capacity}(G).
\]

If the exact catalog theorem is different, formulate the strongest valid entropy-style inequality derivable from it.

### Lean target signature

A schematic target:

```lean

  (J : GrothendieckTopology C)
  (F G : Cᵒᵖ ⥤ Type v) :
  profileCapacity J (F ⊞ G) ≤ profileCapacity J F + profileCapacity J G
```


depending on what the catalog already formalizes.

### Why this matters

This is the theorem that turns a category-theoretic inequality into an information law. It makes `κ_sh` comparable to coding length / entropy / description complexity.

### Proof strategy options

**Strategy A: compose Theorem 2 with the catalog capacity bound**

3. Finish by `calc` with monotonicity of addition/log bounds.

**Strategy B: direct profile counting on coproducts**

2. Derive a cardinality inequality.
3. Translate to compression via the existing profile theorem.
