## Precise Formalization Targets

### Core definitions to introduce
Use concrete finite types and lists / finsets first; do not over-engineer parsing.

Suggested objects:
- `ImportName := String`
- `ThmName := String`

Define a theorem declaration as:
```lean
structure ThmDecl where
  name : String
  deps : Finset String
deriving DecidableEq, Repr
```

Define a proof file abstraction:
```lean
structure ProofFile where
  imports : List String
  theorems : List ThmDecl
deriving Repr
```

Define theorem-name set:
```lean
def theoremNames (pf : ProofFile) : Finset String :=
  pf.theorems.foldl (fun acc t => insert t.name acc) ∅
```

Define well-formedness:
```lean
def UsesEarlierOnly : List ThmDecl → Prop
| [] => True
| t :: ts =>
    t.deps ⊆ (ts.foldl (fun acc s => insert s.name acc) ∅) ∪
             (([] : List ThmDecl).foldl (fun acc s => insert s.name acc) ∅) ∨ False
```

But this is awkward. Better: define using list prefixes:
```lean
def WellFormedDecls : List ThmDecl → Prop :=
  ∀ i hi,
    let t := xs.get ⟨i, hi⟩
    t.deps ⊆ ((xs.take i).foldl (fun acc s => insert s.name acc) ∅)
```
or use a recursive version:
```lean
def WellFormedDecls : List ThmDecl → Prop
| [] => True
| t :: ts =>
    t.deps ⊆ theoremNames ⟨[], ts⟩ ∧ WellFormedDecls ts
```
But this recursive version encodes “uses later only” unless reversed. The cleanest formulation is:

```lean
def DeclsRespectOrder (xs : List ThmDecl) : Prop :=
  ∀ i (hi : i < xs.length),
    let t := xs.get ⟨i, hi⟩
    t.deps ⊆ ((xs.take i).foldl (fun acc s => insert s.name acc) ∅)
```

This says every theorem only depends on earlier theorems.

Define dependency edge relation:
```lean
def Edge (xs : List ThmDecl) (a b : String) : Prop :=
  ∃ t ∈ xs, t.name = a ∧ b ∈ t.deps
```

Define direct import set and transitive import closure if you choose to model an import environment:
```lean
def ImportGraph := String → Finset String

def importClosure (G : ImportGraph) : Nat → Finset String → Finset String
| 0, s => s
| n+1, s => importClosure G n (s ∪ s.biUnion G)
```
A finite-step closure theorem is enough; no need to solve full parser reflection in cycle one.

## Breakthrough Theorems to Target

### Theorem 1: Dependency names are internal to earlier declarations
This is the first certified theorem-level extraction invariant.

```lean
theorem deps_subset_previous_names
  (xs : List ThmDecl)
  (hwf : DeclsRespectOrder xs)
  {i : Nat} (hi : i < xs.length) :
  let t := xs.get ⟨i, hi⟩
  t.deps ⊆ ((xs.take i).foldl (fun acc s => insert s.name acc) ∅)
```

This theorem is almost definitional, but it is the gateway lemma from which acyclicity and linearization follow.

### Theorem 2: No self-dependency in a well-ordered file
This is genuinely structural and nontrivial.

```lean
theorem no_self_dependency_of_respects_order
  (xs : List ThmDecl)
  (hwf : DeclsRespectOrder xs)
  {i : Nat} (hi : i < xs.length) :
  let t := xs.get ⟨i, hi⟩
  t.name ∉ t.deps
```

**Why it matters:** this proves that a proof file respecting declaration order cannot contain direct circularity. It is the first anti-paradox theorem for file-level proof architecture.

### Theorem 3: Acyclicity of the induced theorem dependency graph
This is the real target. Formalize a suitable finite-path notion and prove that edges always decrease index.

A manageable statement is:

```lean
theorem dependency_edge_decreases_index
  (xs : List ThmDecl)
  (hwf : DeclsRespectOrder xs)
  {i j : Nat}
  (hi : i < xs.length)
  (hj : j < xs.length)
  (hEdge :
    let ti := xs.get ⟨i, hi⟩
    let tj := xs.get ⟨j, hj⟩
    tj.name ∈ ti.deps) :
  j < i
```

From this derive:

```lean
theorem no_dependency_cycle_of_respects_order
  (xs : List ThmDecl)
  (hwf : DeclsRespectOrder xs) :
  ¬ ∃ is : List Nat,
      is.length > 1 ∧
      (∀ k, k + 1 < is.length →
        let i := is.get ⟨k, by omega⟩
        let j := is.get ⟨k+1, by omega⟩
        i < xs.length ∧ j < xs.length ∧
        let ti := xs.get ⟨i, ‹_›⟩
        let tj := xs.get ⟨j, ‹_›⟩
        tj.name ∈ ti.deps) ∧
      -- close the cycle from last to first
      True
```

If the fully quantified cycle statement becomes too cumbersome, prove the mathematically cleaner equivalent:

```lean
theorem exists_topological_order
  (xs : List ThmDecl)
  (hwf : DeclsRespectOrder xs) :
  ∃ f : String → Nat,
    ∀ a b, Edge xs a b → f b < f a
```

with `f` induced by declaration index. This is a certified topological ranking theorem.

### Theorem 4: Monotonicity and idempotence of import closure
Now move to imports as a finite reachability operator.

```lean
def stepClosure (G : String → Finset String) (S : Finset String) : Finset String :=
  S ∪ S.biUnion G

theorem stepClosure_monotone
  (G : String → Finset String) :
  Monotone (stepClosure G)
```

```lean
theorem importClosure_monotone
  (G : String → Finset String) {m n : Nat} (h : m ≤ n) (S : Finset String) :
  importClosure G m S ⊆ importClosure G n S
```

And if you define a saturation predicate:
```lean
def ImportClosed (G : String → Finset String) (S : Finset String) : Prop :=
  ∀ x ∈ S, G x ⊆ S
```

then prove:
```lean
theorem stepClosure_idempotent_of_closed
  (G : String → Finset String) {S : Finset String}
  (hS : ImportClosed G S) :
  stepClosure G S = S
```

This is where the catalog theorem `and_idempotent` becomes conceptually relevant: use idempotence not merely as a boolean fact, but as a design pattern for closure operators. You are constructing a finite semantic closure calculus.

## Proof Strategy Architecture

### Strategy A: Index monotonicity via `List.get` and `take`
This is the most promising and should be your primary route.

1. Define `priorNames xs i` as the `Finset` of theorem names in `xs.take i`.
2. From `DeclsRespectOrder`, any dependency of theorem `i` lies in `priorNames xs i`.
3. Prove a lemma: if `(xs.get ⟨j, hj⟩).name ∈ priorNames xs i`, then `j < i`.
4. Conclude edge-decrease, no self-dependency, and acyclicity by strict descent on indices.

**Why this is best:** it reduces graph theory to arithmetic on declaration indices, avoiding a heavy graph library overhead.

### Strategy B: Closure-operator viewpoint for imports
Use imports to build a small algebra of dependency propagation.

1. Define one-step closure `stepClosure`.
2. Prove monotonicity and inflationarity: `S ⊆ stepClosure G S`.
3. Iterate closure by `Nat`.
4. Show stabilized sets are fixed points (`stepClosure_idempotent_of_closed`).

**Why this matters:** it reframes import extraction as a certified dynamical system on finite sets. This links directly to proof architecture and knowledge propagation.

### Strategy C: Rank-function / well-foundedness formulation
If graph acyclicity is cumbersome to state directly, define a ranking into `Nat`.

1. Assign to each theorem a declaration rank.
2. Show every dependency strictly lowers rank.
3. Conclude no cycles by impossibility of strict descent around a loop.

**Why this is powerful:** it is the cleanest bridge to proof complexity, holographic compression, and semantic stratification. It also aligns conceptually with `four_level_hierarchy`.

## How to Build on the Catalog Theorems

Do not cite the catalog passively. Use it to shape the conceptual framework.

### 1. `lawvere_proof_coding_theorem`
This suggests that proofs can be encoded as mathematical objects subject to self-reference constraints. Your dependency formalization is a **safe fragment of proof coding**: by proving no self-dependency and acyclicity under declaration order, you are isolating a regime where Lawvere-style diagonal pathologies are blocked. This is philosophically and technically important: dependency extraction becomes a certified anti-paradox interface for proof code.

### 2. `four_level_hierarchy`
Use this as inspiration to define dependency strata:
- level 0: imports,
- level 1: declarations,
- level 2: direct theorem dependencies,
- level 3: transitive dependency closure / rank.
Even if you do not formalize the full hierarchy theorem now, mention and possibly define a simple stratification function. This opens a route to semantic complexity layers of formal libraries.

### 3. `area_law_proof`
This is the most provocative bridge: dependency graphs in formal mathematics may obey an “area law” where the complexity of a theorem is controlled more by the boundary of its imported interface than by total library volume. Even a finite toy theorem about closure growth bounds would be an opening salvo:
```lean

  (G : String → Finset String) (hB : ∀ x, (G x).card ≤ B) :
  ...
```
You may not complete this now, but orient your formalization so that such cardinality-growth theorems become natural next steps.

### 4. `and_idempotent`
Closure operators are idempotent objects. Use this theorem as a conceptual seed: extraction pipelines should stabilize. If you define a saturated import closure, proving idempotence of the closure step on closed sets is a direct algebraic analogue.

### 5. `evidence_upper_bound`
Dependency extraction can be viewed as an evidence aggregation problem: the extracted dependency set is an upper bound on what a theorem semantically uses. This points toward future quantitative theorems comparing syntactic dependency count and semantic evidence complexity.
