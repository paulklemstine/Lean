## Assignment: Direction 2: Verified Compiler Synthesis via Free-Forgetful Adjunctions

**Mode:** prove

## Core Vision

For a finitely presented algebraic theory `T`, let `U : Alg_T ⥤ Type` be the forgetful functor and `F : Type ⥤ Alg_T` the free functor constructed from pointwise universal arrows. Then every algebra `A : Alg_T` induces a canonical evaluation map
\[
\mathsf{eval}_{A,X} : U(F X) \to (X \to U(A)) \to U(A)
\]
or, equivalently in curried universal-property form,
\[
(X \to U(A)) \to (F X \to A),
\]
and this map is **the verified interpreter** for syntax generated by variables `X` into semantics `A`.

Your task is to prove that this interpreter is not an ad hoc definition for monoids/groups/commutative monoids separately, but the **counit-transpose generated by `left_adjoint_of_pointwise_universal`**.

This is the nontrivial leap: the compiler is synthesized from category theory.

### Theorem 1: Generic synthesized interpreter correctness
Formalize a generic theorem saying that if `F ⊣ U` is built via `left_adjoint_of_pointwise_universal`, then the induced morphism out of `F X` is the unique semantics-preserving interpreter extending a variable assignment.

A plausible Lean 4 shape:

```lean
theorem synthesized_interpreter_unique
  {C D : Type _} [Category C] [Category D]
  (U : D ⥤ C)
  (F : C ⥤ D)
  (hF : F ⊣ U)
  {X : C} {A : D}
  (f : X ⟶ U.obj A) :
  ∃! g : F.obj X ⟶ A,
    f = (Adjunction.homEquiv hF X A).symm g
```

But this is still too abstract unless tied to the pointwise-universal construction. The stronger theorem should explicitly mention the construction:

```lean
theorem pointwise_universal_interpreter_unique

  ∃! g : (left_adjoint_of_pointwise_universal U hU).obj X ⟶ A,

      ((left_adjoint_of_pointwise_universal_adj U hU).homEquiv X A).symm g
```

If the catalog names differ, adapt them, but the theorem should explicitly expose the universal-arrow-generated morphism as the unique interpreter.

**Breakthrough significance:** this theorem says that a compiler can be *derived* from universal mapping properties. It converts “free semantics” into an executable and reusable synthesis principle.

### Theorem 3: Naturality / compositionality of synthesized interpreters
Prove that the synthesized evaluator commutes with algebra homomorphisms. This is the semantic preservation law that makes the construction compiler-like rather than merely algebraic.

For monoids, a representative theorem is:

```lean
theorem freeMonoid_eval_natural
  {X : Type _} {M N : Type _} [Monoid M] [Monoid N]
  (ρ : X → M) (φ : M →* N) :
  (φ.comp (FreeMonoid.lift ρ)) = FreeMonoid.lift (fun x => φ (ρ x))
```

Then prove the analogous theorem for the synthesized interpreter:

```lean
theorem synthesized_eval_natural
  {X : Type _} {A B : MonCat}
  (ρ : X → A) (φ : A ⟶ B) :
  φ ≫ synthesizedEval ρ = synthesizedEval (fun x => φ (ρ x))
```

Similarly for commutative monoids and groups.

**Breakthrough significance:** this is the compiler-correctness law: postcomposition with a semantics morphism is the same as recompiling into the target semantics. It is a formal version of **backend-independence**.

```lean
structure InterpreterSpec
    (Syn Sem : Type _) [Category Syn] [Category Sem]

    ∀ {X A} (ρ : X ⟶ U.obj A),
```

Then instantiate it from pointwise universal arrows.

```lean
def SemanticComplete
```

Then prove that any `InterpreterSpec` arising from `left_adjoint_of_pointwise_universal` is `SemanticComplete`.

## Stronger Mathematical Framing

The right abstraction is not “free object semantics,” but:

> **Adjoint semantics principle:** whenever syntax is a left adjoint to a forgetful functor, interpretation into any semantic algebra is the transpose under the adjunction, and universal arrows provide a construction of this interpreter together with uniqueness and compositionality.

This principle should be formalized as a theorem schema, then instantiated.

A particularly strong formulation is:

```lean
theorem adjoint_semantics_principle
  {C D : Type _} [Category C] [Category D]
  (U : D ⥤ C)
  (hU : ∀ X : C, IsUniversalArrow U X) :
  SemanticComplete U (left_adjoint_of_pointwise_universal U hU)
    (left_adjoint_of_pointwise_universal_adj U hU)
```

This theorem is the real conceptual payload.

## Proof Strategy Architecture

You must include at least 2–3 proof routes in your implementation plan and execute the most promising one.

### Strategy A: Universal-arrow first, then specialize
1. Construct or import `IsUniversalArrow` instances for monoids, commutative monoids, and groups.
2. Apply `left_adjoint_of_pointwise_universal`.
3. Unfold the induced `homEquiv` and prove that its transpose agrees with `FreeMonoid.lift`, `FreeCommMonoid.lift`, and `FreeGroup.lift`.
4. Use uniqueness of universal arrows to show equality of interpreters.

**Why promising:** this directly uses the catalog theorem and demonstrates the advertised synthesis principle. It gives the cleanest “compiler from category theory” story.

### Strategy B: Concrete evaluator first, then identify with adjunction data
1. Define concrete evaluators using `FreeMonoid.lift`, `FreeCommMonoid.lift`, `FreeGroup.lift`.
2. Prove they satisfy the universal-arrow factorization property.
3. Deduce they are equal to the abstract synthesized maps by uniqueness (`∃!` proofs).
4. Package the resulting equality as the theorem that the adjunction engine synthesizes exactly these evaluators.

**Why promising:** easiest for Lean. Most likely to minimize `sorry`, because Mathlib already knows the concrete lifts. The hard work is uniqueness transport, but that is manageable with `rcases`, `refine`, and extensionality.

### Strategy C: Counit/unit coherence route
1. Identify the evaluator as the adjunct transpose of the unit/counit.
2. Use triangle identities and naturality of unit/counit to prove semantic preservation.
3. Derive evaluator equalities from coherence rather than direct extensionality.

**Why promising:** strongest categorical statement and best for follow-on generalization to DSL compilation.  
**Why less practical initially:** heavier category-theory term manipulation in Lean.

**Recommendation:** use **Strategy B** for the concrete theory instantiations and **Strategy A** for the generic theorem. This gives both robust Lean proofs and the conceptual headline.
