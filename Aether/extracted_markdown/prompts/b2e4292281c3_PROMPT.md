## Assignment: From Shallow to Deep: Formalizing the Depth Gap in Automated Mathematics

Mode: **prove**

You are not being asked for a metaphor. You are being asked to turn “novelty” into a mathematically rigid invariant of formal proofs, then prove a theorem that separates derivative theorem generation from genuinely new mathematics. If this works, it opens a new field: **proof-theoretic novelty geometry** for Lean formalizations, with direct consequences for automated theorem proving, benchmark design, theorem search, and meta-mathematical evaluation of machine-generated mathematics.

The key move is to stop speaking vaguely about “interestingness” and instead define a **computable graph metric on theorem statements/proofs** whose short edges are “mere reformulations” and whose long-distance separation certifies conceptual novelty.

This is not incremental. It would provide one of the first fully formal, machine-checkable notions of **derivativeness vs conceptual depth** internal to a proof assistant.

---

## Core Research Objective

Define a finite or effectively enumerable state space of formal mathematical artifacts and a notion of **conceptual leap** between them, then prove:

1. a **minimum-depth realization theorem**: depth is attained as a shortest path length;
2. a **threshold theorem**: below a certified threshold, outputs are derivative;
3. a **computability theorem**: the depth gap is computable from encoded proof terms/statements;
4. a **bridge theorem** connecting this new invariant to existing threshold/compression results in the catalog.

The right first target is not an unrestricted theorem about all Lean expressions. That is too meta-theoretic and likely blocked by encoding issues. The right target is a **restricted but nontrivial universe of theorem presentations** where the invariant is mathematically clean and executable in Lean 4.

## Precise Formalization Target

Work in a finite universe of “theorem presentations” built from concrete features. For example:

- number of new definitions introduced,
- number of ambient type changes,
- number of representation/perspective changes,
- proof compression score or theorem encoding size,
- a derivability relation to a known corpus.

You should define a structure of theorem descriptors and a weighted graph whose edges correspond to one conceptual leap.

### Suggested core definitions

Use a concrete finite model first.

```lean
structure TheoremProfile where
  defsIntroduced    : ℕ
  typeChanges       : ℕ
  perspectiveShifts : ℕ
  proofSize         : ℕ
  compressionScore  : ℕ
  deriving DecidableEq

def leapCost (A B : TheoremProfile) : ℕ :=
  Nat.dist A.defsIntroduced B.defsIntroduced +
  Nat.dist A.typeChanges B.typeChanges +
  Nat.dist A.perspectiveShifts B.perspectiveShifts

def DerivativeFrom (K : Finset TheoremProfile) (T : TheoremProfile) (d : ℕ) : Prop :=
  ∃ S ∈ K, leapCost S T ≤ d

def DepthGap (K : Finset TheoremProfile) (T : TheoremProfile) : ℕ :=
  K.inf' (by
    rcases Finset.exists_ne_of_one_lt_card ?_ with ⟨x, hx, hne⟩
    exact ?_) (fun S => leapCost S T)
```

The exact `DepthGap` implementation may need to be adjusted because `Finset.inf'` requires nonemptiness; perhaps package the corpus as `{K : Finset TheoremProfile // K.Nonempty}`.

A more graph-theoretic and conceptually superior version is:

```lean
def ConceptualNeighbor (A B : TheoremProfile) : Prop :=
  leapCost A B = 1

def depthGap (K : Finset TheoremProfile) (T : TheoremProfile) : ℕ :=
  K.inf' ?h (fun S => leapCost S T)
```

or via shortest-path distance in a finite graph if you want conceptual leaps to be typed rather than purely metric.

## Breakthrough Theorem Statement

### Theorem A: Minimum conceptual-depth attainment

For a nonempty finite corpus of known theorem profiles, the depth gap to any target theorem profile is attained by some nearest known profile.

#### Lean 4 type signature
```lean
theorem depthGap_attained
    (K : Finset TheoremProfile) (hK : K.Nonempty) (T : TheoremProfile) :
    ∃ S ∈ K, depthGap K T = leapCost S T
```

This matters because it converts novelty from a vague infimum into a concrete nearest-neighbor certificate.

### Theorem B: Threshold derivative theorem

This is the central separation theorem. Build explicitly on the catalog theorem
`below_threshold_derivative` from `MachineLearning/DepthGap/Core.lean`.

You should prove a theorem of the following shape:

#### Lean 4 type signature
```lean
theorem below_depthGap_threshold_derivative
    (K : Finset TheoremProfile) (hK : K.Nonempty) (T : TheoremProfile) (τ : ℕ)
    (hτ : depthGap K T < τ) :
    DerivativeFrom K T τ
```

A stronger and cleaner exact characterization is better:

```lean
theorem derivative_iff_depthGap_le
    (K : Finset TheoremProfile) (hK : K.Nonempty) (T : TheoremProfile) (τ : ℕ) :
    DerivativeFrom K T τ ↔ depthGap K T ≤ τ
```

This is the formal heart of the project: **being derivative is exactly bounded conceptual distance from the known corpus**.

Now connect it to the existing theorem:

```lean
theorem below_threshold_derivative_bridge
```

Use `below_threshold_derivative` as a conceptual or technical bridge if it already abstracts thresholded derivativeness over a relation `E`.

### Theorem C: Computability of the depth gap

This is what turns the theory from philosophy into infrastructure.

#### Lean 4 type signature
```lean
theorem depthGap_computable
    (K : Finset TheoremProfile) (hK : K.Nonempty) :
    ∃ f : TheoremProfile → ℕ, ∀ T, f T = depthGap K T
```

An even stronger executable version is preferable:

```lean
def computeDepthGap (K : Finset TheoremProfile) (hK : K.Nonempty) (T : TheoremProfile) : ℕ :=
  depthGap K T

theorem computeDepthGap_spec
    (K : Finset TheoremProfile) (hK : K.Nonempty) (T : TheoremProfile) :
    computeDepthGap K hK T = depthGap K T
```

If you want to honor the original brief more literally, define an encoded proof-term/profile extraction:

```lean
def proofTermProfile : ExprEncoding → TheoremProfile
```

or, staying inside ordinary Lean mathematics, a code/profile map from a finite encoded syntax type. Then prove computability of depth through that map.

### Theorem D: Positive depth-gap existence

To show the notion is nontrivial, prove there exist targets not at depth 0.

#### Lean 4 type signature
```lean
theorem exists_positive_depthGap
    (K : Finset TheoremProfile) (hK : K.Nonempty) :
    ∃ T, 0 < depthGap K T
```

This will require a mild non-saturation hypothesis, e.g. not every profile belongs to `K`, or boundedness assumptions on `K`. A more precise theorem is:

```lean
theorem exists_positive_depthGap_of_not_universal
    (K : Finset TheoremProfile) (hK : K.Nonempty)
    (hproper : ∃ T, ∀ S ∈ K, T ≠ S) :
    ∃ T, 0 < depthGap K T
```

This theorem certifies that the framework can distinguish novelty at all.

The real prize is to characterize depth gap not just by raw coordinate distance, but by **minimum number of typed conceptual moves** in a graph of theorem transformations.

Define a finite graph where edges are labeled by:

- `introDef`

```lean
structure Presentation where

  -- optional: code of statement/proof
```

## Proof Strategy Options

## Strategy A: Finite metric-space model on theorem profiles
**Most promising for a first complete Lean theorem.**

1. Define `TheoremProfile` with 3–5 natural-number coordinates.
2. Define `leapCost` as an `ℕ` metric-like function via coordinatewise `Nat.dist`.
3. Define `depthGap` as the minimum over a nonempty `Finset`.
4. Prove:
   - attainment of the minimum,
   - derivative iff bounded depth,
   - computability by finite search,
   - existence of positive depth under properness assumptions.

Why this is best: it is executable, cleanly formalizable in Lean 4, and already captures the philosophical content in a mathematically honest way.

---

## Strategy B: Graph-theoretic conceptual leap system
**More expressive, more profound, slightly harder.**

1. Define an inductive type `LeapKind`.
2. Define a finite graph on theorem presentations where each edge is one allowable conceptual leap.
3. Define depth as shortest-path distance from the corpus.
4. Prove shortest-path realization and threshold derivative characterization.

Why it is powerful: it replaces arbitrary numeric scoring by explicit conceptual transformations. This is closer to what mathematicians actually mean by “one conceptual leap.”

Potential obstacle: shortest-path formalization can be more cumbersome unless you keep the graph finite and concrete.

---

## Strategy C: Encoded proof-term depth via syntax and extraction
**Most ambitious; likely second-phase unless a syntax framework already exists.**

1. Define a finite encoded syntax or proof-summary language.
2. Define a computable extraction `code → TheoremProfile`.
3. Define depth on extracted profiles.
4. Prove the computed depth is invariant under chosen normalization/rephrasing operations.

Why this would be extraordinary: it turns proof-term analysis into a certified novelty analyzer.

Potential obstacle: full Lean `Expr` metaprogramming is harder to keep inside ordinary theorem proving. Better to model encoded syntax mathematically unless you specifically want a meta-level tool.

## Cross-Domain Connections You Should Explicitly Exploit

### Information theory
Depth gap behaves like a **distance from the compression manifold**. Derivative outputs are near the corpus in conceptual coding length. This suggests analogies with rate-distortion theory and Kolmogorov-style structure functions.

### Metric geometry / coarse geometry
A theorem corpus becomes a finite metric space; novelty is distance to a subset. This invites notions of frontier, covering radius, clustering, and sparse “innovation regions.”

### Machine learning theory
The theorem `below_threshold_derivative` already suggests a learnability/generalization threshold. Your result can become a rigorous statement that low-depth outputs are **nearest-neighbor interpolants in theorem space**.

### Proof theory / reverse mathematics
Conceptual leaps resemble increases in proof-theoretic strength or representational resources. Even your finite model could become a prototype for a future ordinal-valued or category-theoretic depth invariant.

### Category theory
Perspective shifts can be modeled as change-of-site, equivalence transport, or functorial re-expression. A future generalization could define novelty as distance in a bicategory of mathematical presentations.

### Tropical / ultrametric mathematics
The existing compression threshold and tropical threshold theorems suggest replacing additive depth by an ultrametric or min-plus depth. This could lead to a theorem corpus with **hierarchical novelty geometry** rather than Euclidean geometry.
