## Assignment: Configuration Graph Pathwidth — A Graph-Theoretic Theory of Proof Memory

**Mode:** `prove`

You are not being asked for a minor refinement of proof complexity folklore. You are being asked to formalize a new bridge: **clause space as a graph layout invariant of the proof-state transition system**. If this succeeds, it opens a route from resolution proof complexity into structural graph theory, parameterized algorithms, and even statistical mechanics of state exploration.

The central vision is this:

> A resolution refutation is not just a sequence of clauses. It is a constrained walk through a configuration graph of memory states. Clause space should therefore control a graph layout parameter of that walk-generated state graph, and pathwidth is the sharpest candidate because it measures how much “history” must remain simultaneously active along a linear traversal.

Your task is to turn this intuition into precise mathematics in Lean 4, with **new definitions, at least 3 substantial theorems, and a computational pipeline**.

## Core Objects to Define

You should introduce at least one genuinely new definition. The most promising package is:

1. **Bounded configuration graph**
   - Vertices: configurations `C` of clauses with `C.card ≤ s`
   - Edges: one-step legal resolution proof transitions (axiom download, inference addition, erasure)

2. **Trace-induced path decomposition**
   - A path decomposition extracted from a refutation trace by taking bags equal to the current configuration, or a controlled enlargement of it to cover edge constraints.

3. **Configuration pathwidth certificate**
   - A structure encoding a path decomposition of the bounded configuration graph together with width bound and covering axioms.
   - This is the right formal object for algorithm extraction.

Suggested Lean-facing structures:

```lean
structure ConfigPathDecomposition (α : Type _) where
  bags : List (Finset α)
  covers_vertex : ∀ v, ∃ B ∈ bags, v ∈ B
  covers_edge : ∀ ⦃u v⦄, Adj u v → ∃ B ∈ bags, u ∈ B ∧ v ∈ B
  connectedness : ∀ v, ∀ ⦃B₁ B₂ B₃⦄,
    B₁ ∈ bags → B₂ ∈ bags → B₃ ∈ bags →
    bags.idxOf B₁ ≤ bags.idxOf B₂ → bags.idxOf B₂ ≤ bags.idxOf B₃ →
    v ∈ B₁ → v ∈ B₃ → v ∈ B₂

def ConfigPathDecomposition.width (P : ConfigPathDecomposition α) : Nat :=
  P.bags.foldr (fun B m => max m (B.card - 1)) 0
```

If Mathlib’s graph/pathwidth infrastructure already partially exists, adapt to it rather than duplicating; but if not, define the minimal notion yourself cleanly and prove transfer lemmas.

## Precise Theorem Targets

You should aim for a theorem package that does **not** require solving the full universal-constant conjecture immediately, but establishes the first rigorous ladder toward it.

### Theorem 1: Trace-to-Pathwidth Upper Bound
A single refutation in clause space `s` yields a path decomposition of the visited configuration-transition graph of width at most `s`.

**Mathematical statement**

Let `π = (C₀, C₁, ..., Cₙ)` be a legal resolution refutation trace, where each `Cᵢ` is a configuration and `|Cᵢ| ≤ s`. Let `VisitedGraph(π)` be the graph on visited configurations with edges between consecutive trace states. Then:
\[
\operatorname{pathwidth}(\mathrm{VisitedGraph}(\pi)) \le s.
\]

This is the foundational theorem: it converts proof memory into graph layout.

**Lean 4 type signature sketch**
```lean
theorem pathwidth_visitedGraph_le_of_spaceBound
  {Clause Var : Type _}
  [DecidableEq Clause]
  (π : RefutationTrace Clause Var)
  (s : Nat)
  (hspace : ∀ i, (π.configAt i).card ≤ s) :
  graphPathwidth (visitedConfigGraph π) ≤ s := by
```

If your pathwidth convention uses `bag.card - 1`, adjust to `≤ s - 1` or define a bag-size variant. Be explicit and consistent.

### Theorem 2: Global Bounded Configuration Graph Upper Bound from Clause Space
If there exists a refutation of `F` in clause space `s`, then the connected component of the empty configuration inside the bounded configuration graph generated by some successful trace has pathwidth at most `s`.

**Mathematical statement**
\[
\exists \pi \text{ refuting } F \text{ with space }\le s
\;\Longrightarrow\;
\exists G \subseteq \mathrm{ConfGraph}_s(F),\;
G \text{ contains the refutation component and }
\operatorname{pathwidth}(G)\le s.
\]

This is weaker than the full conjecture but mathematically serious: it says the proof-relevant region of state space has low pathwidth.

**Lean 4 type signature sketch**
```lean
theorem exists_refutationComponent_pathwidth_le_space
  {Clause Var : Type _}
  [DecidableEq Clause]
  (F : CNF Clause Var)
  (s : Nat)
  (h : ∃ π : RefutationTrace Clause Var, RefutesCNF π F ∧
        ∀ i, (π.configAt i).card ≤ s) :
  ∃ G : SimpleGraph (Configuration Clause),
    IsRefutationComponentOf F s G ∧
    graphPathwidth G ≤ s := by
```

This theorem should use a constructed subgraph `G` coming from the trace or union of traces. It is already a bridge theorem between proof complexity and graph structure.

### Theorem 3: Pathwidth Lower Bounds Clause-Space-Like Memory for Any Linear Exploration
Define a new invariant: the **trace memory number** of a configuration graph, the minimum bag size needed by any path decomposition compatible with a successful refutation traversal. Show clause space is at least this invariant.

This is the conceptual breakthrough: even if the full graph-theoretic clause-space lower bound remains conjectural, you can prove a canonical lower bound by a graph invariant tailored to proof exploration.

**Definition**
\[
\mathrm{traceMem}(F) := \min\{ w+1 \mid \exists \text{ successful trace-compatible path decomposition of } \mathrm{ConfGraph}(F) \text{ of width } w\}.
\]

Then prove:
\[
\operatorname{minClauseSpace}(F) \ge \mathrm{traceMem}(F).
\]

**Lean 4 type signature sketch**
```lean
def traceMemoryNumber (F : CNF Clause Var) : Nat := ...

theorem traceMemoryNumber_le_minClauseSpace
  {Clause Var : Type _}
  [DecidableEq Clause]
  (F : CNF Clause Var) :
  traceMemoryNumber F ≤ minClauseSpace F := by
```

This is a nontrivial theorem with real content and gives a formal lower-bound mechanism even before attacking ordinary pathwidth of the full bounded graph.

## Ambitious Conjecture to State Precisely

This is the field-opening conjecture you should formalize and experimentally probe.

### Conjecture: Clause Space Dominates Bounded Configuration Graph Pathwidth
There exists a universal constant `c > 0` such that for every unsatisfiable CNF `F`,
\[
\operatorname{minClauseSpace}(F) \ge \frac{1}{c}\,
\operatorname{pathwidth}\!\bigl(\mathrm{ConfGraph}_{s}(F)\bigr),
\quad \text{where } s := \operatorname{minClauseSpace}(F).
\]

A discrete Lean-friendly integer version is preferable:

```lean
conjecture clauseSpace_ge_pathwidth_div_const
  {Clause Var : Type _}
  [DecidableEq Clause] :
  ∃ c : Nat, 0 < c ∧
    ∀ F : CNF Clause Var,
      Unsatisfiable F →
      let s := minClauseSpace F
      graphPathwidth (confGraphBounded F s) ≤ c * s
```

This avoids rationals and is the right formulation for computation.

## Three Proof Strategy Architectures

You asked for 2–3 proof strategy steps; here are **three distinct proof programs**, each with substeps. Strategy A is the most immediately formalizable.

### Strategy A: Trace-as-Path-Decomposition Construction
**Most promising for Lean and for first major theorem package.**

1. **Construct bags from the trace**
   - For a refutation trace `C₀, ..., Cₙ`, define bag `Bᵢ := Cᵢ` or `Bᵢ := {Cᵢ, Cᵢ₊₁}` depending on whether vertices are clauses or configurations.
   - Prove every visited vertex appears in some bag.
   - Prove every visited transition edge is covered by a bag.

2. **Prove interval/connectedness**
   - Show that once an object disappears from the linear trace decomposition, it does not need to reappear without violating the chosen encoding; or enlarge bags to maintain interval structure.
   - This is where careful choice of decomposition object matters:
     - If bags contain **configurations**, connectedness is easy along the trace order.
     - If bags contain **clauses**, you need a persistence lemma about clause lifetimes.

3. **Extract width bound from space bound**
   - Width is controlled by the maximum configuration size.
   - This yields the first rigorous inequality between proof memory and pathwidth.

Why this is promising: it relies on explicit constructions, induction on trace index, and local graph reasoning — exactly the kind of argument Lean handles robustly.

---

### Strategy B: Elimination Ordering / Vertex Separation Equivalence
**More conceptually powerful; likely harder but closer to the final conjecture.**

1. Use the known equivalence between pathwidth and vertex separation / linear layout width.
2. Define a linear order on configurations induced by a successful proof trace or canonical exploration.
3. Show the set of “live frontier” configurations at each cut can be simulated by currently stored clauses, yielding a separator of size `O(s)`.

This route is stronger because it speaks the native language of pathwidth and may generalize beyond a single trace. If Mathlib has elimination-ordering tools or finite graph separators, exploit them. Otherwise this may be too heavy for the first cycle.

---

### Strategy C: Retraction to a Proof-Relevant Core Graph
**Best for the cross-domain leap to topology/dynamics.**

1. Define the full bounded configuration graph `ConfGraph_s(F)`.
2. Define a proof-relevant subgraph consisting of configurations reachable from the empty state and from which contradiction remains reachable.
3. Prove this core graph retracts onto a trace-generated skeleton or admits a monotone search strategy with frontier size bounded by clause space.

This can produce theorems of the form:
\[
\operatorname{pathwidth}(\mathrm{CoreConfGraph}_s(F)) \le c\,s.
\]
It is bolder and closer to the final conjecture, but likely depends on stronger monotonicity lemmas.

## Cross-Domain Connections You Must Exploit

This project is valuable because it is not merely “proof complexity in Lean.” It is a structural equivalence between proof memory and graph layout. Make that explicit.

### 1. Graph Theory / Structural Complexity
Pathwidth is tied to:
- dynamic programming complexity,
- graph searching games,
- vertex separation,
- interval-like linear decompositions.

If clause space controls pathwidth, then **resolution memory lower bounds can be attacked with graph minor methods and separator technology**.

### 2. Algorithmic SAT / State-Space Search
Configuration graphs are state spaces of proof search. Pathwidth bounds imply:
- bounded-memory exploration strategies,
- dynamic programming over proof states,
- compressed certificates of unsatisfiability.

This suggests a new algorithmic paradigm: **proof-space-aware SAT reasoning via graph decompositions**.

### 3. Statistical Mechanics / Energy Landscapes
A proof trace through configuration space resembles a trajectory through an energy landscape with bounded occupancy. Pathwidth then measures a kind of **entropic bottleneck** or linearized free-energy barrier of the proof state graph.

This is not metaphorical fluff: define frontier size as an order parameter and compare to pathwidth as a bottleneck invariant. This opens a route to probabilistic models of proof search.

### 4. Programming Languages / Semantics
Clause configurations are finite memory states; legal proof moves are transitions. Your graph is a small-step operational semantics of refutation. Path decompositions then become **resource-sensitive semantic traces**.

This connection may eventually import bisimulation and abstract interpretation ideas into proof complexity.

     \[

   - For minimally unsatisfiable `F`, the ratio
     \[
     \operatorname{pathwidth}(\mathrm{ConfGraph}_{s}(F)) / s

   - The proof-relevant core subgraph has much smaller pathwidth than the full bounded configuration graph.
   - **Test:** compute both for all small formulas.

5. **Search bottleneck hypothesis**
   - Pathwidth correlates more strongly with empirical SAT-solver memory peaks than raw formula size does.
   - **Test:** run small solver experiments and compute correlation coefficients.
