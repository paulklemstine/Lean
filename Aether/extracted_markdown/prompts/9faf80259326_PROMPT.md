## Core Vision

The catalog already gives abstract theorems of the form:

- profile-injective subfamilies have polynomial size;
- achievable profiles are polynomially bounded;
- width is controlled once collisions inside a profile class are controlled.

That is powerful but generic. The breakthrough here is to show that for **Pythagorean obstruction certificates**, profile collisions are not an arbitrary combinatorial nuisance: they are governed by the rigid algebraic structure of the equation
\[
a^2+b^2=c^2.
\]
If successful, this would convert a general well-quasi-order argument into a **concrete arithmetic compression theorem** for obstruction search.

This opens a program at the interface of:

- **Ramsey theory**: color-obstruction certificates,
- **Diophantine combinatorics**: arithmetic constraints from primitive and imprimitive triples,
- **poset width theory**: antichains and profile classes,
- **algorithm design / SAT extraction**: small canonical certificates for search.

The field-opening point is not “another bound.” It is the claim that **arithmetic equations induce low-collision certificate geometries**, suggesting a new general paradigm: *Diophantine profile rigidity*.

## Theorem 1 — Arithmetic comparability inside a fixed profile class

### Mathematical statement
Prove a theorem of the following shape:

> For Pythagorean certificate families satisfying the sandwich completeness hypotheses, if two certificates have the same arithmetic profile and the same boundary data up to level `N`, then they are comparable in the certificate poset except for membership in a uniformly bounded exceptional set.

This is the structural engine behind constant collision.

### Lean 4 target signature
A representative target is:

```lean
theorem bounded_incomparables_of_same_arithmetic_profile
    {α : Type} [Preorder α]
    (F : CertifiedSandwichFamily α)
    (N K : ℕ)
    (hcomplete : SandwichCompleteUpTo F N)
    :
    ∃ B : ℕ, ∀ s t : α,
      s ∈ F.family →
      t ∈ F.family →
      pythagoreanArithmeticProfile s = pythagoreanArithmeticProfile t →
      localBoundaryData N s = localBoundaryData N t →
      ¬ (s ≤ t) →
      ¬ (t ≤ s) →
      exceptionalPairMeasure s t ≤ B
```

If the existing poset is encoded differently, refactor the theorem into a statement that **profile classes contain only bounded-size antichains**.

A more directly usable corollary:

```lean
theorem profile_class_antichain_bounded
    {α : Type} [Preorder α]
    (F : CertifiedSandwichFamily α)
    (N : ℕ)
    :
    ∃ B : ℕ, ∀ A : Finset α,
      (∀ a ∈ A, a ∈ F.family) →
```

### Why this is a breakthrough
This theorem would be the missing domain-specific bridge from abstract profile-counting to **usable polynomial width with explicit constants**. It says the arithmetic of triples prevents arbitrary combinatorial explosion inside a single profile class.

You must include at least one theorem linking this work to another mathematical or computational domain.

### Option A: SAT / proof complexity connection
Show that bounded profile collision yields a polynomial-size canonical representative system for certificates, hence a finite-state obstruction search.

```lean

    {α : Type} [Preorder α]
    (F : CertifiedSandwichFamily α)

    (∃ B, ∀ P, widthOfProfileClass F pythagoreanArithmeticProfile P ≤ B) →
```

### Why this is a breakthrough

## Proof Strategy Architecture

You must present and pursue at least 2–3 proof routes. Do not give one vague sketch.

### Strategy A — Primitive-triple rigidity via Euclid parameterization
Most promising if you can encode enough arithmetic structure cleanly.

1. Represent primitive triples via parameters `(m,n)` with
   \[
   a = m^2-n^2,\quad b=2mn,\quad c=m^2+n^2.
   \]
2. Show that fixing the arithmetic profile fixes coarse data of the parameter pairs:
   shared hypotenuse support, parity pattern, and overlap multiplicities.
3. Prove that two incomparable certificates with identical profile must differ only in a bounded set of local parameter choices, giving a constant bound on antichain size in each profile class.

Why promising: the source of rigidity is genuinely arithmetic, not combinatorial bookkeeping. This would make the theorem conceptually deep.

### Strategy B — Monotonicity + local boundary determinacy
Most robust for Lean.

1. Define a local boundary data object up to level `N`.
2. Prove monotonicity lemmas: extending a certificate can only increase support / overlap counts in controlled ways.
3. Show that inside a fixed arithmetic profile, equal local boundary data forces comparability except for finitely many local exceptions.
4. Use the abstract width theorem from `Pythagorean/PolynomialWidth.lean` to conclude polynomial width.

Why promising: likely easiest to formalize with existing sandwich definitions and order-theoretic lemmas.

### Strategy C — Conflict graph / forbidden pattern method
Most interesting cross-domain route.

1. Define the graph whose vertices are certificates in one profile class, with edges for incomparability.
2. Show that arithmetic profile equality forbids certain induced patterns, perhaps large matchings or large cliques, because such patterns would require incompatible triple incidences.
3. Conclude bounded antichain size from a graph-theoretic bound.

Why promising: yields the strongest bridge to sparse graph theory and algorithms, though likely the most technically elaborate.

**Recommendation:** Start with Strategy B to secure the formal theorem, then import arithmetic rigidity from Strategy A to sharpen constants and significance. Strategy C is the ideal cross-domain extension theorem.
