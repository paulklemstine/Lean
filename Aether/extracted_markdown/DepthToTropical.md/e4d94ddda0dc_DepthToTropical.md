# A Valuation-Depth → Tropical (Max-Plus) Bridge

**Formalization:** `Catalog/Bridges/DepthToTropical.lean` (module `Bridges.DepthToTropical`)

## 1. Contribution

This note records a small, fully machine-checked result. It is **not** a full
tropicalization framework, nor a categorical reconstruction of tropical geometry.
The contribution is a *minimal verified semantics*: we isolate the exact
valuation-depth inequalities that occur repeatedly in practice and show that they,
on their own, induce a sound **max-plus (tropical) control calculus**. Every
statement is concrete, reusable, and proved from only the standard axioms
(`propext`, `Classical.choice`, `Quot.sound`).

The point of the exercise is the **bridge pattern**, not the individual numbers:
once an object of study is equipped with a depth function satisfying the four
one-step inequalities below, it automatically supports a max-plus cost analysis,
and that analysis is correct on whole computations, not just single operations.

## 2. Encoded assumptions: `DepthSource`

All assumptions are bundled into one lightweight structure. There is no hidden
ambient algebra; the structure carries *exactly* the data the theorems consume:

| Field        | Type                  | Meaning                              |
|--------------|-----------------------|--------------------------------------|
| `α`          | `Type*`               | carrier of objects                   |
| `depth`      | `α → ℕ`               | valuation-depth of an object         |
| `zero`       | `α`                   | distinguished base object            |
| `combine`    | `α → α → α`           | binary combination (branching)       |
| `scale`      | `α → α`               | unary scaling (fixed additive cost)  |
| `norm`       | `α → α`               | normalization                        |
| `scaleCost`  | `ℕ`                   | the additive cost of `scale`         |

subject to the four valuation-depth inequalities:

* `depth_zero    : depth zero = 0`
* `depth_combine : depth (combine x y) ≤ max (depth x) (depth y) + 1`
* `depth_scale   : depth (scale x)     ≤ depth x + scaleCost`
* `depth_norm    : depth (norm x)      ≤ depth x`

These are precisely the max-plus laws: `max` governs branching, `· + c` governs
additive cost, normalization is nonexpansive, and the base object sits at the
tropical zero `0`.

## 3. The tropical target and bridge map

The target is deliberately elementary and self-contained:

```
abbrev TropDepth := ℕ
```

with branching modeled by `max` and cost by `· + c`. The bridge map induced by a
source is simply

```
def toTrop (x : α) : TropDepth := depth x
```

named to mark its role as the image into the semiring control, even though it is
definitionally the depth.

## 4. Main theorems

**Primitive bridge inequalities** (each is the tropical reading of one source law):

* `toTrop_zero    : toTrop zero = 0`
* `toTrop_combine : toTrop (combine x y) ≤ max (toTrop x) (toTrop y) + 1`
* `toTrop_scale   : toTrop (scale x)     ≤ toTrop x + scaleCost`
* `toTrop_norm    : toTrop (norm x)      ≤ toTrop x`

**Nonexpansiveness / 1-Lipschitz packaging.** Each primitive raises depth by at
most its declared tropical cost, uniformly in the inputs:
`toTrop_combine_nonexpansive`, `toTrop_scale_nonexpansive`,
`toTrop_norm_nonexpansive`, together with the transport lemma
`toTrop_combine_mono`, which states that tropical bounds on the two inputs lift to
a tropical bound on their combination. This is the form consumed by the pipeline
induction. In particular the `+ 1` in `combine` is the sharp Lipschitz constant
exposed directly by `depth_combine`.

**Pipeline soundness (the theorem chain).** We define a tiny expression language
`Expr` generated by `atom`, `zero`, `combine`, `scale`, `norm`, with two
interpretations:

* `eval : Expr → α`, the actual evaluation in the source;
* `tropEval : Expr → TropDepth`, the purely max-plus interpretation that replaces
  `combine` by `max (·) (·) + 1`, `scale` by `· + scaleCost`, `norm` by the
  identity, atoms by their depth, and `zero` by `0`.

The main theorem lifts the single-step bounds to whole computations by structural
induction:

```
theorem eval_depth_le_tropEval (e : Expr) :
    toTrop (eval e) ≤ tropEval e
```

i.e. the real evaluation depth of any pipeline is bounded by its tropical cost
interpretation. The proof is a four-case induction, each case closing by
transitivity of the corresponding one-step inequality with the inductive
hypotheses (`max_le_max` for the branching case, `Nat.add_le_add_right` for the
cost case).

## 5. Why this is a reusable bridge pattern

The development is parametric in the `DepthSource`. Any future catalog item that
exhibits a depth/valuation with these four inequalities can instantiate the
structure and immediately inherit:

1. the primitive tropical inequalities for its operations;
2. the nonexpansiveness/1-Lipschitz statements;
3. **automatic** soundness of max-plus cost analysis over arbitrary pipelines
   built from the primitives, via `eval_depth_le_tropEval`.

This factors the recurring "depth bound ⇒ tropical control" reasoning into a
single, once-and-for-all verified semantics, so that downstream work can argue at
the level of the max-plus interpretation `tropEval` and transfer the result back
to true depths with no further proof obligations.
