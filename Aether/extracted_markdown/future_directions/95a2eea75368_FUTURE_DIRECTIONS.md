# Future Directions

This document outlines concrete next steps building on the Berggren hidden-subsemigroup rigidity framework formalized in `Cryptography/BerggrenSubsemigroupRigidity.lean`.

---

## 1. Parikh-Only Reconstruction with Auxiliary Invariants

**Question**: Can the orbit profile hypothesis in `short_word_reconstruction` be replaced by a *cheaper* invariant that, combined with the Parikh triple, still determines the word uniquely?

**Proposed Lean signature**:
```lean
theorem parikh_plus_depth_reconstruction
    (w₁ w₂ : BergWord)
    (hp : parikhTriple w₁ = parikhTriple w₂)
    (hd : depthInvariant w₁ = depthInvariant w₂) :
    w₁ = w₂
```
where `depthInvariant` is a partial geometric invariant (e.g., the hypotenuse of the generated triple modulo a suitable prime).

**Why it matters**: The full orbit profile is expensive to compute for long words (it requires matrix exponentiation). A lightweight invariant like `hypotenuse mod p` would yield a practical hash with provable collision bounds. This bridges the gap between theoretical injectivity (which we have) and efficient cryptographic hashing.

## 2. Quantitative Spectral Gap for Parikh Classes

**Question**: For words of length *n* sharing the same Parikh triple, how far apart are their orbit profiles?

**Proposed Lean signature**:
```lean
theorem parikh_class_separation
    (w₁ w₂ : BergWord)
    (hp : parikhTriple w₁ = parikhTriple w₂)
    (hne : w₁ ≠ w₂) :
    ‖(orbitProfile w₁).1 - (orbitProfile w₂).1‖ +
    ‖(orbitProfile w₁).2 - (orbitProfile w₂).2‖ ≥
      exponentialLowerBound (wordLength w₁)
```

**Why it matters**: A quantitative separation bound would transform the collision-freeness theorem into a *distance* guarantee. In cryptographic applications, this means not just that collisions don't exist, but that near-collisions are also hard to find — the analogue of a hash function having good min-entropy.

## 3. Tropical Analogue: Weight Spectra over the Min-Plus Semiring

**Question**: Replace the integer pair action with a tropical (min-plus) action. Does the tropical Parikh spectrum still determine bounded membership?

**Proposed Lean signature**:
```lean
def tropicalActGen (g : BerggrenGen) (p : ℕ∞ × ℕ∞) : ℕ∞ × ℕ∞

def tropicalEvalPair : BergWord → ℕ∞ × ℕ∞

theorem tropical_evalPair_injective :
    Function.Injective tropicalEvalPair

theorem tropical_hidden_subsemigroup_recovery
    (S T : BergWord → Prop) [DecidablePred S] [DecidablePred T] (R : ℕ)
    (hprof : tropicalBoundedProfileSpectrum S R = tropicalBoundedProfileSpectrum T R) :
    ∀ w, wordLength w ≤ R → (S w ↔ T w)
```

**Why it matters**: Tropical semigroups appear naturally in optimization, phylogenetics, and neural network theory. Showing that the Berggren rigidity principle transfers to the tropical setting would open applications in computational biology (phylogenetic tree recovery from distance data) and in the analysis of ReLU neural networks (whose piecewise-linear structure is governed by tropical geometry).

## 4. Hidden-Subsemigroup Decision Problem Complexity

**Question**: What is the computational complexity of deciding whether a given word belongs to the subsemigroup generated by a hidden finite set of generators, given only access to the bounded profile spectrum?

**Proposed Lean signature**:
```lean
def membershipOracle (G : Finset BergWord) (R : ℕ) : BergWord → Bool :=
  fun w => decide (w ∈ truncation (subsemigroupClosure G) R)

theorem membership_from_spectrum_polynomial
    (G : Finset BergWord) (R : ℕ) (w : BergWord) (hw : wordLength w ≤ R)
    (spectrum : Finset (ℤ × ℤ))
    (hspec : spectrum = boundedProfileSpectrum (subsemigroupClosure G) R) :
    (membershipOracle G R w = true) ↔ (orbitProfile w ∈ spectrum)
```

**Why it matters**: This connects the algebraic rigidity result to computational complexity theory. If membership can be decided in polynomial time from the spectrum, this yields a new class of *efficiently verifiable* group-theoretic commitments. If it cannot, the hardness result would establish a new source of cryptographic one-wayness based on combinatorial semigroup theory rather than number theory.

## 5. Multi-Root Extension: Simultaneous Actions on Multiple Base Pairs

**Question**: Does acting on *multiple* root pairs simultaneously provide additional separation beyond a single root pair?

**Proposed Lean signature**:
```lean
def multiOrbitProfile (roots : List (ℤ × ℤ)) (w : BergWord) : List (ℤ × ℤ) :=
  roots.map (fun r => evalPairFrom r w)

theorem single_root_suffices
    (w₁ w₂ : BergWord)
    (h : evalPair w₁ = evalPair w₂) :
    ∀ roots, multiOrbitProfile roots w₁ = multiOrbitProfile roots w₂
```

**Why it matters**: In the Berggren case, a single root pair already gives injectivity (as we proved with `evalPair_injective`). But for other matrix semigroups where single-root injectivity fails, multi-root actions could recover it. This direction generalizes the framework to arbitrary finitely generated matrix semigroups, where the hidden-subsemigroup problem becomes a genuine cryptographic challenge.
