# Future Directions: Higher-Order Equality Saturation

## Synthesis

The five directions below form a coherent research program extending the semantic soundness of higher-order equality saturation established in this work. Direction 1 generalizes the type system from simple types to polymorphism, addressing the most immediate limitation. Direction 2 bridges to categorical semantics, revealing the algebraic structure underlying binder-aware e-graphs. Directions 3 and 4 push toward practical impact: strong normalization guarantees for termination and integration with real compiler infrastructure. Direction 5, the grand challenge, aims at dependent types—connecting equality saturation to the proof kernels of modern proof assistants, where the stakes for correctness are highest.

All five directions build directly on the formal infrastructure established here: intrinsically typed de Bruijn syntax, the `HOEqvGen` inductive relation, the `denote_renameTerm` and `denote_substTerm` lemmas, and the `ho_extraction_semantics_preserved` theorem. Each direction identifies precisely which components survive unchanged and where new mathematics is required.

## Direction 1: Polymorphic Equality Saturation (System F Extension)

**Conjecture:** The extraction soundness theorem `ho_extraction_semantics_preserved` extends to System F (polymorphic λ-calculus) with type abstraction `Λα. t` and type application `t [σ]`, preserving parametric denotational semantics in a Reynolds-style relational model.

**Test:** Formalize System F terms with de Bruijn indices for both term and type variables. Define the parametric denotation and prove:
1. Type substitution preserves denotation.
2. The equivalence closure including type-β (`(Λα. t) [σ] = t[σ/α]`) is semantically sound.
3. Extraction from a polymorphic e-graph preserves parametric denotation.

Generate 200 random well-typed System F terms. Apply bounded saturation with type-β and term-β. Verify semantic preservation on monomorphic instantiations.

**Impact:** System F is the core calculus of Haskell (via GHC Core) and forms the basis of most modern functional compilers. Polymorphic equality saturation would enable optimization across type abstractions—a capability no current e-graph system provides.

**Catalog References:** `Catalog/Pythagorean/HigherOrderEqSat.lean` (HOEqvGen, ho_extraction_semantics_preserved), `Catalog/Pythagorean/EqualitySaturationExtraction.lean` (extraction_semantics_preserved).

**Proof Strategy:** Extend `HOType` with type variables and universal quantification. The key new lemma is `denote_type_subst`, analogous to `denote_substTerm` but operating on the type level. The `HOEqvGen` inductive gains a `type_beta` constructor. The extraction theorem generalizes with minimal modification since the semantic framework is parametric in the type interpretation.

**Domain Bridges:** Functional compiler optimization (GHC, MLton), parametricity theory, relational semantics.

**Lineage:** Direct extension of `HOEqvGen` with one new constructor and one new denotation lemma.

**Ambition:** High. System F type-β is well-understood mathematically; the challenge is managing the interaction between term and type substitution in the formalization.

## Direction 2: Categorical Semantics of Higher-Order E-Graphs

**Conjecture:** A higher-order e-graph whose class relation is `HOEqvGen R` for semantically sound `R` computes the coequalizer of the corresponding rewrite system in the free cartesian closed category (CCC) generated by the base types. Extraction corresponds to choosing a section of the quotient projection.

**Test:** Formalize the free CCC on a set of base types in Lean 4. Construct the functor from the term algebra to the free CCC. Prove that the e-graph quotient is isomorphic to the coequalizer of the rewrite diagram. Verify that the extraction function computes a section.

Test computationally: for 50 rewrite systems of size ≤ 5, compute the coequalizer explicitly and compare with the e-graph quotient. Any discrepancy falsifies the conjecture.

**Impact:** This would establish equality saturation as a *categorical construction*, connecting it to a century of work in categorical logic. It would unlock new optimization strategies derived from categorical coherence theorems.

**Catalog References:** `Catalog/Pythagorean/HigherOrderEqSat.lean` (HOEqvGen, HOEGraphSound, denote_lam_congr).

**Proof Strategy:** Define the free CCC using the standard presentation (objects = types, morphisms = equivalence classes of terms). The key theorem is that the quotient by `HOEqvGen R` is initial among CCCs satisfying the equations in `R`. The extraction theorem then follows from the universal property.

**Domain Bridges:** Category theory, topos theory, categorical logic, algebraic topology (via nerve construction).

**Lineage:** Builds on `hoEqvGen_egraph_sound` and `ho_extraction_agrees_with_quotient_nf_semantically`.

**Ambition:** Grand challenge. Formalizing free CCCs in Lean 4 is substantial but feasible with Mathlib's category theory library.

## Direction 3: Strong Normalization and Termination Bounds

**Conjecture:** For the simply-typed λ-calculus fragment with β and η rules only (no user axioms), bounded saturation with fuel F = 2^(2^d) where d is the maximum type depth always reaches a fixed point. Moreover, the number of equivalence classes in the saturated e-graph is bounded by the number of βη-normal forms, which is finite for STLC.

**Test:** Generate 1000 well-typed STLC terms with type depth ≤ 3. Run unbounded saturation (no fuel limit but with a timeout). Record:
1. The step at which saturation reaches a fixed point.
2. The number of equivalence classes.
3. The number of distinct βη-normal forms reachable from the seed term.

Fit the saturation depth against the type complexity. Any super-doubly-exponential family falsifies the bound conjecture.

**Impact:** Termination guarantees are essential for compiler integration. A practical bound on saturation depth enables static prediction of optimization time.

**Catalog References:** `Catalog/Pythagorean/HigherOrderEqSat.lean` (BoundedHOEGraph, bounded_ho_extraction_sound), `Catalog/Pythagorean/EqualitySaturationExtraction.lean` (Convergent', nf_constant_on_eqvGen').

**Proof Strategy:** Use the strong normalization theorem for STLC (provable via logical relations). The key insight: β-reductions decrease a suitable measure (e.g., the Girard reducibility candidates), and η-expansions increase type depth but not the number of normal forms. The saturation bound follows from the finite model property of STLC.

**Domain Bridges:** Proof theory, complexity theory, rewriting theory, termination analysis.

**Lineage:** Extends `bounded_ho_extraction_sound` with a concrete fuel bound derived from the type structure.

**Ambition:** Medium-high. Strong normalization of STLC is well-known; the new contribution is the saturation bound.

## Direction 4: Integration with Practical E-Graph Systems

**Conjecture:** The semantic soundness framework can be instantiated with the concrete e-graph implementation of the egg library, yielding a verified higher-order optimizer that matches or beats GHC's simplifier on a benchmark of 100 Haskell Core expressions.

**Test:** Implement the `HOEGraph` interface over egg's Rust e-graph. Translate 100 GHC Core expressions into `HOTerm` syntax. Run bounded saturation with β/η/case-of-case rules. Compare:
1. Output term size vs. GHC -O2 output size.
2. Execution time of optimized programs.
3. Semantic equivalence on test inputs.

**Impact:** Direct practical impact on functional language compilation. A verified optimizer that matches GHC's simplifier would be the first formally guaranteed compiler optimization pass for a major functional language.

**Catalog References:** `Catalog/Pythagorean/HigherOrderEqSat.lean` (ho_extraction_semantics_preserved, hoEqvGen_egraph_sound).

**Proof Strategy:** The key is instantiating `HOEGraph.sameClass` with egg's union-find class relation and proving that each egg merge operation preserves `HOEGraphSound`. This requires showing that egg's congruence closure correctly handles the binder-aware congruence rules.

**Domain Bridges:** Compiler engineering, systems programming, performance optimization.

**Lineage:** Applies `ho_extraction_semantics_preserved` to a concrete implementation.

**Ambition:** Medium. The formal side is a straightforward instantiation; the engineering side requires significant implementation work.

## Direction 5 (Grand Challenge): Dependent Type Equality Saturation

**Conjecture:** The extraction soundness theorem extends to a dependently typed λ-calculus (a fragment of the Calculus of Inductive Constructions), where types depend on terms and the typing judgment is itself a semantic invariant. Concretely: for a semantically sound e-graph over CIC terms, extraction preserves the typing judgment and the denotation in a suitable set-theoretic model.

**Test:** Formalize a core fragment of CIC (Π-types, universes, no inductive types) using intrinsically typed syntax. Define the denotation into a Tarski-style universe hierarchy. Prove:
1. Substitution preserves typing and denotation.
2. β-reduction in CIC preserves denotation.
3. The equivalence closure is semantically sound.
4. Extraction preserves typing.

Generate 100 well-typed CIC terms. Verify extraction preserves typing and denotation on 10 test environments.

**Impact:** This would be paradigm-shifting. Proof assistants (Coq, Lean, Agda) use CIC variants as their kernel calculus. A verified equality saturation framework for CIC would enable:
- Automatic proof simplification in proof assistants
- Verified program extraction with optimization
- Certified refactoring of formal mathematical proofs
- Proof search via equivalence-class enumeration

**Catalog References:** `Catalog/Pythagorean/HigherOrderEqSat.lean` (entire development as starting point), `Catalog/Pythagorean/EqualitySaturationExtraction.lean` (extraction architecture).

**Proof Strategy:** The main obstacle is that in CIC, types depend on terms, so the denotation function must simultaneously interpret types and terms. Use a stratified approach: first prove soundness for a non-dependent fragment, then lift to Π-types using a logical relations argument. The `HOEqvGen` inductive must be extended with conversion rules for dependent types.

**Domain Bridges:** Type theory, proof assistants, homotopy type theory, program extraction, certified compilation.

**Lineage:** The culmination of the entire research program: from first-order extraction (EqualitySaturationExtraction) through higher-order (HigherOrderEqSat) to dependent types.

**Ambition:** Grand challenge, multi-year. No existing formalization handles equality saturation for dependent types. Success would establish a new field at the intersection of rewriting theory, type theory, and program optimization.
