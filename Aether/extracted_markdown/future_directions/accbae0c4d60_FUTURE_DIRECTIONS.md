# Future Directions: Cryptography from Iterated Collatz Maps

This cycle produced `CollatzHashSecurity.lean`, which sharpens the catalog module
`Cryptography.CollatzOWF` into a precise structural account of the candidate
one-way function `f(a, n) = T^a(n)`. The new results are: the exact one-step
inversion law (`step_preimage_iff`), the two-to-one preimage bound and its full
exponential generalization (`preimage_card_le_two`, `preimage_card_le_pow`),
surjectivity onto the positives with exponentially distant preimages
(`f_surjective_pos`, `section_distance`), and — most importantly — an
*unconditional, closed-form* collision family showing the raw integer iterate is
**not** collision-resistant at any depth (`persistent_collision`,
`f_not_injective`), with a matching boundary case (`f_zero_injective`) proving the
security parameter is essential.

The picture that emerges is a clean dichotomy: `T` is a genuine *one-way
candidate* (surjective, exponentially branching preimage tree) but a *broken hash*
in the raw model, because explicit collisions exist for free. The directions below
chase the question this raises: **what quotient or twist of `T` recovers collision
resistance while keeping the exponential inversion barrier?**

---

## Direction 1 — Tight lower bound on the depth-`a` preimage count

We proved the preimage tree has `≤ 2^a` leaves (`preimage_card_le_pow`). The
sharper question is the *average* and *typical* branching: define
`branch(a, c) = |{n : T^a(n) = c}|` and study its distribution. The key insight
is that `preimage_card_le_pow` is an *envelope*, but the true count is governed by
how often the odd preimage `(c-1)/3` is itself odd along the backward tree — a
purely congruential condition mod powers of 3. Conjecture: the expected number of
depth-`a` preimages of a random residue is `Θ((4/3)^a)`, not `2^a`, because only a
`1/3` fraction of nodes admit the odd branch. **Why now?** Our exact inversion law
`step_preimage_iff` reduces the entire backward tree to a deterministic mod-2/mod-3
recursion, so the branching factor is now a finite-state Markov chain on residues
that Lean can model and bound — no Collatz convergence needed.

## Direction 2 — Collision resistance of the *modular* hash `H_k(x) = T^k(x) mod 2^m`

Our `persistent_collision` kills injectivity of the raw map, but the practical
proposal was always the *reduced* hash `H_k(x) = T^k(x) mod 2^m`. The key insight
is that reduction mod `2^m` interacts with the even branch `T(2n) = n` in a
controlled way: halving is a *shift*, so `H` essentially streams parity bits, and
its collisions correspond to inputs whose parity vectors agree on the low `m` bits
after `k` steps. Conjecture (falsifiable): for `k ≥ m`, the family `8, 1` and every
other "short tail" collision of the raw map is *destroyed* by the mod-`2^m`
reduction once `k` exceeds the 2-adic valuation gap, so `H_k` regains injectivity
on `[0, 2^m)` for `k` in an explicit window. **Why now?** The raw collisions we
exhibited are all generated by the even-branch section `n ↦ 2n`; tracking their
2-adic valuation under reduction is elementary arithmetic that the proven
`step_double` and `iter_double` lemmas already encode.

## Direction 3 — A provably one-way *padded* iterate immune to the `8, 1` attack

The collision `8 → 4 ← 1` exists because two trajectories *merge*. The key insight
is that merging is exactly the failure of injectivity of `T`, and one can restore
injectivity by carrying a *parity log*: define `T̂(n) = (T(n), n mod 2)` on
`ℕ × Bool`, recording the bit that was consumed. Conjecture: `T̂^a` is injective on
its reachable set for every `a` (no collisions, ever), while still being as hard to
invert as `T^a` because recovering `n` from `(T^a(n), bits)` requires reconstructing
the trajectory. This trades a `2^a`-leaf preimage tree for a *unique* path, turning
the one-way candidate into a genuine one-way *permutation* on a structured domain.
**Why now?** Our `step_preimage_iff` shows the lost information at each step is
*exactly one bit* (which branch was taken), so the padding is canonical and its
injectivity is provable by the same parity case-split we already automated.

## Direction 4 — Quantitative inversion hardness in a query model

We have an exponential *combinatorial* barrier (`preimage_card_le_pow`), but not a
hardness *theorem* in a computational model. The key insight is that the backward
tree is the only structure an inverter can exploit, so in an oracle model where the
adversary may only evaluate `T` forward, finding a preimage of a random target at
depth `a` requires expected `Ω((4/3)^a)` forward queries (cf. Direction 1's
branching constant). Conjecture: formalize a forward-only query game in Lean and
prove a query lower bound matching the preimage-tree size, giving the first
*unconditional* (model-relative) one-wayness statement for an iterated arithmetic
map. **Why now?** Mathlib now has enough probability and counting infrastructure to
state query lower bounds, and our preimage-counting lemmas supply the exact tree
size that such a bound must match.

## Direction 5 — Cross-domain bridge: Collatz preimage trees as expander-like graphs

The catalog contains substantial expander/random-walk machinery
(`Cryptography.ExpanderWalk`, `ClassicalGroupExpanders`). The key insight is that
the Collatz *backward* graph — vertices `ℕ`, edges from `c` to its `≤ 2`
preimages — is a bounded-degree graph whose mixing properties would directly
control hash diffusion. Conjecture: the backward Collatz graph restricted to
`[0, 2^m)` (with wraparound mod `2^m`) is an expander, and its spectral gap lower
bounds the collision-resistance of `H_k` from Direction 2. This bridges dynamical
irreversibility (this module) with spectral cryptography (the expander catalog).
**Why now?** Our two-to-one bound `preimage_card_le_two` is precisely the
bounded-degree hypothesis every expander argument starts from, so the graph is
already in scope — only the spectral estimate remains.
