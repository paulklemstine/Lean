## Assignment: Define `MonotoneCircuit`

Mode: **prove**

You are not being asked to merely introduce a datatype. You are being asked to carve out a formally robust theory of **monotone min-max circuits** as a tropical / lattice-theoretic computational model, and then prove the first genuinely structural theorems about them in Lean 4.

The target is a new foundational object:
- an inductive type of circuits with input variables, constants, AND-gates interpreted as `min`, and OR-gates interpreted as `max`,
- no negation,
- semantics over linearly ordered types, especially `ℕ` and `ℝ`.

This is not just circuit syntax. This is the algebraic skeleton of:
- monotone Boolean computation after replacing `False/True` by ordered values,
- tropical computation,
- dynamic programming recurrences,
- idempotent semiring signal flow,
- robust aggregation in verification,
- lattice-valued neural and decision architectures.

Your goal is to prove that these circuits are **intrinsically monotone, Lipschitz-stable, and order-theoretically compositional**.

## Breakthrough theorem target 1: semantic monotonicity

This is the foundational theorem. It should be stated at full generality and proved cleanly by structural induction.

### Precise theorem statement

For every linearly ordered type, every monotone circuit computes a monotone function coordinatewise.

### Lean 4 type signature

```lean
theorem MonotoneCircuit.eval_monotone
    {α : Type _} [LinearOrder α] {n : ℕ}
    (c : MonotoneCircuit α n) :
    Monotone fun x : (Fin n → α) => MonotoneCircuit.eval c x
```

Because `Monotone` on function spaces can be awkward, you may also want the explicit pointwise form:

```lean
theorem MonotoneCircuit.eval_mono
    {α : Type _} [LinearOrder α] {n : ℕ}
    (c : MonotoneCircuit α n)
    {x y : Fin n → α}
    (hxy : ∀ i, x i ≤ y i) :
    MonotoneCircuit.eval c x ≤ MonotoneCircuit.eval c y
```

### Why this matters

This theorem identifies `MonotoneCircuit` as a certified model of **positive computation**. It says these circuits preserve information order and can therefore serve as:
- sound abstract interpreters,
- tropical dynamic programs,
- lattice-based control policies,
- monotone aggregators in certified robustness.

It opens a path to formal complexity lower bounds, fixed-point semantics, and tropical verification pipelines.

### Proof strategy options

#### Strategy A: direct structural induction on `c`  
Most promising.

1. Prove the explicit theorem `eval_mono`.
2. `var` and `const` are immediate.
3. For `and` and `or`, apply induction hypotheses to each subcircuit and then use monotonicity of `min` and `max` in each argument.

Mathlib likely already has lemmas like:
- `min_le_min`
- `max_le_max`
or equivalent order lemmas.

This is the cleanest and most reusable proof.

#### Strategy B: first prove local monotonicity combinators
Build auxiliary lemmas:
```lean
lemma monotone_min_fun ...
lemma monotone_max_fun ...
```
showing that pointwise min/max of monotone functions is monotone. Then prove:
- variables are monotone,
- constants are monotone,
- `and`/`or` preserve monotonicity.

This is more modular and will help later for closure theorems.

#### Strategy C: lattice-homomorphism viewpoint
Interpret evaluation as the unique homomorphism from the free min-max term algebra generated by `Fin n`. Then monotonicity follows abstractly because all operations are monotone in a lattice. This is mathematically elegant but may be heavier in Lean unless you formalize a lot of algebraic infrastructure. Use only if you want a reusable universal-algebra interface.

## Breakthrough theorem target 2: 1-Lipschitz stability in sup norm over `ℝ`

This is the theorem that turns the datatype from a mere order gadget into a robust analytic object.

The key insight: `min` and `max` are nonexpansive under the sup norm. Therefore every monotone circuit built from them is nonexpansive. This is a tropical analogue of stability for ReLU-free lattice networks.

### Precise theorem statement

For every circuit `c : MonotoneCircuit ℝ n` and every two inputs `x y : Fin n → ℝ`,
the output difference is bounded by the coordinatewise sup error:
\[
| \mathrm{eval}(c,x) - \mathrm{eval}(c,y) | \le \sup_i |x_i - y_i|.
\]

For finite `n`, formalize the sup by `Finset.univ.sup`/`iSup` or prove a coordinatewise version with an arbitrary bound `ε`.

### Lean-friendly theorem statement

The easiest strong formal version is:

```lean
theorem MonotoneCircuit.eval_le_of_coordwise_le_add
    {n : ℕ} (c : MonotoneCircuit ℝ n)
    {x y : Fin n → ℝ} {ε : ℝ}
    (hε : 0 ≤ ε)
    (hxy : ∀ i, |x i - y i| ≤ ε) :
    |MonotoneCircuit.eval c x - MonotoneCircuit.eval c y| ≤ ε
```

This avoids wrestling immediately with finite sup definitions while still expressing exact 1-Lipschitz behavior.

A useful asymmetric precursor:

```lean
theorem MonotoneCircuit.eval_le_eval_add_eps
    {n : ℕ} (c : MonotoneCircuit ℝ n)
    {x y : Fin n → ℝ} {ε : ℝ}
    (hxy : ∀ i, x i ≤ y i + ε)
    (hyx : ∀ i, y i ≤ x i + ε) :
    |MonotoneCircuit.eval c x - MonotoneCircuit.eval c y| ≤ ε
```

### Build explicitly on catalog theorems

You already have:

- `abs_min_sub_min_le`  
  from `Computation/CollatzTropicalContraction.lean`

This is the crucial bridge theorem. It likely states a contraction property for `min`:
```lean
abs (min a b - min c d) ≤ max (abs (a - c)) (abs (b - d))
```
or a comparable bound. Use it as the induction step for `and`.

You also have:
- `min_max_negation_duality`
- `negation_max_to_min`

These suggest deriving the `max` stability step from the `min` step via negation duality if a direct `abs_max_sub_max_le` lemma is absent. This is exactly the kind of cross-file synthesis that turns catalog fragments into a theory.

### Why this is a breakthrough

This theorem says monotone circuits are not only order-preserving but **robust under perturbation**. That makes them a formally certified model for:
- tropical verification,
- robust decision systems,
- lattice-valued neural architectures,
- stable dynamic programming recurrences,
- adversarially resilient aggregation.

It creates a bridge from order theory to analysis and from formal methods to tropical geometry.

### Proof strategy options

#### Strategy A: induction using `abs_min_sub_min_le` and a derived max analogue  
Most promising.

1. Prove a helper lemma for max:
   ```lean
   lemma abs_max_sub_max_le ...
   ```
   either directly or by reducing to min via
   `max a b = - min (-a) (-b)`.
2. Induct on circuit structure.
3. For `and` use `abs_min_sub_min_le`.
4. For `or` use the max analogue.
5. In variable case, apply `hxy`; in constant case, simp.

This is likely the most executable path in Lean.

#### Strategy B: order-interval preservation plus monotonicity
Show:
- if `∀ i, y i - ε ≤ x i ∧ x i ≤ y i + ε`,
- then by monotonicity and substitution of shifted inputs,
- `eval c y - ε ≤ eval c x ≤ eval c y + ε`.

This may require defining shifted environments and proving compatibility of min/max with adding constants. It is elegant and may avoid absolute-value algebra if min/max arithmetic is painful.

#### Strategy C: semiring / residuation viewpoint
Interpret min/max circuits as nonexpansive maps in the injective metric on a distributive lattice. This is conceptually powerful and points toward a broad theorem for any conditionally complete linear order with a metric compatible with lattice operations. But it may be overkill for the first cycle.

## Breakthrough theorem target 3: distributive normalization soundness

Do not stop at semantics. Show that syntax admits meaning-preserving algebraic rewrites. This creates a normalization engine and a path toward decision procedures.

Introduce a rewrite or normalization operation expressing one distributive law, e.g.
\[
a \wedge (b \vee c) = (a \wedge b) \vee (a \wedge c)
\]
with `∧ = min`, `∨ = max`.

### Precise theorem statement

For all circuits over a linear order, evaluation respects distributivity.

### Lean 4 theorem statement

A semantic version:

```lean
theorem MonotoneCircuit.eval_and_or_distrib
    {α : Type _} [LinearOrder α] {n : ℕ}
    (a b c : MonotoneCircuit α n) (x : Fin n → α) :
    MonotoneCircuit.eval (MonotoneCircuit.and a (MonotoneCircuit.or b c)) x
      =
    MonotoneCircuit.eval
      (MonotoneCircuit.or (MonotoneCircuit.and a b) (MonotoneCircuit.and a c)) x
```

You may also prove the dual:
```lean
min a (max b c) = max (min a b) (min a c)
max a (min b c) = min (max a b) (max a c)
```
at the semantic level first, then lift them into circuit rewrites.

### Why this matters

This is the first step toward:
- canonical normal forms,
- equivalence checking,
- minimization,
- extraction of DNF/CNF-like tropical representations,
- complexity comparisons between monotone formulas and monotone circuits.

It pushes the project from “we can evaluate circuits” to “we can reason algebraically about them.”

### Proof strategy options

#### Strategy A: reduce to `min`/`max` distributivity in linear orders  
Most promising.

At the evaluated expression level, the theorem becomes:
```lean
min A (max B C) = max (min A B) (min A C)
```
for `A B C : α`. This is a standard fact in linear orders. Search Mathlib first; if absent, prove it by cases on comparisons.

Then `simp [MonotoneCircuit.eval]`.

#### Strategy B: prove a generic soundness theorem for local rewrites
Define a relation `Rewrite : MonotoneCircuit α n → MonotoneCircuit α n → Prop` generated by algebraic laws and prove:
```lean
theorem Rewrite.sound ... : Rewrite c d → eval c x = eval d x
```
This is more ambitious but opens the normalization program immediately.

#### Strategy C: Boolean shadow semantics
Map `ℕ` or `ℝ` inputs threshold-wise to Booleans and use distributivity of `and`/`or`; then lift back using order reasoning. Conceptually interesting, but less direct.

### 1. Tropical geometry / idempotent algebra
`min` and `max` are the primitive operations of tropical mathematics. `MonotoneCircuit` is a finitely generated tropical term algebra without addition. This positions the work as a formal foundation for tropical computational geometry and min-plus optimization.

Use catalog bridges:

- formula-vs-circuit separation,
- lower bounds by monotone rank arguments,
- threshold encodings of Boolean monotone functions.

Even proving that thresholding the output yields a monotone Boolean predicate would already create a bridge theorem.

### 3. Formal verification / robust AI
The Lipschitz theorem makes `MonotoneCircuit` a certifiably stable model. This directly connects to:
- robustness certificates,

- safe aggregation in sensor fusion,
- tropical neural surrogates.

### 4. Dynamic programming and shortest-path style recurrences
Min/max circuits express Bellman-like recurrences and decision trees. Their monotonicity and stability theorems become machine-checked lemmas for optimization algorithms and game semantics.
