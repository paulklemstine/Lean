## Primary Theorem Targets

### Theorem A: Orthogonality of eigenvectors for distinct eigenvalues

This is the right first nontrivial theorem. It is classical, highly reusable, and usually much easier to formalize than full diagonalization.

**Precise statement:**

For a real symmetric matrix `A`, if `v` and `w` are eigenvectors with distinct eigenvalues `μ ≠ ν`, then `v` and `w` are orthogonal.

### Suggested Lean 4 type signature
```lean
theorem symmetric_eigenvectors_orthogonal
    {n : ℕ}
    {A : Matrix (Fin n) (Fin n) ℝ}
    (hA : Aᵀ = A)
    {μ ν : ℝ}
    {v w : EuclideanSpace ℝ (Fin n)}
    (hv : v ≠ 0)
    (hw : w ≠ 0)
    (hAv : LinearMap.IsEigenvector
      (Matrix.toLinearMap A) v μ)
    (hAw : LinearMap.IsEigenvector
      (Matrix.toLinearMap A) w ν)
    (hμν : μ ≠ ν) :
    ⟪v, w⟫_ℝ = 0
```

If the exact API around `Matrix.toLinearMap`, `IsEigenvector`, or inner products differs, adapt the signature, but preserve the quantifier structure and mathematical content.

### Why this matters
This theorem is the engine behind orthonormal eigenbasis constructions, spectral clustering, and modal decomposition in mechanics. In Lean, it becomes a reusable lemma for every future diagonalization theorem.

### Theorem B: Existence of an orthonormal eigenbasis for symmetric matrices

This is the flagship theorem.

**Precise statement:**

For every real symmetric matrix `A : Matrix (Fin n) (Fin n) ℝ`, there exists an orthogonal matrix `Q` and a diagonal matrix `D` such that `A = Q * D * Qᵀ`, and the diagonal entries of `D` are real eigenvalues of `A`.

### Suggested Lean 4 type signature
A fully polished Mathlib-compatible signature may need iteration, but the target should look structurally like:

```lean
theorem exists_orthogonal_diagonalization_of_symmetric
    {n : ℕ}
    (A : Matrix (Fin n) (Fin n) ℝ)
    (hA : Aᵀ = A) :
    ∃ Q D : Matrix (Fin n) (Fin n) ℝ,
      Qᵀ ⬝ Q = 1 ∧
      Q ⬝ Qᵀ = 1 ∧
      D.IsDiagonal ∧
      A = Q ⬝ D ⬝ Qᵀ
```

If `Matrix.IsDiagonal` is not the exact predicate in scope, define a local replacement:
```lean
def Matrix.IsDiagonal {n : Type _} [Fintype n] [DecidableEq n]
    (D : Matrix n n ℝ) : Prop :=
  ∀ i j, i ≠ j → D i j = 0
```

A stronger version would additionally package the diagonal entries as eigenvalues:
```lean
∧ ∀ i, ∃ μ : ℝ, D i i = μ ∧ μ ∈ Matrix.eigenvalues A
```
if the eigenvalue multiset API is usable.

### Why this would be a breakthrough
Formalizing full orthogonal diagonalization over `Fin n` provides a canonical finite-dimensional spectral theorem in matrix language, exactly where many applications live. This unlocks certified PCA, normal mode analysis, graph Fourier transforms, and finite-dimensional quantum Hamiltonian simulation.

### Theorem C: Rayleigh quotient extremizers are eigenvectors

This is the conceptual bridge theorem that makes the work field-opening rather than textbook-repetitive.

**Precise statement:**

Let `A` be symmetric. If a nonzero vector `v` maximizes or minimizes the Rayleigh quotient
\[
R_A(v) = \frac{\langle v, Av\rangle}{\langle v,v\rangle},
\]
then `v` is an eigenvector of `A`.

### Suggested Lean 4 type signature
You may need to define the Rayleigh quotient first.

```lean
def rayleighQuotient
    {n : ℕ}
    (A : Matrix (Fin n) (Fin n) ℝ)
    (v : EuclideanSpace ℝ (Fin n)) : ℝ :=
  ⟪v, (Matrix.toLinearMap A) v⟫_ℝ / ⟪v, v⟫_ℝ
```

Then target a theorem of the form:
```lean
theorem isMaxOn_rayleigh_quotient_implies_eigenvector
    {n : ℕ}
    {A : Matrix (Fin n) (Fin n) ℝ}
    (hA : Aᵀ = A)
    {v : EuclideanSpace ℝ (Fin n)}
    (hv : v ≠ 0)
    (hmax : ∀ w : EuclideanSpace ℝ (Fin n),
      w ≠ 0 → rayleighQuotient A w ≤ rayleighQuotient A v) :
    ∃ μ : ℝ, LinearMap.IsEigenvector (Matrix.toLinearMap A) v μ
```

A minimizer version should also be pursued.

### Why this matters
This theorem links spectral theory to optimization, statistics, and machine learning. It is the formal seed of PCA, Courant–Fischer theory, and semidefinite relaxation arguments.

## Proof Strategy Architecture

You must pursue at least 2–3 proof routes in parallel and record what succeeds.

### Strategy 1: Operator-theoretic transfer via self-adjointness
**Most promising.**

1. Convert `Aᵀ = A` into self-adjointness of `Matrix.toLinearMap A` on `EuclideanSpace ℝ (Fin n)`.
2. Use catalog theorem `self_adjoint_eigenvalue_real` and any Mathlib self-adjoint spectral lemmas to obtain reality and orthogonality properties.
3. Pull results back to matrix language, then package them into `Q` and `D`.

**Why promising:** Mathlib is often stronger on linear maps / inner product spaces than on raw matrices. The catalog already contains a self-adjoint eigenvalue theorem, suggesting the operator-side route is structurally aligned with available infrastructure.

---

### Strategy 2: Direct bilinear-form computation in matrix coordinates
Best for Theorem A, and possibly for low-level support lemmas.

1. Start from eigenvector equations `A v = μ v` and `A w = ν w`.
2. Compute
   \[
   \langle Av, w\rangle = \mu \langle v,w\rangle,\quad
   \langle v, Aw\rangle = \nu \langle v,w\rangle.
   \]
3. Use symmetry to show `⟨Av,w⟩ = ⟨v,Aw⟩`, hence
   \[
   (\mu - \nu)\langle v,w\rangle = 0.
   \]
4. Since `μ ≠ ν`, conclude `⟨v,w⟩ = 0`.

**Why promising:** This proof is short, robust, and highly formalization-friendly. It should produce the orthogonality theorem even if full diagonalization remains difficult.

---

### Strategy 3: Induction on dimension using invariant hyperplanes
Best for full diagonalization if direct spectral APIs are incomplete.

1. Use `real_symmetric_eigenvalue_real` to obtain one real eigenvalue and eigenvector.
2. Normalize the eigenvector and consider its orthogonal complement.
3. Prove the orthogonal complement is invariant under `A` using symmetry.
4. Restrict `A` to this complement, prove the restriction remains symmetric/self-adjoint, and invoke induction.
5. Assemble the orthonormal eigenbasis.

**Why promising:** This is mathematically canonical and constructive. It also creates reusable infrastructure for invariant subspaces and restriction of self-adjoint operators.  
**Why difficult:** Lean bookkeeping for orthogonal complements, restricted maps, and basis transport can be substantial.
