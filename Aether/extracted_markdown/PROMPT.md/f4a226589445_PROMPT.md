## Core mathematical object to introduce

You must define at least one new concept not already present in the catalog. The right one is:

- `rad : ℕ → ℕ`, the product of distinct prime divisors of `n`
- `ABCTriple`, encoding pairwise coprime positive triples with `a + b = c`
- `abc_quality`, measuring the ratio `log c / log (rad (abc))` at a discrete or rational proxy level
- a formal proposition `ABCConjecture ε K` or an asymptotic version

A suggested Lean-level design:

```lean
def rad (n : ℕ) : ℕ := ∏ p in n.primeFactors.toFinset, p

structure ABCTriple where
  a b c : ℕ
  ha_pos : 0 < a
  hb_pos : 0 < b
  hc_pos : 0 < c
  hab_coprime : Nat.Coprime a b
  hsum : a + b = c

def ABCTriple.radABC (t : ABCTriple) : ℕ := rad (t.a * t.b * t.c)

def ABCConjectureWeak : Prop :=
  ∀ ε : ℚ, 0 < ε →
  ∃ K : ℕ, ∀ t : ABCTriple,
    t.c ≤ K * (t.radABC) ^ (Nat.ceil (1 + ε))
```

If exponentiation by rational powers is awkward, introduce an **integer-exponent discretization** of the conjecture, e.g. for each integer `m ≥ 1`, a statement with exponent `1 + 1/m`, or formulate in terms of eventual domination after raising both sides to integer powers.

A more Lean-friendly alternative:

```lean
def ABCConjectureDiscrete : Prop :=
  ∀ m : ℕ, 1 ≤ m →
  ∃ K : ℕ, ∀ t : ABCTriple,
    t.c ^ m ≤ K * (t.radABC) ^ (m + 1)
```

This is not the standard abc statement verbatim, but it is a precise formal surrogate with the same consequence pattern. If you can prove implications from the standard-style formulation to this discrete version, even better.

## Precise theorem targets

You must prove at least 3 substantial theorems with multi-step arguments. Here is the theorem package I want.

### Theorem 1: Radical divisibility and squarefree control
This is foundational and nontrivial enough to support everything else.

**Mathematical statement:**  
For every `n > 0`, `rad n ∣ n`, and `rad n` is squarefree. Moreover, if `m ∣ n`, then `rad m ∣ rad n`.

**Lean 4 type signatures:**
```lean
theorem rad_dvd (n : ℕ) : rad n ∣ n

theorem rad_squarefree (n : ℕ) : Squarefree (rad n)

theorem rad_mono {m n : ℕ} (h : m ∣ n) : rad m ∣ rad n
```

**Why this matters:**  
This creates the certified arithmetic infrastructure that lets radicals behave as the “information-compressed support” of prime divisibility. It is the combinatorial heart of abc.

### Theorem 2: Primitive nth-power triples have tiny radical relative to size
This is the engine behind the FLT consequence.

**Mathematical statement:**  
If `a, b, c` are pairwise coprime and satisfy `a^n + b^n = c^n`, then
\[
\operatorname{rad}(abc) \le abc \le c^3,
\]
hence
\[
\operatorname{rad}(a^n b^n c^n) = \operatorname{rad}(abc) \le c^3.
\]
This should be proved in a way that makes the exponent-growth contradiction transparent.

**Lean 4 type signature:**
```lean
theorem rad_pow_eq_rad {n a : ℕ} (hn : 1 ≤ n) :
    rad (a ^ n) = rad a

theorem flt_radical_bound
    {a b c n : ℕ}
    (hn : 1 ≤ n)
    (ha : 0 < a) (hb : 0 < b) (hc : 0 < c)
    (hcop_ab : Nat.Coprime a b)
    (hcop_ac : Nat.Coprime a c)
    (hcop_bc : Nat.Coprime b c)
    (hfermat : a ^ n + b ^ n = c ^ n) :
    rad (a * b * c) ≤ c ^ 3
```

A stronger variant replacing `c^3` by a more precise bound is welcome.

**Why this matters:**  
This theorem converts an additive Diophantine equation into a multiplicative support bound. That is exactly the arithmetic compression phenomenon behind abc.

### Theorem 3: Conditional asymptotic Fermat from discrete abc
This is the headline theorem.

**Mathematical statement:**  
Assume a discrete abc conjecture. Then there exists `N` such that for all `n ≥ N`, there are no positive pairwise coprime integers `a,b,c` with `a^n + b^n = c^n`.

This is the formal asymptotic FLT consequence of abc.

**Lean 4 type signature:**
```lean
theorem abc_implies_asymptotic_FLT
    (hABC : ABCConjectureDiscrete) :
    ∃ N : ℕ, ∀ n ≥ N, ∀ a b c : ℕ,
      0 < a → 0 < b → 0 < c →
      Nat.Coprime a b →
      Nat.Coprime a c →
      Nat.Coprime b c →
      a ^ n + b ^ n ≠ c ^ n
```

If the fully quantified statement is technically heavy, it is acceptable to prove a slightly weaker but still meaningful form, e.g. with `n ≥ 6` under a strengthened discrete abc assumption. But the theorem must have genuine asymptotic content.

**Why this is a breakthrough:**  
A Lean-certified derivation of asymptotic FLT from a formal abc interface would be one of the cleanest examples of “conditional arithmetic transfer” in the theorem prover ecosystem. This is not just formalization; it is infrastructure for future Diophantine consequence extraction.

### Theorem 4: Height-radical obstruction schema for primitive sums
This is your cross-domain bridge theorem.

**Mathematical statement:**  
For primitive triples `a+b=c`, any sufficiently strong inequality of the shape
\[
c^m \le K \,\operatorname{rad}(abc)^{m+1}
\]
imposes an upper bound on a logarithmic quality proxy
\[
m \log c - (m+1)\log \operatorname{rad}(abc) \le \log K.
\]
In Lean, replace real logs if necessary by a discrete monotone proxy using powers.

**Lean 4 type signature, power-based version:**
```lean
theorem abc_power_obstruction
    (m K : ℕ) (hm : 1 ≤ m) :
    ∀ t : ABCTriple,
      t.c ^ m ≤ K * (t.radABC) ^ (m + 1) →
      ¬ ((K + 1) * (t.radABC) ^ (m + 1) < t.c ^ m)
```

This may look tautological, but the real goal is to package the arithmetic inequality as a **certified obstruction principle**. Then connect it to a complexity or coding interpretation.

**Cross-domain interpretation:**  
`rad(abc)` is a compressed support complexity measure. The theorem says that additive synthesis with low prime-support complexity cannot produce arbitrarily large outputs. This links number theory to **description complexity / coding theory**.

## Strongly recommended additional theorem

### Theorem 5: Primitive reduction lemma for Fermat-type solutions
Formalize the standard reduction from arbitrary solutions to primitive ones.

```lean
theorem fermat_reduce_to_primitive
    {a b c n d : ℕ}
    (hd : d ∣ a) (hd' : d ∣ b) (hd'' : d ∣ c)
    (hfermat : a ^ n + b ^ n = c ^ n) :
    ∃ a' b' c' : ℕ, 
      Nat.Coprime a' b' ∧
      a = d * a' ∧ b = d * b' ∧ c = d * c' ∧
      a' ^ n + b' ^ n = c' ^ n
```

A more realistic version using `g = gcd a b c` is also excellent. This theorem is technically meaningful and uses `rcases`, gcd facts, divisibility algebra, and multi-step `calc`.

## Proof strategy architecture

You must not just prove facts; you must organize the proof landscape.

### Strategy A: Prime-support arithmetic route
Most promising for Lean.

1. Define `rad` via `primeFactors`.
2. Prove support lemmas:
   - primes dividing `rad n` iff primes divide `n`
   - `rad_dvd`
   - `rad_squarefree`
   - `rad (n^k) = rad n`
   - `rad (mn) ∣ rad m * rad n`, with equality under coprimality if possible
3. For FLT-style equations, derive
   - `rad(a^n b^n c^n) = rad(abc)`
   - `rad(abc) ≤ abc ≤ c^3`
4. Invoke `ABCConjectureDiscrete` and compare growth rates:
   - left side behaves like `c^n`
   - right side bounded by `K * c^(3(m+1))`
   - choose `m` and large `n` to force contradiction

**Why most promising:**  
It stays inside elementary number theory, divisibility, and inequalities already accessible in Mathlib.

4. Package the result as a generic **height-vs-support obstruction theorem**.

**Why this matters:**  
This creates a formal language that could later connect to Roth/Szpiro/Mordell-style statements without needing full algebraic geometry immediately.
