## Primary Theorem Cluster

### 1. Binary Search: exact correctness + logarithmic depth from interval halving

Define a binary search over a monotone predicate on `Fin n` or over a sorted array `Vector α n` with decidable order. The theorem should not be “the algorithm returns something correct” in vague terms. It should identify the exact insertion point / least witness.

A strong target is:

```lean
theorem binarySearch_spec
  {n : ℕ} (p : Fin n → Prop) [DecidablePred p]
  (hmono : ∀ ⦃i j : Fin n⦄, i ≤ j → p i → p j) :
  let r := binarySearch p
  (∀ i : Fin n, i < r.val → ¬ p i) ∧
  (r.val < n → p ⟨r.val, r.isLt⟩) ∧
  (∀ j : Fin n, p j → r.val ≤ j.val)
```

If your implementation returns `Option (Fin n)` or a boundary index in `Nat`, adjust the statement accordingly, but preserve the **least witness** content.

Then prove a genuine complexity theorem:

```lean
theorem binarySearch_steps_le_log2
  {n : ℕ} (p : Fin n → Prop) [DecidablePred p] :
  steps (binarySearchWithTrace p) ≤ Nat.ceilLog2 (n + 1)
```

If `Nat.ceilLog2` integration is awkward, prove a power-of-two version first, explicitly building on:

```lean
binary_search_depth_pow2
```

A sharper version worth targeting:

```lean
theorem binarySearch_steps_exact_pow2
  (k : ℕ) :
  steps (binarySearchWithTrace (n := 2^k) p) ≤ k
```

This is not just algorithm verification. It is a formal theorem that **decision under monotonicity equals information contraction by interval bisection**.

#### Why this is a breakthrough
This turns binary search into the first certified instance of an **information-geometric algorithmics** library: correctness by order structure, complexity by entropy reduction. That architecture can later absorb parametric search, branch-and-bound, and noisy binary search.

### 2. Dijkstra: certified shortest paths with a global frontier invariant

Do not settle for path existence. Formalize weighted finite graphs and prove that Dijkstra computes the least path weight under nonnegative edge weights. The key theorem should expose the frontier invariant: settled vertices already have optimal distance, and unsettled tentative distances are upper bounds obtained by one-edge relaxations.

Suggested graph model: finite vertex type `V` with `[Fintype V] [DecidableEq V]`, weight function
`w : V → V → Option ℕ` or `w : V → V → WithTop ℕ`, where absent edges are `⊤`.

Core target:

```lean
theorem dijkstra_correct
  {V : Type} [Fintype V] [DecidableEq V]
  (w : V → V → WithTop ℕ) (src : V)
  (hnonneg : ∀ u v, 0 ≤ w u v) :
  let dist := dijkstra w src
  ∀ v : V, dist v = shortestPathDist w src v
```

If `0 ≤ w u v` is syntactically unsuitable because `WithTop ℕ` is automatically nonnegative, replace it with a graph predicate ensuring admissible finite weights.

Then prove a complexity statement for the list/array implementation, e.g. for adjacency matrix representation:

```lean
theorem dijkstra_cost_dense
  {V : Type} [Fintype V] [DecidableEq V]
  (w : V → V → WithTop ℕ) (src : V) :
  cost (dijkstraDense w src) ≤ Fintype.card V ^ 2 + Fintype.card V
```

Or for a heap-based version, if you formalize one:

```lean
theorem dijkstra_cost_heap
  {V : Type} [Fintype V] [DecidableEq V]
  (adj : V → Finset (V × ℕ)) (src : V) :
  cost (dijkstraHeap adj src) ≤
    C * (numEdges adj + numVerts adj) * Nat.ceilLog2 (numVerts adj + 1)
```

#### Why this is a breakthrough
This would create a reusable Lean theory of **greedy optimality via frontier separation**, a pattern that reaches far beyond shortest paths: A*, Prim, Huffman coding, matroid optimization, and even best-first proof search. The deepest point is not Dijkstra itself; it is the formal extraction of the invariant schema.

### 3. FFT / NTT: algebraic divide-and-conquer with certified convolution

Do not formalize FFT merely as a recursive program over complex numbers. The strategically superior move is to formalize the **number-theoretic transform (NTT)** over a commutative ring with a principal `2^k`-th root of unity, because this gives exact algebra and clean convolution theorems.

A serious theorem target:

```lean
theorem ntt_mul_eq_cyclicConvolution
  {R : Type} [CommRing R]
  (n : ℕ) (hn : n = 2^k)
  (ω : R)
  (hω : IsPrimitiveRoot ω n)
  (a b : Fin n → R) :
  invNTT ω (pointwiseMul (NTT ω a) (NTT ω b)) = cyclicConvolution a b
```

If inverse transform infrastructure is too heavy initially, first prove the diagonalization theorem:

```lean
theorem NTT_diagonalizes_circulant
  {R : Type} [CommRing R]
  (n : ℕ) (ω : R) (hω : IsPrimitiveRoot ω n)
  (c x : Fin n → R) :
  NTT ω (circulantMul c x) =
    pointwiseMul (NTT ω c) (NTT ω x)
```

Then derive convolution correctness.

For complexity, prove a recurrence-based theorem for power-of-two sizes:

```lean
theorem ntt_cost_pow2
  {R : Type} [CommRing R]
  (k : ℕ) (ω : R) :
  cost (NTT (n := 2^k) ω) ≤ C * 2^k * k + C
```

You may need a machine-independent cost model counting ring additions/multiplications. That is acceptable and desirable.

#### Why this is a breakthrough
A certified NTT library in Lean is not just algorithm verification. It opens the door to:
- verified fast polynomial multiplication
- verified coding theory
- verified lattice cryptography primitives
- formal links between harmonic analysis and algorithmic complexity

It is the right abstraction layer for future formalized FHE, SNARK arithmetic, and computational number theory.

## Unifying Meta-Theorem

The field-opening result is to prove one abstract theorem that all three algorithms instantiate.

Define a structure like:

```lean
structure AlgorithmicCertificate (State Spec : Type) where
  step : State → State
  invariant : State → Prop
  potential : State → ℕ
  terminal : State → Bool
  extract : State → Spec
```

Then prove a theorem of the form:

```lean
theorem correctness_of_decreasing_potential
  {State Spec : Type}
  (A : AlgorithmicCertificate State Spec)
  (init : State)
  (hInv0 : A.invariant init)
  (hPres : ∀ s, A.invariant s → !A.terminal s → A.invariant (A.step s))
  (hDec : ∀ s, A.invariant s → !A.terminal s →
      A.potential (A.step s) < A.potential s)
  (hSpec : ∀ s, A.invariant s → A.terminal s = true → CorrectSpec (A.extract s)) :
  ∃ t ≤ A.potential init, CorrectSpec (A.extract ((A.step^[t]) init))
```

Then instantiate:
- binary search: potential = interval length
- Dijkstra: potential = number of unsettled vertices plus sum of slack values
- NTT recursion: potential = recursion depth / problem size

This is where the assignment becomes original. The theorem says: **verified algorithms are dynamical systems with monotone certificates**.

## Proof Strategy Architecture

### Strategy A: Direct algorithm-by-algorithm formalization
1. Define executable implementations with traces/costs.
2. Prove local loop invariants and recursion equations.
3. Derive correctness and asymptotic bounds separately.

This is the most robust path if you need early theorems quickly. It is also the best way to mine reusable lemmas.

### Strategy B: Abstract certificate framework first, then instantiate
1. Build a generic theorem for terminating invariant-preserving state machines with decreasing potentials.
2. Encode binary search, Dijkstra, and NTT recursion as instances.
3. Push correctness and complexity through a common interface.

This is the most visionary approach. It is riskier upfront but has the highest scientific payoff because it creates a new reusable Mathlib-adjacent architecture for algorithm verification.

### Strategy C: Information/entropy bridge
1. Use `binary_search_depth_pow2` as the prototype that search depth is an information bound.
2. Connect `compressor_gives_complexity_bound` and `complexity_bound_implies_finite_entropy_bound` to show that certified reductions in search space imply complexity bounds.
3. Reinterpret Dijkstra frontier narrowing and NTT divide-and-conquer splitting as entropy-reduction processes.

This is the most original cross-domain strategy. It may not be needed for the first complete proofs, but even one successful bridge theorem here would be a genuine research contribution.

**Recommended order:** A for traction, B for architecture, C for breakthrough synthesis.
