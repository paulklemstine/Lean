## Core Vision

The guiding principle is:

> **Contraction of support in the algebraic polynomial corresponds, after tropicalization, to deleting a face or coordinate layer of the Newton support and reindexing the remaining lattice points; this operation preserves tropical exchange structure.**

The key insight is that **support sets are Newton polytopes in combinatorial disguise**. Differentiation/contraction is not just an operation on coefficients; it acts geometrically on exponent configurations. Tropicalization strips away classical coefficient arithmetic and reveals the polyhedral skeleton. If contraction commutes with this passage, then the earlier M-convexity closure theorem is not an isolated fact — it becomes the first theorem in a broader tropical-geometric calculus.

## Theorem 1 — Tropical contraction equals support contraction on supports

This is the first fundamental compatibility theorem.

### Mathematical statement

Let `f` be a multivariate polynomial. Let `supp(f)` be its support in exponent space. Let `contract_i(supp(f))` be the classical support contraction in direction `i`, i.e. all exponent vectors obtained by subtracting one from the `i`-th coordinate wherever possible. Then the support of the tropical truncation of `f` in direction `i` is exactly `contract_i(supp(f))`.

### Suggested Lean theorem signature

You will likely need to adapt names to the actual catalog theorem names, but the target should look essentially like:

```lean
theorem supp_tropicalTruncate_eq_supportContraction
    {σ : Type _} [DecidableEq σ]
    (i : σ) (T : TropicalSupport σ) :
    (tropicalTruncate i T).supp =
      Finset.image
        (fun m => Option.getD (exponentContract i m) 0)
        (T.supp.filter fun m => 0 < m i)
```

If you define support contraction as a separate `Finset` operation, then state equality with that operation directly:

```lean
theorem supp_tropicalTruncate_eq_contract
    {σ : Type _} [DecidableEq σ]
    (i : σ) (T : TropicalSupport σ) :
    (tropicalTruncate i T).supp = supportContract i T.supp
```

### Stronger polynomial-level version

If catalog infrastructure permits, prove a version starting from `MvPolynomial` support:

```lean
theorem tropicalized_support_contracts
    {σ : Type _} [DecidableEq σ]
    (i : σ) (f : MvPolynomial σ ℤ) :
    tropicalSupportOfPolynomial (contractPolynomial i f) =
      tropicalTruncate i (tropicalSupportOfPolynomial f)
```

If polynomial contraction is not yet defined canonically, define the support-level statement first and then prove the polynomial corollary.

### Why this matters

This theorem is the bridge: it says the algebraic operation and the tropical polyhedral operation are the same combinatorial transformation after passing to exponent geometry. That is a real conceptual theorem, not bookkeeping.

## Theorem 3 — Newton polytope truncation theorem

You need one theorem that explicitly connects to geometry, not only support combinatorics.

### Mathematical statement

Let `S` be a finite set of exponent vectors. Let `Newt(S)` be its convex hull. Contracting in direction `i` corresponds to intersecting with the half-space `{x_i ≥ 1}`, translating by `-e_i`, and projecting back to lattice points. At the support level:

\[
\operatorname{contract}_i(S)
=
\{m - e_i \mid m \in S,\ m_i > 0\}.
\]

At the polytope level:

\[
\operatorname{conv}(\operatorname{contract}_i(S))
=
\operatorname{conv}(S \cap \{x_i \ge 1\}) - e_i.
\]

You may need to formalize this first for finite subsets of `σ →₀ ℕ`, then embed into `σ → ℝ`.

### Suggested Lean theorem signature

A support-level affine statement:

```lean
theorem convexHull_supportContract_eq_translate
    {σ : Type _} [Fintype σ] [DecidableEq σ]
    (i : σ) (S : Finset (σ →₀ ℕ)) :
    convexHull ℝ ((supportContract i S : Finset (σ →₀ ℕ)) : Set (σ →₀ ℕ))
      =
    ((fun x => x - single i 1) ''
      convexHull ℝ ({m : σ →₀ ℕ | m ∈ (S : Set (σ →₀ ℕ)) ∧ 0 < m i}))
```

This exact type may need adaptation because convex hull over `ℕ`-valued finsupp is awkward; likely you should map to `σ → ℝ` or `EuclideanSpace`. That is fine — just be explicit in the formalization.

A more tractable finite-dimensional version may be:

```lean
theorem image_supportContract_eq_sub_single
    {σ : Type _} [DecidableEq σ]
    (i : σ) (S : Finset (σ →₀ ℕ)) :
    ((supportContract i S).image (fun m => m + single i 1)) =
      S.filter (fun m => 0 < m i)
```

and then derive the convex hull corollary by functoriality of convex hull under translation.

### Why this matters

This theorem makes the tropical story geometric. It identifies contraction as a **face-truncation-plus-translation** operation on Newton polytopes. That is exactly the kind of statement that algebraic geometers recognize: you are not manipulating lists of monomials, you are transforming polyhedral objects in a controlled way.

## Proof Strategy Architecture

You must not present a single-path proof sketch. Use at least 2–3 strategies and choose among them deliberately.

### Strategy A — Direct finsupp/combinatorial transport
Most likely the best first route.

1. Define `exponentContract` on `σ →₀ ℕ` and prove its coordinatewise characterization.
2. Define `supportContract` as image/filter on finite supports.
3. Prove support equality theorems by:
   - extensionality on exponent vectors,
   - `rcases` on whether `m i = 0`,
   - explicit witness construction,
   - multi-step `calc` reasoning on coordinates.
4. Transfer M-convexity/exchange using the existing support contraction theorem from `Pythagorean/MConvexDifferentiation.lean`.

**Why promising:** it minimizes dependence on immature tropical infrastructure and lets you leverage the existing support-contraction result immediately.

### Strategy B — Tropicalization as a functor from polynomial data to weighted supports
Conceptually strongest.

1. Define `tropicalSupportOfPolynomial : MvPolynomial σ R → TropicalSupport σ`, forgetting coefficients except through valuation/weight.
2. Define a polynomial contraction operator and prove functoriality:
   `tropicalSupportOfPolynomial (contractPolynomial i f) = tropicalTruncate i (tropicalSupportOfPolynomial f)`.
3. Deduce support and exchange preservation as corollaries.

**Why promising:** this is the theorem the field actually wants.  
**Risk:** depends on how much coefficient/valuation infrastructure is already available in the catalog.

### Strategy C — Newton polytope / convex-geometric route
Best for the geometric theorem.

1. Prove support contraction equals filtering by `m_i > 0` and subtracting `e_i`.
2. Embed exponent vectors into a real vector space.
3. Use affine invariance of convex hull to show truncation corresponds to translation of a sliced hull.
4. Recover tropical exchange preservation from polyhedral combinatorics if possible.

**Why promising:** yields the most striking cross-domain theorem.  
**Risk:** formal convex geometry over finitely supported integer vectors can be technically heavy.

**Recommendation:**  
Start with **Strategy A** to secure the support-level theorem and M-convex preservation. Then layer **Strategy C** for geometric significance. Attempt **Strategy B** if catalog tropicalization tools are strong enough; if not, implement a support-based tropicalization and state clearly how it models the polynomial-level functor.
