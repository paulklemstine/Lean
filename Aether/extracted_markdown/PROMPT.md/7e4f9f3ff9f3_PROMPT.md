## Theorem 1: Monotonicity of the EML Closure Operator

### Mathematical statement
For all sets of real-valued functions `A B`, if `A ⊆ B`, then every function obtainable from `A` by the EML closure rules is also obtainable from `B`.

### Lean 4 type signature
```lean
theorem eml_closure_mono
    (A B : Set (ℝ → ℝ))
    (hAB : A ⊆ B) :
    EMLClosure A ⊆ EMLClosure B
```

If `EMLClosure` is not introduced and membership is already primitive:
```lean
theorem eml_closure_mono
    (A B : Set (ℝ → ℝ))
    (hAB : A ⊆ B) :
    ∀ ⦃f : ℝ → ℝ⦄, f ∈ eml_closure A → f ∈ eml_closure B
```

### Why this is a breakthrough
This upgrades closure from a syntactic gadget into a genuine order-theoretic operator. Once monotonicity is available, every inclusion theorem on generators becomes an inclusion theorem on whole model classes. This is the first step toward a Galois-style theory of EML expressivity.

## Theorem 2: Idempotence of Closure

### Mathematical statement
Closing an already closed class adds nothing new:
\[
\mathrm{EMLClosure}(\mathrm{EMLClosure}(A)) = \mathrm{EMLClosure}(A).
\]

### Lean 4 type signature
```lean
theorem eml_closure_idempotent
    (A : Set (ℝ → ℝ)) :
    EMLClosure (EMLClosure A) = EMLClosure A
```

Or in subset form if equality is easier:
```lean
theorem eml_closure_idempotent_subset
    (A : Set (ℝ → ℝ)) :
    EMLClosure (EMLClosure A) ⊆ EMLClosure A
```
together with the easy extensivity theorem
```lean
theorem subset_eml_closure
    (A : Set (ℝ → ℝ)) :
    A ⊆ EMLClosure A
```

### Why this is a breakthrough
Idempotence is the hallmark of a true closure operator. Once you have extensivity + monotonicity + idempotence, you can import the entire conceptual toolkit of closure systems, Moore families, lattice fixed points, and abstract interpretation. This would reposition the EML framework as a semantics of compositional generation rather than a list of isolated closure lemmas.

## Theorem 3: Closure Preservation Under Composition

This should explicitly leverage the catalog theorem:

- `eml_comp_mem_closure_of_mem` from `EML/EMLFunctionalCalculus.lean`

### Mathematical statement
If `f` and `g` lie in the closure of `A`, then their composition also lies in the closure of `A`.

### Lean 4 type signature
```lean
theorem eml_closure_closed_under_comp
    (A : Set (ℝ → ℝ))
    {f g : ℝ → ℝ}
    (hf : f ∈ EMLClosure A)
    (hg : g ∈ EMLClosure A) :
    (fun x => f (g x)) ∈ EMLClosure A
```

Depending on the exact existing theorem, you may need a slightly different statement, e.g. one side in closure and the other in generators. But the strong target above is the right theorem to aim for.

### Why this is a breakthrough
This theorem says the closure is not merely generated by composition—it is compositionally self-stable. That is the formal gateway to fixed-point iteration, semigroup actions, and operator-algebraic interpretations of model classes.

## Theorem 4: Quantitative Invariant Transport Through Closure

This is the most ambitious and most interesting theorem. It should connect closure operators to one of the catalog’s quantitative domains.

A strong candidate is to transport a pointwise approximation property using `eml_add_closure`.

### Mathematical statement
If a class `A` satisfies a pointwise approximation/error envelope and the closure rules are additive/compositional in the right way, then the same envelope extends to all functions in the closure, with an explicitly transformed bound.

A first formally tractable version:

```lean
theorem eml_closure_preserves_pointwise_additive_generation
    (A : Set (ℝ → ℝ))
    {f g : ℝ → ℝ}
    (hf : f ∈ EMLClosure A)
    (hg : g ∈ EMLClosure A) :
    (fun x => f x + g x) ∈ EMLClosure A
```

If additive closure is too strong globally, prove a weaker theorem instantiated by affine generators using `eml_add_closure`:

```lean
theorem affine_eml_term_mem_closure
    (A : Set (ℝ → ℝ))
    (hbase : (fun x : ℝ => w₁ * x + b₁) ∈ EMLClosure A)
    (hbase' : (fun x : ℝ => w₂ * x + b₂) ∈ EMLClosure A) :
    (fun x : ℝ => (w₁ * x + b₁) + (w₂ * x + b₂)) ∈ EMLClosure A
```

But the deeper target is an invariant statement, for example:

### Information-decay transport target
Use `info_decays_with_depth` as a monotone quantitative analogue. Formalize the principle that if a quantity decays monotonically under one-step closure extension, then it decays across iterated closure depth.

A possible theorem shape:
```lean
theorem closure_iterate_info_decay
    (alpha : ℝ) (n : ℕ)
    (halpha0 : 0 ≤ alpha) (halpha1 : alpha ≤ 1) :
    -- some information quantity at depth n is bounded by alpha^n times the base quantity
    True
```

You should replace `True` by the actual quantity already formalized in `EML/AIResearch/InformationTheory.lean`. The key point is conceptual: **closure depth behaves like information depth**.

### Why this is a breakthrough
This is the bridge theorem. It says closure is not only qualitative (“membership survives”) but quantitative (“decay/growth laws survive”). That is the seed of a full theory of compositional thermodynamics for expressive systems.

## Most Promising Proof Strategies

### Strategy A: Induction on closure membership derivations
This is likely the best route.

1. **Identify the inductive structure** behind `eml_closure` or its membership theorem constructors.
2. Prove monotonicity and idempotence by induction on derivations:
   - base generators transported by subset inclusion,
   - closure steps preserved recursively.
3. Use `eml_comp_mem_closure_of_mem` as the composition case or as the main induction step.

**Why promising:** closure operators are almost always easiest to reason about by induction on the generation rules. This minimizes new definitions and maximizes reuse of the existing theorem infrastructure.

---

### Strategy B: Repackage closure as the intersection of all closed supersets
If the existing closure definition is flexible enough, prove:
\[
\mathrm{EMLClosure}(A) = \bigcap \{C \mid A \subseteq C \land C \text{ is closed under the EML operations}\}.
\]

Then monotonicity and idempotence become almost formal.

1. Define what it means for `C : Set (ℝ → ℝ)` to be `EMLClosed`.
2. Show `EMLClosure A` is itself closed.
3. Show it is the least closed superset of `A`.

**Why promising:** this gives a conceptually superior theorem and opens the door to lattice-theoretic fixed-point results.  
**Why harder:** it may require more foundational setup than Strategy A.

---

### Strategy C: Iterate one-step generation and identify closure as a least fixed point
Define a one-step operator `Step : Set (ℝ → ℝ) → Set (ℝ → ℝ)` and study its iterates.

1. Show `Step` is monotone.
2. Show `EMLClosure A` is a fixed point of `Step`.
3. Prove leastness via induction on iterate depth or Knaster–Tarski style arguments if the order setup is manageable.

**Why promising:** this is the path toward a real theory of expressive depth and information decay.  
**Why harder:** more abstract machinery; likely a second-wave theorem after Strategy A.

## Cross-Domain Connections You Should Make Explicit

### Order theory / lattice theory
Closure operators are fundamental in lattice theory, topology, logic, and abstract interpretation. Proving EML closure is a genuine closure operator imports all of that machinery.

### Information theory
`info_decays_with_depth` suggests that repeated composition induces contraction or attenuation of information. Closure depth can be interpreted as a semantic depth parameter, making closure theory a skeleton for compositional information thermodynamics.

### Quantum/search complexity
`grover_fewer_with_more_solutions` is an order-monotonicity theorem in a different costume. The same abstract principle—larger admissible sets reduce search cost / enlarge expressivity—suggests a unifying monotone systems perspective.

### Approximation theory
`eml_add_closure` indicates that closure can generate richer approximation classes from simple affine pieces. If you can show additive/compositional stability cleanly, this becomes a theorem about universal synthesis from primitive modules.

### Abstract interpretation / programming languages
A closure operator on function classes behaves like a semantics of reachable behaviors under compositional constructors. This is directly relevant to certified program transformation and compositional verification.
