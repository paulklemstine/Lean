## Precise Theorem Targets

### Theorem A: Canonical tropical pruning preserves semantics on a domain

Formalize a tropical polynomial as a finite family of affine forms evaluated by `sup`/`max`. Let `canonical` remove monomials that are pointwise dominated on a domain `D`.

A clean finite-domain statement is likely the most Lean-feasible first breakthrough.

### Lean-style type signature target
```lean
theorem canonical_pruning_preserves_on_finite_domain
  (D : Finset (Fin n → ℝ))
  (p : TropicalPoly n)
  (hp : ∀ x ∈ D, p.eval x = p.canonicalOn D |>.eval x) :
  ∀ x ∈ D, p.eval x = p.canonicalOn D |>.eval x
```

That signature is tautological as written, so the actual target should encode canonicalization by construction. A more meaningful target is:

```lean
theorem canonicalOn_eval_eq_of_mem_domain
  (D : Finset (Fin n → ℝ))
  (p : TropicalPoly n) :
  ∀ x ∈ D, (p.canonicalOn D).eval x = p.eval x
```

where `canonicalOn D` is defined by removing monomials `m` for which there exists another monomial `m'` satisfying
```lean
∀ x ∈ D, m.eval x ≤ m'.eval x
```
and strict inequality somewhere if you want uniqueness/minimality refinements.

This is the theorem that turns pruning into a **certified semantics-preserving transformation**.

### Theorem C: Canonical monomials are exactly the essential decision templates

This is the intellectually strongest theorem. It upgrades soundness into interpretability.

Define a monomial `m` to be **essential on `D`** if there exists `x ∈ D` such that
```lean
m.eval x = p.eval x
```
and perhaps uniquely or as a witness of active support. Then prove canonical monomials coincide with essential monomials under an appropriate anti-domination definition.

### Lean-style type signature target
```lean
theorem mem_canonicalOn_iff_essential
  (D : Finset (Fin n → ℝ))
  (p : TropicalPoly n)
  (m : TropicalMonomial n) :
  m ∈ (p.canonicalOn D).support ↔
    m ∈ p.support ∧
    ∃ x ∈ D, m.eval x = p.eval x
```

This theorem is the real bridge to interpretability:
- each surviving monomial has a witness input where it is active,
- each removed monomial is globally redundant on the domain.

If the biconditional is too strong initially, split it into two theorems:
1. `mem_canonicalOn → essential`
2. `essential → mem_canonicalOn` under a generic-position or tie-breaking hypothesis.

### Theorem D: Compression ratio is bounded by the number of distinct active regions

This is the first complexity theorem and could become the headline result.

Let `activeSupports D p` be the set of monomials attaining the max somewhere on `D`. Then canonical support size is bounded by active support size, often equal to it.

### Lean-style type signature target
```lean
theorem card_canonicalOn_support_le_card_active_templates
  (D : Finset (Fin n → ℝ))
  (p : TropicalPoly n) :
  (p.canonicalOn D).support.card ≤
    (Finset.biUnion D (fun x => p.argmaxMonomials x)).card
```

A more elementary theorem, easier for Lean, is:
```lean
theorem card_canonicalOn_support_le_card_support
  (D : Finset (Fin n → ℝ))
  (p : TropicalPoly n) :
  (p.canonicalOn D).support.card ≤ p.support.card
```
but that is only a warm-up. The deeper theorem relates compression to **geometric activity**, not just set deletion.

## Recommended formal definitions

To keep the proof tractable in Lean 4, define objects minimally and finitely.

### Tropical monomial / affine template
Represent as:
```lean
structure TropicalMonomial (n : ℕ) where
  coeff : ℝ
  weight : Fin n → ℝ

def TropicalMonomial.eval (m : TropicalMonomial n) (x : Fin n → ℝ) : ℝ :=
  m.coeff + ∑ i, m.weight i * x i
```

### Tropical polynomial
```lean
structure TropicalPoly (n : ℕ) where
  support : Finset (TropicalMonomial n)

def TropicalPoly.eval (p : TropicalPoly n) (x : Fin n → ℝ) : ℝ :=
  p.support.sup (fun m => m.eval x)
```
You may need a nonempty/default convention or use `sSup` over a finite image if `ℝ` order instances cooperate better.

### Domain-canonicalization
```lean
def dominatedOn (D : Finset (Fin n → ℝ)) (m m' : TropicalMonomial n) : Prop :=
  ∀ x ∈ D, m.eval x ≤ m'.eval x

def TropicalPoly.canonicalOn (D : Finset (Fin n → ℝ)) (p : TropicalPoly n) : TropicalPoly n :=
  { support := p.support.filter (fun m =>
      ¬ ∃ m' ∈ p.support, m' ≠ m ∧ dominatedOn D m m') }
```

This finite-domain formulation is powerful enough to prove real theorems and avoids measure/topology/compactness overhead initially.

## Proof strategy architecture

## Strategy A: Finite-domain domination elimination via `Finset.sup`
**Most promising for first formal breakthrough**

1. Define `canonicalOn D` by filtering out monomials dominated on all points of `D`.
2. Prove a one-step deletion lemma:
   ```lean
   theorem erase_dominated_eval_eq
     (hdom : dominatedOn D m m')
     (hm : m ∈ p.support)
     (hm' : m' ∈ p.support) :
     ∀ x ∈ D, p.eval x = (p.erase m).eval x
   ```
   This should follow from the fact that at each `x ∈ D`, `m.eval x ≤ m'.eval x`, so removing `m` does not change the `sup`.
3. Iterate deletion over the filtered support to conclude:
   ```lean
   ∀ x ∈ D, p.eval x = (p.canonicalOn D).eval x
   ```

Why this is promising:
- It uses only finite combinatorics and order theory.
- It directly leverages lattice/max lemmas.
- It produces a theorem strong enough for applications immediately.

---

## Strategy B: Essential-support characterization via argmax witnesses
**Best for interpretability theorem**

1. Define:
   ```lean
   def EssentialOn (D : Finset (Fin n → ℝ)) (p : TropicalPoly n) (m : TropicalMonomial n) : Prop :=
     m ∈ p.support ∧ ∃ x ∈ D, m.eval x = p.eval x
   ```
2. Prove canonical monomials are essential:
   if `m` survives canonicalization but is never active, derive domination by the pointwise max of others; in finite settings, this may require a stronger pairwise-domination definition or a genericity hypothesis.
3. Prove essential monomials survive:
   if `m` is active at some `x`, no single competing monomial can dominate it on all of `D`.

Why this matters:
- This theorem transforms pruning from “safe deletion” to “meaningful explanation extraction.”
- It is the theorem interpretability people actually need.

Risk:
- The reverse implication may fail without careful definition; if so, refine “canonical” to “active-support canonical” or add tie-breaking.

**Best for field-opening cross-domain impact after Strategy A**

## Cross-domain connections you should explicitly exploit

### Tropical geometry × interpretability
Canonical monomials define the upper hull of affine templates. In geometric terms, pruning removes templates that never appear on the tropical hypersurface arrangement governing decisions. This is not just compression; it is **polyhedral explanation extraction**.

### Neural network verification × certified pruning
Most verification asks whether a network is robust after training. Your theorem asks something stronger:
- which parts of the network are semantically inert on a certified domain?
This could integrate with certified robustness regions and adversarial analysis.

### Convex analysis × support functions
A tropical polynomial as max of affine forms is a convex piecewise-linear function. Canonicalization resembles removal of non-exposed faces in a support representation. This ties the project to:
- Legendre-Fenchel duality,
- polytope support functions,
- minimal H-representations / V-representations.

### Boolean logic × tropical semantics
Through `bool_and_as_tropical_max`, monomials can be viewed as discrete decision clauses. Canonicalization then becomes clause minimization in a semiring semantics. This suggests a future bridge to:
- circuit minimization,
- explainable AI,
- symbolic distillation of neural nets.

### Complexity theory × representation size
The cardinality of canonical support is a semantic complexity measure. It may become a new invariant:
- “tropical explanation complexity,”
- the minimum number of affine templates needed on a domain.

This is the seed of a complexity theory for piecewise-linear models.
