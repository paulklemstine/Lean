## Precise Theorem Targets

You should aim for a hierarchy of theorem statements, from foundational to ambitious.

### Target A: Finite-set Erdős–Szekeres upper bound

Define a predicate expressing general position and convex position for finite indexed point families in `ℝ × ℝ` or `Fin m → ℝ × ℝ`.

A clean theorem statement to formalize:

```lean
theorem erdos_szekeres_upper_bound
    (n m : ℕ)
    (hn : 3 ≤ n)
    (hm : Nat.centralBinom (n - 2) + 1 ≤ m)
    (p : Fin m → ℝ × ℝ)
    (hgp : generalPosition p) :
    ∃ s : Finset (Fin m),
      s.card = n ∧ inConvexPosition p s
```

If `Nat.centralBinom` is inconvenient, use the equivalent binomial form:

```lean
theorem erdos_szekeres_upper_bound_choose
    (n m : ℕ)
    (hn : 3 ≤ n)
    (hm : Nat.choose (2 * n - 4) (n - 2) + 1 ≤ m)
    (p : Fin m → ℝ × ℝ)
    (hgp : generalPosition p) :
    ∃ s : Finset (Fin m),
      s.card = n ∧ inConvexPosition p s
```

This is the canonical breakthrough formalization target.

### Target B: Cups-caps extraction theorem

This is likely the most formalization-friendly core combinatorial theorem.

```lean
theorem cups_caps_bound
    (r s m : ℕ)
    (hr : 2 ≤ r)
    (hs : 2 ≤ s)
    (hm : Nat.choose (r + s - 4) (r - 2) + 1 ≤ m)
    (p : Fin m → ℝ × ℝ)
    (hStrictX : StrictMono fun i => (p i).1)
    (hgp : generalPosition p) :
    hasCup p r ∨ hasCap p s
```

Here `hasCup p r` and `hasCap p s` should be defined by monotonicity of successive slopes or by orientation signs of consecutive triples after sorting by `x`-coordinate.

This theorem is the real engine. Once proved, the standard Erdős–Szekeres theorem follows by setting `r = s = n`.

## Core Definitions to Introduce

Use concrete, Lean-friendly predicates. Avoid dependence on advanced affine-geometry APIs unless they reduce proof burden.

### General position
For finite point families, the essential condition is no three collinear points:

```lean
def orient (a b c : ℝ × ℝ) : ℝ :=
  (b.1 - a.1) * (c.2 - a.2) - (b.2 - a.2) * (c.1 - a.1)

def generalPosition {m : ℕ} (p : Fin m → ℝ × ℝ) : Prop :=
  ∀ i j k, i ≠ j → j ≠ k → i ≠ k → orient (p i) (p j) (p k) ≠ 0
```

### Cup / cap
After ordering by increasing `x`, define cups/caps by strict monotonicity of adjacent slopes, or more elegantly by signs of orientations of consecutive triples.

A cup can be encoded as all consecutive triples having positive orientation; a cap as all negative orientation:

```lean
def isConvexChain {m k : ℕ} (p : Fin m → ℝ × ℝ) (f : Fin k ↪ Fin m) : Prop := ...
def isCup {m k : ℕ} (p : Fin m → ℝ × ℝ) (f : Fin k ↪ Fin m) : Prop := ...
def isCap {m k : ℕ} (p : Fin m → ℝ × ℝ) (f : Fin k ↪ Fin m) : Prop := ...
```

Then

```lean
def hasCup {m : ℕ} (p : Fin m → ℝ × ℝ) (k : ℕ) : Prop := ∃ f : Fin k ↪ Fin m, isCup p f
def hasCap {m : ℕ} (p : Fin m → ℝ × ℝ) (k : ℕ) : Prop := ∃ f : Fin k ↪ Fin m, isCap p f
```

### Convex position
A finite subset is in convex position if every chosen point is a vertex of the convex hull of the chosen set. If convex hull APIs are heavy, first formalize an equivalent polygonal criterion for points sorted by `x` and consistently oriented.

## Proof Strategy Architecture

You must pursue at least 2–3 proof paths in parallel and choose the one that formalizes best.

### Strategy A: Classical cups-caps dynamic programming
**Most promising.**

1. Sort points by increasing `x`-coordinate, using general position to ensure enough strict inequalities after perturbation or by assuming pairwise distinct `x` as an auxiliary normalization theorem.
2. Define for each point the maximal cup-length and cap-length ending there.
3. Prove the binomial-counting recurrence: if there is no `r`-cup and no `s`-cap, then the number of points is at most `choose (r+s-4) (r-2)`.

Why this is promising:
- It is combinatorial and finite.
- It avoids heavy convex hull infrastructure early.
- It yields explicit witnesses and a recursive counting skeleton suited to Lean induction.

Key intermediate lemma shape:

```lean
theorem no_big_cup_no_big_cap_card_le
    (r s m : ℕ)
    (p : Fin m → ℝ × ℝ)
    (hStrictX : StrictMono fun i => (p i).1)
    (hgp : generalPosition p)
    (hno : ¬ hasCup p r ∧ ¬ hasCap p s) :
    m ≤ Nat.choose (r + s - 4) (r - 2)
```

### Strategy B: Monotone subsequence reduction via slopes
1. For points ordered by `x`, encode a triple’s orientation sign by comparing successive slopes.
2. Translate cups/caps into increasing/decreasing subsequences in a derived slope sequence.
3. Invoke or prove an Erdős–Szekeres monotone subsequence theorem on finite sequences.

Why it matters:
- This ties the happy end problem directly to the original 1935 monotone subsequence phenomenon.
- It may leverage existing order-theoretic lemmas in Mathlib more easily than bespoke geometric induction.

Risk:
- The slope sequence is not independent of chosen subsequences, so some care is needed.
- Real division and denominator positivity can complicate Lean unless orientation inequalities are used instead of literal slopes.

### Strategy C: Oriented matroid / sign-pattern abstraction
1. Replace coordinates by the sign of `orient`.
2. Develop the theorem for rank-3 uniform oriented matroids realizable over `ℝ`.
3. Specialize back to point sets in the plane.

Why this is revolutionary:
- It upgrades the theorem from Euclidean geometry to combinatorial geometry.
- It opens direct formal routes to order types and pseudoline arrangements.

Risk:
- Too ambitious for first-cycle completion unless you keep the abstraction very light.
- Best used as a conceptual north star and future directions section, not necessarily as the primary proof.
