## Assignment: Prove closure properties for weighted tree automata in the tropical semiring

Prove genuinely new closure theorems for **finite rooted tree automata with tropical weights**, not merely the word-automata analogue copied line-by-line. The target is to show that the semantic class of tropical-recognizable tree series is closed under **pointwise tropical product** and **finite inf/union-type combination**, with a formal construction of the automata realizing these operations.

This should be treated as a bridge theorem between:
- automata theory on ranked trees,
- tropical semiring semantics,

The breakthrough is not “tree automata also have products.” The breakthrough is:

> **The semantics of compositional inference on trees is internally tropical.**
> Product constructions become min-plus convolution over state spaces, and union constructions become semantic infima. This opens a route from verified automata closure to verified tropical parsing, circuit lower bounds on tree computations, and compositional robustness certificates for hierarchical models.

### Core theorem A: tropical product closure

Mathematical statement:

Let `A₁, A₂` be weighted bottom-up tree automata over the same ranked signature, with semantics
`⟦A₁⟧, ⟦A₂⟧ : Tree σ → α`
for a tropical semiring `α` where multiplication is tropical addition and addition is tropical infimum/minimum.

Then there exists a product automaton `Aprod` with state space `Q₁ × Q₂` such that for every tree `t`,
\[
\llbracket A_{\mathrm{prod}}\rrbracket(t)
=
\llbracket A_1\rrbracket(t) \otimes \llbracket A_2\rrbracket(t),
\]
which in min-plus notation is
\[
\llbracket A_{\mathrm{prod}}\rrbracket(t)
=
\llbracket A_1\rrbracket(t) + \llbracket A_2\rrbracket(t).
\]

If your semantics is expressed by infimum over runs, this becomes the nontrivial identity
\[
\inf_{r_1} w_1(r_1,t) + \inf_{r_2} w_2(r_2,t)
=
\inf_{(r_1,r_2)} (w_1(r_1,t)+w_2(r_2,t)),
\]
and this is exactly where a distributivity lemma like `tropical_add_distrib_inf` should enter.

### Core theorem B: finite union / inf closure

Mathematical statement:

Let `A₁, A₂` be weighted tree automata over the same signature. Then there exists an automaton `Aunion` such that
\[
\llbracket A_{\mathrm{union}}\rrbracket(t)
=
\llbracket A_1\rrbracket(t) \oplus \llbracket A_2\rrbracket(t),
\]
which in min-plus notation is
\[
\llbracket A_{\mathrm{union}}\rrbracket(t)
=
\inf(\llbracket A_1\rrbracket(t), \llbracket A_2\rrbracket(t)).
\]

This is the weighted-tree analogue of nondeterministic union, but semantically it is an infimum construction, not a boolean disjunction. If your automata include designated final-state costs, the disjoint sum state space should realize the infimum by taking the better branch.

### Suggested Lean 4 type signature for Core theorem B

```lean
theorem eval_union
  {σ : Type u} {Q₁ Q₂ : Type v}
  [Fintype Q₁] [Fintype Q₂] [DecidableEq Q₁] [DecidableEq Q₂]
  (A₁ : WeightedTreeAutomaton σ Q₁)
  (A₂ : WeightedTreeAutomaton σ Q₂)
  (t : Tree σ) :
  eval (unionAutomaton A₁ A₂) t
    = inf (eval A₁ t) (eval A₂ t)
```

If your codomain is `ℝ` with `min` rather than lattice `inf`, use:

```lean
theorem eval_union_min
  {σ : Type u} {Q₁ Q₂ : Type v}

  (t : Tree σ) :
```

### Core theorem C: simultaneous closure schema over finite families

Do not stop at binary closure. Push to a finite-family theorem:

\[
\forall (I : \mathrm{Finset}\,\iota),\;
\exists A_I,\;
\forall t,\;
\llbracket A_I\rrbracket(t)=\inf_{i\in I}\llbracket A_i\rrbracket(t).
\]

This is the true compositional theorem needed for dynamic programming and parser combination.

Suggested Lean shape:

```lean
theorem eval_finset_inf
  {σ : Type u} {ι : Type v} [DecidableEq ι]
  (I : Finset ι)
  (Q : ι → Type w)
  [∀ i, Fintype (Q i)] [∀ i, DecidableEq (Q i)]
  (A : ∀ i, WeightedTreeAutomaton σ (Q i))
  (t : Tree σ) :
  eval (finsetInfAutomaton I A) t
    = I.inf' (by intro h; simpa using h) (fun i => eval (A i) t)
```

If `Finset.inf'` is annoying over your codomain, formulate first for nonempty lists or use iterated `min`.

This finite-family theorem is where the field opens up: automata become a verified algebra of tree cost functions.

Then define


or `Finset.inf` if `Q` is finite and you want computable semantics.

This finite-state computable `Finset.inf` route is probably the most Lean-friendly.

## Why this is mathematically nontrivial

For words, closure under product/union is standard. For trees, the transition relation depends on a whole tuple of child states, so the semantic proof is not a trivial port. The key identity is a higher-arity tropical distributivity through the run-combinatorics of a branching object. That branching makes this a theorem about **compositional optimization on free operads**, not just automata.

The product theorem says:
- independent tropical costs on subcomputations compose additively,
- and the global optimum on paired runs equals the sum of independent optima.

That is a min-plus Fubini principle for tree runs.

The union theorem says:
- tropical recognizability is stable under competitive model aggregation,
- so one can build verified ensembles of hierarchical recognizers.

These are foundational for tropical parsing, algebraic dynamic programming, and semantics of tree-structured neural computations.

## Proof strategy architecture

### Strategy A: statewise structural induction on trees
This is the most promising route.

1. **Prove a stronger state-indexed theorem**  
   For product, prove `evalState` at `(q₁,q₂)` equals the sum of the two component `evalState`s.  
   For union, prove `evalState` on the sum-state construction agrees with the corresponding branch semantics.

2. **At the node case, normalize the infimum over product child-state assignments**  
   Rewrite a function
   `(Fin k → Q₁ × Q₂)`  
   as a pair of functions
   `(Fin k → Q₁) × (Fin k → Q₂)`.  
   This is the tree-specific combinatorial heart. Then use the induction hypotheses pointwise on children.

3. **Apply tropical distributivity**  
   Use `tropical_add_distrib_inf` to exchange addition with infimum:
   \[
   \inf_x(f(x)+c)=\inf_x f(x)+c
   \]
   or the two-variable version needed to separate `Q₁` and `Q₂` choices.  
   This is where the catalog hint should be used explicitly.

Why this is best: it keeps the theorem computational and avoids abstract semiring bureaucracy. It is likely the shortest path to robust Lean code.

---

### Strategy B: formulate semantics as dynamic programming over algebras
A more conceptual route.

1. Define the semantics of a weighted tree automaton as a fold into the tropical semiring over the state-cost algebra.
2. Show product automata correspond to the monoidal product of algebras, and union corresponds to coproduct/disjoint sum plus tropical addition.
3. Derive closure as functoriality of the fold.

Why this is powerful: it reveals the theorem as an instance of compositional semantics for free term algebras.  
Why it is riskier: more abstraction, more typeclass friction in Lean.

---

### Strategy C: run-based semantics first, DP semantics second
If direct `evalState` recursion becomes messy.

1. Define a run on a tree explicitly as a labeling of each node by a state satisfying transition compatibility.
2. Define run weight and semantics as the infimum over all runs.
3. Prove product closure by explicit bijection between:
   - runs of `Aprod` on `t`, and
   - pairs of runs of `A₁` and `A₂` on `t`.
4. Then derive the recursive DP formula as a corollary.

Why this may help: the product theorem becomes almost tautological once the run bijection is formalized.  
Why it may hurt: dependent tree indexing for runs can be heavier than recursion.

## Stretch the result if the core theorem lands

### Stretch theorem 1: state complexity bound
If `A₁` has `|Q₁|` states and `A₂` has `|Q₂|` states, prove the constructed product automaton has exactly `|Q₁| * |Q₂|` states and union has `|Q₁| + |Q₂|` states. Formalize with `Fintype.card`.

```lean
theorem card_productAutomaton_states
  [Fintype Q₁] [Fintype Q₂] :
  Fintype.card (Q₁ × Q₂) = Fintype.card Q₁ * Fintype.card Q₂
```

and similarly for `Sum`.

### Stretch theorem 2: monotonicity / domination
If `∀ t, eval A₁ t ≤ eval A₁' t` and `∀ t, eval A₂ t ≤ eval A₂' t`, then
\[
\forall t,\;
eval(productAutomaton A₁ A₂)\, t
\le
eval(productAutomaton A₁' A₂')\, t.
\]

This is a verified comparison principle for hierarchical tropical models.

### Stretch theorem 3: finite-family ensemble closure
Generalize binary union to `Finset`-indexed infimum closure, yielding an automata ensemble theorem.
