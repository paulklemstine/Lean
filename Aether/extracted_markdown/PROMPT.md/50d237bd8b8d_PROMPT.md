## Core Theorem Vision

Let `G` be a finite connected graph, let `q` be a distinguished base vertex, and let `S ⊆ V \ {q}`. Write `L_S` for the principal minor of the graph Laplacian indexed by `S`. Define the tropical kernel of `L_S` in min-plus algebra as the set of vectors `v : S → TropicalVal` such that each row minimum in `L_S ⊗ v` is attained at least twice, or equals tropical zero in whatever kernel notion is already used in the catalog. You must **choose one precise kernel notion and keep it consistent throughout**.

The conjectural dimension formula is:

\[
\dim_{\mathrm{trop}}(\ker_{\mathrm{trop}}(L_S))
= \beta_1(G[S]) + \kappa(G,q,S),
\]

where:

- `β₁(G[S])` is the first Betti number / cycle rank of the induced subgraph on `S`,
- `κ(G,q,S)` is the number of connected components of `G[S]` that are “q-visible” in the precise sense that you define,
- `dim_trop` is the maximal size of a tropically independent generating family.

This is important because it upgrades a scalar defect formula into a **classification theorem for tropical null modes**.

## Mathematical Insight: What the Formula Really Says

Do not present this as a combinatorial curiosity. The theorem says that the tropical kernel of a graph Laplacian remembers **two distinct topological layers**:

1. **Internal topology** of `G[S]`, measured by `β₁`, producing cycle modes.
2. **External topology relative to q**, measured by `κ`, producing boundary interaction modes.

This is the tropical analogue of a Hodge-type decomposition:
- cycle generators behave like harmonic 1-dimensional homology classes,
- q-visible component generators behave like relative cohomology classes or boundary potentials.

That interpretation is the reason this direction matters. It opens a path from tropical linear algebra to:
- combinatorial Hodge theory,
- chip-firing and divisor theory on graphs,
- persistent homology on weighted networks,
- tropical PDE analogues on discrete spaces.

## Proof Strategy Architecture

You must present and attempt multiple proof routes. Here are three viable approaches.

### Strategy A: Direct generator analysis from row minima
**Most concrete; probably best for Lean.**

1. Define explicit `cycleGenerator` and `componentGenerator` vectors.
2. Prove each generator satisfies the tropical kernel condition by analyzing each row of `L_S`.
3. Show any kernel vector induces a “flatness decomposition” on `G[S]`: equal-slope regions correspond to components, and violations propagate around cycles.
4. Extract a spanning family from the cycle space plus visible components.
5. Prove tropical independence by support-separation or minimal-attainment arguments.

**Why promising:** This aligns closely with Laplacian row formulas and is likely compatible with existing `graphLaplacian` infrastructure.

### Strategy B: Tropical rank-nullity via universal defect, then identify generators
**Best if catalog already has strong defect/rank theorems.**

1. Use `UniversalDefect.lean` to obtain:
   \[
   \operatorname{tropRank}(L_S) + \dim_{\mathrm{trop}}(\ker(L_S)) = |S|.
   \]
2. Prove independently that
   \[
   \operatorname{tropRank}(L_S) = |S| - \beta_1(G[S]) - \kappa(G,q,S).
   \]
3. Conclude the dimension formula.
4. Then prove the structural generator theorem as a strengthening.

**Why promising:** Efficient if the defect side is already close to formalized.  
**Why incomplete alone:** It gives the count, but not the decomposition. You should still pursue generator structure.

### Strategy C: Incidence-complex / homological factorization
**Most visionary; hardest but deepest.**

1. Express `L = ∂ᵀ∂` combinatorially through an incidence map.
2. Interpret tropical kernel constraints as balancing conditions on a discrete tropical chain complex.
3. Show kernel classes split into cycle-space classes and relative component classes.
4. Derive the formula as a tropical Euler characteristic statement.

**Why important:** This would connect the result directly to simplicial homology and create reusable machinery for higher-dimensional tropical complexes.  
**Why risky:** Likely heavier formal overhead.

**Recommendation:** Execute Strategy A as the main proof, use Strategy B as a consistency check/corollary path, and write Strategy C into `FUTURE_DIRECTIONS.md` as the next frontier.
