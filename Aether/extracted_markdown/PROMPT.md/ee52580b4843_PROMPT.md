## Precise Theorem Statement

### Theorem 1: Binary multiplicative subadditivity
For bounded functions `f, g : ℝ → ℝ` on `[a,b]`, if `ε ≤ 2*(B+1)` and both are uniformly bounded by `B`, then the EML description complexity of the product is at most the sum of the complexities of the factors at rescaled accuracy, plus one composition node.

Suggested Lean 4 type signature:

```lean
theorem emlComplexity_mul_le
    (a b B ε : ℝ)
    (f g : ℝ → ℝ)
    (hBf : ∀ x, x ∈ Set.Icc a b → |f x| ≤ B)
    (hBg : ∀ x, x ∈ Set.Icc a b → |g x| ≤ B)
    (hε : 0 < ε)
    (hε' : ε ≤ 2 * (B + 1)) :
    EMLComplexityOn a b (fun x => f x * g x) ε ≤
      EMLComplexityOn a b f (ε / (2 * (B + 1))) +
      EMLComplexityOn a b g (ε / (2 * (B + 1))) + 1
```

This is the foundational theorem. If the catalog already contains a verified `k=2` statement, do **not** merely restate it; instead:
1. identify the exact catalog theorem,
2. repackage it into a stronger reusable interface,
3. derive at least one nontrivial corollary from it.

### Theorem 2: k-fold multiplicative subadditivity
For a finite family `f_i`, all bounded by `B` on `[a,b]`, prove the complexity of the pointwise product is bounded by the sum of individual complexities at a common reduced tolerance plus the number of multiplication gates.

Suggested Lean 4 type signature:

```lean
theorem emlComplexity_prod_le
    (a b B ε : ℝ)
    (k : ℕ)
    (f : Fin k → ℝ → ℝ)
    (hB : ∀ i x, x ∈ Set.Icc a b → |f i x| ≤ B)
    (hε : 0 < ε)
    (hk : 0 < k)
    (hB0 : 1 ≤ B) :
    EMLComplexityOn a b (intervalProd f) ε ≤
      (∑ i : Fin k, EMLComplexityOn a b (f i) (prodErrorBudget k B ε)) + (k - 1)
```

This is the real target. The theorem should not be a shallow fold-unfold exercise: the proof should use induction on `k`, nontrivial control of accumulated sup-norm error, and careful inequality management.

### Theorem 3: Polynomial complexity upper bound
Derive a cross-domain theorem connecting EML complexity to algebraic structure: bounded polynomials restricted to `[a,b]` admit EML descriptions with complexity controlled by the number of monomials and coefficient magnitudes through repeated multiplication.

Suggested statement shape:

```lean
theorem emlComplexity_polynomial_eval_le
    (a b B ε : ℝ)
    (p : Polynomial ℝ)
    (hε : 0 < ε)
    (hB : 1 ≤ B)
    (hp : ∀ x, x ∈ Set.Icc a b → |Polynomial.eval x p| ≤ B) :
    ∃ C : ℕ,
      EMLComplexityOn a b (fun x => Polynomial.eval x p) ε ≤ C
```

But do not stop at existence. Strengthen this to a bound in terms of:
- support size of `p`,
- maximal degree,
- coefficient encoding cost or absolute coefficient sum,
- multiplicative depth from Horner form.

This theorem is where the work becomes bigger than the original conjecture: it links **representation complexity** with **symbolic algebraic complexity**.

## Proof Architecture: Multiple Viable Strategies

### Strategy A: Induction on product length via binary theorem
This is the most promising route if the binary theorem already exists in catalog form.

1. **Base cases `k = 1` and `k = 2`:**
   - `k = 1` should reduce to a trivial sum bound but must be handled without relying on vacuous automation.
   - `k = 2` should invoke the certified binary multiplication theorem, ideally through a strengthened wrapper lemma.

2. **Inductive decomposition:**
   - Write
     ```lean
     intervalProd f = (intervalProd (fun i : Fin k => f (Fin.castSucc i))) * f (last)
     ```
     or use `Fin.cons` / `Fin.snoc` decomposition.
   - Apply the binary multiplicative subadditivity theorem to the partial product and the last factor.

3. **Control the new boundedness constant:**
   - Prove the partial product is bounded by `B^(k-1)` or by a coarser but induction-stable bound.
   - Use this to justify the scaling `δ_k = ε / (2 * k * B^(k-1))`.

4. **Error bookkeeping:**
   - The key inequality is that if each factor is approximated within `δ_k`, then the product error is bounded by a telescoping estimate of order `k * B^(k-1) * δ_k`.
   - Formalize this as a separate sup-norm lemma on finite products.

Why this is promising: it modularizes the proof around one deep analytic lemma and one deep combinatorial lemma.

---

### Strategy B: Direct telescoping product inequality
This is analytically cleaner and may yield a sharper constant than the inductive route.

1. Prove the finite-product perturbation inequality:
   ```lean
   |∏ i, u i - ∏ i, v i| ≤
     ∑ i, |u i - v i| * ∏ j ≠ i, max (|u j|) (|v j|)
   ```
   or a simpler corollary under uniform bound `B`.

2. Deduce the uniform estimate:
   ```lean
   |∏ i, u i - ∏ i, v i| ≤ k * B^(k-1) * δ
   ```
   whenever `|u i| ≤ B`, `|v i| ≤ B`, and `|u i - v i| ≤ δ`.

3. Translate this perturbation estimate into EML complexity by choosing approximants to each factor at tolerance `δ_k`.

Why this is powerful: it isolates the true mathematics — a Lipschitz-type estimate for finite products — and makes the complexity theorem a corollary. This route also generalizes to multilinear maps and eventually to determinant/permanent-style constructions.

---

### Strategy C: Hornerization / arithmetic circuit semantics
Best for the polynomial theorem and for future generalization.

1. Define an arithmetic-expression semantics for EML descriptions with node cost.
2. Show multiplication contributes additive node cost `+1`.
3. Interpret finite products and Horner forms as arithmetic circuits.
4. Derive complexity bounds by circuit size rather than repeated analytic approximation from scratch.

Why this matters: it transforms the theorem from an isolated bound into a **formal cost semantics for symbolic expressions**. This could become a foundational interface for future EML complexity results.
