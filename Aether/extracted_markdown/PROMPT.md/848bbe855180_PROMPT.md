```lean
def closureIter (R : FiniteResonanceSystem α) : Nat → Finset α → Finset α
| 0, S => S
| n+1, S => stepClosure R (closureIter n S)
```

### 3. Accessibility Radius / Proof Depth
Define the least number of closure steps needed to derive a theorem.

```lean

  Nat.findGreatest (fun n => v ∉ closureIter R n S) (Fintype.card α) + 1
```

```lean

  sInf {n | reachableIn R S n v}
```

### Theorem 1: Closure Monotonicity and Stabilization
This theorem says that derivability behaves like a finite dynamical system: adding lemmas never hurts, and the closure process stabilizes in at most `|α|` steps.

**Statement:**
For every finite resonance system `R`, every seed sets `S ⊆ T`, and every `n`,
1. `closureIter R n S ⊆ closureIter R n T`;
2. `closureIter R n S ⊆ closureIter R (n+1) S`;
3. `closureIter R (Fintype.card α) S = closureIter R (Fintype.card α + k) S` for all `k`;
4. hence `closure R S` is a fixed point of `stepClosure`.

**Lean 4 target signature:**
```lean
theorem closureIter_mono
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α) :
    ∀ {n : Nat} {S T : Finset α}, S ⊆ T →
      closureIter R n S ⊆ closureIter R n T

theorem closureIter_extensive
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α) (n : Nat) (S : Finset α) :
    closureIter R n S ⊆ closureIter R (n+1) S

theorem closure_stabilizes
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α) (S : Finset α) :
    stepClosure R (closure R S) = closure R S
```

**Why this matters:**  
This gives the formal “thermodynamic limit” of a theorem library under inference closure. It is the base theorem that turns vague emergence into exact finite mathematics.

**Proof ideas:**
1. Induction on `n` for monotonicity.
2. Use finite cardinality and strict growth impossibility: if closure keeps changing beyond `|α|` steps, cardinality strictly increases too many times.
3. Convert stabilization into fixed-point property by unfolding `closure`.

This should involve real induction and subset/cardinality reasoning, not automation.

### Theorem 2: Synergy from a Dependency Diamond
This is the first true resonance theorem. It formalizes the idea that two arithmetic lemmas together unlock a theorem that neither unlocks alone.

**Mathematical statement:**
Let `a,b,t` be distinct nodes with
- `deps t = {a,b}`,
- `a ∉ S`, `b ∉ S`, `t ∉ S`,
- neither `a` nor `b` is derivable from `S`,
- both become available when explicitly added.

Then
- `t ∉ closure R (S ∪ {a})`,
- `t ∉ closure R (S ∪ {b})`,
- but `t ∈ closure R (S ∪ {a,b})`.

This is the atomic form of superadditive gain.

**Lean 4 target signature:**
```lean
theorem dependency_diamond_synergy
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α)
    (S : Finset α) (a b t : α)
    (hab : a ≠ b)
    (hdeps : R.deps t = {a, b})
    (haS : a ∉ S) (hbS : b ∉ S) :
    t ∉ closure R (S ∪ {a}) ∧
    t ∉ closure R (S ∪ {b}) ∧
    t ∈ closure R (S ∪ {a, b})
```

You may need slightly stronger hypotheses depending on your exact closure setup, e.g. acyclicity or no alternate derivation path to `t`. If so, define a local nonredundancy condition:
```lean
def UniqueDependencyWitness ... : Prop := ...
```

**Why this is a breakthrough:**  
This theorem is the minimal rigorous model of “emergence” in proof search. It says that arithmetic competence can appear discontinuously because the library contains jointly necessary prerequisite motifs.

**Proof ideas:**
1. Analyze closure iterates directly; prove by contradiction that deriving `t` from `S ∪ {a}` would force `b ∈ closure`, impossible under the hypotheses.
2. Use a minimal-step argument: let `n` be the first stage where `t` appears, then unpack `deps t ⊆ closureIter ...`.
3. If you define acyclicity/rank, do induction on rank to rule out hidden alternate derivations.

This should use `rcases`, induction on closure stages, and `by_contra`.

### Theorem 3: Selective Resonance from Arithmetic Bottlenecks
This theorem distinguishes arithmetic targets from controls. It captures the original conjecture’s asymmetry.

**Mathematical statement:**
Suppose there is an arithmetic package `A` such that every arithmetic target in `targetArithmetic` has a dependency chain passing through `A`, while every control target in `targetControl` has a derivation from `S` avoiding `A`. Then adding `A` strictly decreases aggregate proof depth for arithmetic targets, while leaving control targets unchanged.

A clean finite version:
- For every `t ∈ targetArithmetic`, `proofDepth R (S ∪ A) t < proofDepth R S t`.
- For every `c ∈ targetControl`, `proofDepth R (S ∪ A) c = proofDepth R S c`.

**Lean 4 target signature:**
```lean
theorem arithmetic_bottleneck_selective
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α)
    (S A : Finset α) :
    A ⊆ R.arithmetic →
    BottleneckFor R S A R.targetArithmetic →
    AvoidableFor R S A R.targetControl →
    (∀ t, t ∈ R.targetArithmetic →
      proofDepth R (S ∪ A) t < proofDepth R S t) ∧
    (∀ c, c ∈ R.targetControl →
      proofDepth R (S ∪ A) c = proofDepth R S c)
```

You will need to define:
```lean
def BottleneckFor ... : Prop := ...
def AvoidableFor ... : Prop := ...
```
A practical formalization may replace exact `proofDepth` with bounded reachability:
```lean
∀ t ∈ targetArithmetic, ∃ n, t ∉ closureIter R n S ∧ t ∈ closureIter R n (S ∪ A)
```
and similarly a no-change statement for controls.

**Why this matters:**  
This is the formal analog of the empirical conjecture: arithmetic prerequisite density changes arithmetic theorem accessibility in a way not shared by unrelated domains.

**Proof ideas:**
1. Build from path/dependency-chain lemmas in finite DAGs.
2. Prove arithmetic targets require passing through `A`; then adding `A` shortens or enables derivations.
3. For controls, construct witness derivations avoiding `A` and show closure equality on those nodes.

This is the key cross-domain theorem: number-theoretic structure represented via graph dynamics and complexity.

### Theorem 4: Superadditive Gain Lower Bound
Once you have a package of pairwise independent arithmetic bottlenecks feeding many targets, total gain scales superlinearly.

**Mathematical statement:**
Assume there are `m` arithmetic targets each depending on at least two mutually independent arithmetic prerequisites from `A`, and no target is unlocked by any single prerequisite alone. Then the aggregate accessibility gain from adding all of `A` is strictly larger than the sum of gains from adding each element separately.

**Lean 4 target signature:**
```lean
theorem superadditive_gain_of_independent_bottlenecks
    {α : Type _} [Fintype α] [DecidableEq α]
    (R : FiniteResonanceSystem α)
    (S A T : Finset α) :
    IndependentBottleneckFamily R S A T →
    SuperadditiveGain R S A T
```

**Why this matters:**  
This is the mathematically precise “phase transition precursor”: nonlinear aggregate gain from arithmetic structure.

**Proof ideas:**
1. Sum theorem-by-theorem local synergy inequalities.
2. Use disjoint witness families to avoid double counting.
3. Define aggregate gain on finite targets and prove strict inequality by `calc`.
