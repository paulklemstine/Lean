## Precise Theorem Targets

Work toward the following theorem cluster. If full generality is too heavy initially, first prove binary stabilizer versions over `ZMod 2`.

### Theorem A: Binary Quantum Hamming Bound for Stabilizer Codes

For a binary stabilizer code with parameters `[[n, k, d]]`, letting `t = (d - 1) / 2`, prove
\[
\sum_{i=0}^{t} 3^i \binom{n}{i} \le 2^{n-k}.
\]

This is the exact packing inequality for nondegenerate binary stabilizer codes.

### Lean 4 target signature
A plausible first formalization target is:

```lean
theorem binary_quantum_hamming_bound
    (n k d t : ℕ)
    (ht : t = (d - 1) / 2)
    (hcode : NondegenerateStabilizerCode n k d)
    (hd : 1 ≤ d) :
    ∑ i in Finset.range (t + 1), (3 ^ i) * Nat.choose n i ≤ 2 ^ (n - k)
```

If your local codebase already has a `StabilizerCodeParams` structure, adapt the theorem to that type:

```lean
theorem stabilizer_quantum_hamming_bound
    (p : StabilizerCodeParams)
    (h_nondeg : p.Nondegenerate)
    (hd : 1 ≤ p.d)
    (ht : p.t = (p.d - 1) / 2) :
    ∑ i in Finset.range (p.t + 1), (3 ^ i) * Nat.choose p.n i ≤ 2 ^ (p.n - p.k)
```

### Why this matters
This converts one isolated special-case theorem (`quantum_hamming_bound_5_1_3`) into a full finite theorem schema. It would be the first genuinely reusable packing theorem in the formal quantum coding library.

### Theorem B: Quantum Singleton Bound in Parameter Form

For stabilizer parameters `[[n, k, d]]`, prove
\[
2d + k \le n + 2.
\]

This should subsume or bridge the existing Singleton statements into one parameterized theorem over stabilizer code data.

### Lean 4 target signature

```lean
theorem stabilizer_quantum_singleton_bound
    (n k d : ℕ)
    (hcode : StabilizerCode n k d) :
    2 * d + k ≤ n + 2
```

or, in structure form,

```lean
theorem stabilizer_params_quantum_singleton_bound
    (p : StabilizerCodeParams)
    (hcode : p.Valid) :
    2 * p.d + p.k ≤ p.n + 2
```

### Why this matters
The breakthrough is not the inequality itself, but a clean Lean formalization showing how code distance forces dimension loss via erasure-correction arguments. That proof architecture can later support subsystem codes, qudit codes, and holographic/topological variants.

### Theorem C: Perfect-Code Exclusion in Small Parameters

Go beyond bounds: show that some tempting parameter sets saturating Hamming or Singleton cannot exist under stabilizer constraints.

Example target:
prove nonexistence of a nondegenerate binary stabilizer code with parameters `[[6, 1, 3]]` if that follows from the Hamming inequality:
\[
1 + 3n \le 2^{n-k}.
\]
For `n=6`, `k=1`, this becomes `19 ≤ 32`, so Hamming alone does not exclude it; therefore choose a stronger target based on exact arithmetic or symplectic constraints. A better theorem is to classify the smallest perfect case and show uniqueness or extremality of `[[5,1,3]]` in the nondegenerate single-error-correcting regime.

### Theorem D: Topological Distance–Rate Tradeoff for Toric-Type Codes

Use the existing toric-code theorem as a bridge to topological quantum computing. For toric code parameters on an `L × L` torus:
- `n = 2L^2`,
- `k = 2`,
- `d = L`.

Then prove the code saturates a topological asymptotic tradeoff and satisfies the general Singleton bound strictly except in trivial size.

### Lean 4 target signature

```lean
theorem toric_code_params
    (L : ℕ) (hL : 1 ≤ L) :
    ToricCode.n L = 2 * L^2 ∧ ToricCode.k L = 2 ∧ ToricCode.d L = L
```

```lean
theorem toric_code_singleton_specialization
    (L : ℕ) (hL : 1 ≤ L) :
    2 * ToricCode.d L + ToricCode.k L ≤ ToricCode.n L + 2
```

A stronger and more visionary target:

```lean
theorem toric_code_distance_rate_tradeoff
    (L : ℕ) (hL : 1 ≤ L) :
    ToricCode.k L * ToricCode.d L^2 ≤ (ToricCode.n L)^2
```

This inequality is easy numerically for toric parameters, but its value is as a prototype for a future general theorem on 2D local stabilizer codes.

### Why this matters
This is the first bridge from abstract coding inequalities to topological order and fault-tolerant quantum memory. It opens the door to formalizing Bravyi–Poulin–Terhal-type tradeoffs later.

## Proof Strategy Architecture

You must pursue at least 2–3 proof routes and choose the strongest.

### Strategy 1: Finite Packing via Syndrome Counting
Most promising for the Hamming bound.

1. Model binary Pauli errors as vectors in `F₂^(2n)` with symplectic commutation.
2. Show distinct correctable errors of weight `≤ t` must yield distinct syndromes in a nondegenerate stabilizer code.
3. Since the syndrome space has cardinality `2^(n-k)`, conclude the packing inequality.

Why promising: every ingredient is finite and combinatorial, ideal for Lean. It also naturally generalizes from the existing `quantum_hamming_bound_5_1_3`.

---

### Strategy 2: Erasure-Correction Dimension Count
Most promising for the Singleton bound.

1. Formalize the statement “distance `d` implies correction of any erasure on `d-1` qubits.”
2. Partition the `n` qubits into two sets of size `d-1` and the remainder.
3. Use injectivity / no-cloning-style dimension counting to show the logical subspace dimension cannot exceed the Hilbert space of the remaining qubits, giving `k ≤ n - 2(d-1)`.

Why promising: this is the clean conceptual proof and would make the existing Singleton theorems more transparent. It also interfaces well with topological code interpretations.

---

### Strategy 3: Symplectic Linear Algebra / Isotropic Subspace Rank
Most promising for structural theorems and future extensions.

1. Represent the stabilizer as an isotropic subspace of a symplectic vector space over `ZMod 2`.
2. Prove rank bounds on isotropic subspaces and connect syndrome spaces to quotients by orthogonal complements.
3. Derive code parameter inequalities from rank formulas, then specialize to Hamming and Singleton consequences.

Why promising: highest long-term payoff. This is the right abstraction for qudit stabilizer codes, CSS codes, and connections to finite geometry. More setup is required, but it creates a reusable theory.

Recommendation: start with Strategy 1 for a concrete theorem win, then Strategy 2 for the conceptual Singleton theorem, and finally refactor toward Strategy 3.

## Cross-Domain Connections You Should Explicitly Exploit

### 1. Finite Geometry and Symplectic Polar Spaces
Stabilizer codes are isotropic subspaces in finite symplectic spaces. This connects quantum coding theory to incidence geometry and polar spaces. Formalizing this would let future work import counting theorems from finite geometry into quantum code classification.

### 2. Topological Quantum Computing
Toric codes and surface codes realize stabilizer constraints geometrically. Use the existing `Physics/Quantum/ToricCode.lean` theorem to show how abstract bounds manifest in topological phases with nontrivial homology.

### 3. Information Theory / Entropy
The theorem `post_quantum_security_entropy_defect_bound` suggests a route from correctability to entropy constraints. Even a modest bridge theorem relating distance or syndrome count to entropy defect would be scientifically valuable.

Possible bridge target:
```lean
theorem stabilizer_syndrome_entropy_upper_bound
    (n k : ℕ) :
    Real.log (2 ^ (n - k)) ≤ (n - k : ℝ) * Real.log 2
```
This is elementary, but can serve as a scaffold for later operational entropy statements.

### 4. Post-Quantum Cryptography
Quantum codes underlie authentication, secret sharing, and fault-tolerant cryptographic primitives. The formal packing bounds may translate into certified lower bounds on redundancy needed for adversarial noise resistance.

### 5. Topological Order and Statistical Mechanics
Surface-code decoding is deeply linked to Ising-like partition functions and homological percolation thresholds. Even if not fully formalized now, note this as a future bridge opened by the current finite code formalization.

1. **Combinatorial counting lemma**
   - Count Pauli errors of weight exactly `i`.
   - Sum over `i ≤ t`.

2. **Syndrome-space cardinality lemma**

3. **Injectivity of syndrome map**

   - Derive Singleton in parameter form.

6. **Specialize to toric code**
