## Proof Strategy Architecture

### Strategy A: Pure iteration/dynamics route
Most promising for fast formal success.

1. Define stabilization and nontrivial depth via function iteration `Function.iterate`.
2. Prove idempotence gives stabilization at depth 1.
3. Prove stabilization at depth 1 propagates to all larger depths by induction on `k`.
4. Package this as a collapse theorem for any hierarchy defined via iterate-distinguishability.

Why promising: Mathlib already handles function iteration well; this avoids heavy combinatorics and gives a reusable engine.

### Strategy B: Boolean proof operators via `and_idempotent`
Use logic gates as a toy proof system.

1. Model a proof-state update as conjunction with fixed evidence: `F(s) = s && a`.
2. Use `and_idempotent` to show repeated application stabilizes instantly.
3. Show any hierarchy defined by repeated conjunction collapses.
4. Contrast with a non-idempotent update (e.g. toggling, affine Boolean map) to witness separation.

Why important: this gives a concrete proof-complexity semantics instead of an abstract dynamical one.

### Strategy C: Adversarial/evidence bridge
Most visionary, possibly harder.

1. Use `evidence_upper_bound` as an analytic upper control on accumulated proof evidence.
2. Use `expert_regret_bound_nonneg` to interpret proof search as online prediction against an adversary.
3. Show that idempotent updates imply no adaptive gain beyond the first round, hence regret/evidence cannot witness a deep hierarchy.
4. Derive a bounded-gap theorem: adaptive hardness requires persistent non-stabilization.

Why this matters: it imports learning-theoretic lower-bound language into proof complexity. This is the route that could become a paper, not just a Lean exercise.

5. **Statistical physics**
