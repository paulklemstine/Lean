## Mode: prove

### Breakthrough Objective
Turn the elementary observation “a multivariate polynomial restricts to a low-degree univariate polynomial on every affine line” into a **formal line-testing theorem over finite fields**: a bridge between algebraic geometry, coding theory, and property testing. The target is not the tautology that substitution preserves degree; the target is a theorem schema showing that **global polynomial structure is detectable from one-dimensional shadows**.

This opens a path toward formalized low-degree testing, Reed–Muller local decoding, affine-invariant property testing, and eventually PCP-style algebraic certification inside Lean.

## Core Theorem Targets

Work over a finite field `𝔽 = ZMod q`, preferably with `q` prime so Mathlib’s field instances are smooth.

Let `m : ℕ`, `r : ℕ`, and let `f : MvPolynomial (Fin m) (ZMod q)`.

For `a d : Fin m → ZMod q`, define the affine line restriction
\[
f_{a,d}(t) := f(a + t \cdot d).
\]

Formalize the restriction operator as an actual `Polynomial (ZMod q)` and prove degree control.

```lean
  -- implement by `MvPolynomial.eval₂` into `Polynomial (ZMod q)`
```

Precise theorem statement:
```lean
theorem natDegree_lineRestriction_le_totalDegree
    {q m : ℕ}
    [Fact q.Prime]
    (f : MvPolynomial (Fin m) (ZMod q))
    (a d : Fin m → ZMod q) :

```

If `totalDegree` is awkward in Mathlib, prove a supportwise version:

```lean
theorem natDegree_lineRestriction_le_of_mem_support
    {q m r : ℕ}

    (lineRestriction f a d).natDegree ≤ r := by
```

This is the foundational certification theorem: every multivariate degree bound collapses correctly along every affine line.

### Target Theorem 2: Evaluation compatibility
You need the exact semantic identity, not just a degree bound.

```lean
theorem eval_lineRestriction
    {q m : ℕ}
    [Fact q.Prime]
    (f : MvPolynomial (Fin m) (ZMod q))
    (a d : Fin m → ZMod q)
    (t : ZMod q) :
    Polynomial.eval t (lineRestriction f a d)
      = MvPolynomial.eval (fun i => a i + t * d i) f := by
```

This theorem is the algebraic hinge: it converts a univariate statement into a multivariate one and vice versa.

### Target Theorem 3: Constant-on-all-lines implies constant polynomial
This is the first genuinely nontrivial structural theorem.

Let “constant line restriction” mean `natDegree ≤ 0` for every line. Then prove that over a nontrivial field, the polynomial itself is constant.

A robust formulation:
```lean
theorem constant_of_all_lineRestrictions_constant
    {q m : ℕ}
    [Fact q.Prime]
    (hq : 1 < q)
    (f : MvPolynomial (Fin m) (ZMod q))
    (h :
      ∀ a d : Fin m → ZMod q,
        (lineRestriction f a d).natDegree ≤ 0) :
    ∃ c : ZMod q, f = MvPolynomial.C c := by
```

Even better, if easier:
```lean
theorem eq_C_of_eval_affine_line_independent_of_t
    {q m : ℕ}
    [Fact q.Prime]
    (hq : 1 < q)
    (f : MvPolynomial (Fin m) (ZMod q))
    (h :
      ∀ a d t₁ t₂,
        MvPolynomial.eval (fun i => a i + t₁ * d i) f =
        MvPolynomial.eval (fun i => a i + t₂ * d i) f) :
    ∃ c : ZMod q, f = MvPolynomial.C c := by
```

This is a finite-field rigidity theorem: if every one-dimensional probe sees no variation, then there is no hidden multivariate complexity.

### Target Theorem 4: Degree-1 line restrictions characterize affine linearity
This is the field-opening theorem.

If every affine-line restriction has univariate degree at most `1`, then the original multivariate polynomial has total degree at most `1`.

Suggested theorem:
```lean
theorem totalDegree_le_one_of_all_lineRestrictions_le_one
    {q m : ℕ}
    [Fact q.Prime]
    (hq : 2 < q)
    (f : MvPolynomial (Fin m) (ZMod q))
    (h : ∀ a d : Fin m → ZMod q,
      (lineRestriction f a d).natDegree ≤ 1) :
    f.totalDegree ≤ 1 := by
```

If proving this exact statement is too hard due to `totalDegree` API friction, prove the equivalent structural decomposition:
```lean
theorem exists_affine_form_of_all_lineRestrictions_le_one
    {q m : ℕ}
    [Fact q.Prime]
    (hq : 2 < q)
    (f : MvPolynomial (Fin m) (ZMod q))
    (h : ∀ a d : Fin m → ZMod q,
      (lineRestriction f a d).natDegree ≤ 1) :
    ∃ c : ZMod q, ∃ w : Fin m → ZMod q,
      f = MvPolynomial.C c +
          ∑ i : Fin m, MvPolynomial.C (w i) * MvPolynomial.X i := by
```

This is the finite-field affine-line converse. It is conceptually powerful: **one-dimensional linearity in every direction forces global affine linearity**.

## Most Promising Proof Strategies

### Strategy A: Coefficient-expansion via monomials
This is the safest and most Lean-native route.

1. Define `lineRestriction` by sending each variable `X i` to the polynomial
   \[
   C(a_i) + C(d_i) X.
   \]
   This is naturally an `eval₂` from `MvPolynomial` to `Polynomial`.

2. Prove the degree bound on monomials:
   for a monomial with exponent vector `s`,
   \[
   \prod_i (a_i + d_i X)^{s_i}
   \]
   has univariate degree at most
   \[
   \sum_i s_i.
   \]

3. Extend from monomials to sums using support and `natDegree` inequalities.

Why this is promising: it aligns perfectly with Mathlib’s `eval₂`, support, monomial, and degree lemmas. It should also yield the semantic theorem `eval_lineRestriction` almost for free.

---

### Strategy B: Vanishing of higher directional derivatives
This is more visionary and may support stronger future theorems.

1. Show that if every line restriction has degree ≤ 1, then every second derivative along every direction vanishes:
   \[
   \Delta_d^2 f(a) = 0.
   \]

2. Prove that vanishing of all second directional finite differences forces all degree-≥2 monomials to vanish.

3. Conclude affine linearity.

Why this matters: this is the finite-field analogue of Hessian rigidity and connects directly to analysis, additive combinatorics, and property testing. It may be harder in Lean initially, but it sets up future work on degree-`r` tests via `(r+1)`-st differences.

---

### Strategy C: Contrapositive via a highest-degree monomial
Best for the converse theorem.

1. Assume `f` has total degree ≥ 2; pick a support monomial of maximal total degree.

2. Choose a direction `d` so that when substituting `x_i = a_i + t d_i`, the top-degree contribution in `t` does not cancel.

3. Produce one line restriction of degree ≥ 2, contradicting the hypothesis.

Why this is powerful: this is the mathematically sharp local-to-global mechanism. If formalized cleanly, it generalizes to the theorem “all line restrictions degree ≤ r imply total degree ≤ r,” which is the true Reed–Muller-testing statement.

Most promising overall:
- **Start with Strategy A** for `lineRestriction`, evaluation, and degree upper bounds.
- Use **Strategy C** for the converse `≤ 1` characterization.
- Reserve **Strategy B** for FUTURE_DIRECTIONS and possibly a stronger follow-up theorem.

## Concrete Lean Design Suggestions

### Definition architecture
Use `eval₂` into `Polynomial (ZMod q)`:
```lean
def affineVarPoly
    {q m : ℕ} [Fact q.Prime]
    (a d : Fin m → ZMod q) (i : Fin m) :
    Polynomial (ZMod q) :=
  Polynomial.C (a i) + Polynomial.C (d i) * Polynomial.X
```

Then:
```lean
def lineRestriction
    {q m : ℕ} [Fact q.Prime]
    (f : MvPolynomial (Fin m) (ZMod q))
    (a d : Fin m → ZMod q) :
    Polynomial (ZMod q) :=
  MvPolynomial.eval₂ Polynomial.C (affineVarPoly a d) f
```

This should make `eval_lineRestriction` a short proof via `Polynomial.eval₂_at`-style lemmas or direct simp.

### Useful intermediate lemmas
You will likely want:
```lean
lemma natDegree_affineVarPoly_le_one ...
lemma natDegree_monomial_lineRestriction_le ...
lemma degree_prod_affine_powers_le ...
lemma coeff_lineRestriction_eq_sum_over_support ...
```

### Avoiding API traps
If `natDegree` behaves badly on zero, consider proving with `degree` first:
```lean
(lineRestriction f a d).degree ≤ some bound
```
and only then derive `natDegree` under nonzero hypotheses where needed.

If `totalDegree` is awkward, use a support-bounded formulation:
```lean
∀ s ∈ f.support, s.sum (fun i n => n) ≤ r
```
This is often easier to prove against than `totalDegree` directly.
