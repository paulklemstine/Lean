## Assignment: Goal

Prove a genuinely new transfer theorem for tropical circuit semantics: **min-plus and max-plus circuit models are not merely analogous, they are definitionally intertranslatable by negation**, and therefore any simulation theorem proved on one side can be transported to the other with no new combinatorial argument. This should become a reusable Lean bridge that collapses duplicated development across tropical conventions.

Minimize sorry. If possible, package the result so future files can prove a theorem once and obtain its dual for free.

### Research Direction

Formalize the syntactic duality between min-plus and max-plus tropical circuits, then prove a **semantic transport / simulation transfer theorem**:

- a circuit dualization operation sends min-gates to max-gates and negates all constants,
- evaluation commutes with dualization up to output negation,
- any simulation bound/theorem for min-plus circuits automatically yields the corresponding theorem for max-plus circuits by conjugation with negation.

This is not a cosmetic refactor. It is a categorical symmetry principle for tropical computation.

### Why this is a breakthrough

Right now, tropical formalization risks bifurcating into two parallel worlds:
- min-plus algebra, common in optimization and shortest paths,
- max-plus algebra, common in scheduling, automata, and idempotent analysis.

A transfer theorem means:
1. **one proof library serves both worlds**;
2. complexity and expressivity results can be stated convention-independently;
3. tropical cryptography, circuit complexity, dynamic programming, and weighted automata gain a shared formal substrate.

This opens a new field direction inside Lean: **formal tropical meta-complexity**, where equivalence of semiring conventions is proved once at the syntax/semantics level and then exploited automatically.

Application keywords: tropical circuits, min-plus algebra, max-plus algebra, simulation theorem, circuit complexity, idempotent semirings, weighted automata, shortest paths, dynamic programming, formal verification, cryptographic hardness, categorical duality.

### Core definitions to introduce

A minimal but powerful design:

```lean
inductive MinTropCircuit
| var   : ℕ → MinTropCircuit
| const : ℝ → MinTropCircuit
| add   : MinTropCircuit → MinTropCircuit → MinTropCircuit   -- tropical multiplication = +
| min   : MinTropCircuit → MinTropCircuit → MinTropCircuit

inductive MaxTropCircuit
| var   : ℕ → MaxTropCircuit
| const : ℝ → MaxTropCircuit
| add   : MaxTropCircuit → MaxTropCircuit → MaxTropCircuit
| max   : MaxTropCircuit → MaxTropCircuit → MaxTropCircuit
```

Semantics over assignments `σ : ℕ → ℝ`:

```lean
def evalMin : MinTropCircuit → (ℕ → ℝ) → ℝ
def evalMax : MaxTropCircuit → (ℕ → ℝ) → ℝ
```

Dualization maps:

```lean
def dualVarAssign (σ : ℕ → ℝ) : ℕ → ℝ := fun i => -(σ i)

def dualMinToMax : MinTropCircuit → MaxTropCircuit
def dualMaxToMin : MaxTropCircuit → MinTropCircuit
```

with the intended action:
- variables unchanged syntactically,
- constants negated,
- `add` preserved structurally,
- `min` swapped with `max`.

### The fundamental semantic duality theorem

This is the central result.

```lean
theorem eval_dualMinToMax
    (C : MinTropCircuit) (σ : ℕ → ℝ) :
    evalMax (dualMinToMax C) (dualVarAssign σ) = - evalMin C σ
```

and symmetrically

```lean
theorem eval_dualMaxToMin
    (C : MaxTropCircuit) (σ : ℕ → ℝ) :
    evalMin (dualMaxToMin C) (dualVarAssign σ) = - evalMax C σ
```

These should be proved by structural induction, using the catalog duality lemmas:
- `min_max_duality`
- `min_max_neg_duality`
- `tropical_duality_min_to_max`

### Involutivity / equivalence theorem

Prove that dualization is an involution up to definitional equality:

```lean
theorem dualMinToMax_dualMaxToMin_inv
    (C : MinTropCircuit) :
    dualMaxToMin (dualMinToMax C) = C

theorem dualMaxToMin_dualMinToMax_inv
    (C : MaxTropCircuit) :
    dualMinToMax (dualMaxToMin C) = C
```

This upgrades the bridge from “semantic coincidence” to a true syntactic equivalence.

### Simulation theorem schema

Define a simulation relation concretely. The cleanest route is semantic simulation by a size-bounded target circuit.

For example:

```lean
def MinSimulatesMax (s : ℕ → ℕ) : Prop :=
  ∀ (n : ℕ) (C : MaxTropCircuit),
    circuitSize C ≤ n →
    ∃ D : MinTropCircuit,
      circuitSize D ≤ s n ∧
      ∀ σ, evalMin D σ = evalMax C (dualVarAssign σ) * (-1)
```

But a more elegant convention is to phrase exact functional equality after dualization:

```lean
def SimulatesMinByMax (s : ℕ → ℕ) : Prop :=
  ∀ (n : ℕ) (C : MinTropCircuit),
    circuitSize C ≤ n →
    ∃ D : MaxTropCircuit,
      circuitSize D ≤ s n ∧
      ∀ σ, evalMax D σ = evalMax (dualMinToMax C) σ
```

Then prove the transfer theorem:

```lean
theorem simulation_transfer_min_to_max
    (s : ℕ → ℕ)
    (h : SimulatesMinByMax s) :
    SimulatesMaxByMin s
```

or, if you choose a different simulation predicate, state the exact analogous theorem. The key mathematical content must be:

> If every min-plus circuit of size ≤ n is simulated by a max-plus circuit of size ≤ s n, then every max-plus circuit of size ≤ n is simulated by a min-plus circuit of size ≤ s n.

This should be a one-line corollary once the duality framework is built correctly.

A particularly strong and elegant theorem would be:

```lean
theorem simulation_transfer_iff
    (s : ℕ → ℕ) :
    SimulatesMinByMax s ↔ SimulatesMaxByMin s
```

This is the research-grade target. It says the simulation problem is invariant under tropical convention.

## Proof strategy architecture

### Strategy A: structural induction on syntax
Most promising.

1. Define `dualMinToMax`, `dualMaxToMin`, `evalMin`, `evalMax`.
2. Prove `eval_dualMinToMax` and `eval_dualMaxToMin` by induction on the circuit.
   - variable case: immediate from `dualVarAssign`;
   - constant case: arithmetic simplification;
   - add case: use induction hypotheses and `ring`;
   - min/max case: rewrite using `min_max_duality` or `min_max_neg_duality`.
3. Define simulation predicates and derive transfer by applying the simulator to the dual circuit, then dualizing back and using involutivity.

Why this is best: it is robust, local, and directly formalizable in Lean without heavy abstractions.

### Strategy B: package duality as a semantic conjugacy
Higher-level and elegant.

1. Define the denotation of a circuit as a function `(ℕ → ℝ) → ℝ`.
2. Define an operator on functions:
   ```lean
   def negateConjugate (f : (ℕ → ℝ) → ℝ) : (ℕ → ℝ) → ℝ :=
     fun σ => - f (dualVarAssign σ)
   ```
3. Prove that `dualMinToMax` realizes this conjugacy on denotations:
   ```lean
   denoteMax (dualMinToMax C) = negateConjugate (denoteMin C)
   ```
4. Then show simulation predicates are preserved under semantic conjugacy.

Why this matters: it reveals the theorem as a **functorial equivalence of semantics**, not just a syntax trick. This is mathematically cleaner and more extensible to matrix-weighted or automata semantics.

### Strategy C: abstract over a tropical gate signature
Ambitious, potentially field-opening.

1. Introduce a generic circuit language parameterized by an idempotent binary operator `⊗` and additive operator `⊕`.
2. Specialize to min-plus and max-plus instances.
3. Define a duality isomorphism between these interpretations over `ℝ` via negation.
4. Recover the transfer theorem as an instance of interpretation invariance.

Why this is powerful: it opens the door to a generic “circuit semantics under semiring isomorphism” theorem. But this may be too large for one cycle unless the syntax layer is already mature.

Recommendation: complete Strategy A first, then elevate to Strategy B if time permits.

## Concrete theorem refinement suggestions

If the full simulation theorem feels too abstract initially, prove the following sequence:

### Step 1: gate-level duality
```lean
theorem eval_min_gate_duality (x y : ℝ) :
    min x y = -(max (-x) (-y))

theorem eval_max_gate_duality (x y : ℝ) :
    max x y = -(min (-x) (-y))
```

The first may already be `min_max_duality`; prove the second as a corollary.

### Step 2: circuit semantic duality
```lean
theorem eval_dualMinToMax
    (C : MinTropCircuit) (σ : ℕ → ℝ) :
    evalMax (dualMinToMax C) (fun i => -σ i) = - evalMin C σ
```

### Step 3: denotational extensionality
```lean
theorem duality_extensional
    (C₁ C₂ : MinTropCircuit)
    (h : ∀ σ, evalMin C₁ σ = evalMin C₂ σ) :
    ∀ σ, evalMax (dualMinToMax C₁) σ = evalMax (dualMinToMax C₂) σ
```

### Step 4: size preservation
```lean
theorem circuitSize_dualMinToMax
    (C : MinTropCircuit) :
    circuitSize (dualMinToMax C) = circuitSize C
```

and similarly in the other direction.

### Step 5: transfer theorem
```lean
theorem simulation_transfer_iff
    (s : ℕ → ℕ) :
    SimulatesMinByMax s ↔ SimulatesMaxByMin s
```

The size-preservation lemma is critical: without it, the complexity statement is mathematically weaker.
