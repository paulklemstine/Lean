## Precise Theorem Targets

You must formalize precise statements, and at least one should closely resemble the following signatures. Adapt names/types to the actual catalog APIs, but preserve the mathematical content.

### Theorem 1: Congruence closure soundness under incremental merging

**Mathematical statement.**  
Let `G₀` be a typed e-graph whose same-class relation is sound with respect to the equivalence closure of a rewrite system `R`. If `G₁` is obtained from `G₀` by one incremental congruence-closure step (merging classes only when justified by either a rewrite instance or congruent parents), then `G₁` remains sound.

**Lean 4 target shape:**
```lean
theorem incremental_step_sound
  {σ : Type u} {τ : Type v}
  [DecidableEq τ]
  (R : TypedRewriteSystem σ τ)
  (G G' : TypedCongruenceEGraph σ τ)
  (hstep : IncrementalCongruenceStep R G G')
  (hsound : G.SoundFor R) :
  G'.SoundFor R
```

**Why it matters.**  
This is the invariance theorem that makes the algorithm trustworthy. Without it, completeness is irrelevant.

### Theorem 2: Congruence-generated relation is closed under typed function application

**Mathematical statement.**  
If for each argument position we have terms `tᵢ ~ uᵢ` in the e-graph’s generated equivalence, then for every typed function symbol `f`, we have `f(t₁,...,t_m) ~ f(u₁,...,u_m)`.

**Lean 4 target shape:**
```lean
theorem eqvGen_closed_under_fun
  {σ : Type u} {τ : Type v}
  [DecidableEq τ]
  (R : TypedRewriteSystem σ τ)
  (f : TypedSymbol σ τ)
  (ts us : HVector (Term σ) (argSorts f))
  (hargs : ∀ i, EqvGen R (ts.get i) (us.get i)) :
  EqvGen R (mkApp f ts) (mkApp f us)
```

If the catalog already packages `EqvGen` differently, adapt. The point is to prove **typed congruence** at the level of generated equivalence.

**Why it matters.**  
This is the algebraic heart of congruence closure: the equivalence generated by rewriting must itself be a congruence, not just an arbitrary relation.

### Theorem 3: Completeness of saturated typed congruence e-graphs relative to normal forms

**Mathematical statement.**  
Assume `R` is convergent on the explored typed term universe. Let `G` be a saturated typed congruence e-graph built from all rewrite instances and all congruent parent merges over that universe. Then two represented terms lie in the same e-class iff they have the same normal form under `R`, equivalently iff they are related by `EqvGen R`.

**Lean 4 target shape:**
```lean
theorem saturated_congruence_complete
  {σ : Type u} {τ : Type v}
  [DecidableEq τ]
  (R : TypedRewriteSystem σ τ)
  (G : TypedCongruenceEGraph σ τ)
  (hconv : R.Convergent)
  (hsat : G.SaturatedFor R)
  (hterms : ExploredUniverseComplete G R) :
  ∀ {α : τ} (t u : Term σ α),
    G.Represents t → G.Represents u →
    (G.SameClass t u ↔ EqvGen R t u)
```

A stronger and even better variant, if supported by the catalog, is:
```lean
theorem sameClass_iff_nf_eq
  {σ : Type u} {τ : Type v}
  [DecidableEq τ]
  (R : TypedRewriteSystem σ τ)
  (G : TypedCongruenceEGraph σ τ)
  (hconv : R.Convergent)
  (hsat : G.SaturatedFor R)
  (hterms : ExploredUniverseComplete G R) :
  ∀ {α : τ} (t u : Term σ α),
    G.Represents t → G.Represents u →
    (G.SameClass t u ↔ nf R t = nf R u)
```

Then derive the equivalence to `EqvGen R` using `nf_constant_on_eqvGen`.

**Why it matters.**  
This is the breakthrough theorem. It identifies a concrete algorithmic object—typed congruence closure on a saturated e-graph—with the semantic quotient induced by a convergent rewrite theory.

## Proof Strategy Architecture

You must include 2–3 plausible proof paths and choose the most promising one.

### Strategy A: Quotient-semantic route via normal forms
1. Use `nf_constant_on_eqvGen` from `Pythagorean/ConvergentRewriteOptimizer.lean` to show `EqvGen R t u → nf R t = nf R u`.
2. Prove converse on the explored universe under convergence: equal normal forms imply both terms rewrite into the same canonical representative.
3. Show saturation forces all terms with equal normal form into one e-class.
4. Conclude `SameClass ↔ nf equality ↔ EqvGen`.

**Why promising:** it leverages an existing catalog theorem and reduces completeness to canonicality. This is likely the shortest route to a breakthrough theorem.

### Strategy B: Induction on `EqvGen` derivations
1. Define the typed congruence closure relation generated by rewrite edges and parent congruence.
2. Prove by induction on the derivation of `EqvGen R t u` that every generating step is reflected by same-class membership in the saturated e-graph.
3. Handle the congruence case by a separate theorem showing closure under typed application.
4. For soundness, induct on merge history.

**Why promising:** conceptually clean and closer to SMT congruence closure literature. Best if the existing `EqvGen` inductive structure is accessible.

### Strategy C: Universal algebra / initial algebra route
1. View terms as the free many-sorted algebra on the signature.
2. Show the e-graph same-class relation defines a congruence on the explored subalgebra.
3. Show rewrite saturation generates the least congruence containing the rewrite rules.
4. Identify this least congruence with `EqvGen`.

**Why promising:** deepest and most reusable. This route opens future work on algebraic semantics, but may require more infrastructure than this cycle permits.

**Recommended choice:** Start with **Strategy A**, use **Strategy B** for the key inductive reflection lemma, and reserve **Strategy C** as the conceptual framing in the paper.

## Deeper Mathematical Insight to Emphasize

The real conceptual point is:

> Congruence closure is not merely a data-structure operation; it computes the least compatible equivalence extending local rewrite evidence.

In a typed setting, this becomes subtler and more powerful:
- function symbols live over many sorts,
- only well-typed contexts are admissible,
- closure under application becomes a theorem about **many-sorted congruences**,
- and completeness requires saturation over typed parent contexts.

This is exactly where practical systems gain power and where current formalizations are usually weakest.

You should explicitly frame your development as a theorem about the **free many-sorted algebra modulo a convergent equational theory**.

For a convergent typed rewrite system `R` over a finite explored universe with `n` function symbols of maximum arity `k`, the incremental typed congruence closure algorithm reaches saturation with merge growth bounded empirically by a polynomial in `n^k`, and the final e-class partition coincides with the partition by rewrite normal forms.

### Computational test
For random typed signatures with:
- 3–10 function symbols,
- arities 0–3,
- multiple sorts,
- random convergent oriented rewrite systems,

generate 1000 systems per signature size and measure:
- total merge operations,
- total candidate parent checks,
- whether `sameClass` equals normal-form equivalence on the explored universe,
- empirical growth rate as signature complexity increases.

### Falsification criterion
Any explored instance where:
- the final e-graph misses an `EqvGen` equivalence witnessed by equal normal forms, or
- merge/candidate-check growth is clearly super-polynomial relative to the bounded-universe combinatorial baseline,

counts as evidence against the conjecture.
