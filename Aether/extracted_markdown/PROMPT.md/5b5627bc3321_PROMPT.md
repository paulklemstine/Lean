## Research Direction A: Circuit-Complexity-Aware Polynomial Identity Testing

### Breakthrough Goal

Formalize a theorem saying that if an algebraic circuit computes a nonzero polynomial, then the fraction of inputs on which it vanishes is bounded by a quantity controlled simultaneously by:

1. the polynomial degree,
2. the field size,
3. and, via certified degree bounds, the circuit’s multiplicative complexity.

This is the exact semantic–syntactic bridge needed before one can even dream of formal Kabanets–Impagliazzo style statements.

### Precise Theorem Statement

Assume:
- `K` is a finite field,
- `C : AlgCircuit K n`,
- `C.toMvPolynomial ≠ 0`,
- and we have available a theorem of the shape `bounded_circuit_degree_bound` controlling `C.toMvPolynomial.totalDegree` by a syntactic measure of `C`,
- together with `mulGates_lower_bound_from_degree` giving a converse lower bound.

Then prove a theorem of the following form.

```lean
theorem circuit_pit_soundness_degree
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (C : AlgCircuit K n)
    (hC : C.toMvPolynomial ≠ 0) :
    Fintype.card {x : Fin n → K // C.eval x = 0}
      ≤ C.toMvPolynomial.totalDegree * (Fintype.card K) ^ (n - 1)
```

Then strengthen it to a complexity-aware version:

```lean
theorem circuit_pit_soundness_mulGate
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (C : AlgCircuit K n)
    (hC : C.toMvPolynomial ≠ 0) :
    Fintype.card {x : Fin n → K // C.eval x = 0}
      ≤ boundedCircuitDegree C * (Fintype.card K) ^ (n - 1)
```

where `boundedCircuitDegree C` is the certified syntactic upper bound coming from the catalog theorem `bounded_circuit_degree_bound`.

And if `mulGates_lower_bound_from_degree` is available in the direction
`degree ≤ f(mulGates)` or equivalently `mulGates ≥ g(degree)`, extract a lower-bound corollary:

```lean
theorem many_zeros_force_mulGate_complexity
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (C : AlgCircuit K n)
    (hzeros :
      boundedCircuitDegree C * (Fintype.card K) ^ (n - 1)
        < Fintype.card {x : Fin n → K // C.eval x = 0}) :
    C.toMvPolynomial = 0
```

or, contrapositively, a lower bound on multiplicative complexity whenever the zero set is too large for the claimed circuit class.

### Why This Is a Breakthrough

This is not “just Schwartz–Zippel.” It is the first formally certified theorem connecting:
- **syntax**: multiplicative gate complexity,
- **semantics**: zero-set size / PIT soundness,
- **complexity theory**: lower bounds from derandomization heuristics.

A Lean theorem of this shape becomes the entry point for formal work on:
- black-box PIT,
- hitting sets,
- arithmetic circuit lower bounds,
- algebraic pseudorandomness,
- and eventually formal Kabanets–Impagliazzo implications.

### Lean 4 Formalization Target

You likely want a file in a bridge namespace, e.g.
`Bridges/AlgebraComplexityPIT/CircuitPITSoundness.lean`.

Core statement should use whichever of these is already defined:
- `AlgCircuit.eval`
- `AlgCircuit.toMvPolynomial`
- `MvPolynomial.totalDegree`

If `C.eval x = MvPolynomial.eval x C.toMvPolynomial` is not already a theorem, prove and exploit a compatibility lemma first:

```lean
theorem AlgCircuit.eval_eq_eval_toMvPolynomial
    {K : Type*} [CommSemiring K]
    {n : ℕ} (C : AlgCircuit K n) (x : Fin n → K) :
    C.eval x = MvPolynomial.eval x C.toMvPolynomial
```

That lemma is likely the true hinge.

### Proof Strategy 1: Reduce Completely to Multivariate Schwartz–Zippel
Most promising.

1. Prove `C.eval x = 0 ↔ MvPolynomial.eval x C.toMvPolynomial = 0`.
2. Invoke the existing polynomial zero-count theorem in Mathlib or derive it from the catalog theorem `polynomial_verification_bound`.
3. Replace the polynomial degree by the circuit-certified degree upper bound using `bounded_circuit_degree_bound`.

Why this is best: it minimizes bespoke circuit induction and turns the whole theorem into a transport result from semantic algebra to circuit syntax.

### Proof Strategy 2: Induction on Circuit Structure
Use only if the polynomial bridge is underdeveloped.

1. Define a recursive upper bound on the zero set under `+` and `*`.
2. Show multiplication increases degree additively and preserves nonzeroness constraints over a field.
3. Derive the global bound by structural induction and compare with the syntactic degree bound.

Why this is weaker: zero sets of sums are hard to control directly. This path is elegant only if the circuit API is much stronger than the polynomial API.

### Proof Strategy 3: Fiberwise Induction on the Number of Variables
Classical Schwartz–Zippel style.

1. View the multivariate polynomial as univariate in one variable with coefficients in `MvPolynomial`.
2. Bound, for each fixed assignment to `n-1` variables, the number of roots in the last variable by the degree.
3. Sum over all fibers.

Why this may be useful: if Mathlib’s exact zero-count theorem is unavailable, this proof is formalizable from first principles and gives a reusable library for finite-field counting arguments.

## Research Direction B: Polynomial Fingerprinting for Equality and Streaming Verification

### Breakthrough Goal

Formalize the algebraic fingerprinting principle: encode a bitstring as a polynomial, compare two strings by evaluating the difference polynomial at a random field point, and prove the soundness error is bounded by degree over field size.

This would create a formal bridge between:
- communication complexity,
- streaming algorithms,
- randomized verification,
- and algebraic identity testing.

### Precise Theorem Statement

Let a bitstring `s : Fin n → Fin 2` be encoded as
\[
p_s(X) = \sum_{i=0}^{n-1} s_i X^i.
\]
If `s₁ ≠ s₂`, then `p_{s₁} - p_{s₂}` is a nonzero polynomial of degree `< n`, hence has at most `n-1` roots over a field.

A clean Lean target is:

```lean
def bitPoly {K : Type*} [Semiring K] (s : Fin n → Fin 2) : Polynomial K := ...

theorem bitPoly_injective
    {K : Type*} [Semiring K] [Nontrivial K]
    {n : ℕ} :
    Function.Injective (bitPoly (K := K) (n := n))

theorem fingerprint_soundness
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (s₁ s₂ : Fin n → Fin 2)
    (hneq : s₁ ≠ s₂) :
    Fintype.card {x : K // bitPoly (K := K) s₁ x = bitPoly (K := K) s₂ x}
      ≤ n - 1
```

More probabilistic / PIT-facing version:

```lean
theorem fingerprint_error_probability_bound
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (s₁ s₂ : Fin n → Fin 2)
    (hneq : s₁ ≠ s₂) :
    Fintype.card {x : K // bitPoly (K := K) s₁ x = bitPoly (K := K) s₂ x}
      ≤ (n - 1) := by ...
```

and then derive the normalized probability statement informally or formally if a finite uniform probability space is already developed.

### Stronger Cross-Domain Variant

Generalize from equality testing of strings to equality testing of streamed vectors over any finite alphabet embedded in a field:

```lean
def vecPoly {K : Type*} [Semiring K] (a : Fin n → K) : Polynomial K := ...

theorem vecPoly_eval_collision_bound
    {K : Type*} [Field K] [Fintype K]
    {n : ℕ} (a b : Fin n → K)
    (hneq : a ≠ b) :
    Fintype.card {x : K // Polynomial.eval x (vecPoly a) = Polynomial.eval x (vecPoly b)}
      ≤ n - 1
```

This is the algebraic heart of Rabin–Karp style fingerprinting and streaming verification.

### Why This Is a Breakthrough

This opens a formally verified path from pure algebra to randomized algorithms:
- streaming equality,
- communication protocols,
- rolling hashes,
- low-memory verification,
- interactive proof primitives.

It is a foundational theorem that can seed an entire formal theory of **algorithmic algebraic randomness**.

### Proof Strategy 1: Difference Polynomial + Root Bound
Most promising.

1. Define `q = bitPoly s₁ - bitPoly s₂`.
2. Show `hneq` implies `q ≠ 0` using coefficient extensionality.
3. Apply the standard theorem that a nonzero univariate polynomial over a domain/field has at most `natDegree` roots.

This is the cleanest and closest to textbook fingerprinting.

### Proof Strategy 2: Injectivity First, Then Root Bound
1. Prove `bitPoly_injective`.
2. Conclude `s₁ ≠ s₂ → bitPoly s₁ ≠ bitPoly s₂`.
3. Apply root-count bound to the polynomial difference.

This modularizes the theory and gives a reusable encoding theorem.

### Proof Strategy 3: Build from `polynomial_verification_bound`
If the catalog theorem already states a suitable counting bound:

1. Re-express the difference fingerprint test as an instance of `polynomial_verification_bound`.
2. Verify the degree hypothesis mechanically.
3. Specialize to string-encoding polynomials.

This is ideal if `Bridges/SpectralApplications.lean` already contains a finite-field verification lemma with the right shape.
