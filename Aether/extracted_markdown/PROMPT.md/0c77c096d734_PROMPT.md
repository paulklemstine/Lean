## Assignment: EML Single Operator Church–Turing Thesis

**Mode:** `prove` + `discover`

You are not being asked for a cosmetic extension of existing EML lemmas. You are being asked to carve out a mathematically serious fragment of a real-analytic Church–Turing thesis for a single nonlinear primitive. The central object is the EML operator
\[
\mathrm{eml}(a,b) := e^a \log b,
\]
or the equivalent normalized form already present in the catalog if that is how the library defines `eml`. Your task is to isolate and prove **nontrivial universality theorems for expressive closure classes generated by `exp`, `log`, constants, and field operations**, then connect that closure to computation, analytic differential equations, and representation of classical elementary functions.

The slogan is bold but precise:

> A single `exp ∘ log` interaction, when compositionalized with field operations, may already generate the entire elementary real calculus.

This is not the full Church–Turing thesis over reals yet. But if you can prove a mathematically robust elementary-fragment universality theorem with verified closure properties, normal forms, and constructive compilation, it opens a new field: **operator minimality for analog computation**.

## Core Research Objective

Define a formally verified class of functions generated from the primitives:
- constants in `ℝ`
- coordinate projections
- addition, subtraction, multiplication, division
- `Real.exp`
- `Real.log`
- and optionally the binary primitive `eml`

Then prove that broad families of classical functions belong to this class, and that this class admits a **finite compositional normal form**.

The deep scientific question is:

> How small can a generating set of analytic primitives be while still expressing all elementary real functions?

Your formal target should not be the impossible-in-one-cycle claim “every computable real function.” Instead, establish a decisive theorem for the **elementary closure fragment**, with a roadmap toward computable analysis.

### Theorem 3: Explicit compilation through `eml`

Now exploit the catalog theorem
- `eml_log_exp : eml (log a) (exp b) = a - b`
and related involution/gap lemmas.

Use these to prove that subtraction, and then more elaborate operations, can be implemented via `eml` in controlled ways.

A strong target:

**Mathematical statement.**  
On the positive domain, multiplication by logarithmic coding and subtraction by `eml` yields a compositional compiler from a fragment of elementary expressions to expressions using only constants, field operations, and `eml`.

For a first-cycle theorem, make this precise for a subclass such as expressions built from:
- constants
- variables constrained to positive values
- multiplication/division
- `exp`, `log`
- subtraction encoded by `eml`

**Lean-style theorem sketch:**
```lean
theorem positive_elementary_compiles_to_eml
  {n : ℕ} :
  ∀ e : PositiveExpr n, ∃ c : EMLOnlyExpr n,
    ∀ x, PositiveEnv x → evalPositiveExpr e x = evalEMLOnlyExpr c x := by
```

If full compilation is too ambitious, prove a **normal-form theorem**:

```lean
theorem elementary_expr_has_eml_normal_form
  {n : ℕ} (e : EMLExpr) :
  ∃ e' : EMLNormalForm n, ∀ x, eval e x = evalNormalForm e' x := by
```

**Why this matters.**  
This is the breakthrough theorem. It says `eml` is not merely present in a language containing `exp` and `log`; it can act as a **compilation target**. That is the right formal shadow of a single-operator universality thesis.

## Strong Optional Theorem 4: Differential closure / ODE connection

This is your cross-domain bridge to dynamical systems and analog computation.

**Mathematical statement.**  
If `f` is EML-representable and differentiable on a domain where all logs are well-defined, then its derivative is again definable in the differential field generated by `exp`, `log`, and rational operations.

A fully formal differential-algebra theorem may be too heavy, but even a verified theorem for explicit examples is powerful:

```lean
theorem deriv_eml_log_exp
  {a b : ℝ → ℝ}
  (ha : Differentiable ℝ a) (hb : Differentiable ℝ b)
  (hpos : ∀ x, 0 < b x) :
  HasDerivAt (fun x => Real.exp (a x) * Real.log (b x))
    ((Real.exp (a x)) * (deriv a x) * Real.log (b x) +
      Real.exp (a x) * (deriv b x / b x)) x := by
```

Even better, package a closure statement for differentiable EML terms.

**Why this matters.**  
This connects EML expressibility to **Shannon GPAC / analog computation**, differential algebra, and neural ODEs. If EML-generated functions are stable under differentiation, then the operator is not just expressive statically but dynamically.

**Why promising:**  
This turns “representation” into “computational physics.” It links EML to analog models of computation, control, and continuous-time learning.
