# Assignment: EML Category — The Category of EML-Computable Maps

Aristotle, do not settle for the toy statement “closure under composition.” That is merely the entrance fee. The real objective is to isolate a mathematically meaningful fragment of real computation generated by `exp`, `log`, affine operations, multiplication, and constants, and then prove that this fragment supports universal constructions strong enough to function as a semantic category of analytic computation. If successful, this is not just “another closure theorem”: it is a blueprint for a categorical semantics of exponential-logarithmic computation, with direct consequences for differentiable programming, o-minimal geometry, and the algebra of symbolic models.

Your mission is to define a genuinely new formal structure capturing *EML-definable maps of finite arity*, then prove at least three nontrivial theorems establishing that this structure behaves categorically and analytically in a way that existing catalog results do not already cover.

## Core formalization target

The existing catalog theorem

  `eml_closure_closed_under_comp (A : Set (ℝ → ℝ))`

gives you a certified one-variable composition closure principle. Build on it, but do **not** remain in unary land. The breakthrough is to lift the closure logic from unary generators to finite-product semantics.

Define a new inductive or syntactic-semantic notion of multivariate EML computability. A strong target is:

```lean
def EMLMap (n m : ℕ) : Type := {f : (Fin n → ℝ) → (Fin m → ℝ) // EMLComputable f}
```

where `EMLComputable` is your new predicate generated by:
- coordinate projections,
- constants,
- pointwise addition and multiplication,
- pointwise `Real.exp`,
- pointwise `Real.log` on a positivity-restricted sublanguage or on a bundled domain,
- tupling / vector assembly,
- composition.

If unrestricted `log : ℝ → ℝ` becomes technically awkward in Lean because of domain subtleties, then define a *positive-input fragment* first. This is mathematically stronger than it sounds: it isolates the genuinely exponential-logarithmic part and aligns with the theorem `power_via_exp_log` in `FINAL/EML/ExtendedTheory.lean`.

A clean foundational object would be a bundled domain:


and then define EML maps either on `Fin n → ℝ` without log, or on `PosVec n` with log available.

## Precise theorem targets

You must prove at least 3 deep theorems. Here is the recommended theorem suite.

### Theorem 1: Product stability / finite-product semantics

Prove that EML-computable maps are closed under pairing, yielding a category with finite products.

Suggested Lean target:

```lean
theorem emlComputable_pair
  {n m k : ℕ}
  {f : (Fin n → ℝ) → (Fin m → ℝ)}
  {g : (Fin n → ℝ) → (Fin k → ℝ)}
  (hf : EMLComputable f) (hg : EMLComputable g) :
  EMLComputable (fun x : Fin n → ℝ =>
    Sum.elim (fun i => f x i) (fun j => g x j) : Fin (m + k) → ℝ)
```

or, if you package products explicitly:

```lean
theorem emlComputable_prod_mk
  {α β γ : Type}
  {f : α → β} {g : α → γ}
  (hf : EMLComputable f) (hg : EMLComputable g) :
  EMLComputable (fun x => (f x, g x))
```

Why this matters: this is the first genuinely categorical theorem. It upgrades “a class of formulas” into a semantic universe with product structure, making EML maps compositional in the same sense as circuits, probabilistic programs, and neural architectures.

### Theorem 2: Coordinatewise exponentiation yields EML-definable power laws

Build on `FINAL/EML/ExtendedTheory.lean::power_via_exp_log` and prove a multivariate closure theorem showing that positive-coordinate monomials are EML-computable.

Suggested theorem:

```lean
theorem emlComputable_weightedGeomMean
  {n : ℕ} (w : Fin n → ℝ) :
  EMLComputable (fun x : PosVec n =>
    Real.exp (∑ i, w i * Real.log (x.toFun i)))
```

and then derive, for positive scalar input:

```lean
theorem emlComputable_realPower
  (a : ℝ) (ha : 0 < a) :
  EMLComputable (fun b : ℝ => a ^ b)
```

if you choose a notion of computability broad enough to include parameters/constants, or instead the two-variable version:

```lean
theorem emlComputable_pow_pos :
  EMLComputable (fun p : {ab : ℝ × ℝ // 0 < ab.1} =>
    let a := p.1.1
    let b := p.1.2
    a ^ b)
```

using `power_via_exp_log`.

Why this matters: it shows that the category is not just syntactically closed but expressive enough to internalize nonlinear scaling laws, geometric means, and multiplicative statistics. This connects EML semantics to information geometry, multiplicative optimization, and log-linear statistical models.

### Theorem 3: A nontrivial cross-domain theorem — EML maps preserve semialgebraic-analytic structure in a logarithmic chart

You need one theorem that reaches outside category theory. The strongest accessible cross-domain bridge is to convexity / information geometry / dynamical systems via log-coordinates.

Define a class of *log-affine* maps on positive domains:

```lean
def LogAffine (n : ℕ) (f : PosVec n → ℝ) : Prop :=
  ∃ w : Fin n → ℝ, ∃ c : ℝ,
    ∀ x, f x = Real.exp (∑ i, w i * Real.log (x.toFun i) + c)
```

Then prove:

```lean
theorem logAffine_mul_closed
  {n : ℕ} {f g : PosVec n → ℝ}
  (hf : LogAffine n f) (hg : LogAffine n g) :
  LogAffine n (fun x => f x * g x)
```

and ideally:

```lean
theorem logAffine_becomes_affine_in_log_chart
  {n : ℕ} {f : PosVec n → ℝ}
  (hf : LogAffine n f) :
  ∃ w : Fin n → ℝ, ∃ c : ℝ,
    ∀ x, Real.log (f x) = ∑ i, w i * Real.log (x.toFun i) + c
```

under the positivity needed to simplify `log (exp y)` and `log (f x)`.

Why this is a breakthrough: this theorem identifies a multiplicative fragment of EML computation with affine geometry in logarithmic coordinates. That is a precise bridge from analytic computation to convex analysis, tropicalization heuristics, chemical reaction network scaling laws, and statistical mechanics partition functions.

### Theorem 4 (optional but visionary): Partial Cartesian closure for parameterized families

Do **not** overclaim full Cartesian closure for all finite-dimensional Euclidean spaces unless you can formalize a genuine internal hom object. In finite dimensions, the exponential object `R^n ⇒ R^m` generally cannot be represented again as `R^k` for unrestricted function spaces. The right move is to prove a *parameterized closure theorem* that captures what your framing called “currying via EML parameter sharing.”

Define a family-coded internal hom:

```lean
def EMLFamily (p n m : ℕ) :=
  (Fin p → ℝ) → (Fin n → ℝ) → (Fin m → ℝ)
```

and prove a currying equivalence at the level of computability:

```lean
theorem emlComputable_curry
  {p n m : ℕ}
  {f : (Fin (p + n) → ℝ) → (Fin m → ℝ)}
  (hf : EMLComputable f) :
  EMLComputable
    (fun θ : Fin p → ℝ =>
      fun x : Fin n → ℝ =>
        f (sumElim θ x))
```

together with an uncurry theorem. If full higher-order codomain typing is inconvenient, formulate this as an equivalence between “EML-computable with parameters” and “EML-computable on the combined input space.”

This is the mathematically correct replacement for the naive Cartesian closed conjecture. It still opens the door to semantics of trainable models and differentiable program families.

## Proof strategy architecture

### Strategy A: Inductive syntax-first semantics
Most promising.

1. Define scalar EML expressions inductively.
2. Interpret them semantically as functions on `Fin n → ℝ` or `PosVec n`.
3. Define vector-valued maps coordinatewise.
4. Prove closure theorems by induction on derivations, using `rcases` on constructors and multi-step `calc`.
5. Import unary closure facts from `FINAL/EML/ClosureOperator.lean` when reducing coordinatewise composition to unary generators.

Why this is best: Lean likes inductive predicates. It gives you exact control over what “computable by finite EML compositions” means, and every closure theorem becomes a structural induction theorem rather than an ad hoc semantic argument.

### Strategy B: Generated closure operator on function classes
Potentially elegant, but technically heavier.

1. Define the smallest set of scalar/vector functions closed under generators and operations.
2. Use lattice-theoretic arguments to prove least fixed-point closure.
3. Lift existing theorem `eml_closure_closed_under_comp` from unary maps to coordinatewise maps by embedding each coordinate as a unary term with frozen parameters.
4. Derive category laws as closure facts of the generated class.

Why it may be powerful: if successful, this produces a reusable closure algebra for future EML projects. Why it is harder: multivariate closure operators over dependent function spaces are more cumbersome in Lean than inductive predicates.

### Strategy C: Positive-domain logarithmic chart
Best for the cross-domain theorem.

1. Work on `PosVec n`.
2. Encode multiplicative formulas via additive formulas in log-coordinates.
3. Use `power_via_exp_log` from `FINAL/EML/ExtendedTheory.lean` to convert powers into `exp ∘ log`.
4. Prove weighted geometric mean and log-affine closure theorems with `field_simp`, `ring_nf`, and `calc` chains around `Real.log_mul`, `Real.log_rpow`, `Real.exp_add`.

Why this matters: this route reveals the hidden affine geometry of EML maps and yields the strongest “unexpected connection” theorem.

## What not to claim naively

Do **not** simply assert “`EML_Comp` is Cartesian closed with natural numbers object `ℝ`.” That statement is mathematically suspect in the finite-dimensional setting. If you want a bold conjecture, formulate it in a corrected and falsifiable way:

### Testable conjecture
**Conjecture (parameterized weak Cartesian closure).**
For every `n m`, there exists a natural number `p = p(n,m,k)` such that every EML-computable family
`(Fin k → ℝ) → ((Fin n → ℝ) → (Fin m → ℝ))`
is representable by an EML-computable map on combined input coordinates, and conversely every such combined-input map admits a computable currying operation preserving EML-definability.

This is falsifiable:
- implement a syntactic enumerator for bounded-depth EML expressions,
- test whether currying/uncurrying preserves definability and size bounds,
- search for minimal parameter dimensions needed to encode bounded-depth families.

A second sharper conjecture:

**Conjecture (log-affine normal form for multiplicative positive fragment).**
Every positive-fragment scalar EML expression built without addition is equivalent to
`x ↦ exp(∑ i w_i log x_i + c)`.
This can be computationally falsified by expression enumeration and symbolic normalization.
