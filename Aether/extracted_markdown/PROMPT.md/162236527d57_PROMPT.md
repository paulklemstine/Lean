## Assignment: Proof-Complexity Order Parameters from Persistence of Dependency Hypergraphs

**Mode:** discover / prove / formalize

You should treat this as the opening move of a new field: a **topological theory of proof complexity** in which proof traces are not merely syntactic objects but evolving geometric-combinatorial structures whose persistent features detect computational hardness. The goal is not to repackage existing SAT/PH folklore. The goal is to isolate a formally verified invariant that behaves like an **order parameter** for proof complexity phase transitions.

Prove new, non-trivial theorems. Build on catalog theorems where available for finite hypergraphs, simplicial complexes, filtrations, persistent invariants, finite combinatorics, and graph/path-width style complexity surrogates. Minimize sorry.

## Central Vision

Given a successful proof trace for a theorem, clause set, or tactic execution, form a **dependency hypergraph**:
- vertices = goals / lemmas / clauses / derived facts,
- hyperedges = dependency relations used in each inference,
- filtration parameter = confidence score, clause width, tactic cost, derivation depth, or timestamp.

From this filtered object, derive a simplicial complex (for example, the downward closure of hyperedges, a nerve of dependency neighborhoods, or a line/interaction complex), and define a computable persistence statistic. The thesis is:

> there exists a topological observable of proof traces whose behavior changes sharply when proof complexity crosses from easy to hard regimes.

This would be a breakthrough because it would create:
- a **structural science of theorem-proving hardness**,
- a mathematically principled basis for **adaptive prover control**,
- a bridge between **proof complexity, topological data analysis, and automated reasoning**,
- a route toward **machine-independent hardness diagnostics**.

This is not just about benchmarking. It is about identifying a mathematically canonical invariant analogous to magnetization in statistical mechanics or Betti transitions in random topology.

### New definitions to introduce

A promising minimal core:

```lean
/-- A weighted dependency hypergraph on a finite vertex type. -/
structure WeightedDepHypergraph (V : Type _) [Fintype V] where
  Edge : Type _
  verts : Edge → Finset V
  weight : Edge → ℕ
  nonempty_verts : ∀ e, (verts e).Nonempty

/-- The filtration subhypergraph consisting of edges of weight at most `k`. -/
def WeightedDepHypergraph.trunc (H : WeightedDepHypergraph V) (k : ℕ) :
    WeightedDepHypergraph V := ...

/-- The simplicial support at scale `k`: all finite subsets contained in some
truncated hyperedge. -/
def WeightedDepHypergraph.supportComplex
    (H : WeightedDepHypergraph V) (k : ℕ) : Finset (Finset V) := ...

/-- The first scale at which two vertices become co-supported by some hyperedge. -/
def WeightedDepHypergraph.codependencyTime
    (H : WeightedDepHypergraph V) (u v : V) : ℕ := ...

/-- A proof-width surrogate: maximal cardinality of an active truncated hyperedge. -/
def WeightedDepHypergraph.widthAt (H : WeightedDepHypergraph V) (k : ℕ) : ℕ := ...

/-- A topological hardness proxy extracted from the filtration. -/
def WeightedDepHypergraph.betaGap
    (H : WeightedDepHypergraph V) (k : ℕ) : ℤ := ...
```

You may replace `supportComplex` by a nerve or clique complex if that integrates better with Mathlib. The point is to define a **filtered combinatorial-topological object** attached to proof dependencies.

## Exact Theorem Program

You must prove at least 3 substantial theorems. Here is a recommended core trio.

### Theorem 1: Monotonicity of filtered support and induced persistence surrogate

This is the foundational theorem that makes the object a filtration rather than a bag of snapshots.

**Mathematical statement**

For every weighted dependency hypergraph `H`, if `k ≤ l`, then every simplex present at scale `k` is present at scale `l`. Consequently, any monotone complexity statistic extracted from the support complex is monotone along the filtration.

**Lean 4 type signature sketch**
```lean
theorem supportComplex_mono
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) {k l : ℕ} (hkl : k ≤ l) :
    H.supportComplex k ⊆ H.supportComplex l := ...
```

If you formalize a numeric invariant:
```lean
theorem widthAt_mono
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) {k l : ℕ} (hkl : k ≤ l) :
    H.widthAt k ≤ H.widthAt l := ...
```

**Why this matters**
This is the first nontrivial certification that proof traces naturally carry a filtered topological structure. Without this, “persistent proof topology” is only metaphor.

---

### Theorem 2: Width lower bound from topological co-dependency obstruction

This should be your first genuinely new hardness theorem. The ideal shape is: if the support complex exhibits a nontrivial obstruction, then some proof-width surrogate must be large.

A robust formal version, achievable without full homology machinery if needed:

**Mathematical statement**

Suppose `u` and `v` are vertices that first become jointly supported only at scale `t = codependencyTime H u v`. Then every scale `k < t` fails to contain any simplex containing both `u` and `v`, while at scale `t` such a simplex exists. Hence any derivation whose success requires co-dependency of `u` and `v` must incur width at least `2` at scale `t`, and more generally at least the minimal size of a simplex witnessing the co-dependency event.

**Lean 4 type signature sketch**
```lean
theorem no_pair_before_codependencyTime
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (u v : V) {k : ℕ}
    (hk : k < H.codependencyTime u v) :
    {u, v} ∉ H.supportComplex k := ...

theorem pair_enters_at_codependencyTime
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (u v : V) :
    {u, v} ∈ H.supportComplex (H.codependencyTime u v) := ...

theorem width_lower_bound_of_pair_entry
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (u v : V) :
    2 ≤ H.widthAt (H.codependencyTime u v) := ...
```

**Why this matters**
This is the first theorem turning a persistence event into a lower bound on a complexity surrogate. It is the seed of the whole program: topological events forcing combinatorial complexity.

### Theorem 3: Helly-type or nerve-type collapse criterion implying easy regime

You need a theorem in the opposite direction: a structural condition under which the topology is simple and the complexity surrogate remains controlled.

A strong and elegant target:

**Mathematical statement**

If every truncated hyperedge family at scale `k` has a common vertex (or satisfies a suitable Helly/intersection property), then the support complex at scale `k` is a cone, hence topologically contractible; in particular the first obstruction statistic vanishes, and the complexity surrogate `betaGap H k` is zero (or bounded by a trivial constant).

**Lean 4 type signature sketch**
```lean
def IsConeAt
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (k : ℕ) : Prop :=
    ∃ apex : V, ∀ σ ∈ H.supportComplex k, apex ∈ σ ∨ insert apex σ ∈ H.supportComplex k

theorem isConeAt_of_common_vertex
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (k : ℕ)
    (h : ∃ a : V, ∀ e, H.weight e ≤ k → a ∈ H.verts e) :
    H.IsConeAt k := ...

theorem betaGap_eq_zero_of_isConeAt
    {V : Type _} [DecidableEq V] [Fintype V]
    (H : WeightedDepHypergraph V) (k : ℕ)
    (hcone : H.IsConeAt k) :
    H.betaGap k = 0 := ...
```

If full contractibility/homology is too heavy, define `betaGap` combinatorially so that conicality forces vanishing. The theorem must still be mathematically meaningful.

**Why this matters**
This gives a certified “easy regime”: proofs whose dependency geometry collapses around a common hub cannot exhibit the same kind of topological hardness. That is already a nontrivial classifier.

## Proof Strategy Architecture

You must not rely on one proof path. Develop at least 2–3 viable routes and choose the strongest.

### Strategy A: Finset / hyperedge combinatorics first
Most promising for Lean implementation.

1. Define the filtration purely combinatorially via `Finset`.
2. Prove monotonicity and entry-time lemmas by unpacking minimality of `codependencyTime`.
3. Define `betaGap` as a combinatorial obstruction statistic: e.g. number of pair-entry events not explained by conical extension, or an Euler-characteristic-like defect on the support complex.
4. Prove easy-regime vanishing under cone/common-apex hypotheses.

**Why promising:** avoids heavy homology infrastructure while still producing meaningful “persistent topology” theorems.

### Strategy B: Nerve-theorem-inspired route
More visionary, stronger if Mathlib support suffices.

1. Regard each truncated hyperedge as a cover element.
2. Build the nerve complex of the family of active hyperedges.
3. Use intersection conditions to prove contractibility or nontrivial cycles in the nerve.
4. Translate nerve features into width/codependency lower bounds.

**Why promising:** connects directly to topological data analysis and gives canonical cross-domain interpretation. Harder to formalize, but more conceptually revolutionary.

### Strategy C: Graph-theoretic reduction to treewidth/pathwidth surrogates
Best for complexity-theoretic impact.

1. Replace each hypergraph by an incidence graph or 2-section graph.
2. Define filtered clique or neighborhood complexes.
3. Use known graph-width inequalities to prove that nontrivial topology forces large separators / width.
4. Interpret width as a lower bound on proof search coordination cost.

**Why promising:** opens a bridge to proof complexity proper, because width/pathwidth/treewidth already interact with resolution and SAT hardness.

**Recommendation:** start with Strategy A to secure core theorems, then use Strategy C for the cross-domain hardness connection. Strategy B is the highest-upside extension.

## Cross-Domain Connections You Should Explicitly Exploit

### 1. Proof complexity ↔ topological data analysis
Persistent features of dependency filtrations are to proofs what persistent cycles are to noisy data clouds: stable structural signatures surviving local perturbations. Formalize this analogy, not just rhetorically but theorem-by-theorem.

### 2. Automated reasoning ↔ statistical mechanics
The conjectured sharp threshold is a **phase transition**. `betaGap` is an order parameter. Easy proofs correspond to topologically collapsed phases; hard proofs correspond to emergence of robust mesoscale cycles/obstructions. This language suggests finite-size scaling experiments in `demo.py`.

### 3. Hypergraph topology ↔ algorithm design
If `betaGap` or `codependencyTime` predicts hardness early, one can adapt tactics:
- restart before topological obstruction forms,
- switch to width-oriented search when pair-entry time spikes,
- compress derivations in conical regimes.

### 4. Simplicial topology ↔ learning theory
A learned prover may implicitly estimate proof hardness. Your invariant could serve as an interpretable feature, connecting formal proof traces to explainable ML.

### 5. SAT / resolution ↔ Lean tactic traces
Even if the formal theorem is stated for abstract weighted dependency hypergraphs, the scientific narrative must explain how the same object models:
- resolution derivations,
- CDCL implication graphs,
- Lean tactic dependency trees,
- completion/rewriting traces.

## Benchmark Family Suggestions

Choose at least one infinite family formalizable in Lean.

### Option 1: Layered overlap family
Vertices are indexed by layers; hyperedges join local windows with a tunable overlap parameter. Low overlap gives cone-like behavior; high overlap creates delayed but abrupt co-dependency events.

### Option 2: Resolution-inspired clause family
Synthetic clause-dependency hypergraphs where edge weight = clause width or derivation depth. This is closest to proof complexity.

Use graph edges as 2-uniform hyperedges and activate them by time. Then the support complex is graph-like and first-cycle formation can be proved exactly. This is the cleanest path to a genuine theorem with topological meaning.

Recommendation: start with Option 3 for one complete theorem stack, then lift to hypergraphs.
