## Central Theorem Target

Let `κ(C)` denote the compression number / minimal cardinality of a Yoneda-separating family of probes for a finite category `C`.

### Breakthrough theorem statement

For finite categories `C, D`, prove a product upper bound of the form

\[
\forall C D,\quad \kappa(C \times D) \le \kappa(C)\cdot |Ob(D)| + \kappa(D)\cdot |Ob(C)|.
\]

This is the first serious candidate for a **composition law** for `κ`. If true, it shows that `κ` is neither a raw dimension nor a crude rank, but a probe-covering complexity that scales linearly with objectwise replication across factors.

### Lean 4 formalization target

You should adapt the exact names to the catalog API, but the theorem should be formalized at approximately this level of precision:

```lean
theorem compressionNumber_prod_le
  (C D : FiniteCategory)
  :
  CompressionNumber (prodCategory C D)
    ≤ CompressionNumber C * Fintype.card C.Obj
      + CompressionNumber D * Fintype.card D.Obj
```

If the catalog encodes finite categories as a typeclass rather than a structure, then produce the corresponding theorem in that idiom, e.g.

```lean
theorem compressionNumber_prod_le
  (C D : Type*)
  [SmallCategory C] [Fintype C]
  [SmallCategory D] [Fintype D]
  [DecidableEq C] [DecidableEq D]
  :
  CompressionNumber (C × D)
    ≤ CompressionNumber C * Fintype.card D
      + CompressionNumber D * Fintype.card C
```

The exact signature may need to use the catalog’s preferred notion of “finite category,” but the quantified theorem must be present.

## Required Theorem Suite

### Theorem 1: Product upper bound for κ
This is the flagship theorem.

**Mathematical statement**
\[
\kappa(C\times D)\le \kappa(C)\,|Ob(D)|+\kappa(D)\,|Ob(C)|.
\]

**Conceptual content**
A separating family for `C × D` can be assembled by:
- replicating each `C`-probe across every object of `D`, and
- replicating each `D`-probe across every object of `C`.

This is a categorical covering-design statement: one family catches differences in the first coordinate, the other catches differences in the second.

### Theorem 2: Thin-factor exact formula
Formalize and prove a sharp specialization.

**Mathematical statement**
If `C` is thin, then under suitable nondegeneracy hypotheses on `D`,
\[
\kappa(C\times D)=\kappa(D)\cdot |Ob(C)|.
\]

At minimum, prove the upper bound and a matching lower bound under explicit hypotheses strong enough to make the proof go through. If the full conjectured equality is too ambitious in one pass, isolate the exact obstruction and prove the strongest correct theorem.

A precise Lean target could look like:

```lean
theorem compressionNumber_prod_thin_left
  (C D : FiniteCategory)
  (hCthin : IsThinCategory C)
  :
  CompressionNumber (prodCategory C D)
    ≤ CompressionNumber D * Fintype.card C.Obj
```

and, if possible,

```lean
theorem compressionNumber_prod_thin_left_eq
  (C D : FiniteCategory)
  (hCthin : IsThinCategory C)
  (hD : NonThinWitness D) :
  CompressionNumber (prodCategory C D)
    = CompressionNumber D * Fintype.card C.Obj
```

where `NonThinWitness D` is a new definition you introduce capturing the existence of a genuinely parallel pair in `D` that must be separated.

### Theorem 3: Refutation of max-law by infinite family
Do not stop at a single counterexample. Prove a **family theorem** showing `max` is structurally wrong.

**Mathematical statement**
Construct a family of finite categories `P_n` and `E_m` (or use catalog-defined examples like `ParallelArrows n` and `Discrete m`) such that
\[
\kappa(P_n \times E_m) > \max(\kappa(P_n), \kappa(E_m))
\]
for all appropriate parameters, e.g. `m ≥ 2`.

A Lean target could be:

```lean
theorem compressionNumber_prod_gt_max_family
  (n m : ℕ) (hm : 2 ≤ m) :
  max (CompressionNumber (ParallelArrows n)) (CompressionNumber (DiscreteCat m))
    < CompressionNumber ((ParallelArrows n) × (DiscreteCat m))
```

If the exact family above is not supported by existing catalog objects, define a formal family that is.

This theorem is important because it shows `κ` is not rank-like. It rules out an entire class of simplistic structural heuristics.

## New Definitions You Must Introduce

You are required to define at least one genuinely new concept not already in the catalog. Recommended definitions:

### 1. Fiberwise probe lift
A construction that turns a separating family in one factor into a family in the product by placing it over every object of the other factor.

Example Lean-style skeleton:

```lean
def LiftLeftProbes
  (S : Finset C.Obj) (D : FiniteCategory) :
  Finset (ProdCategory C D).Obj := ...
```

and similarly `LiftRightProbes`.

This should not be a mere convenience alias: it should encapsulate the mechanism behind the product inequality.

### 2. Non-thin witness
A structure encoding the existence of a genuine parallel pair.

```lean
structure NonThinWitness (C : FiniteCategory) : Prop where
  X Y : C.Obj
  f g : X ⟶ Y
  hneq : f ≠ g
```

This lets you state lower-bound theorems cleanly and test hypotheses computationally.

### 3. Coordinate-separating family
A family in `C × D` designed to separate morphisms by one coordinate only.

```lean
def CoordinateSeparatingLeft (S : Finset (ProdCategory C D).Obj) : Prop := ...
def CoordinateSeparatingRight (S : Finset (ProdCategory C D).Obj) : Prop := ...
```

This concept could be the key intermediate abstraction making the proof modular.

## Proof Strategy Architecture

You must present and pursue at least 2-3 proof routes, even if one becomes primary.

### Strategy A: Explicit lifted-probe construction via Yoneda separation
**Most promising.**

1. Start with minimal or arbitrary Yoneda-separating families `SC` for `C` and `SD` for `D`.
2. Lift `SC` to product probes by pairing each probe object `Qc ∈ SC` with every object `d ∈ D`.
3. Lift `SD` symmetrically by pairing each `Qd ∈ SD` with every object `c ∈ C`.
4. Prove the union is Yoneda-separating in `C × D`:
   - for a parallel pair `((f₁,f₂),(g₁,g₂))`, use `Prod.ext`/componentwise decomposition;
   - if `f₁ ≠ g₁`, use a left-lifted probe;
   - if `f₂ ≠ g₂`, use a right-lifted probe;
   - if both differ, either side suffices.
5. Conclude cardinality bound by counting the two lifted families.

Why this is strongest: it matches the operational meaning of `κ` directly and should align best with catalog lemmas around `YonedaSeparating`.

### Strategy B: Hypergraph/covering reformulation
This is conceptually deeper and may yield stronger corollaries.

1. Model each parallel pair of morphisms in `C` as a “distinguishability demand.”
2. A probe object covers a demand if postcomposition separates the pair.
3. In `C × D`, demands decompose into left-coordinate demands and right-coordinate demands.
4. Show the demand hypergraph of the product embeds into the union of two replicated hypergraphs:
   \[
   \mathcal H_{C\times D} \subseteq (\mathcal H_C \wr Ob(D)) \cup (\mathcal H_D \wr Ob(C)).
   \]
5. Deduce the covering-number inequality.

Why this matters: it connects `κ` to extremal combinatorics and may suggest sharper bounds, asymptotics, and approximation algorithms.

### Strategy C: Information-theoretic interpretation
This is the most speculative but potentially revolutionary.

1. Treat a probe family as a deterministic observation scheme distinguishing morphism channels.
2. Product categories correspond to product channels.
3. The inequality becomes a subadditivity law for observation complexity under tensorized experiments.
4. Use this interpretation to motivate lower bounds and to formulate conjectures about optimality and independence.

Why pursue it: even if not needed for the main formal proof, this language can guide the paper and future directions, especially around channel capacity and distinguishability.

## Cross-Domain Connections You Must Make Explicit

This project becomes field-opening only if you articulate that `κ` is not just a category-theoretic curiosity.

### 1. Combinatorics: covering designs and hitting sets
A Yoneda-separating family is a hitting set for distinguishability constraints. The product theorem is a categorical analogue of a product bound for covering numbers. This suggests approximation algorithms, lower bounds, and extremal constructions.

### 2. Information theory: observation complexity / channel discrimination
Parallel morphisms are hypotheses; probes are experiments; postcomposition is readout. Then `κ` measures the minimal number of experiments needed to distinguish all hypotheses. The product bound resembles a subadditivity law for composite systems.

### 3. Theoretical computer science: compositional complexity
If `κ` admits efficient product laws, then one can compute or bound complexity for large categories built from small components. This is analogous to circuit complexity under composition, communication complexity under product inputs, or state complexity of automata products.

### 4. Physics-inspired viewpoint: composite systems and observables
In a product system, observables lifted from one subsystem and replicated over the other already suffice to distinguish many joint states. This is the categorical shadow of locality of observables in composite physical systems.

**Application keywords:** categorical complexity, product categories, Yoneda separation, covering designs, hitting sets, channel discrimination, compositional invariants, finite categories, information complexity, observable complexity.

If `C` is thin and `D` has a non-thin witness, then

\kappa(C\times D)=|Ob(C)|\kappa(D).

\[
\kappa(C_n\times D_n)
\sim \kappa(C_n)|Ob(D_n)|+\kappa(D_n)|Ob(C_n)|.

**Test:** Evaluate explicit families such as repeated parallel-arrow constructions or poset/product hybrids.

### Conjecture C: Hypergraph equality criterion

**Test:** For all small categories up to 4 objects, enumerate optimal separating families and check decomposability.

### Conjecture D: Information bottleneck phenomenon
There exist categories with large `|Ob|` but small `κ`, and their products exhibit a phase transition where the upper bound is very loose.

**Test:** Search over sparse categories with many objects but few nontrivial parallel pairs.
