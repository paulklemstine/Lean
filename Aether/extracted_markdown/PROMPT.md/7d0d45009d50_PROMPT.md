## Core Formalization Target

Define a robust notion of planar point configuration in general position, ordered by increasing `x`-coordinate, and develop the combinatorics of cups and caps.

### New definitions required

You must introduce at least one genuinely new definition not already in the catalog. Recommended definitions:

1. `GeneralPosition`
   - no three points are collinear.

2. `XStrict`
   - the points are indexed in strictly increasing `x`-coordinate order.

3. `IsCup` / `IsCap`
   - a finite indexed configuration has strictly increasing / strictly decreasing adjacent slopes, or equivalently consistent orientation inequalities.

4. `ConvexChainSignature`
   - a new extremal combinatorial invariant encoding the longest cup and cap lengths through each point. This is the most important new concept: it should be designed so that injectivity or counting arguments yield Erdős–Szekeres-type bounds.

This last definition is where the real originality should live.

Possible Lean-style sketches:

```lean
def Point := ℝ × ℝ

def xCoord (p : Point) : ℝ := p.1
def yCoord (p : Point) : ℝ := p.2

def GeneralPosition (p : Fin N → Point) : Prop :=
  ∀ ⦃i j k : Fin N⦄, i ≠ j → j ≠ k → i ≠ k →
    ((xCoord (p j) - xCoord (p i)) * (yCoord (p k) - yCoord (p i)) ≠
     (xCoord (p k) - xCoord (p i)) * (yCoord (p j) - yCoord (p i)))

def XStrict (p : Fin N → Point) : Prop :=
  StrictMono (fun i => xCoord (p i))

def orient (a b c : Point) : ℝ :=
  (xCoord b - xCoord a) * (yCoord c - yCoord a) -
  (yCoord b - yCoord a) * (xCoord c - xCoord a)

def IsCup (p : Fin N → Point) : Prop :=
  ∀ ⦃i j k : Fin N⦄, i < j → j < k → 0 < orient (p i) (p j) (p k)

def IsCap (p : Fin N → Point) : Prop :=
  ∀ ⦃i j k : Fin N⦄, i < j → j < k → orient (p i) (p j) (p k) < 0

def ConvexChainSignature (p : Fin N → Point) (i : Fin N) : ℕ × ℕ := ...
```

You may refine these definitions to something more workable in Lean, but the invariant must support actual theorem proving, not just documentation.

## Precise Theorem Statements to Target

You must prove at least 3 substantial theorems. The following are the recommended targets.

### Theorem 1: Cup/Cap forcing theorem

A finite planar point set in general position with strictly increasing `x`-coordinates and sufficiently many points contains either a large cup or a large cap.

Mathematical statement:

For all natural numbers `r s ≥ 2`, any sequence of at least `(r-1)*(s-1)+1` planar points in general position with strictly increasing `x`-coordinates contains either an `r`-cup or an `s`-cap.

Lean 4 target signature sketch:

```lean
theorem cups_caps_forcing
    {r s N : ℕ}
    (hr : 2 ≤ r) (hs : 2 ≤ s)
    (hN : (r - 1) * (s - 1) + 1 ≤ N)
    {p : Fin N → Point}
    (hx : XStrict p)
    (hgp : GeneralPosition p) :
    (∃ I : Fin r ↪ Fin N, IsCup (fun i => p (I i))) ∨
    (∃ I : Fin s ↪ Fin N, IsCap (fun i => p (I i)))
```

Why this matters:
This is the combinatorial engine behind the Happy End theorem. Formalizing it cleanly creates a reusable Ramsey-style extraction theorem for planar geometry.

### Theorem 2: Cup or cap implies convex polygon

Any `n`-cup or `n`-cap with `n ≥ 3` forms the vertex set of a convex `n`-gon.

Lean 4 target signature sketch:

```lean
def FormsConvexNGon {n : ℕ} (p : Fin n → Point) : Prop := ...

theorem cup_implies_convex
    {n : ℕ} (hn : 3 ≤ n) {p : Fin n → Point}
    (hx : XStrict p) (hcup : IsCup p) :
    FormsConvexNGon p

theorem cap_implies_convex
    {n : ℕ} (hn : 3 ≤ n) {p : Fin n → Point}
    (hx : XStrict p) (hcap : IsCap p) :
    FormsConvexNGon p
```

Why this matters:
This is the geometric conversion theorem. It turns combinatorial slope/order data into actual convexity.

### Theorem 3: Verified Erdős–Szekeres upper bound

For every `n ≥ 3`, any set of at least `((n - 1)^2 + 1)` planar points in general position with distinct `x`-coordinates contains a convex `n`-gon.

This is not the sharp classical bound `2^(n-2)+1`, but it is a genuinely nontrivial formal theorem if derived from your cup-cap machinery. If you can reach the classical exponential bound, do so — that would be a major success. But a verified nontrivial upper bound with reusable infrastructure is already worthwhile if the proof architecture is deep and general.

### Theorem 5: Extremal signature injectivity theorem

This is the novel theorem that can differentiate your work from a standard textbook formalization.

Let `ConvexChainSignature p i = (a_i, b_i)` record the maximal cup-length ending at `i` and cap-length ending at `i`. Prove that if the configuration contains no `r`-cup and no `s`-cap, then these signatures lie in `{1,...,r-1} × {1,...,s-1}` and are pairwise distinct.

Lean 4 target signature sketch:

```lean
theorem signature_injective
    {r s N : ℕ}
    {p : Fin N → Point}
    (hx : XStrict p)
    (hgp : GeneralPosition p)
    (hnoCup : ¬ ∃ I : Fin r ↪ Fin N, IsCup (fun i => p (I i)))
    (hnoCap : ¬ ∃ I : Fin s ↪ Fin N, IsCap (fun i => p (I i))) :
    Function.Injective (ConvexChainSignature p)
```

Combined with cardinality bounds, this gives a counting proof of cup-cap forcing. This is exactly the kind of reusable extremal invariant that can support future improvements.

## Proof Strategy Architecture

You must present and implement at least 2–3 proof strategies, even if one becomes primary.

### Strategy A: Dynamic-programming extremal signatures via injective counting
Most promising.

1. Define for each point `i`:
   - `cupLen i`: maximum length of a cup ending at `i`
   - `capLen i`: maximum length of a cap ending at `i`
2. Show local extension lemmas:
   - for `i < j`, orientation sign between predecessors and `j` forces either cup-extension or cap-extension.
3. Prove that if two indices had the same signature, one could extend one chain past the other, contradicting maximality.
4. Count signatures to derive `N ≤ (r-1)(s-1)` in the absence of an `r`-cup and `s`-cap.
5. Contrapose to obtain `cups_caps_forcing`.

Why this is best:
It is structurally finite, combinatorial, and Lean-friendly. It avoids needing a heavy external Ramsey theory library and yields an actual algorithm for extracting extremal chains.

### Strategy B: Reduction to monotone subsequences of slopes
Use catalog theorem `erdos_szekeres_monotone`.

1. Order points by increasing `x`.
2. Associate to each point or adjacent pair a slope sequence.
3. Use `erdos_szekeres_monotone` to force a monotone subsequence of slopes.
4. Prove monotone slope subsequences correspond to cups or caps.
5. Convert cups/caps to convex polygons.

Why useful:
This strategy leverages existing verified infrastructure directly. It may be simpler for smaller intermediate lemmas and can help bootstrap Theorem 1, especially if full signature machinery is hard to complete immediately.

### Strategy C: Oriented matroid / order-type abstraction
Most visionary, perhaps for future extension.

1. Replace coordinates by orientation predicates.
2. Define cups/caps entirely in terms of chirotope signs.
3. Prove polygon extraction depends only on order type, not metric coordinates.
4. Deduce affine invariance and pave the way for finite order-type enumeration.

Why important:
This generalizes the theorem beyond Euclidean coordinates and opens the door to certified classification of extremal configurations.

You should likely implement Strategy A as the main engine, use Strategy B as a supporting bridge to existing catalog material, and state Strategy C as a future abstraction layer if time does not permit full formalization.
