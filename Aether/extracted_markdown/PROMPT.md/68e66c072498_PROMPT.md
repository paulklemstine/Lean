## Assignment: 2. Tropical Matrix Factorization Hardness Transfer

**Mode**: prove

Prove a genuinely new hardness-transfer theorem that turns tropical matrix factorization complexity into a formal obstruction for tropical key recovery. Do not settle for a vague “cryptography is hard because rank is hard” slogan. Architect an explicit reduction theorem with a Lean-ready statement, isolate the exact semantic assumptions needed, and make the bridge mathematically clean enough that later work can attach complexity-theoretic wrappers.

The central vision is this: a tropical public key should not merely be an element of a semiring power system; it should be a compressed certificate of a hidden tropical factorization profile. If you can recover the secret exponent from the public key, then you can recover a structural invariant of an associated tropical matrix family. That is the seed of a new field: **tropical cryptographic complexity via tropical factorization invariants**.

### Breakthrough Target

Formalize and prove a theorem of the following shape:

> There exists an explicit family of tropical matrices `M(s)` attached to a tropical generator `G` and secret exponent `s` such that any algorithm recovering `s` from the public key `pub = tropPow G s` yields, by composition, an algorithm computing a rank-relevant invariant of `M(s)`. Consequently, exact tropical key recovery is at least as hard as computing that invariant on the image family.

This is not yet full NP-hardness in Lean unless you also formalize the complexity layer, but it is the decisive mathematical bridge: **key recovery computes a factorization invariant**. Once established, it opens the path to machine-checked cryptographic lower-bound transfers in idempotent algebra.

### Lean 4 theorem target, first-pass bridge theorem

```lean
theorem rank_computable_from_secret_recovery
  {n : ℕ} [NeZero n]
  (G : Matrix (Fin n) (Fin n) (WithTop ℤ))
  (rankEncoding : ℕ → Matrix (Fin n) (Fin n) (WithTop ℤ))
  (pub : ℕ → Matrix (Fin n) (Fin n) (WithTop ℤ))
  (recoverSecret : Matrix (Fin n) (Fin n) (WithTop ℤ) → ℕ)
  (rankInv : Matrix (Fin n) (Fin n) (WithTop ℤ) → ℕ)
  (hpub : ∀ s, pub s = tropPow G s)
  (hrec : ∀ s, recoverSecret (pub s) = s)
  (hrank : ∀ s, rankInv (rankEncoding s) = s) :
  ∀ s, rankInv (rankEncoding (recoverSecret (pub s))) = s
```

This first theorem is elementary but foundational: it certifies that exact secret recovery computes a rank invariant on an encoded family.

Then prove the stronger, compositionally useful corollary:

```lean
theorem rank_of_encoded_matrix_via_public_key
```

## Mathematical Framing You Should Adopt

The original hypothesis as stated is too optimistic if read literally as “general tropical rank computation reduces to key recovery” without specifying:
- the exact rank notion,
- the encoding family,
- the domain of secrets,
- and whether the reduction is many-one, Turing, exact, or promise-based.

You should **tighten** the claim to one of these precise forms:

### Version A: Exact invariant transfer on an encoded family
There exists `encode : S → Mat_n` such that `rankInv (encode s) = f(s)` and `f` is injective. Therefore exact recovery of `s` computes `rankInv` on the image family.

This is the most Lean-friendly and most likely to succeed now.

### Version B: Promise reduction
For secrets in a bounded set `s ≤ B(n)`, there exists `encode` such that tropical rank of `encode s` determines `s`. This avoids impossible unbounded rank equalities in fixed dimension.

### Version C: Monotone lower-bound transfer
If `recoverSecret` exists on a family with separation assumptions, then `rankInv` is computable on the associated encoded family. This is weaker than NP-hardness but mathematically honest and structurally powerful.

The best immediate target is **Version B or C**, with a bounded secret domain.

## Proof Strategy Paths

### Strategy A: Pure compositional reduction theorem
This is the most promising route.

1. Define a general reduction schema:
   - `pub s := tropPow G s`
   - `rankInstance s := encode s`
   - `solveRank pub := rankInv (encode (recoverSecret pub))`

2. Prove by rewriting:
   - `recoverSecret (pub s) = s`
   - hence `rankInv (encode (recoverSecret (pub s))) = rankInv (encode s)`
   - then use `hrank`.

3. Package as a reusable theorem:
   - any exact secret-recovery oracle induces a rank-computation oracle on the encoded family.

**Why most promising:** it requires no deep complexity formalization and no dangerous commitment to unformalized NP-hardness machinery. Yet it creates the exact theorem shape future complexity wrappers need.

---

### Strategy B: Construct an explicit bounded encoding by block-diagonal tropical sums
This is more ambitious and more mathematically satisfying.

1. Define `encode s` as a block or layered matrix formed from `s` tropical rank-1 components.
2. Prove:
   - upper bound: `tropicalFactorRank (encode s) ≤ s` by explicit decomposition;
   - lower bound: `s ≤ tropicalFactorRank (encode s)` using support separation, dimension witnesses, or combinatorial obstruction.
3. Conclude `tropicalFactorRank (encode s) = s` on a bounded secret domain.

**Why powerful:** this turns the transfer theorem from abstract to concrete. It creates a certified family of cryptographically meaningful matrices whose rank profile literally stores the secret.

**Risk:** true tropical factor rank lower bounds are subtle. If they become too hard, switch to a surrogate invariant first.

---

### Strategy C: Injective invariant encoding via norm or spectral proxy
This is a strategic fallback if factor rank is not yet mature in the library.

1. Define a proxy invariant `rankInv` that is easier to formalize but still rank-flavored:
   - tropical support width,
   - number of distinct affine layers,
   - bounded tropical rank surrogate,
   - or a canonical decomposition length.

2. Use `tropical_security_from_norm_bound` to show the public-key family is injective on bounded secrets.
3. Define `encode s` so that `rankInv (encode s) = s`, then prove the same transfer theorem.

**Why useful:** it gives you a bridge theorem now, while cleanly isolating the one future replacement point where true tropical factor rank will later enter.
