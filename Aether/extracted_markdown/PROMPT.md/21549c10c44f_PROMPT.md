## Assignment: Rank-Sensitive Exact Kernel Cardinality over `ZMod q`

Aristotle, this is the right theorem to formalize now because it converts a coarse probabilistic estimate into an exact structural law. The current inequality `|ker(M)| ≤ q^(p-1)` is a one-bit shadow of a much sharper invariant: the kernel size is governed exactly by rank deficiency. Formalizing this is not just linear algebra bookkeeping — it upgrades randomized verification bounds into rank-aware exact acceptance laws and creates a reusable finite-field cardinality interface for future work in coding theory, derandomization, and finite-model complexity.

You should aim not merely to prove a bound, but to certify the finite-field avatar of rank-nullity as an exact counting theorem in Lean.

## Precise theorem target

The mathematically natural theorem is:

> For a prime `q`, and any matrix `M : Matrix (Fin m) (Fin p) (ZMod q)`,
> the number of vectors `r : (Fin p → ZMod q)` satisfying `M.mulVec r = 0`
> is exactly `q^(p - rank(M))`, where `rank(M)` is the finite dimension of the image
> of the associated linear map `Matrix.mulVecLin M`.

A Lean 4 target signature, close to your current proposal, is:

```lean
theorem card_mulVec_kernel_exact
    {q m p : ℕ} [Fact q.Prime]
    (M : Matrix (Fin m) (Fin p) (ZMod q)) :
    Fintype.card {r : Fin p → ZMod q // M.mulVec r = 0}
      = q ^ (p - Module.finrank (ZMod q) (Matrix.mulVecLin M).range)
```

But you should also strongly consider proving the cleaner intermediate theorem first:

```lean
theorem card_mulVecLin_ker_exact
    {q m p : ℕ} [Fact q.Prime]
    (M : Matrix (Fin m) (Fin p) (ZMod q)) :
    Fintype.card (LinearMap.ker (Matrix.mulVecLin M))
      = q ^ Module.finrank (ZMod q) (LinearMap.ker (Matrix.mulVecLin M))
```

followed by the rank-nullity specialization

```lean
theorem finrank_ker_mulVecLin
    {q m p : ℕ} [Fact q.Prime]
    (M : Matrix (Fin m) (Fin p) (ZMod q)) :
    Module.finrank (ZMod q) (LinearMap.ker (Matrix.mulVecLin M))
      = p - Module.finrank (ZMod q) (LinearMap.range (Matrix.mulVecLin M))
```

and then bridge the subtype kernel with the submodule kernel.

An even stronger final theorem, if feasible, is the probability statement that opens the algorithmic door:

```lean
theorem freivalds_false_accept_exact
    {q m p : ℕ} [Fact q.Prime]
    (M : Matrix (Fin m) (Fin p) (ZMod q)) :
    ((Fintype.card {r : Fin p → ZMod q // M.mulVec r = 0} : ℕ) : ℚ)
      / q^p
      = (q : ℚ) ^ (-(Module.finrank (ZMod q) (Matrix.mulVecLin M).range))
```

This exact acceptance law is the real conceptual prize.

## Why this is a breakthrough

This theorem turns a yes/no “nonzero matrix implies at most `1/q` error” statement into a rank-sensitive spectrum:
- rank `1` gives acceptance probability `q⁻¹`,
- rank `k` gives `q⁻ᵏ`,
- full column rank gives a unique kernel vector,
- rank deficiency becomes a measurable algebraic resource.

That shift is profound because it exposes the hidden geometry of randomized linear identity testing. In one stroke, you connect:
- **finite linear algebra**: rank-nullity and exact cardinality,
- **randomized algorithms**: Freivalds-style false acceptance probability,
- **coding theory**: nullspace size as code dimension,
- **complexity theory**: witness-space counting and entropy over finite fields.

This is the kind of theorem that becomes infrastructure. Once formalized, it will support exact analyses of randomized verification, syndrome decoding counts, and finite-field concentration statements.

## Core mathematical architecture

Let `φ := Matrix.mulVecLin M`. Then:
- the ambient space `(Fin p → ZMod q)` has dimension `p`,
- `ker φ` is a finite-dimensional `ZMod q`-vector space,
- `|ker φ| = q^(finrank ker φ)`,
- rank-nullity gives `finrank ker φ = p - finrank (range φ)`.

The only genuine Lean challenge is not the mathematics — it is the transportation layer between:
1. the subtype `{r // M.mulVec r = 0}`,
2. the submodule `LinearMap.ker (Matrix.mulVecLin M)`,
3. finite-cardinality lemmas stated for finite modules/submodules.

That transportation is exactly where the reusable formalization value lies.

## Proof strategy A: linear-map-first, then transport back to the subtype
This is the most promising route.

### Step 1: Replace the raw equation by a linear map kernel
Define or use:
```lean
φ := Matrix.mulVecLin M
```
and prove an equivalence
```lean
{r : Fin p → ZMod q // M.mulVec r = 0} ≃ LinearMap.ker φ
```
Most likely this is essentially definitional once you unfold `Matrix.mulVecLin`, but if not, build an explicit `Equiv`.

Key point: the submodule `LinearMap.ker φ` is a type of vectors together with proof of kernel membership, so the bridge should be straightforward.

### Step 2: Count the kernel as a finite-dimensional vector space
Use a theorem of the shape:
- `Module.card_eq_pow_finrank`
or the corresponding Mathlib lemma for finite modules over finite fields.

You want:
```lean
Fintype.card (LinearMap.ker φ) = q ^ Module.finrank (ZMod q) (LinearMap.ker φ)
```
This is the exact finite-field counting law.

### Step 3: Apply rank-nullity
Invoke the finite-dimensional theorem giving:
```lean
Module.finrank (ZMod q) (LinearMap.ker φ) +
Module.finrank (ZMod q) (LinearMap.range φ)
= Module.finrank (ZMod q) (Fin p → ZMod q)
```
and then identify the ambient finrank with `p`.

Finally rewrite:
```lean
Module.finrank (ZMod q) (Fin p → ZMod q) = p
```
to conclude
```lean
Module.finrank (ZMod q) (LinearMap.ker φ)
= p - Module.finrank (ZMod q) (LinearMap.range φ)
```

### Why Strategy A is best
It aligns exactly with Mathlib’s abstractions. You avoid coordinate-level basis arguments and instead leverage the existing finite-dimensional API. It also produces reusable lemmas for any future theorem about kernels of linear maps over finite fields.

## Proof strategy B: explicit basis / Gaussian elimination / row-reduction
This is more concrete but less elegant.

### Step 1
Show that `(Fin p → ZMod q)` is isomorphic to `(ZMod q)^p` with standard basis.

### Step 2
Use row reduction or existence of a basis adapted to the kernel and image to show the solution set of `M r = 0` is isomorphic to `(Fin (p-rank) → ZMod q)`.

### Step 3
Count directly:
```lean
Fintype.card (Fin (p-rank) → ZMod q) = q^(p-rank)
```

### Why it is less promising
Lean’s linear algebra library already packages the invariant content in `finrank`, `ker`, and `range`. Rebuilding row-reduction machinery for this theorem is likely to create unnecessary proof overhead. Still, it can be useful if transport lemmas around `LinearMap.ker` become awkward.

## Proof strategy C: cardinality via quotient-image fibers
This is conceptually rich and may support future counting theorems.

### Step 1
View `φ : V → W` as partitioning `V` into fibers, each a coset of `ker φ`.

### Step 2
Use:
```text
|V| = |ker φ| * |range φ|
```
for finite vector spaces.

### Step 3
Compute
```text
|V| = q^p,  |range φ| = q^rank
```
to deduce
```text
|ker φ| = q^(p-rank)
```

### Why this is interesting
This route generalizes naturally to exact counting of affine solution spaces `M r = b`, not just homogeneous kernels. If you can package the finite-fiber cardinality theorem cleanly, it opens a second wave of results immediately.

## Cross-domain connections you should explicitly exploit

### 1. Randomized algorithms / Freivalds
The theorem exactly computes the false acceptance mass for a matrix witness test:
```text
Pr_r[M r = 0] = q^(-rank(M))
```
This is stronger than the standard Schwartz–Zippel-flavored coarse bound and turns rank into a probabilistic certificate.

### 2. Coding theory
`ker(M)` is a linear code. Your theorem is exactly the dimension-cardinality law:
```text
|C| = q^dim(C)
```
for the nullspace code defined by a parity-check matrix. This creates a bridge from matrix verification to syndrome-space counting.

### 3. Finite entropy and information
The quantity `log_q |ker(M)| = p - rank(M)` is the exact number of unconstrained degrees of freedom. This is linear-algebraic entropy. It invites future formalization of min-entropy and information loss under linear maps over finite fields.

### 4. Complexity theory
Rank-sensitive acceptance probabilities naturally feed into:
- derandomization analyses,
- interactive proof soundness over finite fields,
- exact counting classes for linear constraint systems.

This is not “just” a finite linear algebra lemma. It is a portal theorem.
