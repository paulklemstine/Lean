## Core Definitions to Introduce

Use concrete finite index types and matrix identities.

A robust formal definition:

```lean
def IsHadamard {n : ℕ} (H : Matrix (Fin n) (Fin n) ℤ) : Prop :=
  (∀ i j, H i j = 1 ∨ H i j = -1) ∧
  H * H.transpose = (n : ℤ) • (1 : Matrix (Fin n) (Fin n) ℤ)
```

Also define a normalized version:

```lean
def IsNormalizedHadamard {n : ℕ} (H : Matrix (Fin n) (Fin n) ℤ) : Prop :=
  IsHadamard H ∧
  (∀ i, H 0 i = 1) ∧
  (∀ i, H i 0 = 1)
```

And an existence predicate on orders:

```lean
def HadamardOrder (n : ℕ) : Prop :=
  ∃ H : Matrix (Fin n) (Fin n) ℤ, IsHadamard H
```

If needed, also introduce a `±1`-valued matrix predicate separately so orthogonality lemmas can be reused outside Hadamard theory.

## Precise Theorem Targets

### Theorem 1: Tensor-product closure
This is the structural theorem that turns isolated constructions into an algebra.

```lean
theorem hadamardOrder_mul
    {m n : ℕ}
    (hm : HadamardOrder m)
    (hn : HadamardOrder n) :
    HadamardOrder (m * n)
```

Stronger matrix-level version:

```lean
theorem IsHadamard.kronecker
    {m n : ℕ}
    {A : Matrix (Fin m) (Fin m) ℤ}
    {B : Matrix (Fin n) (Fin n) ℤ}
    (hA : IsHadamard A)
    (hB : IsHadamard B) :
    IsHadamard (Matrix.kroneckerMap (fun a b => a * b) A B)
```

Breakthrough significance: once this is certified, Hadamard existence becomes a multiplicative semigroup problem. This is the backbone enabling all infinite-family arguments and all later connections to coding/design products.

### Theorem 5: Hadamard-to-design bridge
This is the cross-domain theorem that elevates the project beyond matrix existence.

Define the core extracted incidence matrix from a normalized Hadamard matrix by deleting first row and column and converting `-1 ↦ 1`, `1 ↦ 0` or vice versa. Then prove it yields a symmetric design.

A concrete target:

```lean
theorem normalizedHadamard_gives_symmetric_BIBD
    {n : ℕ}
    {H : Matrix (Fin (4*n)) (Fin (4*n)) ℤ}
    (hH : IsNormalizedHadamard H) :
    ∃ A : Matrix (Fin (4*n - 1)) (Fin (4*n - 1)) ℕ,
      IsSymmetricBIBD A (4*n - 1) (2*n - 1) (n - 1)
```

If full BIBD infrastructure is absent, prove the matrix equations characterizing it:
- constant row sums,
- constant column sums,
- pairwise row intersections constant.

For instance:
```lean
theorem core_incidence_row_sums
theorem core_incidence_pairwise_intersections
```

This is a true bridge theorem. It transforms Hadamard matrices into finite geometries, enabling applications to block designs, experimental design, and extremal combinatorics.

### Theorem 6: Hadamard-to-code bridge
Construct binary codes from rows of a normalized Hadamard matrix.

Target theorem:
```lean
theorem normalizedHadamard_gives_code
    {n : ℕ}
    {H : Matrix (Fin (4*n)) (Fin (4*n)) ℤ}
    (hH : IsNormalizedHadamard H) :
    ∃ C : Finset (Vector Bool (4*n)),
      card C = 8*n ∧

```

If this exact coding statement is cumbersome, prove a weaker but still nontrivial equidistance theorem for the binary images of rows and their complements.

This theorem opens the signal-processing and coding-theoretic applications: Walsh codes, spread-spectrum communication, low-correlation sequences, and orthogonal modulation.

## 2–3 Proof Strategy Architectures

### Strategy A: Matrix-algebra first, then specialize
Most promising for Lean.

1. Define `IsHadamard` via matrix multiplication and scalar identity.
2. Prove general lemmas:
   - transpose orthogonality,
   - row-dot-product characterization,
   - closure under row/column sign flips and permutations,
   - Kronecker product compatibility with transpose and multiplication.
3. Use these lemmas to certify Sylvester and tensor constructions uniformly.

Why this is promising: Mathlib’s matrix API is strongest on algebraic identities. This minimizes bespoke combinatorics and lets you reuse semiring/ring structure aggressively.

---

### Strategy B: Row-dot-product combinatorics
Best for divisibility and design extraction.

1. Recast `IsHadamard` as:
   - each entry is `±1`,
   - each row has self-dot-product `n`,
   - distinct rows have dot-product `0`.
2. Normalize by sign-flipping rows/columns so the first row/column are all `1`.
3. Count `1` and `-1` entries in each remaining row to derive:
   - exactly `n/2` ones and `n/2` minus ones,
   - pairwise intersection counts,
   - hence `4 ∣ n` for `n > 2`,
   - design parameters from the core matrix.

Why this is promising: the arithmetic of counts is clearer than matrix multiplication when proving combinatorial consequences. It also naturally connects to `Finset.card` lemmas and incidence structures.

---

### Strategy C: Finite-field character construction for Paley
Highest upside, highest risk.

1. Formalize the Paley matrix using quadratic character on `𝔽_q`.
2. Prove the relevant row orthogonality via character sum identities.
3. Lift the finite-field matrix to an integer `±1` matrix and conclude Hadamard existence.

Why this is revolutionary: this imports number-theoretic harmonic analysis into certified combinatorics. If successful, it creates reusable Lean infrastructure for quadratic characters, Gauss sums, and finite-field combinatorics with implications far beyond Hadamard matrices.

Recommended order: A → B → C. Strategy A gives the reusable skeleton. Strategy B extracts deep consequences. Strategy C is the bold frontier theorem.

## Cross-Domain Connections You Must Exploit

### 1. Combinatorial designs
Hadamard matrices generate symmetric block designs. This is the correct bridge from orthogonal sign matrices to incidence geometry. Formalizing this opens future work on finite projective planes, difference sets, and strongly regular graphs.

### 2. Coding theory
Rows of normalized Hadamard matrices produce equidistant binary codes and connect to Reed–Muller / Walsh–Hadamard transforms. This creates a path toward formalized extremal bounds in coding theory and certifiable constructions for communication systems.

### 3. Signal processing and harmonic analysis
Hadamard transforms are discrete orthogonal transforms with fast algorithms. A future formal theorem could connect matrix orthogonality to energy preservation:
```lean
‖Hx‖₂^2 = n * ‖x‖₂^2
```
for real embeddings of Hadamard matrices. This is the formal doorway to compressed sensing, spread-spectrum sequences, and low-correlation waveform design.

### 4. Number theory
Paley constructions sit on quadratic residues in finite fields. This is where additive combinatorics, character sums, and arithmetic geometry enter. If you can formalize even one Paley theorem, you have created infrastructure reusable for Weil-sum arguments and pseudorandomness.

### 5. Graph theory
A normalized Hadamard core corresponds to a strongly regular graph in certain constructions. Even partial formalization here could seed a future theory of spectral graph certificates from orthogonal sign matrices.
