## Core Vision

The conjectural paradigm is that for suitable pairs `(g,h)` in `GL(n, 𝔽_q)`, one can verify generation of a large irreducible subgroup — and in favorable cases all of `GL(n, 𝔽_q)` or at least a certificate-excluding all standard geometric maximal subgroups — by checking only a bounded amount of polynomial data attached to `g`, `h`, and `g*h`.

The catalog already gives the seed: irreducible characteristic polynomial data is a compact witness of irreducibility of the induced module. Your task is to **upgrade irreducibility certificates into generation-exclusion certificates**, and then prove complexity bounds for their verification.

This is not merely an algorithmic convenience. It is a conceptual shift:

- from **enumerating generated elements** to **excluding ambient obstruction classes**;
- from **group search** to **polynomial identity verification**;
- from **combinatorial explosion** to **certificate complexity**.

That is a new language for constructive finite group theory.

### Theorem 1: Irreducible charpoly forbids nontrivial invariant subspaces

This should be the bridge from catalog results to certificate verification.

**Mathematical statement.**  
Let `F` be a field, `V = F^n`, and `g ∈ GL(V)`. If the characteristic polynomial of `g` is irreducible over `F`, then every `g`-stable subspace of `V` is trivial. Hence any subgroup containing `g` acts irreducibly.

If this already exists in the catalog, strengthen it to the two-generator conclusion or package it in certificate form.

**Lean target signature (representative):**
```lean
theorem no_nontrivial_invariant_subspace_of_charpoly_irreducible
    {n : ℕ} {F : Type*} [Field F]
    (g : Matrix (Fin n) (Fin n) F)
    (hg : IsUnit g.det)
    (hirr : Irreducible (Matrix.charpoly g)) :
    ∀ U : Submodule F (Fin n → F),
      U ≠ ⊥ →
      U ≠ ⊤ →
      ¬ IsInvariantSubmodule
          (Matrix.toLin' g)
          U
```

If `IsInvariantSubmodule` is not already available in this exact form, define the appropriate predicate.

**Why this matters.**  
This theorem converts a one-line algebraic certificate (`Irreducible (charpoly g)`) into a structural statement about all subgroup geometry. It is the atomic mechanism behind every certificate-based generation theorem.

**Proof strategies.**
1. **Minimal polynomial divisibility route**  
   Show that if `U` is a nontrivial invariant subspace, then the characteristic/minimal polynomial of the restriction divides `charpoly g` and has degree strictly between `0` and `n`, contradicting irreducibility.  
   Most promising if catalog already has divisibility theorems for restricted endomorphisms.

2. **Cyclic module route**  
   View `V` as an `F[X]`-module via `g`. Irreducibility of `charpoly g` should force simplicity of the module under suitable finite-dimensional hypotheses, so submodules correspond to ideals in `F[X]/(p)`, hence are trivial.  
   Most conceptually powerful; opens direct links to module complexity.

3. **Contrapositive via block form**  
   If there exists a proper invariant subspace, choose a basis adapted to it and write `g` in block upper-triangular form; then `charpoly g` factors as product of the diagonal block characteristic polynomials. Contradiction with irreducibility.  
   Most Lean-friendly if basis/block-triangular charpoly lemmas are available.

### Theorem 2: Certificate verification implies irreducible action of the generated subgroup

**Mathematical statement.**  
If a pair certificate verifies irreducibility of `g`, `h`, and `gh`, then the subgroup generated by `g` and `h` acts irreducibly on `F^n`. At minimum, irreducibility of one of `g`, `h`, or `gh` should already imply irreducibility of the generated subgroup; the stronger triple condition should be used to exclude additional obstruction classes.

**Lean target signature (representative):**
```lean
theorem certificate_implies_irreducible_action
    {n : ℕ} {F : Type*} [Field F]
    (C : PairGenerationCertificate n F) :
    IrreducibleLinearAction F
      (Subgroup.closure ({C.g, C.h} : Set (Matrix (Fin n) (Fin n) F)))
      (Fin n → F)
```

If a notion like `IrreducibleLinearAction` does not exist, define it carefully and prove basic equivalences with “no nontrivial common invariant subspace”.

**Why this matters.**  
This theorem is the formal hinge between **local polynomial checks** and **global group action structure**. It is the first step toward avoiding subgroup enumeration entirely.

**Proof strategies.**
1. **Direct common-subspace exclusion**  
   Any subspace invariant under the generated subgroup is invariant under `g` and `h`; if `g` alone has irreducible charpoly, apply Theorem 1.  
   Best for immediate progress and clean Lean implementation.

2. **Triple-certificate strengthening**  
   Use irreducibility of `g`, `h`, and `gh` to show not only irreducibility but also exclusion of decompositions preserved up to permutation.  
   More ambitious and more novel; this begins to approach imprimitive obstruction elimination.

3. **Submodule lattice contradiction**  
   Assume reducibility of the generated subgroup, obtain a nontrivial common invariant subspace, and derive factorization contradictions for all three characteristic polynomials.  
   Strongest certificate-theoretic flavor.

### Theorem 3: Polynomial-time verifiability of the algebraic certificate

You must formalize a theorem saying that verification uses only polynomially many field operations in `n`, assuming irreducibility testing and determinant computation as primitives with known complexity. If exact bit-complexity is too heavy for this cycle, formalize a **symbolic operation count bound**.

Introduce a new complexity measure.

```lean
def certificateVerificationCost (n : ℕ) : ℕ := ...
```

or a richer structure:

```lean
structure VerificationCostBound where
  determinantCost : ℕ
  charpolyCost : ℕ
  irreducibilityCost : ℕ
  totalCost : ℕ
```

Then prove a theorem of the form:

```lean
theorem certificateVerificationCost_polynomial
    : ∃ k C : ℕ,
        ∀ n : ℕ,
          certificateVerificationCost n ≤ C * n^k
```

or, if `q` is tracked:

```lean
theorem certificateVerificationCost_poly_in_n_logq
    : ∃ k C : ℕ,
        ∀ n q : ℕ,
          certificateVerificationCost n q ≤ C * (n + Nat.log q)^k
```

This theorem must not be fake asymptotics. You should define a concrete symbolic cost model and prove the bound by explicit estimates.

**Why this matters.**  
Without this theorem, “certificate verification” is just rhetoric. With it, you obtain a mathematically clean complexity separation between:
- algebraic witness checking, and
- subgroup enumeration/BFS in the Cayley graph.

That is the beginning of a **verified complexity theory for constructive finite group recognition**.

**Proof strategies.**
1. **Operation-count decomposition**  
   Define cost as sum of determinant, multiplication, charpoly, and irreducibility-test costs; prove each is polynomial and combine with `calc`.  
   Most realistic in Lean.

2. **Recursive characteristic polynomial bound**  
   If you formalize a specific charpoly algorithm (e.g. Faddeev–LeVerrier style), prove by induction that it is polynomial-time in symbolic arithmetic cost.  
   More ambitious and algorithmically meaningful.

3. **Reduction to catalog-certified subroutines**  
   If the catalog contains verified polynomial arithmetic complexity lemmas, instantiate them to the three-polynomial verification pipeline.  
   Best if such lemmas exist in `FINAL/` or vetted complexity files.

### Theorem 4: A nontrivial obstruction-exclusion theorem beyond irreducibility

This is where the project becomes field-opening rather than incremental. Prove at least one theorem excluding a genuine geometric obstruction class using the triple `(g, h, gh)` certificate.

A plausible target:

**Mathematical statement.**  
Suppose `V = F^n` admits a decomposition into equal-size blocks permuted by the generated subgroup. Then the characteristic polynomial of every element preserving that decomposition in a single-block-cyclic manner factors in a constrained way. In particular, if `charpoly (gh)` is irreducible of degree `n`, then the subgroup generated by `g, h` is not imprimitive of certain block types.

**Lean target signature (representative):**
```lean
theorem irreducible_charpoly_mul_excludes_nontrivial_block_system
    {n b m : ℕ} (hn : n = b * m) (hb : 1 < b) (hm : 1 < m)
    {F : Type*} [Field F]
    (g h : Matrix (Fin n) (Fin n) F)
    (hirr : Irreducible (Matrix.charpoly (g * h))) :
    ¬ PreservesBlockSystem F b m (Subgroup.closure ({g, h} : Set _))
```

You will likely need to define `PreservesBlockSystem`.

**Why this matters.**  
This theorem is the first step toward an Aschbacher-style certificate theory. Even one rigorously excluded maximal subgroup family is already a new bridge between finite group recognition and formalized complexity.

**Proof strategies.**
1. **Block-triangular factorization argument**  
   In a basis respecting blocks, preserving a block system imposes factorization or compositional constraints on characteristic polynomials. Contradict irreducibility.  
   Most direct.

2. **Permutation-module reduction**  
   Extract the induced action on the set of blocks and analyze how irreducibility of `gh` rules out a nontrivial quotient structure.  
   More conceptual, connects to representation theory.

3. **Tensor/imprimitive decomposition contradiction**  
   Show that block imprimitivity yields a proper algebraic subvariety of matrices whose characteristic polynomials satisfy specific coefficient identities; irreducibility avoids that variety.  
   Most novel, potentially strongest for future work.

## Conjecture with Testable Prediction

State at least one falsifiable conjecture with a concrete computational disproof protocol.

### Primary conjecture
For finite fields `𝔽_q` and dimension `n ≥ 2`, there exists a predicate `GoodCertificate(g,h)` depending only on:
- invertibility of `g`, `h`,
- irreducibility of `charpoly g`, `charpoly h`, `charpoly (g*h)`,
- one additional non-degeneracy condition excluding extension-field or imprimitive embeddings,

such that for a density tending to `1` as `q → ∞`, `GoodCertificate(g,h)` implies
`Subgroup.closure ({g,h}) = GL(n, 𝔽_q)`.

Write this conjecture explicitly in prose and, if feasible, as a Lean `def` plus comment.

### Computational test
For `GL(2, 𝔽_q)` and `GL(3, 𝔽_q)` over sampled prime powers `q ≤ 1000`:
1. enumerate random invertible pairs `(g,h)`;
2. test `GoodCertificate(g,h)`;
3. independently compute the generated subgroup by BFS or Schreier-style closure;
4. measure false positives and empirical density.

A single false positive disproves the conjecture in its strongest form. This is excellent: dead conjectures are progress.

A sharper falsifiable prediction:
- In `GL(2, 𝔽_q)` for odd `q`, if `charpoly g`, `charpoly h`, and `charpoly (gh)` are irreducible and `tr(g)^2/det(g)`, `tr(h)^2/det(h)`, `tr(gh)^2/det(gh)` avoid a finite exceptional set, then `⟨g,h⟩` contains `SL(2, 𝔽_q)`.

This touches Dickson-style subgroup classification and would be a major result if formalized even partially.
