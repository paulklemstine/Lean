## Breakthrough Objective: Branching-program/circuit duality as a tropical-computation bridge

Do **not** treat this as a routine simulation theorem. The real target is to formalize a structural equivalence that turns bounded-width branching programs into layered circuit objects with explicit size bounds, and then reinterpret that equivalence in the tropical setting as a transfer principle between **path semantics** and **min/max-plus circuit semantics**. If done cleanly in Lean, this becomes a reusable compiler between two computational worlds.

The theorem you should aim for is a precise, constructive simulation result:

> **Main theorem (constructive BP-to-circuit simulation).**  
> For every width `w` and depth `d`, every layered deterministic branching program with at most `w` states per layer and `d` transition layers can be converted into a layered Boolean circuit of size at most `C * w^2 * d` for an explicit constant `C`, computing the same Boolean function on every input. Conversely, every layered circuit of size `s` admits a branching-program style evaluation graph whose width is controlled by the number of gates in each layer.  
> 
> The first direction is the priority target: it is the mathematically sharp statement that bounded-width sequential computation can be unfolded into bounded-size parallel syntax. In the tropical interpretation, each state-transition layer becomes a tropical matrix update, and circuit gates aggregate path weights. This is the gateway theorem for relating tropical branching programs to tropical circuits.

You should define the objects minimally but concretely, using `Fin`, `Bool`, `Nat`, `Finset`, and layer-indexed transition data. Avoid over-abstracting on the first pass. A clean formalization with explicit combinatorial semantics is more valuable than a vague universal theorem.

## Precise formalization target

Introduce a simple layered branching program model. One robust choice is:

- `d+1` layers indexed by `Fin (d+1)`
- each layer has at most `w` nodes, indexed by `Fin w`
- transitions only go from layer `i` to `i+1`
- each transition carries a local Boolean test or literal condition
- acceptance is reachability of a designated accepting node in the final layer

Then define a layered circuit model where each node in layer `i+1` is an OR of predecessors, each predecessor guarded by an AND with the relevant literal.

The key quantitative theorem should look like the following Lean-style signature sketch:

```lean
structure Literal (n : ℕ) where
  var : Fin n
  neg : Bool

def Literal.eval {n : ℕ} (ℓ : Literal n) (x : Fin n → Bool) : Bool :=
  x ℓ.var != ℓ.neg

structure BP (n w d : ℕ) where
  start : Fin w
  accept : Fin w
  edge : Fin d → Fin w → Fin w → Option (Literal n)

def BP.accepts {n w d : ℕ} (P : BP n w d) (x : Fin n → Bool) : Prop := sorry

structure LayeredCircuit (n : ℕ) where
  layers : ℕ
  gatesInLayer : Fin (layers + 1) → ℕ
  eval : (Fin n → Bool) → Fin (layers + 1) → Fin (gatesInLayer ·) → Bool
```

You may prefer a simpler circuit encoding specialized to this theorem rather than a fully general circuit datatype. That is likely better.

The core theorem should be formalized in a form like:

```lean
theorem bp_to_circuit_size_bound
    (n w d : ℕ) :
    ∃ C : ℕ, ∀ P : BP n w d,
      ∃ S : ℕ, S ≤ C * w^2 * d ∧
      ∃ Ckt : LayeredCircuit n,
        circuitSize Ckt = S ∧
        ∀ x : Fin n → Bool, circuitAccepts Ckt x ↔ P.accepts x
```

If explicit constants become annoying, prove the sharper explicit version:

```lean
theorem bp_to_circuit_explicit
    (n w d : ℕ) (P : BP n w d) :
    ∃ Ckt : LayeredCircuit n,
      circuitSize Ckt ≤ 2 * w * w * d + w ∧
      ∀ x : Fin n → Bool, circuitAccepts Ckt x ↔ P.accepts x
```

This explicit theorem is better than asymptotic notation in Lean.

A second theorem, if the first succeeds, should connect directly to tropical computation:

```lean
theorem tropical_bp_unrolling_bound
    (w d : ℕ) (hw : 1 ≤ w) :
    ∃ S : ℕ, S ≤ 2 * w * w * d + w ∧
      TropicalBPExpressible w d → TropicalCircuitExpressible S
```

Even if you must define `TropicalBPExpressible` and `TropicalCircuitExpressible` yourself in a modest way, this would be a genuine bridge theorem.

## Proof strategies

### Strategy A: Direct layer-unrolling via reachability formulas
This is the most promising and should be your primary route.

**Step 1.** For each layer `i : Fin (d+1)` and node `v : Fin w`, define a formula/circuit gate `G(i,v)` meaning: “node `v` is reachable after `i` steps on input `x`.”

- Base layer: `G(0,v)` is true iff `v = start`.
- Inductive layer:
  `G(i+1,v) = OR_u ( G(i,u) AND edgeCond(i,u,v) )`.

**Step 2.** Count gates explicitly.

- For each pair `(u,v)` in a transition layer, at most one AND gate for `G(i,u) ∧ cond(i,u,v)`.
- Then one OR aggregation per target `v`.
- This gives size bounded by something like `2*w^2*d + w*d + O(w)`, which is certainly `O(w^2 d)`.

**Step 3.** Prove correctness by induction on layers.

- Define semantic reachability in the BP.
- Show each gate exactly computes reachability.
- Final acceptance is `G(d, accept)`.

**Why this is best:**  
It is elementary, constructive, and Lean-friendly. It avoids global path quantification and turns the theorem into a straightforward finite induction with explicit combinatorial bookkeeping.

---

### Strategy B: Matrix semantics over the Boolean semiring
This is mathematically elegant and especially good if you want the tropical generalization.

**Step 1.** Encode each layer as a `w × w` Boolean matrix `M_i(x)` whose `(u,v)` entry is the truth value of the edge predicate from `u` to `v`.

**Step 2.** Interpret BP computation as iterated Boolean-semiring matrix-vector multiplication:
`state_{i+1} = state_i ⋅ M_i(x)`.

**Step 3.** Realize each matrix-vector multiplication as a circuit layer with `w^2` pairwise conjunctions and `w` disjunctions, then compose over `d` layers.

**Why this is powerful:**  
This is the correct abstraction for the tropical extension. Replace Boolean semiring operations by min-plus or max-plus operations, and you get a tropical transfer theorem almost for free. This path is more visionary, though it may require more infrastructure than Strategy A.

---

### Strategy C: Path-normal-form circuit via bounded-length existential reachability
This is less likely to be Lean-efficient, but conceptually rich.

**Step 1.** Define acceptance as existence of a path of length `d` whose every edge condition is satisfied.

**Step 2.** Write the function as a disjunction over all state-sequences `v_0, …, v_d` with `v_0 = start`, `v_d = accept`, of conjunctions of edge predicates.

**Step 3.** Compress the resulting formula by dynamic programming, recovering the layered circuit and the `w^2 d` bound.

**Why to consider it:**  
This strategy clarifies that the theorem is a compression theorem: from exponentially many raw paths to polynomial-size dynamic syntax. It is a good explanatory route for `ARTICLE.md`, but not the best first Lean proof.

## Concrete Lean engineering guidance

Use explicit finite types:
- `Fin w` for states
- `Fin d` for transition layers
- `Fin n → Bool` for inputs
- `Option (Literal n)` for possible edges, where `none` means absent edge

Prefer propositions for semantics first:
```lean
def edgeHolds (e : Option (Literal n)) (x : Fin n → Bool) : Prop := ...
```

Then, if needed, bridge to booleans later.

For counting size, avoid sophisticated asymptotic libraries. Define:
```lean
def circuitSize : LayeredCircuit n := ...
```
and prove an explicit arithmetic inequality over `Nat`.

Use induction on `i : Nat` with hypotheses `i ≤ d`; only convert to `Fin` at the edge interface if necessary. This is often easier than dependent recursion directly over `Fin`.

If a full general circuit datatype is too heavy, define a **specialized simulation object**:
```lean
structure SimLayer (n w d : ℕ) where
  gateVal : (Fin n → Bool) → Fin (d+1) → Fin w → Bool
  ...
```
Then prove it satisfies circuit-style recurrence and size accounting. You can always package it into a more generic circuit later.
