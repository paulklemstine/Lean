# Categorical Semantics of Exponential-Logarithmic Computation: Finite Products, Log-Affine Geometry, and Verified Normalization

## Abstract

We introduce a formally verified categorical framework for multivariate exponential-logarithmic-multiplicative (EML) computation. We define an inductive predicate `ScalarEML` characterizing scalar functions on `ℝⁿ` built from coordinate projections, constants, arithmetic, exponentiation, and generalized composition, then lift this to vector-valued maps via the coordinatewise predicate `VecEMLComp`. We prove three foundational categorical theorems — identity, composition closure, and finite product structure (pairing) — establishing that EML-computable maps form a category with finite products. On the positive-input domain `PosVec n`, we define log-affine maps and prove closure under multiplication and a log-chart linearization theorem. We provide a verified normalization algorithm for the multiplicative positive fragment, showing that every expression in this fragment reduces to a weighted geometric monomial. All results are machine-verified, with no unproven assumptions beyond standard mathematical axioms.

**Keywords:** Categorical semantics, EML computation, finite products, log-affine maps, formal verification, normalization, weighted geometric mean.

## 1. Introduction

### 1.1 Motivation

The operations of exponentiation, logarithm, and multiplication appear throughout quantitative science: radioactive decay, compound interest, scaling laws in biology, production functions in economics, partition functions in statistical mechanics, and activation functions in deep learning. Despite their ubiquity, these operations have not been studied as a *closed computational category* with the tools of modern categorical semantics.

Previous work established that the *unary* EML closure — functions `ℝ → ℝ` generated by constants, addition, multiplication, and composition — forms a closure operator satisfying extensivity, monotonicity, and idempotence [ClosureOperator.lean]. The vector-valued EML approximation theory [VecEML.lean] showed that scalar EML generators produce dense subalgebras in `C(X, ℝⁿ)` via Stone-Weierstrass arguments.

However, these results remain in the "approximation-theoretic" and "unary" worlds. The categorical question — *do EML-computable maps between finite-dimensional spaces compose, pair, and curry in a way that constitutes a genuine semantic category?* — had not been addressed.

### 1.2 Contributions

1. **Multivariate EML predicate.** We define `ScalarEML n` as an inductive predicate on functions `(Fin n → ℝ) → ℝ`, with a generalized composition rule through intermediate dimensions. The vector-valued predicate `VecEMLComp n m` is defined coordinatewise.

2. **Categorical structure (Theorems 1–3).** We prove:
   - `vecEMLComp_id`: the identity is EML-computable.
   - `vecEMLComp_comp`: EML maps compose.
   - `vecEMLComp_pair`: EML maps support pairing (finite products).

3. **Log-affine cross-domain theorems (Theorems 4–5).**
   - `logAffine_mul_closed`: log-affine maps are closed under multiplication.
   - `logAffine_log_is_affine`: log-affine maps become affine in log coordinates.

4. **Currying theorem (Theorem 6).**
   - `vecEMLComp_curry`: fixing parameters of an EML-computable map preserves computability.

5. **Verified normalization algorithm.**
   - `PosEMLExpr` syntax for the multiplicative positive fragment.
   - `toLogAffineForm`: syntactic normalization to weights and constant.
   - `evalPosEML_eq_logAffine`: semantic correctness of normalization.

6. **All results are formally verified** in Lean 4 with Mathlib, with no `sorry` or non-standard axioms.

### 1.3 Related Work

- **O-minimal structures** (van den Dries, 1998): The real exponential field (ℝ, +, ·, exp) generates an o-minimal structure `ℝ_exp`. Our EML fragment is contained in the definable functions of `ℝ_exp`. However, o-minimality does not provide categorical semantics or explicit normalization.

- **Closure operators** (Birkhoff, 1967; ClosureOperator.lean): The unary EML closure is a Moore family. We extend this from unary to multivariate with explicit finite-product structure.

- **Stone-Weierstrass approximation** (VecEML.lean): The vector-valued density theorem shows EML generators approximate all continuous functions. Our categorical results are *exact*, not approximate.

- **Differentiable programming** (Abadi et al., 2016; Baydin et al., 2018): The currying theorem connects to the semantics of parameterized models in differentiable programming.

## 2. Definitions and Notation

### 2.1 Scalar EML Computability

**Definition 2.1** (`ScalarEML`). The predicate `ScalarEML n f` is defined inductively on `f : (Fin n → ℝ) → ℝ`:

| Constructor | Rule |
|---|---|
| `coord i` | `ScalarEML n (fun x => x i)` |
| `const c` | `ScalarEML n (fun _ => c)` |
| `add hf hg` | `ScalarEML n f → ScalarEML n g → ScalarEML n (fun x => f x + g x)` |
| `mul hf hg` | `ScalarEML n f → ScalarEML n g → ScalarEML n (fun x => f x * g x)` |
| `exp hf` | `ScalarEML n f → ScalarEML n (fun x => exp(f x))` |
| `comp hh hg` | `ScalarEML m h → (∀ i, ScalarEML n (gᵢ)) → ScalarEML n (fun x => h(g₁(x), …, gₘ(x)))` |

The composition rule is the key design choice: it allows composing a scalar function of `m` variables with `m` scalar EML functions of `n` variables, effectively enabling multivariate-to-multivariate composition at the scalar level.

### 2.2 Vector-Valued EML Computability

**Definition 2.2** (`VecEMLComp`). A function `f : (Fin n → ℝ) → (Fin m → ℝ)` is EML-computable if each output coordinate is scalar EML:

```
VecEMLComp n m f ≡ ∀ j : Fin m, ScalarEML n (fun x => f x j)
```

### 2.3 Positive Vectors

**Definition 2.3** (`PosVec`). A positive vector of dimension `n`:
```
structure PosVec (n : ℕ) where
  val : Fin n → ℝ
  pos : ∀ i, 0 < val i
```

### 2.4 Log-Affine Maps

**Definition 2.4** (`LogAffine`). A function `f : PosVec n → ℝ` is log-affine if:
```
∃ w : Fin n → ℝ, ∃ c : ℝ, ∀ x, f x = exp(∑ᵢ wᵢ · log(xᵢ) + c)
```

Equivalently, `f(x) = eᶜ · ∏ᵢ xᵢ^{wᵢ}`, a weighted geometric monomial.

## 3. Main Results

### 3.1 Theorem 1: Identity

**Theorem** (`vecEMLComp_id`). *For all n, the identity map `id : (Fin n → ℝ) → (Fin n → ℝ)` is EML-computable.*

*Proof.* For each coordinate `j`, the function `x ↦ x j` is `ScalarEML.coord j`. □

### 3.2 Theorem 2: Composition Closure

**Theorem** (`vecEMLComp_comp`). *If `f : (Fin n → ℝ) → (Fin m → ℝ)` and `g : (Fin m → ℝ) → (Fin k → ℝ)` are both EML-computable, then `g ∘ f` is EML-computable.*

*Proof.* For each output coordinate `j : Fin k`, we need `ScalarEML n (fun x => g(f(x)) j)`. We have `hg j : ScalarEML m (fun y => g y j)` and `hf : ∀ i, ScalarEML n (fun x => f x i)`. By `ScalarEML.comp`, composing `hg j` with the family `hf` gives `ScalarEML n (fun x => g(fun i => f x i) j) = ScalarEML n (fun x => g(f x) j)`. □

*Remark.* This is the multivariate generalization of `eml_closure_closed_under_comp` from the unary theory. The generalized composition rule in `ScalarEML` is precisely designed to make this proof work: it lifts unary composition to vector composition by packaging all coordinate functions as the intermediate vector.

### 3.3 Theorem 3: Finite Products (Pairing)

**Theorem** (`vecEMLComp_pair`). *If `f : (Fin n → ℝ) → (Fin m → ℝ)` and `g : (Fin n → ℝ) → (Fin k → ℝ)` are EML-computable, then the paired map `(f, g) : (Fin n → ℝ) → (Fin (m+k) → ℝ)` defined by `Fin.addCases (f x) (g x)` is EML-computable.*

*Proof.* For `j : Fin (m+k)`, apply `Fin.addCases`:
- If `j` is in the first `m` coordinates (i.e., `j = Fin.castAdd k i`), the output is `f x i`, which is `ScalarEML n` by `hf i`.
- If `j` is in the last `k` coordinates (i.e., `j = Fin.natAdd m i`), the output is `g x i`, which is `ScalarEML n` by `hg i`.

The `Fin.addCases` eliminator handles the case split definitionally. □

*Significance.* This establishes that the category of EML-computable maps has finite products. The product of objects `m` and `k` is `m + k`, with projections given by coordinate restriction and the pairing map given by `Fin.addCases`.

### 3.4 Theorem 4: Log-Affine Closure Under Multiplication

**Theorem** (`logAffine_mul_closed`). *If `f, g : PosVec n → ℝ` are both log-affine, then `f · g` is log-affine.*

*Proof.* Let `f(x) = exp(∑ w₁ᵢ · log xᵢ + c₁)` and `g(x) = exp(∑ w₂ᵢ · log xᵢ + c₂)`. Then:
```
f(x) · g(x) = exp(∑ w₁ᵢ · log xᵢ + c₁) · exp(∑ w₂ᵢ · log xᵢ + c₂)
            = exp((∑ w₁ᵢ · log xᵢ + c₁) + (∑ w₂ᵢ · log xᵢ + c₂))    [by exp_add]
            = exp(∑ (w₁ᵢ + w₂ᵢ) · log xᵢ + (c₁ + c₂))               [by sum_add_distrib]
```
So `f · g` is log-affine with weights `w₁ + w₂` and constant `c₁ + c₂`. □

### 3.5 Theorem 5: Log Chart Linearization

**Theorem** (`logAffine_log_is_affine`). *If `f : PosVec n → ℝ` is log-affine, then there exist `w : Fin n → ℝ` and `c : ℝ` such that `log(f(x)) = ∑ᵢ wᵢ · log(xᵢ) + c` for all positive `x`.*

*Proof.* Since `f(x) = exp(∑ wᵢ · log xᵢ + c)`, we have `log(f(x)) = log(exp(∑ wᵢ · log xᵢ + c)) = ∑ wᵢ · log xᵢ + c` by `log_exp`. □

*Significance.* This identifies the multiplicative EML fragment with affine geometry in logarithmic coordinates. The change of variables `yᵢ = log xᵢ` transforms the multiplicative world into the additive world, and log-affine functions become genuinely affine functions `y ↦ w · y + c`.

### 3.6 Theorem 6: Currying

**Theorem** (`vecEMLComp_curry`). *If `f : (Fin (p+n) → ℝ) → (Fin m → ℝ)` is EML-computable and `θ : Fin p → ℝ`, then the specialized map `x ↦ f(θ, x)` is EML-computable on `Fin n → ℝ`.*

*Proof.* For each output coordinate `j`, compose `hf j : ScalarEML (p+n) (fun y => f y j)` with the family of functions that maps `x : Fin n → ℝ` to `Fin.addCases θ x : Fin (p+n) → ℝ`. For index `i : Fin (p+n)`:
- If `i < p`: the function `x ↦ (Fin.addCases θ x) i = θ i` is `ScalarEML.const (θ i)`.
- If `i ≥ p`: the function `x ↦ (Fin.addCases θ x) i = x (i-p)` is `ScalarEML.coord (i-p)`.

By `ScalarEML.comp`, the composition is `ScalarEML n`. □

### 3.7 Normalization Theorem

**Theorem** (`evalPosEML_eq_logAffine`). *For every expression `e : PosEMLExpr n` and positive vector `x : PosVec n`:*
```
eval(e)(x) = exp(∑ᵢ toLogAffineForm(e).w[i] · log(x[i]) + toLogAffineForm(e).c)
```

*Proof.* By structural induction on `e`:
- **coord i**: `eval = xᵢ`, normal form has `w = eᵢ, c = 0`. Then `exp(1 · log xᵢ + 0) = exp(log xᵢ) = xᵢ`.
- **posConst c**: `eval = c`, normal form has `w = 0, c' = log c`. Then `exp(0 + log c) = c`.
- **mul e₁ e₂**: By IH, both subexpressions equal their normal forms. The product `exp(a) · exp(b) = exp(a + b)` and the weight/constant addition follows from `sum_add_distrib`.
- **rpow e r**: By IH, `eval(e) = exp(s)`. Then `exp(s)^r = exp(r · s)` (by `rpow_def_of_pos` and `exp_pos`), and `r · (∑ wᵢ log xᵢ + c) = ∑ (r · wᵢ) log xᵢ + r · c`.

□

## 4. Algorithms

### 4.1 Log-Affine Normalization

**Algorithm** (`toLogAffineForm`).

```
Input: PosEMLExpr e, dimension n
Output: (w : ℝⁿ, c : ℝ) such that eval(e, x) = exp(w · log(x) + c)

function normalize(e, n):
  match e with
  | Coord(i)     → return (eᵢ, 0)
  | PosConst(c)  → return (0, log(c))
  | Mul(e₁, e₂)  → (w₁,c₁) ← normalize(e₁,n); (w₂,c₂) ← normalize(e₂,n)
                     return (w₁+w₂, c₁+c₂)
  | RPow(e, r)   → (w,c) ← normalize(e,n)
                     return (r·w, r·c)
```

**Complexity.** Time: O(n · |e|) where |e| is the expression size. Space: O(n · depth(e)) for the recursion stack.

**Correctness.** Verified by `evalPosEML_eq_logAffine` — the algorithm's output satisfies the log-affine identity for all positive inputs.

### 4.2 Log-Affine Composition

Given `outer : LogAffine(m)` with weights `v` and constant `d`, and `inners : LogAffine(n)^m` with weights `W` and constants `c`, the composed function is log-affine with:
- Weights: `w'[i] = ∑ⱼ v[j] · W[j][i]` (matrix-vector product)
- Constant: `c' = ∑ⱼ v[j] · c[j] + d`

**Complexity.** O(n · m).

## 5. Applications

### 5.1 Economics: Cobb-Douglas Production Functions

The Cobb-Douglas function `Y = A · L^α · K^β` is log-affine with weights `(α, β)` and constant `log A`. By `logAffine_mul_closed`, products of Cobb-Douglas functions (e.g., aggregating economic sectors) remain log-affine. By `logAffine_log_is_affine`, the function becomes affine in log coordinates: `log Y = α · log L + β · log K + log A`. This provides a rigorous foundation for the common econometric practice of log-log regression.

### 5.2 Chemistry: Mass-Action Kinetics

Reaction rates `r = k · [A]^a · [B]^b` are log-affine maps on concentrations. The multiplicative closure theorem (`logAffine_mul_closed`) ensures that combining multiple reaction pathways preserves log-affine structure.

### 5.3 Machine Learning: Parameterized Families

The currying theorem (`vecEMLComp_curry`) formalizes the structure of trainable models: an EML-computable map `F(θ, x)` on the joint parameter-input space gives rise, for each parameter value `θ`, to an EML-computable map `F_θ(x)`. This connects to the semantics of differentiable programming.

### 5.4 Portfolio Theory: Geometric Mean Returns

The weighted geometric mean `GM(x; w) = exp(∑ wᵢ log xᵢ)` is a log-affine function (`emlComputable_weightedGeomMean`). Portfolio rebalancing — computing geometric mean returns across time periods — is a composition of log-affine maps, which by `vecEMLComp_comp` remains EML-computable.

### 6.1 Normalization Verification

We randomly generated 100 multiplicative positive EML expressions of depth up to 4, dimension 3, and verified that direct evaluation agrees with log-affine normal form evaluation to within machine precision (max log-space error: 1.78 × 10⁻¹⁵). See `algorithms.py`.

## 7. Discussion

### 7.1 Relationship to O-Minimal Geometry

The EML-computable functions are contained in the definable functions of the o-minimal structure ℝ_exp. However, our results are complementary to o-minimality:
- O-minimality gives *finiteness* results (definable sets have finitely many connected components) but not *categorical structure*.
- Our framework gives *compositional semantics* (identity, composition, products, currying) but not finiteness guarantees.

### 7.2 Limitations

1. **No logarithm in the general fragment.** Our `ScalarEML` does not include `log` as a primitive because `log` is only defined on positive reals. The positive-domain fragment (`LogAffine`, `PosEMLExpr`) handles logarithms correctly, but the general theory works only with `exp`.

2. **No full Cartesian closure.** We prove currying (parameter specialization) but not uncurrying. Full Cartesian closure would require representing function spaces `(Fin n → ℝ) → (Fin m → ℝ)` as EML objects, which is impossible in finite dimensions for the full function space.

3. **No smoothness or analyticity proofs.** We conjecture that all EML-computable functions are real-analytic but have not yet formalized this.

### 7.3 Comparison with Existing Catalog Results

| Result | Unary (ClosureOperator.lean) | Multivariate (this work) |
|---|---|---|
| Closure under composition | ✓ (`eml_closure_closed_under_comp`) | ✓ (`vecEMLComp_comp`) |
| Closure under pairing | N/A (unary) | ✓ (`vecEMLComp_pair`) |
| Product structure | N/A | ✓ (finite products) |
| Currying | N/A | ✓ (`vecEMLComp_curry`) |
| Log-affine theory | Implicit via `power_via_exp_log` | Explicit (`LogAffine`, normalization) |
| Normalization | None | ✓ (`evalPosEML_eq_logAffine`) |

## 8. Future Work

1. **Tropical limits.** Formalize the limit `limₜ→∞ (1/t) · log(∑ⱼ exp(t · fⱼ))` as a bridge from EML to tropical geometry.

2. **Analyticity.** Prove that all `ScalarEML` functions are `AnalyticAt` using Mathlib's analytic function library.

3. **Uncurrying.** Investigate conditions under which parameterized EML families can be "uncurried" to EML maps on the joint space.

4. **Complexity bounds.** Relate the depth/size of `ScalarEML` derivations to computational complexity of the resulting functions.

5. **Differential structure.** Prove that EML-computable maps are smooth and that the resulting category embeds faithfully into `Diff` (smooth manifolds and smooth maps).
