# Certified AC Canonical Forms for Tropical Expressions: A Decision Procedure Kernel

## Abstract

We present a machine-verified canonical form normalizer for the associative-commutative (AC) fragment of tropical (min-plus) expression algebra. Working over the expression language generated by constants in ℝ, variables indexed by ℕ, binary minimum (`tmin`), and binary addition (`add`), we define a normalizer `normalize_ca` that flattens same-head operator trees, sorts children by a total order, and rebuilds right-associated canonical trees. We prove three main theorems:

1. **Soundness**: `∀ σ e, eval σ (normalize_ca e) = eval σ e`
2. **Completeness**: `∀ e₁ e₂, ACEquiv e₁ e₂ → normalize_ca e₁ = normalize_ca e₂`
3. **Idempotence**: `∀ e, normalize_ca (normalize_ca e) = normalize_ca e`

Together, these establish a certified decision procedure for AC equivalence of tropical expressions: two expressions are AC-equivalent if and only if they have the same canonical form. All proofs are formalized in Lean 4 with Mathlib and verified by the Lean kernel, using only the standard axioms (`propext`, `Classical.choice`, `Quot.sound`).

## 1. Introduction

### 1.1 Motivation

The tropical semiring `(ℝ ∪ {∞}, min, +)` appears throughout optimization, algebraic geometry, phylogenetics, and machine learning. Expressions in this semiring encode shortest-path computations, linear programming relaxations, and piecewise-linear functions arising from ReLU neural networks. A fundamental question for any algebraic structure is: *when are two expressions semantically equivalent?*

For the full tropical semiring, this question is complicated by the interaction between `min` and `+` via distributivity. However, the associative-commutative fragment—where we only quotient by commutativity and associativity of each operation independently—admits a clean canonical form.

### 1.2 Contributions

- A complete formalization of a canonical form normalizer for AC tropical expressions.
- A proof that the normalizer is a decision procedure for the AC congruence.
- Precise identification of the boundary: distributivity and idempotence create equivalences outside the scope of AC canonicalization.
- A modular proof architecture that separates flattening, sorting, and rebuilding concerns.

### 1.3 Related Work

Term rewriting modulo AC has a long history, starting with Peterson and Stickel (1981). Knuth-Bendix completion modulo AC was developed by Jouannaud and Kirchner (1986). Our work specializes these general frameworks to tropical expressions and provides full machine verification.

In the setting of proof assistants, the `ring` tactic normalizes polynomial expressions via Horner forms. Our work provides the tropical analogue of this infrastructure.

## 2. Definitions and Notation

### 2.1 Expression Language

```
inductive TropExpr where
  | const : ℝ → TropExpr
  | var   : ℕ → TropExpr
  | tmin  : TropExpr → TropExpr → TropExpr
  | add   : TropExpr → TropExpr → TropExpr
```

### 2.2 Semantics

Given an environment `σ : ℕ → ℝ`:

```
eval σ (const r) = r
eval σ (var n) = σ n
eval σ (tmin a b) = min (eval σ a) (eval σ b)
eval σ (add a b) = eval σ a + eval σ b
```

### 2.3 AC Congruence

The AC congruence `ACEquiv` is the smallest equivalence relation on `TropExpr` containing:
- `tmin_comm`: `tmin a b ≡ tmin b a`
- `tmin_assoc`: `tmin (tmin a b) c ≡ tmin a (tmin b c)`
- `add_comm`: `add a b ≡ add b a`
- `add_assoc`: `add (add a b) c ≡ add a (add b c)`

closed under congruence (`cong_tmin` and `cong_add`).

### 2.4 Comparison Function

We define a total order `TropExpr.cmp : TropExpr → TropExpr → Ordering` that compares expressions lexicographically:
- Cross-constructor: `const < var < tmin < add` (by tag)
- Same constructor: recursively compare children

We prove:
- **Reflexivity**: `cmp e e = .eq`
- **Antisymmetry**: `cmp e₁ e₂ = .eq ↔ e₁ = e₂`
- **Totality**: `ble e₁ e₂ ∨ ble e₂ e₁`
- **Transitivity**: `ble e₁ e₂ → ble e₂ e₃ → ble e₁ e₃`

where `ble e₁ e₂ = (cmp e₁ e₂ ≠ .gt)`.

## 3. Normalization Algorithm

### 3.1 Flattening

```
flattenMin (tmin a b) = flattenMin a ++ flattenMin b
flattenMin e = [e]  -- for non-tmin e

flattenAdd (add a b) = flattenAdd a ++ flattenAdd b
flattenAdd e = [e]  -- for non-add e
```

**Lemma 3.1**: `flattenMin` produces nonempty lists with no `tmin` elements. Similarly for `flattenAdd`.

### 3.2 Sorting and Rebuilding

```
normalize_ca (const r) = const r
normalize_ca (var n) = var n
normalize_ca (tmin a b) =
  let a' := normalize_ca a
  let b' := normalize_ca b
  buildMin (mergeSort ble (flattenMin (tmin a' b')))
normalize_ca (add a b) =
  let a' := normalize_ca a
  let b' := normalize_ca b
  buildAdd (mergeSort ble (flattenAdd (add a' b')))
```

where `buildMin` and `buildAdd` construct right-associated trees from sorted lists.

### 3.3 Complexity

The normalization runs in O(n log n) time where n is the expression size, dominated by the merge sort step at each level. The total work across all levels is O(n log²n) in the worst case.

## 4. Main Results

### 4.1 Soundness (Theorem 4.1)

**Statement**: `∀ σ e, eval σ (normalize_ca e) = eval σ e`

**Proof sketch**: By structural induction. For `tmin a b`, the evaluation chain is:

```
eval σ (normalize_ca (tmin a b))
= eval σ (buildMin (mergeSort ...))     -- by definition
= evalMinList σ (mergeSort ...)          -- by eval_buildMin_eq
= evalMinList σ (flattenMin ...)         -- by permutation invariance of evalMinList
= eval σ (tmin (normalize_ca a) (normalize_ca b))  -- by eval_flattenMin
= min (eval σ (normalize_ca a)) (eval σ (normalize_ca b))
= min (eval σ a) (eval σ b)             -- by IH
= eval σ (tmin a b)
```

The key lemmas are:
- `evalMinList_perm`: evalMinList is invariant under permutations
- `evalMinList_append`: evalMinList distributes over concatenation as min
- `eval_flattenMin`: flattenMin preserves evalMinList semantics

### 4.2 Completeness (Theorem 4.2)

**Statement**: `∀ e₁ e₂, ACEquiv e₁ e₂ → normalize_ca e₁ = normalize_ca e₂`

**Proof sketch**: By induction on the ACEquiv derivation.

- **refl, symm, trans**: trivial from properties of equality
- **tmin_comm**: `flattenMin(tmin(a',b')) = flattenMin(a') ++ flattenMin(b')` and `flattenMin(tmin(b',a')) = flattenMin(b') ++ flattenMin(a')`. These are permutations, so `mergeSort_perm_eq` gives the same sorted output.
- **tmin_assoc**: Both sides flatten to `flattenMin(a') ++ flattenMin(b') ++ flattenMin(c')` (by associativity of list concatenation), so the sorted outputs are identical.
- **cong_tmin**: If `normalize_ca a = normalize_ca a'` and `normalize_ca b = normalize_ca b'`, then the flattened lists are identical, hence the sorted outputs are identical.

The crucial lemma is `mergeSort_perm_eq`: if two lists are permutations, their merge sort outputs are equal. This follows from the uniqueness of sorted permutations (via `List.Perm.eq_of_pairwise`) combined with the totality and antisymmetry of `ble`.

### 4.3 Idempotence (Theorem 4.3)

**Statement**: `∀ e, normalize_ca (normalize_ca e) = normalize_ca e`

**Proof sketch**: We prove a helper lemma `normalize_ca_ACEquiv`: for all `e`, `ACEquiv (normalize_ca e) e`. This follows because:
1. `buildMin(mergeSort(flattenMin(...)))` is ACEquiv to `buildMin(flattenMin(...))` (by `buildMin_perm_ACEquiv` with the merge sort permutation)
2. `buildMin(flattenMin(e))` is ACEquiv to `e` (by `buildMin_flattenMin_ACEquiv`, using tmin_assoc to reassociate)
3. The recursive structure preserves ACEquiv via `cong_tmin` and `cong_add`.

Then idempotence follows immediately from completeness: `normalize_ca(normalize_ca e) = normalize_ca e` because `ACEquiv (normalize_ca e) e` implies `normalize_ca (normalize_ca e) = normalize_ca e`.

### 4.4 ACEquiv Soundness (Theorem 4.4)

**Statement**: `∀ σ e₁ e₂, ACEquiv e₁ e₂ → eval σ e₁ = eval σ e₂`

This is a straightforward induction using `min_comm`, `min_assoc`, `add_comm`, `add_assoc`.

## 5. Proof Architecture

### 5.1 Lemma Dependencies

The proof is organized in layers:

1. **List evaluation** (`evalMinList`, `evalAddList`): Fold-based semantics for lists of expressions under min/+.
2. **Flattening correctness** (`eval_flattenMin`, `eval_flattenAdd`): Flattening preserves list evaluation.
3. **Permutation invariance** (`evalMinList_perm`, `evalAddList_perm`): List evaluation is invariant under permutations.
4. **Build correctness** (`eval_buildMin_eq`, `eval_buildAdd_eq`): Building from lists preserves list evaluation.
5. **Total order properties** (`cmp_refl`, `cmp_eq_iff`, `cmp_symm`, `cmp_trans`, `ble_total`, `ble_antisymm`, `ble_trans`): The comparison function is a decidable total order.
6. **Merge sort determinism** (`mergeSort_perm_eq`): Permutations sort to the same output.
7. **AC structure** (`flattenMin_buildMin`, `buildMin_perm_ACEquiv`, `buildMin_flattenMin_ACEquiv`, `normalize_ca_ACEquiv`): The flatten-sort-rebuild cycle respects AC equivalence.

### 5.2 Total Order Proof Structure

The transitivity of `cmp` required careful decomposition:
- **Cross-constructor**: Follows from tag ordering (const < var < tmin < add).
- **Same-constructor base cases**: `const` uses ℝ-order transitivity; `var` uses ℕ-comparison transitivity.
- **Same-constructor recursive cases**: Factored into `cmp_trans_lex`, which handles the lexicographic comparison pattern and calls `cmp_trans` recursively on subexpressions.

## 6. Why Completeness Fails Outside AC

### 6.1 Distributivity

The identity `a + min(b, c) = min(a + b, a + c)` creates an equivalence between `add a (tmin b c)` and `tmin (add a b) (add a c)`. These have different head constructors (`add` vs `tmin`), so no amount of flattening within each operator can detect this equivalence.

### 6.2 Idempotence

The identity `min(a, a) = a` creates an equivalence between `tmin a a` and `a`. These have different sizes, so the flattened lists have different lengths, and sorting cannot reconcile them.

### 6.3 Precise Boundary

Our normalizer is complete for exactly the AC congruence and nothing more. Any extension to distributivity or idempotence requires fundamentally different techniques (completion, polynomial normal forms, or multiset quotients with deduplication).

## 7. Applications

### 7.1 Shortest-Path Verification

Two routing configurations produce identical shortest paths iff their tropical expression representations have the same AC canonical form (modulo the AC fragment).

### 7.2 Neural Network Analysis

ReLU networks define piecewise-linear functions expressible in the tropical semiring. AC canonicalization identifies structurally redundant computations.

### 7.3 Proof Automation

The canonical form theorem enables a reflection-based tactic for automatically proving AC-tropical identities, analogous to the `ring` tactic for polynomial identities.

## 8. Conclusion

We have formalized a complete, sound, and idempotent canonical form normalizer for the AC fragment of tropical expressions, verified in Lean 4 with Mathlib. The key technical contributions are:

1. A modular flatten-sort-rebuild architecture with clean separation of concerns.
2. A complete proof of the total order properties of the structural comparison function.
3. A proof that merge sort determinism (permutations sort to the same output) bridges the gap between multiset equality and syntactic equality.
4. Precise characterization of the completeness boundary at the AC fragment.

This work establishes the foundation for certified tropical algebra automation and opens concrete paths toward handling distributivity, idempotence, and full tropical polynomial canonicalization.
