# Future Directions: Abstract Σ-Protocol Theory

## 1. OR-Composition via Challenge Splitting (CDS Technique)

The Cramer-Damgård-Schoenmakers (CDS) OR-composition allows proving knowledge of a witness for *at least one* of two relations without revealing which one. The prover splits the challenge `e = e₁ + e₂` (over a group), simulates one component, and honestly executes the other. The key insight is that the additive constraint on challenges makes the composition simulatable even when only one witness is known, because the prover can choose one challenge freely and derive the other. Why now? We have `ANDCompose` and `IsHVZK` infrastructure; OR-composition requires extending the simulator definition to allow the prover to choose one component's challenge, which is a natural next step that would complete the picture of basic Σ-protocol combinators.

## 2. Fiat-Shamir Transform and Non-Interactive Zero-Knowledge

The Fiat-Shamir heuristic transforms any Σ-protocol into a non-interactive proof by replacing the verifier's random challenge with a hash of the commitment: `e = H(x, a)`. This is the foundation of modern SNARKs and signature schemes. The key insight is that in the random oracle model, the hash function is modeled as a uniformly random function, and soundness follows from the "forking lemma" — if an adversary can produce a valid proof, rewinding with a different oracle gives two accepting transcripts with the same commitment but different challenges, enabling extraction via special soundness. Why now? We have `IsSpecialSound` and `special_sound_answerable_bound`; formalizing the random oracle model as a function type `(X × A) → E` with appropriate uniformity conditions would connect our abstract theory to the non-interactive setting used in practice.

## 3. Computational Zero-Knowledge and One-Way Functions

Our current formalization captures *perfect/statistical* zero-knowledge (simulator output exactly matches real transcripts). Computational zero-knowledge relaxes this to computational indistinguishability, which is the standard in practice. The key insight is that computational ZK requires formalizing polynomial-time computability and computational indistinguishability of distribution ensembles, which would bridge our abstract Σ-protocol theory to complexity-theoretic cryptography. This is a substantial infrastructure investment but would enable formalizing the GMW theorem (every NP language has a computational ZK proof). Why now? The abstract framework is in place; the gap is a formalization of "efficient computation" that connects to our protocol definitions.

## 4. Soundness Amplification with Tight Bounds

Our `par_repeat_special_sound` shows that parallel repetition preserves special soundness. The quantitative question is: does k-fold repetition reduce soundness error from `1/|E|` to exactly `(1/|E|)^k`? The key insight is that for *parallel* repetition of Σ-protocols (not general interactive proofs!), the tight bound holds because the prover must cheat on all k instances independently — unlike Raz's parallel repetition theorem for general interactive proofs, where the decay is not perfectly exponential. Proving the tight `(1/|E|)^k` bound requires formalizing the product structure of the answerable set in the repeated protocol. Why now? We have `answerableSet` and `special_sound_answerable_bound`; the product bound is a natural cardinality argument on `Fin k → E` that extends our existing combinatorial framework.

## 5. Σ-Protocol for Graph 3-Coloring

Graph 3-coloring is NP-complete, so a Σ-protocol for it (combined with the GMW compiler) yields ZK proofs for all of NP. The protocol uses commitment schemes: the prover commits to a random permutation of a valid 3-coloring, the verifier challenges with an edge, and the prover opens the commitments for that edge's endpoints. The key insight is that special soundness follows from the binding property of the commitment scheme (two openings of the same edge with the same commitment but different revealed colors extract a coloring inconsistency), while HVZK follows from the hiding property (the simulator picks two random colors for the challenged edge). Formalizing this requires our `SigmaProto` framework instantiated with graph types from Mathlib's `SimpleGraph`. Why now? We have the abstract Σ-protocol theory; instantiating it with `SimpleGraph` and `CommitmentScheme` (already defined in the catalog) would produce the first machine-verified proof that graph 3-coloring has a zero-knowledge proof.
