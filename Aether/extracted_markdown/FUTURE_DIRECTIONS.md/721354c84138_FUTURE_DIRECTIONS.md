# Future Directions: Coefficient Extraction Framework

## Overview

The formalization of the coefficient extraction identity and the Combinatorial Nullstellensatz opens a rich landscape of research opportunities. Each direction below includes a precise theorem target, a proof strategy, and cross-domain applications.

---

## Direction 1: Cauchy-Davenport via Coefficient Extraction

### Theorem Statement
For a prime *p* and nonempty subsets *A*, *B* ⊂ ℤ/pℤ:
$$|A + B| \geq \min(p,\; |A| + |B| - 1)$$

### Lean Target
```lean
theorem cauchy_davenport (p : ℕ) [hp : Fact (Nat.Prime p)]
    (A B : Finset (ZMod p)) (hA : A.Nonempty) (hB : B.Nonempty) :
    (Finset.image (fun ab => ab.1 + ab.2) (A ×ˢ B)).card ≥
      min p (A.card + B.card - 1)
```

### Proof Strategy
1. Assume for contradiction that |A + B| = m < |A| + |B| - 1.
2. Choose C ⊆ A + B with |C| = m.
3. Define f(x, y) = ∏_{c ∈ C} (x + y - c) in (ZMod p)[x, y].
4. Show deg_x(f) = m ≤ |A| - 1 and deg_y(f) = m ≤ |B| - 1.
5. Show f vanishes on A × B (since a + b ∈ A + B ⊇ C).
6. Show the coefficient of x^{|A|-1} y^{|B|-1} is C(m, |A|-1) ≠ 0 in ℤ/pℤ (using Lucas's theorem and m < p).
7. Apply `exists_eval_ne_zero_mv` to get a contradiction.

### Cross-Domain Payoff
- **Additive combinatorics**: Opens the door to restricted sumset bounds (Erdős-Heilbronn, Davenport transform).
- **Coding theory**: Sumset lower bounds are related to minimum distance bounds for algebraic codes.
- **Number theory**: Connections to Freiman-Ruzsa theorem and inverse sumset problems.

### Estimated Difficulty: Medium
The main challenge is establishing that the binomial coefficient C(m, |A|-1) is nonzero mod p, which requires Lucas's theorem formalized in Mathlib.

## Direction 2: Vanishing Ideal of a Finite Grid

### Theorem Statement
The ideal of polynomials in K[X₁, …, Xₙ] vanishing on the grid ∏ᵢ Sᵢ is generated by the univariate vanishing polynomials:
$$I(\prod_i S_i) = \langle g_1(X_1), \ldots, g_n(X_n) \rangle$$
where $g_i(T) = \prod_{s \in S_i} (T - s)$.

### Lean Target
```lean
theorem vanishing_ideal_grid
    {ι : Type*} [Fintype ι] [DecidableEq ι]
    {K : Type*} [Field K] [DecidableEq K]
    (S : ι → Finset K) (hS : ∀ i, (S i).Nonempty)
    (f : MvPolynomial ι K)
    (hf : ∀ x ∈ grid S, MvPolynomial.eval x f = 0) :
    f ∈ Ideal.span {g | ∃ i, g = ∏ s ∈ S i, (MvPolynomial.X i - MvPolynomial.C s)}
```

### Proof Strategy
1. Prove the univariate case first: if p vanishes on S, then ∏_{s ∈ S}(X - s) | p. (Already done in our framework as `gridPoly_dvd_of_roots`.)
2. For multivariate: fix one variable i₀ and perform polynomial division of f by g_{i₀}(X_{i₀}), viewing f as a univariate polynomial in X_{i₀} with coefficients in K[other variables].
3. The remainder has degree < |S_{i₀}| in X_{i₀} and still vanishes on the grid.
4. By induction on the number of variables, the remainder lies in the ideal generated by the remaining g_i.
5. Combine to get f in the full ideal.

### Cross-Domain Payoff
- **Algebraic geometry**: Characterizes the coordinate ring of a finite grid as a quotient.
- **Gröbner basis theory**: The grid polynomials form a Gröbner basis for the vanishing ideal.
- **Sparse interpolation**: Quotient ring structure enables efficient multipoint evaluation.

### Estimated Difficulty: Hard
Requires formalizing polynomial division in the multivariate setting, viewing MvPolynomial ι K as a univariate polynomial ring over MvPolynomial (ι \ {i₀}) K.

## Direction 3: Tropical Support Extraction Conjecture

### Conjecture Statement
In the tropical semiring (ℝ ∪ {∞}, min, +), the "support extraction" principle states: if a tropical polynomial f has a monomial with coefficient strictly smaller (more extreme) than all other monomials at the exponent vector d, and if variable bounds are given by finite sets S_i, then there exists a point in the tropical Cartesian product where f achieves a value determined by the d-monomial.

### Lean Target (Conjectural)
```lean
theorem tropical_support_extraction
    {ι : Type*} [Fintype ι] [DecidableEq ι]
    (coeffs : (ι →₀ ℕ) → WithTop ℝ)
    (d : ι →₀ ℕ)
    (S : ι → Finset ℝ)
    (hmin : ∀ m ≠ d, coeffs d < coeffs m) :
    ∃ x ∈ tropicalGrid S,
      tropicalEval coeffs x = coeffs d + ∑ i, d i • tropicalMin (S i)
```

### Proof Strategy
1. Define tropical polynomials as functions (ι →₀ ℕ) → WithTop ℝ.
2. Define tropical evaluation as min over monomials: tropEval(f, x) = min_m (f_m + ∑ᵢ mᵢ · xᵢ).
3. Show that if one coefficient dominates, the minimum at certain extremal grid points is achieved by that monomial.
4. This is an optimization argument rather than an algebraic one.

### Cross-Domain Payoff
- **Tropical geometry**: Formal foundation for tropical algebraic combinatorics.
- **Optimization**: Connections to linear programming duality and min-cost flow.
- **Phylogenetics**: Tropical geometry of tree spaces and distance matrices.

### Estimated Difficulty: Exploratory
The statement itself needs refinement. This direction is more about formulating the right conjecture than proving a known result.

## Direction 4: Quantitative Rational-Height Nonvanishing

### Theorem Statement
Over ℚ, if f ∈ ℤ[X₁, …, Xₙ] has integer coefficients and the coefficient of the top monomial is nonzero, then there exists a grid point x with:
1. f(x) ≠ 0
2. Each |xᵢ| ≤ |Sᵢ|_max (the maximum element of Sᵢ)
3. |f(x)| can be bounded in terms of the coefficient heights and set sizes

### Lean Target
```lean
theorem height_bounded_witness
    (S : ι → Finset ℤ)
    (hS : ∀ i, (S i).Nonempty)
    (f : MvPolynomial ι ℤ)
    (hdeg : ∀ i, f.degreeOf i ≤ (S i).card - 1)
    (hcoeff : MvPolynomial.coeff (gridExpZ S) f ≠ 0) :
    ∃ x ∈ gridZ S, MvPolynomial.eval x f ≠ 0 ∧
      ∀ i, |x i| ≤ Finset.max' (S i) (hS i)
```

### Proof Strategy
1. Apply the Nullstellensatz over ℚ (embed ℤ → ℚ).
2. The grid consists of integer points, so height bounds come for free from the Finset structure.
3. For the evaluation bound, use the triangle inequality and coefficient height estimates.

### Cross-Domain Payoff
- **Number theory**: Effective results in Diophantine problems.
- **Computational algebra**: Bit complexity bounds for polynomial identity testing.
- **Cryptography**: Security proofs for algebraic extraction schemes require quantitative bounds.

### Estimated Difficulty: Medium
Most of the infrastructure is already available; the main work is lifting from fields to integral domains.

## Direction 5: Interpolation-as-Extraction Bridge to Coding Theory

### Theorem Statement
Reed-Solomon decoding can be expressed as coefficient extraction: the message symbols are specific coefficients of the encoding polynomial, recovered via evaluation at the code points.

Formally: for a Reed-Solomon code with evaluation points S ⊂ 𝔽_q and message length k < |S|, the encoding map is p ↦ (p(s))_{s ∈ S}, and the coefficient extraction identity gives the decoding map:

$$p_j = \sum_{s \in S} r(s) \cdot w_j(s)$$

where r is the received word and w_j are recovery weights derived from Lagrange denominators.

### Lean Target
```lean
theorem reed_solomon_decode
    {q : ℕ} [Fact (Nat.Prime q)]
    (S : Finset (ZMod q)) (hS : S.Nonempty)
    (k : ℕ) (hk : k < S.card)
    (p : Polynomial (ZMod q)) (hdeg : p.natDegree < k)
    (received : ZMod q → ZMod q)
    (h_no_errors : ∀ s ∈ S, received s = p.eval s) :
    ∀ j < k, p.coeff j = ∑ s ∈ S, received s * recoveryWeight S j s
```

### Proof Strategy
1. Define recovery weights as coefficients of Lagrange basis polynomials.
2. Show that the extraction identity applied to X^j for each degree j gives the recovery formula.
3. Handle the error-free case first; error correction requires syndrome decoding infrastructure.

### Cross-Domain Payoff
- **Coding theory**: Formal foundations for algebraic coding and decoding.
- **Distributed computing**: Secret sharing schemes (Shamir's) are special cases.
- **Cryptography**: Verifiable computation and algebraic proof systems.

### Estimated Difficulty: Medium-Hard
Requires working over ZMod and connecting the extraction identity to code-theoretic operations.

## Team Directive

Each direction should be pursued by a team with:
- A **formalization lead** responsible for Lean code architecture
- A **mathematics lead** responsible for proof strategy and correctness
- A **applications lead** responsible for connecting to downstream uses

The teams should share a common library of grid definitions, Lagrange interpolation tools, and polynomial arithmetic lemmas built in this project. Weekly iteration cycles should validate hypotheses computationally (Python demos) before formal proof attempts.

The coefficient extraction framework is the common language. Every direction adds to it, and every addition makes the others easier.
