# Future Research Directions

## Synthesis

This cycle established the **EML Derivation Calculus** — a verified symbolic differential algebra for the class of functions generated by exp, log, constants, and arithmetic operations including reciprocal. The key discoveries were: (1) the original EML class without reciprocal is NOT closed under differentiation, and reciprocal is the minimal fix; (2) the inv/log-free fragment is preserved by differentiation, enabling unconditional derivative computation; (3) the derivation tower of exp(x) is semantically constant despite unbounded syntactic growth.

These results connect three catalog threads: the EML closure operator framework (`EML/ClosureOperator.lean`), the Hardy hierarchy for EML functions (`Speculative/HardyHierarchy/Theorems.lean`), and the EML extended theory with its HasDerivAt results (`EML/EMLv17Core.lean`, `EML/ExtendedTheory.lean`). The most promising cross-domain connection is between the **derivation tower** construct and **Hardy field theory** — the tower's semantic behavior classifies functions by their differential complexity, which directly relates to their growth rate in the Hardy hierarchy.

The highest breakthrough potential lies in Direction 1 (formalizing Liouville-Risch theory), which would resolve the integration non-closure question and connect to a major open area in formalized mathematics. Direction 3 (multivariate extension) has the broadest applicability, enabling connections to PDE theory and neural network expressivity.

### Direction 1: Formalized Liouville-Risch Integration Decision Procedure

**Conjecture**: There exists a computable decision procedure, formalizable in Lean 4, that determines whether a given EML expression has an EML antiderivative. Specifically: the antiderivative of `exp(x²)` is not EML-expressible, provable via the Liouville-Risch structure theorem.

**Test**: Formalize Liouville's theorem: if ∫f·exp(g) dx is elementary (where f, g are rational functions), then ∫f·exp(g) dx = R·exp(g) for some rational function R, and R satisfies R' + R·g' = f. Apply to f=1, g=x² to derive a contradiction (no rational R satisfies R' + 2xR = 1). This is a concrete, falsifiable computational test.

**Impact**: If formalized, this would be the first machine-verified proof of a non-elementary integral, establishing a beachhead for formal integration theory. If the approach fails (e.g., Lean's real analysis API lacks the necessary infrastructure for rational function fields), the failure would precisely identify what Mathlib needs.

**Catalog References**: `EML/DifferentialAlgebra.lean` (the `IsAntideriv` predicate and `exp_is_own_antideriv`), `EML/DerivationTower.lean` (the `expXSquared` and `derivExpXSquared` definitions).

**Proof Strategy**: 
1. Define the field of rational functions ℝ(x) within the EML expression framework
2. Formalize the Liouville structure theorem for ∫f·exp(g) dx
3. Apply to the specific case g = x² to derive a contradicting ODE
4. Use `sdiff_eval_hasDerivAt` to connect symbolic and analytic derivatives

**Domain Bridges**: Differential Algebra ↔ Computer Algebra ↔ Computability Theory

**Lineage**: Builds on `exp_is_own_antideriv`, `sdiff_eval_hasDerivAt`, and `deriv_expXSquared_eval` from this cycle.

**Ambition**: grand_challenge

### Direction 2: Derivation Tower Classification and Normal Forms

**Conjecture**: Every EML expression has a unique "differential normal form" — a canonical representative of its derivation tower's semantic equivalence class. The normal form satisfies: (a) `sdiff(NF(e)).eval = sdiff(e).eval` pointwise, and (b) `size(NF(e)) ≤ size(e)`. Furthermore, the normal form is computable in polynomial time.

**Test**: Define a simplification function `simplify : Expr → Expr` that eliminates redundancies (e.g., `mul (cnst 1) e → e`, `add (cnst 0) e → e`, `neg (neg e) → e`). Prove that simplified expressions have strictly smaller or equal size and equal semantics. Then test whether iterated simplification after sdiff prevents the expression swell observed in the derivation tower.

**Impact**: A positive result would give an efficient symbolic differentiation algorithm with controlled expression size — directly applicable to computer algebra systems. A negative result (no polynomial-time normal form exists) would establish a complexity-theoretic lower bound for symbolic differentiation.

**Catalog References**: `EML/DifferentialAlgebra.lean` (`sdiff_size_le`, `exp_semantic_fixpoint`), `EML/DerivationTower.lean` (`exp_tower_eval_eq`).

**Proof Strategy**:
1. Define `simplify` by recursion on expression structure
2. Prove `simplify_eval_eq : (simplify e).eval x = e.eval x`
3. Prove `simplify_size_le : (simplify e).size ≤ e.size`
4. Study `simplify ∘ sdiff` as a "normalized differentiation" operator
5. Prove or disprove polynomial-time convergence of iterated normalized differentiation

**Domain Bridges**: Computer Algebra ↔ Complexity Theory ↔ Term Rewriting

**Lineage**: Builds on `sdiff_size_le` and the observation that exp's tower is semantically constant but syntactically explosive.

**Ambition**: extension

### Direction 3: Multivariate EML Differential Algebra

**Conjecture**: The EML derivation calculus extends to multiple variables with full Schwarz symmetry: mixed partial derivatives commute (∂²f/∂x∂y = ∂²f/∂y∂x) at the symbolic level, not just semantically.

**Test**: Define `ExprN : ℕ → Type` for expressions in n variables, with `sdiff_i` for partial differentiation with respect to variable i. Prove `sdiff_i (sdiff_j e) = sdiff_j (sdiff_i e)` as a syntactic identity (not just after evaluation). If syntactic commutativity fails, characterize the obstruction and determine whether a quotient algebra achieves it.

**Impact**: A multivariate EML calculus would enable formalization of: (a) gradient computations for neural network training, (b) Jacobian and Hessian structure, (c) differential forms and exterior calculus connections. Syntactic Schwarz symmetry would make the calculus practically useful for automatic differentiation.

**Catalog References**: `EML/DifferentialAlgebra.lean` (the univariate `Expr` and `sdiff`), `EML/ClosureOperator.lean` (`EMLGenerated` for set-level closure).

**Proof Strategy**:
1. Extend `Expr` with `var_i : Fin n → Expr` replacing `var`
2. Define `sdiff_i` by structural recursion
3. Attempt to prove `sdiff_i ∘ sdiff_j = sdiff_j ∘ sdiff_i`
4. If it fails, identify the obstruction (likely in the mul case)
5. Define a quotient that achieves commutativity

**Domain Bridges**: Differential Algebra ↔ Automatic Differentiation ↔ Neural Network Theory

**Lineage**: Natural extension of this cycle's univariate calculus.

**Ambition**: extension

### Direction 4: EML Functions as a Hardy Field

**Conjecture**: The set of EML functions, quotiented by eventual equality, forms a Hardy field — an ordered field of germs of real-valued functions closed under differentiation. Furthermore, the derivation tower induces a well-ordering on Hardy field elements by "differential complexity".

**Test**: Formalize Hardy fields in Lean (partially available in Mathlib). Define the quotient of EML functions by eventual equality. Verify the field axioms (specifically: every nonzero EML germ is eventually positive or eventually negative). The key test: show that exp(x) - x^n is eventually positive for all n, establishing that exp dominates all polynomials in the Hardy field ordering.

**Impact**: Connecting EML to Hardy field theory would import the powerful machinery of asymptotic analysis, including L'Hôpital's rule, asymptotic expansions, and transseries. It would also connect to the Catalog's `hardyLevel_closed_under_eml` result, completing a bridge between syntactic EML expressions and asymptotic growth analysis.

**Catalog References**: `Speculative/HardyHierarchy/Theorems.lean` (`hardyLevel_closed_under_eml`), `EML/DifferentialAlgebra.lean` (the differential algebra structure).

**Proof Strategy**:
1. Define the equivalence relation "eventually equal" on ℝ → ℝ
2. Show EML functions are eventually monotone (key Hardy field property)
3. Use `sdiff_eval_hasDerivAt` to transfer derivative properties to germs
4. Construct the Hardy field ordering using the sign of leading terms

**Domain Bridges**: Differential Algebra ↔ Asymptotic Analysis ↔ Model Theory (via Hardy field axiomatics)

**Lineage**: Builds on `sdiff_eval_hasDerivAt`, `exp_tower_eval_eq`, and the existing `hardyLevel_closed_under_eml`.

**Ambition**: grand_challenge

### Direction 5: Verified Automatic Differentiation via EML

**Conjecture**: The `sdiff` operator, composed with a simplification pass, provides a verified automatic differentiation (AD) engine whose output is provably correct. Specifically: for any EML expression e representing a neural network layer, `sdiff(e).eval x = deriv(e.eval) x` with machine-verified correctness.

**Test**: Encode a simple neural network (e.g., a two-layer MLP with exp activations) as an EML expression. Compute its gradient via `sdiff`. Compare numerically with finite-difference gradients. Prove the correctness formally using `sdiff_eval_hasDerivAt`.

**Impact**: Verified AD is a critical need in safety-critical machine learning. Current AD frameworks (JAX, PyTorch autograd) are unverified. An EML-based verified AD engine, even for a restricted function class, would demonstrate the feasibility of formally verified gradient computation.

**Catalog References**: `EML/DifferentialAlgebra.lean` (`sdiff_eval_hasDerivAt`, `sdiff_leibniz`), `EML/DerivationTower.lean` (iterated differentiation properties).

**Proof Strategy**:
1. Define neural network layers as EML expressions
2. Implement forward-mode AD as repeated `sdiff`
3. Prove correctness via `sdiff_eval_hasDerivAt`
4. Add a simplification pass and prove it preserves semantics
5. Benchmark against numerical differentiation

**Domain Bridges**: Formal Verification ↔ Machine Learning ↔ Numerical Analysis

**Lineage**: Direct application of `sdiff_eval_hasDerivAt` and the Leibniz rule.

**Ambition**: extension
