# Future Directions: Higher-Order Completion Modulo β

## Synthesis

The bounded higher-order critical pair theorem established in this work opens a systematic research program connecting rewriting theory, typed λ-calculus, and practical compiler verification. The five directions below form a coherent progression: from lifting the size bound (Direction 1) through decidable termination integration (Direction 2), to full completion loops (Direction 3), type-theoretic applications (Direction 4), and ultimately certified compiler infrastructure (Direction 5). Each direction builds on specific verified theorems from this work, and each is falsifiable through concrete computational predictions.

The overarching vision is a **verified equational reasoning engine for functional programs** — a system that takes rewrite rules from a compiler, automatically certifies their coherence, and produces machine-checkable evidence that optimizations are semantics-preserving.

---

## Direction 1: Unbounded Local Confluence for Structurally Recursive Systems

**Conjecture**: For finite left-linear Miller-pattern rewrite systems where every rule's RHS is "structurally bounded" by its LHS (in the sense that every substitution instance of the RHS is no larger than the corresponding instance of the LHS plus a fixed constant), bounded local confluence at any finite bound N implies global local confluence.

**The key insight is** that structural recursion on rule shapes creates a "size ceiling" effect: if all critical pairs up to a computable threshold are joinable, no new critical pair patterns can emerge at larger sizes. The bounded monotonicity theorem (`bounded_confluence_mono`) is the foundation — extending it to an unbounded limit requires showing that the critical pair set stabilizes.

**Why now?** The formalized monotonicity of `BetaCriticalPairsUpTo` and the bounded-to-global lift via `globalLocalConfluence_of_allJoinable` provide the exact infrastructure needed. The gap is proving that for structurally recursive systems, `BetaCriticalPairsUpTo E N = BetaCriticalPairsUpTo E (N+1)` for sufficiently large N.

**Test**: Implement a critical pair stabilization detector and run it on 50+ benchmark systems. If stabilization occurs at size ≤ 2 × max_rule_size for all tested systems, the conjecture gains strong empirical support. A single counterexample disproves it.

**Impact**: Global local confluence certificates without size bounds — full Knuth-Bendix theory for higher-order pattern systems.

**Catalog References**: `Pythagorean/BetaCompletionTheory.lean` (bounded_confluence_mono, critical_pairs_mono), `Pythagorean/HOCriticalPairs.lean` (BetaCriticalPairsUpTo).

**Proof Strategy**: Prove a "pumping" lemma: if a critical pair at size N+1 is not generated by rules of combined size ≤ N, it must arise from a "redundant" overlap that is already subsumed by a smaller critical pair. Use the Miller pattern structure to bound the relevant substitution growth.

**Domain Bridges**: First-order completion theory (where finite convergence is well-understood), recursion theory (structural recursion as a termination argument).

**Lineage**: Builds directly on `bounded_confluence_from_joinable_cps`.

**Ambition**: Grand challenge — would resolve the fundamental limitation of the bounded approach.

## Direction 2: Integration with Higher-Order Recursive Path Ordering

**Conjecture**: There exists a decidable termination criterion for Miller-pattern rewrite systems that is compatible with the critical pair theorem — specifically, a higher-order recursive path ordering (HORPO) that is stable under β-reduction and can be checked automatically for rules with Miller-pattern LHS.

**The key insight is** that Miller patterns have a natural "spine" structure (the head variable applied to bound-variable arguments) that can be mapped to a first-order recursive path ordering. If the spine ordering is well-founded, the entire system is terminating modulo β.

**Why now?** The full pipeline theorem (`full_pipeline_to_unique_nf`) shows that termination + joinable critical pairs = unique normal forms. The missing piece is automated termination checking, which HORPO would provide.

**Test**: Implement a spine-based HORPO checker for Miller-pattern systems. Test on 20+ benchmark systems from functional programming. If all systems that are obviously terminating (structurally recursive rules) pass the HORPO check, the approach is viable. If a simple terminating system fails, the ordering needs refinement.

**Impact**: Fully automated convergence checking for higher-order rewrite systems — the complete Knuth-Bendix pipeline without manual termination proofs.

**Catalog References**: `Pythagorean/BetaCompletionTheory.lean` (full_pipeline_to_unique_nf, completion_pipeline_newman), `Pythagorean/HOCriticalPairs.lean` (Terminating, newman_lemma).

**Proof Strategy**: Define a HORPO on HOTerm by lexicographic comparison of (a) head symbol precedence, (b) multiset ordering on arguments, (c) subterm ordering. Prove well-foundedness by embedding into the natural number ordering.

**Domain Bridges**: Termination analysis (the "dependency pairs" method from first-order TRS theory), type theory (strong normalization proofs for typed λ-calculi).

**Lineage**: Extends the termination hypothesis in `full_pipeline_to_unique_nf` from an assumption to a checkable property.

**Ambition**: Solid extension — well-established first-order techniques adapted to the higher-order setting.

## Direction 3: Full Higher-Order Completion Loop

**Conjecture**: For every finite left-linear Miller-pattern rewrite system E with decidable word problem, there exists a finite set of additional rules R such that E ∪ R is convergent (terminating and confluent) — and this set R can be computed by an iterative completion procedure that terminates.

**The key insight is** that the certificate structure (`CompletionCertificateβ`) is already designed to be extensible: when a non-joinable critical pair is found, it can be oriented into a new rule and added to the system. The challenge is proving that this process terminates (i.e., only finitely many rules need to be added).

**Why now?** The formalized `mkCompletionCertificateβ` constructor and the first-order bridge (`first_order_completion_bridge` using `concrete_completion_correct`) provide the architectural template. The gap is the iterative loop and its termination proof.

**Test**: Implement a completion loop and run it on 10 benchmark systems where the initial system has non-joinable critical pairs. If the loop terminates with a convergent system in all cases, the conjecture is supported. A system where the loop diverges (infinitely many new rules added) would be a counterexample.

**Impact**: A verified higher-order completion procedure — the first of its kind. This would enable automated equational reasoning for functional programs.

**Catalog References**: `Pythagorean/ConcreteTermAlgebra.lean` (concrete_completion_correct, ConcreteDerives), `Pythagorean/BetaCompletionTheory.lean` (CompletionCertificateβ, mkCompletionCertificateβ).

**Proof Strategy**: Lift the first-order completion loop from `ConcreteTermAlgebra.lean` to the higher-order setting. The key step is showing that the "orient" operation (turning a critical pair into a rule) preserves the Miller pattern and left-linearity properties.

**Domain Bridges**: Automated theorem proving (completion-based equational reasoning), universal algebra (Birkhoff's completeness theorem for equational logic).

**Lineage**: Direct lift of `concrete_completion_correct` to the higher-order setting.

**Ambition**: Grand challenge — would create a fundamentally new tool for higher-order equational reasoning.

## Direction 4: Definitional Equality Extensions in Type Theory

**Conjecture**: The bounded local confluence theorem can be used to certify extensions of definitional equality in dependent type theory. Specifically, if a set of computation rules (beyond β and δ) forms a locally confluent Miller-pattern system, adding them to the definitional equality of a type theory preserves type safety.

**The key insight is** that type-checking in dependent type theory relies on definitional equality being confluent. Adding new computation rules (e.g., for propositional computation, pattern matching, or user-defined reductions) can break confluence. The bounded critical pair theorem provides a checkable criterion: if critical pairs are joinable, the extension is safe.

**Why now?** Modern proof assistants (Lean, Agda, Coq) increasingly allow user-defined computation rules and custom reducibility. The `equiv_iff_joinable_confluent` theorem shows that confluence gives the right notion of equality. The gap is connecting the abstract rewriting theory to the concrete type-checking algorithm.

**Test**: Take the computation rules of a real type theory (e.g., Lean 4's reduction rules for `Nat.rec`, `List.rec`, etc.) and check whether they form a locally confluent Miller-pattern system. If so, this provides independent verification of the type checker's correctness.

**Impact**: A new foundation for extensible type theories with certifiably confluent computation rules.

**Catalog References**: `Pythagorean/BetaCompletionTheory.lean` (equiv_iff_joinable_confluent, word_problem_decidability), `Pythagorean/HOCriticalPairs.lean` (HoEquiv, ho_word_problem_decidable).

**Proof Strategy**: Define a "typed HoRewrite" relation that restricts rewriting to well-typed terms. Show that the bounded critical pair theorem lifts to the typed setting (typed terms form a subset of all terms, so bounded local confluence on all terms implies bounded local confluence on typed terms).

**Domain Bridges**: Type theory (definitional equality, subject reduction), proof assistants (type checker certification), category theory (coherence for categorical models of type theory).

**Lineage**: Extends `word_problem_decidability` to the type-theoretic setting.

**Ambition**: Paradigm-shifting — would connect abstract rewriting theory directly to the foundations of proof assistants.

## Direction 5: Certified Compiler Optimization Passes

**Conjecture**: The coherent optimization pipeline theorem (`coherent_optimization_on_closed_programs`) can be instantiated to certify real compiler optimization passes. Specifically, for a Haskell-like language with list fusion rules (map fusion, foldr/build fusion, stream fusion), the bounded critical pair theorem produces a machine-checkable certificate that the optimization pipeline is semantics-preserving.

**The key insight is** that compiler optimization passes for functional languages are essentially rewrite systems on λ-terms. Map fusion, deforestation, CPS transformation — these are all rewrite rules with Miller-pattern LHS. If their critical pairs are joinable, the compiler is free to apply them in any order without changing the program's meaning.

**Why now?** The benchmark systems already formalized (mapFusionRule, mapIdRule, etaRule) are exactly the rules used in GHC's simplifier. The `CompletionCertificateβ` structure is designed to be extracted as a reusable artifact. The gap is scaling up from toy benchmarks to production rule sets.

**Test**: Extract the fusion rules from GHC's rewrite rule database (approximately 50-100 rules). Run the critical pair enumerator and joinability checker. If all critical pairs at bound 100 are joinable, this provides a formal certificate of optimization coherence for a real compiler.

**Impact**: The first machine-checked certificate of coherence for a production compiler's optimization pipeline.

**Catalog References**: `Pythagorean/BetaCompletionTheory.lean` (coherent_optimization_on_closed_programs, CompletionCertificateβ, benchmarkSystem), `Pythagorean/HOCriticalPairs.lean` (mapFusionRule, mapIdRule).

**Proof Strategy**: Encode GHC's rewrite rules as HOTerm rules. Run the completion pipeline. For non-joinable pairs, either add rules to complete the system or prove that the non-joinable pair is unreachable (the corresponding overlap cannot occur in well-typed programs).

**Domain Bridges**: Compiler verification (CompCert, CakeML), programming language semantics (denotational semantics of optimization), software engineering (certified build systems).

**Lineage**: Direct application of `coherent_optimization_on_closed_programs` and `CompletionCertificateβ`.

**Ambition**: Solid extension with transformative practical impact.
