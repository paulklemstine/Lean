## Drift-Free IMU: Trace Reversal Checksum — Expanded & Formally Verified

### Critical Correction

The identity as originally stated — `tr(R₁R₂⋯Rₖ · Rₖ⋯R₂R₁) = 3` — is **mathematically false**. Multiplying by the *same* rotations in reverse does NOT yield the identity matrix. 

**Counterexample**: A single 90° rotation R around the z-axis gives tr(R·R) = tr(R²) = -1 ≠ 3. This is formally proven in the Lean file.

The **correct** identity uses *inverse* (= transposed) rotations in the reversal:
```
R₁R₂⋯Rₖ · Rₖ⁻¹⋯R₂⁻¹R₁⁻¹ = I,  hence tr = 3
```

### Formal Verification (Lean 4 + Mathlib)

All proofs are machine-verified with no `sorry` and only standard axioms. See `RequestProject/DriftFreeIMU.lean`:

1. **`group_reversal_identity`** — For any group G and list L, the product `L.prod * (L.map (·⁻¹)).reverse.prod = 1`. This is the abstract algebraic checksum.

2. **`trace_identity_eq`** — The trace of the n×n identity matrix equals n.

3. **`imu_checksum`** — The main theorem: for any list of invertible n×n matrices, composing the forward product with the reversed-inverse product yields trace = n. This works over GL(n,ℝ), which contains all rotation matrices.

4. **`rot90z_sq_trace`** — Formal counterexample showing the original claim is false (tr(R²) = -1 for a 90° rotation).
