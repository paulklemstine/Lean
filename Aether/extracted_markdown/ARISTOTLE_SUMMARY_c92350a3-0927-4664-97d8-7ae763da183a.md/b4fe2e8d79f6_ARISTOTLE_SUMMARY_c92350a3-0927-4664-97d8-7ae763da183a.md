#### Theorems Proved:

**Stereographic Geometry (§1–§4):**
1. `inverse_stereo_on_sphere` — Inverse stereographic projection maps ℝ² → S² (the image lies on the unit sphere)
2. `inverse_stereo_on_circle` — 1D version: maps ℝ → S¹
3. `stereo_roundtrip` — Forward ∘ Inverse = Identity (σ(σ⁻¹(t)) = t)
4. `stereo_inverse_forward_fst` — Inverse ∘ Forward recovers first component
5. `stereo_inverse_forward_snd` — Inverse ∘ Forward recovers second component
6. `stereo_z_bounded` — Z-coordinate always in [−1, 1]
7. `solid_angle_nonneg` — Solid angle factor 1−Z ≥ 0
8. `solid_angle_formula` — 1−Z = 2/(u²+v²+1)
9. `solid_angle_decreasing` — Solid angle monotonically decreases as radius grows

**Compression Impossibility (§5–§6):**
10. `compression_pigeonhole` — No injection from Fin M to Fin N when N < M
11. `stereo_compression_impossible` — Stereographic encoding can't beat pigeonhole
12. `lossless_is_injective` — Lossless encoding ⟹ injective
13. `infinite_compression_impossible` — **Main theorem**: No lossless encode/decode pair can map 2ⁿ values into 2ⁿ⁻¹ slots
14. `quantization_resolution` — M distinct values need ≥ ⌈log₂ M⌉ bits

**Warped Arithmetic (§7):**
15. `circle_mul_on_circle` — Complex multiplication preserves S¹
16. `tangent_addition` — Tangent addition formula maps to S¹

**Information Density (§8):**
17. `density_diverges` — Information density → ∞ as solid angle → 0
18. `density_vs_pigeonhole` — But infinite density doesn't enable compression

**Bug found in Python script:** The original Python code uses inconsistent stereographic conventions — `stereo_inverse` projects from the north pole but `stereo_forward` uses south-pole projection formula `x/(1+y)`. The Lean formalization correctly uses consistent north-pole conventions: σ(x,y) = x/(1−y).
