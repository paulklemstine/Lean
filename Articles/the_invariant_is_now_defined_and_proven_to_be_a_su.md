# The Arithmetic of Coming Back: What a Machine's Return Times Reveal

## A clock that only tells you one thing

Imagine a machine — any machine. A traffic-light controller, a chemical reactor, a protocol between two servers, a shuffling of a deck of cards. Whatever it is, it has *configurations*, and it has *moves*: from configuration $a$ it may step to configuration $b$. Now put a stopwatch on a single configuration $a$ and record only one thing: **the possible numbers of steps after which the machine can find itself back in configuration $a$**.

That is a very lossy measurement. We throw away what the states are, what the moves mean, and which route was taken. All that survives is a set of numbers,
$$D(a) \;=\; \{\, n \in \mathbb{N} \;:\; \text{$a$ can return to $a$ in exactly $n$ steps} \,\}.$$

The question this article is about is deceptively simple: **which sets of numbers can arise this way?** And once you know that, what does the set tell you back about the machine?

The answers turn out to be crisp, complete, and surprisingly rich. The measurement is never arbitrary — it is always an algebraic object called an *additive submonoid* of $\mathbb{N}$. Every such object occurs, and already for machines with only finitely many states. And the shape of the set detects something no single observation of the machine can: whether the machine is deterministic, i.e. whether its next move is ever a genuine choice.

## Two numbers you can always add

Start with two easy observations, which together already pin down what kind of object $D(a)$ is.

First, $0 \in D(a)$: doing nothing returns you to where you were. Second, if the machine can return in $m$ steps and can return in $n$ steps, then it can return in $m+n$ steps — just run the first loop and then the second. Nothing else is guaranteed. In particular you cannot subtract: the ability to return in $5$ steps and in $2$ steps does *not* let you return in $3$.

A set of natural numbers containing $0$ and closed under addition is exactly what algebraists call an **additive submonoid of $\mathbb{N}$**. So we have our first theorem, free of charge.

> **The invariant is a monoid.** For every transition relation and every state $a$, the set $D(a)$ of return lengths is an additive submonoid of $\mathbb{N}$.

Call $D(a)$ the **degree monoid** of the state. Some examples, to get a feel:

- A state with no outgoing moves at all is *dead*: it can never leave and never return except trivially, so $D(a) = \{0\}$, the smallest possible value.
- A state with a self-loop can idle: $D(a) = \mathbb{N}$, the largest possible value.
- A single cycle of length $n$ — a carousel with $n$ seats — gives $D(a) = n\mathbb{N} = \{0, n, 2n, 3n, \dots\}$.
- A state sitting at the junction of two loops, one of length $2$ and one of length $3$, gives $D(a) = \{0, 2, 3, 4, 5, 6, \dots\}$: everything except $1$. You can go around the short loop, the long loop, or any combination — $4 = 2+2$, $5 = 2+3$, $7 = 2+2+3$ — but there is no way to come back in exactly one step. That single missing value, that little hole in an otherwise complete set, is going to matter enormously.

## Everything is possible — the realisation theorem

Is the monoid condition the *only* constraint? Yes, exactly, and the construction that shows it is a small, vivid machine.

Fix any set $S$ of positive numbers — your wish list of loop lengths. Build the **chain machine** of $S$: the states are $0,1,2,3,\dots$; from a positive state $i$ the only move is $i \to i-1$, a deterministic countdown; and from the base state $0$ the machine may, at its discretion, jump to $s-1$ for any $s \in S$. Jumping to $s-1$ and then counting down takes exactly $s$ steps and returns you to $0$. That is a loop of length $s$, and these loops share only the base state.

> **Realisation Theorem.** The degree monoid of the base state of the chain machine of $S$ is precisely the submonoid of $\mathbb{N}$ generated by $S$.

One inclusion is the easy direction just described. The other requires an argument that no *other* return is possible, and it is a nice one: any path from a state $b$ back to the base must spend at least $b$ steps just counting down, and after those $b$ steps it is sitting at the base again — so every return decomposes as "one loop, then a shorter return", and induction finishes the job.

Taking $S$ to be a whole submonoid $M$ (a set generates itself) we get the punchline:

> **Completeness.** Every additive submonoid of $\mathbb{N}$ is the degree monoid of some state of some machine. The invariant's range of values is exactly the lattice of submonoids of $\mathbb{N}$ — no more, no less.

This single theorem absorbs all four examples above: $\{0\}$, $\mathbb{N}$, $n\mathbb{N}$ and $\langle 2,3\rangle$ are the cases $S = \varnothing$, $S = \{1\}$, $S = \{n\}$, $S=\{2,3\}$ of one construction, not four unrelated tricks.

And you do not need infinitely many states. Every submonoid of $\mathbb{N}$ is generated by a *finite* set — a fact with a pretty proof of its own — and a chain machine with a finite generating set never needs to climb higher than the largest generator. Truncate it there:

> **Finite-state realisation.** Every additive submonoid of $\mathbb{N}$ is the degree monoid of a state of a machine with finitely many states.

## The invariant behaves well

An invariant is only useful if it interacts with the natural operations on the objects it measures. This one does, in three ways.

**Simulation makes it grow.** If a map $f$ from one machine to another turns every move into a move, then every loop maps to a loop, so $D(a) \subseteq D(f(a))$. Abstracting a machine can only add return times, never remove them.

**Bisimulation preserves it exactly.** If $f$ is injective, reflects moves as well as preserving them, and its image is closed under moves, then $D(a) = D(f(a))$. So the degree monoid is a genuine *behavioural* invariant: it cannot tell apart two machines that are behaviourally the same, which is precisely what one wants of a measurement.

**Products are intersections.** Run two machines in lockstep — one step of each per tick. Then the pair $(a,b)$ returns to itself exactly when both components do simultaneously, so
$$D(a,b) \;=\; D(a) \cap D(b).$$
Synchronising machines corresponds to intersecting their monoids. The invariant translates a construction on machines into an operation on numbers.

**Speeding up divides.** If you redefine "one step" to mean "$k$ steps of the old machine", then the new degree monoid consists of exactly those $n$ with $kn \in D(a)$ — the *colon monoid* $(D(a) : k)$. Time rescaling becomes division inside the arithmetic.

## The shape of a degree monoid: period and gaps

Knowing that all submonoids occur is only half a theory. The other half is knowing what a submonoid of $\mathbb{N}$ *looks like*, and it looks like this. Define the **period** of a state,
$$d(a) \;=\; \gcd D(a),$$
the greatest common divisor of all its return lengths (with $d(a)=0$ for the dead state, by convention $\gcd\{0\}=0$).

> **Structure Theorem.** Every return length is a multiple of the period; and conversely, all sufficiently large multiples of the period *are* return lengths. Hence a degree monoid is an arithmetic progression $d\mathbb{N}$ with only finitely many members removed.

The removed values — multiples of the period that are not achievable return lengths — are the **gaps**. They are the whole subtlety of the invariant, and there are always only finitely many.

This gives a sharp dichotomy: either $d(a) = 0$, and the state is dead ($D(a)=\{0\}$); or $d(a) > 0$, all return lengths are multiples of $d(a)$, and all large ones occur.

Periods also synchronise in the expected way. If two live machines run in lockstep, the period of the product is the *least common multiple* of the periods:
$$d\big((a,b)\big) \;=\; \operatorname{lcm}\big(d(a), d(b)\big).$$
Two gears of $6$ and $10$ teeth realign every $30$ ticks — the theorem says that this classical intuition is exactly right for arbitrary machines, once "period" is defined as a gcd of return lengths.

## Determinism is visible in the gaps

Now for the result that makes the invariant do real work.

A machine is **deterministic** if each state has at most one successor: no choices, no branching. Determinism has an immediate and powerful consequence for return times. Suppose a deterministic machine returns to $a$ in $m$ steps and also in $n \ge m$ steps. Run it for $m$ steps: because the machine is deterministic, the state after $m$ steps is *unique*, and we know one such state — namely $a$ itself. So the $n$-step loop, chopped at time $m$, must also be at $a$; its remaining $n-m$ steps form a return of length $n-m$.

> **Subtraction closure.** In a deterministic machine, $m, n \in D(a)$ with $m \le n$ implies $n - m \in D(a)$.

A submonoid of $\mathbb{N}$ closed under subtraction is a subgroup's worth of structure, and there is only one shape it can have: taking $d$ to be its smallest nonzero element, repeated subtraction (i.e. the Euclidean algorithm, run inside the machine's own return times) shows every element is a multiple of $d$ and every multiple of $d$ occurs.

> **Determinism forces an arithmetic progression.** For a deterministic machine, $D(a) = d\mathbb{N}$ exactly, for a single number $d$ — the period. Deterministic machines have **no gaps**.

Turn it around, and you get a diagnostic:

> **Gaps certify nondeterminism.** If some multiple of the period of a state fails to be a return length, the machine is not deterministic.

You do not need to inspect the transition table. You do not need to find the branching state. A single missing return time — one length that "should" be there by divisibility but is not observed — is a proof that the machine makes a genuine choice somewhere.

The sharpest instance is the little two-loop machine from the beginning. Its degree monoid is $\langle 2,3 \rangle = \{0,2,3,4,\dots\}$, whose period is $\gcd(2,3)=1$ and whose unique gap is $1$.

> **Separation Theorem.** No deterministic machine, on any state space whatsoever, has $\langle 2,3\rangle$ as the degree monoid of a state.

The proof is three lines of arithmetic: for a deterministic machine $D(a) = d\mathbb{N}$; if $2$ and $3$ both lie in it then $d \mid 2$ and $d \mid 3$, so $d = 1$ and $D(a) = \mathbb{N}$ — which contains $1$, and $\langle 2,3 \rangle$ does not. The Frobenius gap $1$ is an intrinsic, unremovable witness of nondeterminism.

Combined with finite-state realisation, this says something clean about expressive power: **finite nondeterministic machines realise every possible value of the invariant, while deterministic machines — even with unboundedly many states — realise only the arithmetic progressions $d\mathbb{N}$.** The invariant separates the two computational models.

One more finiteness fact rounds out the deterministic picture. On a finite state space a deterministic machine that has any nonempty loop at $a$ has period at most the number of states. The reason is that the loop through $a$, of length $d$, visits $d$ pairwise distinct states: if the states at times $i < j$ coincided, splicing the first $i$ steps onto the last $d-j$ steps would produce a shorter loop, of length $i + (d-j)$ strictly between $0$ and $d$ — impossible when every loop length is a multiple of $d$.

## Counting the holes: Sylvester enters

For nondeterministic machines the gaps are the interesting data, and for two-loop machines we can count them exactly.

Take the machine with two loops at the base, of coprime lengths $p, q > 1$. Its return times are the numbers $ap + bq$ with $a,b \ge 0$ — the classical **numerical semigroup** $\langle p, q \rangle$, also known to the world as the Chicken McNugget problem. Two classical facts, both provable directly from the machine's own combinatorics, describe its gaps completely.

The first is a *residue criterion*. Since $q$ is invertible modulo $p$, every $n$ has a unique $b \in \{0,1,\dots,p-1\}$ with $bq \equiv n \pmod p$; and then
$$n \in \langle p,q\rangle \iff bq \le n.$$
Indeed if $bq \le n$, the difference $n - bq$ is a nonnegative multiple of $p$, giving the representation; and any representation $n = ap + b'q$ forces $b' \equiv b \pmod p$, hence $b' \ge b$, hence $n \ge bq$.

From the criterion, the largest gap is $F = pq - p - q$, the **Frobenius number**: every larger value is representable, and $F$ itself is not. For $p=2,q=3$ this is $F = 1$, the single hole we already found; for $p=3,q=5$ it is $F=7$, and the gaps are $1,2,4,7$.

The second fact is a beautiful *symmetry*: for every $n$ with $0 \le n \le F$, exactly one of $n$ and $F-n$ is a return length. (Again the residue criterion does it: the residues of $n$ and $F-n$ are complementary, and the two inequalities $bq \le n$ and $b'q \le F-n$ cannot both hold nor both fail.) The map $n \mapsto F-n$ is therefore an involution on $\{0,1,\dots,F\}$ that swaps gaps with non-gaps — so exactly half of those $F+1$ numbers are gaps:

> **Sylvester's Gap Count.** For coprime $p, q > 1$, the two-loop machine fails to realise exactly
> $$\frac{(p-1)(q-1)}{2}$$
> computation lengths.

For $(p,q) = (2,3)$ this gives $1$ gap; for $(3,5)$, $4$ gaps; for $(5,7)$, $12$ gaps; for $(7,11)$, $30$. The invariant of a two-loop machine is thus completely explicit: an arithmetic progression of period $1$ with a precisely counted, precisely located finite set of holes, all of them below $pq-p-q$.

## Why this is more than a curiosity

Three threads come together here.

**A complete invariant with a small alphabet.** Return-time sets are the coarsest possible observation of a dynamical system, and yet their range of values is exactly a well-understood algebraic lattice. Coarse measurements with clean, complete classifications are rare and useful; they let you reason about a machine you cannot see inside.

**A structural obstruction, not a complexity bound.** The statement "no deterministic machine realises $\langle 2,3\rangle$" is not about resources — it holds for machines with infinitely many states, unbounded memory, anything. It is an obstruction of *shape*. Nondeterminism, so often characterised by counting (how many accepting paths, how much guessing), here shows up as an arithmetic hole.

**A bridge to classical number theory.** Once loops become generators, the achievable running times of a machine become a numerical semigroup, and the questions "which lengths are impossible?" and "how many are impossible?" become the Frobenius problem and Sylvester's count. Coin problems and machine behaviour turn out to be the same mathematics: a coin of value $p$ is a loop of length $p$, and an unpayable amount is an unachievable running time.

That last correspondence suggests where to look next. Determinism forces $D(a) = d\mathbb{N}$, so any deterministic machine simulating a nondeterministic one must distort the invariant, and the rescaling law tells us exactly what "distortion" means: speeding up by a factor $k$ sends $M$ to the colon monoid $(M:k) = \{n : kn \in M\}$. Define the *determinisation cost* of $M$ as the least $k_0$ such that every rescaling by $k \ge k_0$ yields a gapless monoid. For the two-loop machine the answer is exactly the Frobenius number plus one: if $k > F = pq-p-q$ then every multiple $kn$ with $n \ge 1$ exceeds $F$ and is therefore achievable, so the rescaled invariant is all of $\mathbb{N}$; while rescaling by $F$ itself yields $\{0,2,3,4,\dots\}$ — our old friend $\langle 2,3\rangle$, gap and all. Clocking a nondeterministic machine slowly enough hides its nondeterminism, and the price of hiding it is precisely the largest impossible running time.

The stopwatch, it turns out, was never a crude instrument. It was measuring algebra all along.
