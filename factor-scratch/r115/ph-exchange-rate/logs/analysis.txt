STEP 4.  Q1.  At what residual-prime size b does PH stop being worth it?
==========================================================================================================
  leading-term crossover set {(s,b): 2^(s/2)+2^(b/2) >= 2^((s+b)/2)} =
    [(1, 1), (1, 2), (1, 3), (2, 1), (2, 2), (3, 1)]
  For s,b >= 3 the PH leading term is STRICTLY below the generic one, so PH cannot
  lose inside the square-root term.  The only loss region is below the O(log n)
  subgroup-encoding overhead; the measurement pins its boundary:
     (s,b)=( 4, 4): generic      26.5  PH      38.2  -> PH LOSES by 0.526 bits
     (s,b)=( 8, 8): generic     362.5  PH      97.2  -> PH WINS by 1.899 bits
     (s,b)=(12,12): generic    5312.8  PH     259.6  -> PH WINS by 4.355 bits
  ANSWER: NO such b exists in the ECDSA-relevant regime.  For every s,b >= 8 the
  saving is positive, and the saving is essentially FLAT in b (it saturates at s/2):
     s= 20 : b=40:10.00,  b=60:10.00,  b=80:10.00,  b=100:10.00,  b=120:10.00
     s= 40 : b=40:19.00,  b=60:20.00,  b=80:20.00,  b=100:20.00,  b=120:20.00
     s= 60 : b=40:20.00,  b=60:29.00,  b=80:30.00,  b=100:30.00,  b=120:30.00
  The binding constraint is NOT b crossing generic; it is the ABSOLUTE residual cost
  1.47*2^(b/2), which no amount of small-part knowledge reduces.

STEP 5.  Q2.  How much of n must the attacker know before the residual work drops
          below generic by a useful margin?
==========================================================================================================
  exact identity from the model (s <= b):
      PH / generic  ->  2^(-s/2)      and      savings = s/2
  ONE bit of known factorization buys HALF a bit of ECDLP work.  Exchange rate 2:1.

   D-bit saving  <=>  need BOTH  s >= 2D  and  log2(q) >= 2D
      saving    1 bits  <=>  s >=    2 bits known  AND  q >= 2 bits
      saving    2 bits  <=>  s >=    4 bits known  AND  q >= 4 bits
      saving    4 bits  <=>  s >=    8 bits known  AND  q >= 8 bits
      saving    8 bits  <=>  s >=   16 bits known  AND  q >= 16 bits
      saving   10 bits  <=>  s >=   20 bits known  AND  q >= 20 bits
      saving   20 bits  <=>  s >=   40 bits known  AND  q >= 40 bits
      saving   30 bits  <=>  s >=   60 bits known  AND  q >= 60 bits
      saving   40 bits  <=>  s >=   80 bits known  AND  q >= 80 bits
      saving   60 bits  <=>  s >=  120 bits known  AND  q >= 120 bits
      saving   80 bits  <=>  s >=  160 bits known  AND  q >= 160 bits
      saving  100 bits  <=>  s >=  200 bits known  AND  q >= 200 bits
      saving  120 bits  <=>  s >=  240 bits known  AND  q >= 240 bits
