# Arrow-Depth Insufficiency and Size-Exponential Sharpness for the Semantic State Complexity of Simple Types

## Abstract

We develop a structural complexity theory for the simple types of the simply typed
λ-calculus and settle the question of which structural invariant controls *semantic
state complexity*. Working with the **type-state bound** `typeStateBound`, a
multiplicative invariant that upper-bounds the number of behaviorally distinct states
of a higher-order computation at a given type, we prove four principal results. First,
`typeStateBound` coincides exactly with the independently defined type-complexity
measure, certifying that it is canonical rather than ad hoc. Second, on the family of
**chain types** (right-spined arrow types with base-typed arguments) the bound is
*singly* exponential in arrow depth: `typeStateBound(A) ≤ 3^(depth(A)+1)`. Third, on
the family of **bushy types** (balanced binary arrow trees) the bound is *doubly*
exponential in depth: `typeStateBound(bushy(n)) + 1 ≥ 2^(2^n)`. Fourth, and centrally,
we prove an **impossibility theorem**: no constant `c` yields a uniform bound
`typeStateBound(A) ≤ c^(depth(A)+1)`. Depth alone is therefore an insufficient
controlling parameter. We then identify the correct one: the **size-exponential
bound** `typeStateBound(A) + 1 ≤ 2^(size(A))` holds universally, and is order-tight:
the bushy family attains `log2(typeStateBound) = Θ(size)`. A width–size identity and a depth-to-size bound complete the picture,
showing that depth governs complexity exactly when arrow width is constrained, and that
the worst-case double-exponential-in-depth regime is precisely single-exponential in
size. All results are fully formalized and machine-checked.

**Keywords:** higher-order semantics, semantic state complexity, type-theoretic
complexity, bisimulation minimization, arrow depth, structural parameterization,
fixed-parameter tractability, descriptive complexity, automata state explosion,
width–depth tradeoff, semantic compression.

## 1. Introduction

Higher-order computation pays for its expressive power with the threat of explosion.
When functions take and return functions, the space of behaviors a single typed
expression can exhibit can grow alarmingly fast in the structure of its type. A central
practical and theoretical question is: *which structural invariant of a type controls
this growth?* If we can name a parameter `p` and prove a bound of the form
`complexity ≤ f(p)`, then problems whose `p` is small become tractable, minimization
algorithms acquire predictable budgets, and "state explosion" acquires a precise
diagnosis.

The most intuitive candidate is **arrow depth**: the maximal nesting level of function
arrows. Depth is the higher-order analogue of "order" (a first-order function has depth
1, a functional taking first-order functions has depth 2, and so on), and it is the
parameter most practitioners would reach for. This paper proves that depth is, on its
own, the *wrong* parameter — not merely loose, but fundamentally incapable of bounding
semantic complexity — and identifies **type size** (equivalently, arrow width) as the
sharp controlling invariant.

Our vehicle is the type-state bound `typeStateBound`, a multiplicative invariant that
ceilings the canonical-quotient (Myhill–Nerode / bisimulation) state count of
computations at a type. The contributions are:

1. A proof that `typeStateBound` equals the standard type-complexity measure
   (Section 4.1), establishing canonicity.
2. A single-exponential-in-depth bound for chain types (Section 4.2).
3. A double-exponential-in-depth lower bound for bushy types (Section 4.3).
4. An impossibility theorem ruling out any uniform exponential-in-depth bound
   (Section 4.4).
5. A universal size-exponential upper bound and its certified predicted-bound corollary
   (Section 4.5).
6. Structural identities (width–size, depth–size, bushy invariants) that explain the
   phenomenon as a width–depth tradeoff (Section 5).

All statements are formalized; proof sketches below follow the formal arguments.

## 2. Preliminaries: simple types and their measures

We work with the type grammar of the simply typed λ-calculus over a single base type.

**Definition 2.1 (Simple types).** The set `Ty` of simple types is generated by

```
A, B ::= base | arrow A B          (written A → B)
```

That is, `Ty` is the free magma on one generator `base` under the binary arrow
constructor.

**Definition 2.2 (Depth).** The arrow **depth** `depth : Ty → ℕ` is
```
depth(base)      = 0
depth(A → B)     = 1 + max(depth(A), depth(B)).
```

**Definition 2.3 (Size).** The **size** `size : Ty → ℕ` counts constructors:
```
size(base)       = 1
size(A → B)      = 1 + size(A) + size(B).
```

**Definition 2.4 (Complexity).** The type **complexity** `complexity : Ty → ℕ` is the
multiplicative measure
```
complexity(base)  = 1
complexity(A → B) = (complexity(A) + 1) · (complexity(B) + 1).
```
It satisfies `complexity(A) > 0` for all `A`.

**Definition 2.5 (Type-state bound).** The **type-state bound**
`typeStateBound : Ty → ℕ` is defined by the same recurrence:
```
typeStateBound(base)  = 1
typeStateBound(A → B) = (typeStateBound(A) + 1) · (typeStateBound(B) + 1).
```
Semantically, `typeStateBound(A)` is an upper bound on the canonical-quotient state
count (the number of bisimulation-distinct, Myhill–Nerode–distinct behaviors) achievable
by closed well-typed terms at type `A`, taken over all reduction depths. The
multiplicative arrow rule reflects that a function from `A` to `B` may, in the worst
case, exhibit one behavior per pairing of an `A`-input behavior class (including the
"untouched" class, hence the `+1`) with a `B`-output behavior class.

We additionally use a structural width measure.

**Definition 2.6 (Arrow width).** `arrowWidth : Ty → ℕ` counts arrow constructors:
```
arrowWidth(base)  = 0
arrowWidth(A → B) = 1 + arrowWidth(A) + arrowWidth(B).
```

## 3. The two probing families and a predicted bound

To separate depth from size we use two extremal families that share depth but differ
maximally in width.

**Definition 3.1 (Chain types).** A type is a **chain type** when it is a right-spine of
arrows whose every left argument is `base`:
```
ChainTy(base)    = True
ChainTy(A → B)   = (A = base) ∧ ChainTy(B).
```
Chains are the pipelines `base → base → ⋯ → base`, the minimally branching types at each
depth.

**Definition 3.2 (Bushy types).** The **bushy** family `bushy : ℕ → Ty` is the balanced
binary arrow tree:
```
bushy(0)     = base
bushy(n + 1) = bushy(n) → bushy(n).
```
Bushes are the maximally branching types at each depth.

**Definition 3.3 (Predicted bound).** `predictedBound(A) = 2^(size(A)) − 1`, the
certified, size-computable upper bound on `typeStateBound(A)` established in
Section 4.5.

**Definition 3.4 (Depth profile, auxiliary).** `depthProfile : Ty → ℕ → ℕ` counts type
nodes at each residual depth level:
```
depthProfile(base, 0)      = 1
depthProfile(base, k+1)    = 0
depthProfile(A → B, 0)     = 1
depthProfile(A → B, k+1)   = depthProfile(A, k) + depthProfile(B, k),
```
recording the width of a type at every horizontal slice.

## 4. Main results

### 4.1 Canonicity: the type-state bound is the complexity measure

**Theorem 4.1.** For every `A : Ty`, `typeStateBound(A) = complexity(A)`.

*Proof sketch.* Structural induction on `A`. The base cases are `1 = 1`. For the arrow
case, both sides unfold to `(x_A + 1)(x_B + 1)` where `x_A, x_B` are the respective
values on the components; the inductive hypotheses `typeStateBound(A) = complexity(A)`
and `typeStateBound(B) = complexity(B)` make the two factorizations identical. ∎

**Corollary 4.2.** `depth(A) ≤ complexity(A)` for all `A`.

*Proof sketch.* Induction on `A`. Base: `0 ≤ 1`. Arrow: with `depth(A → B) =
1 + max(depth A, depth B)` and `complexity(A → B) = (complexity A + 1)(complexity B +
1)`, the inductive hypotheses plus positivity of complexity (`complexity_pos`) give
`1 + max(depth A, depth B) ≤ (complexity A + 1)(complexity B + 1)` by a routine
nonlinear arithmetic step, since each factor is at least `2` and `max(a,b) ≤ a + b`. ∎

These results certify that we measure a canonical quantity, and that depth never exceeds
it — leaving open only whether depth can *predict* it.

### 4.2 Chains are singly exponential in depth

**Theorem 4.3 (Chain bound).** If `ChainTy(A)`, then
`typeStateBound(A) ≤ 3^(depth(A) + 1)`.

*Proof sketch.* Induction on the chain structure. For `base`, `typeStateBound(base) =
1 ≤ 3^1`. For a chain `base → B` with `ChainTy(B)`, the arrow rule gives
`typeStateBound(base → B) = (1 + 1)(typeStateBound(B) + 1) = 2·(typeStateBound(B) + 1)`.
Since a chain's depth increases by exactly one at each step (`depth(base → B) =
1 + depth(B)` because the left argument `base` has depth `0`), the inductive hypothesis
`typeStateBound(B) ≤ 3^(depth(B)+1)` yields
`2·(typeStateBound(B)+1) ≤ 2·(3^(depth(B)+1) + 1) ≤ 3·3^(depth(B)+1) = 3^(depth(B)+2)
= 3^(depth(base → B)+1)`,
using `2(m+1) ≤ 3m` for `m ≥ 2`. ∎

Thus for thin types depth genuinely controls complexity, with growth no faster than a
clean single exponential. The chain sequence is `1, 4, 10, 22, 46, …` (the recurrence
`x_{d+1} = 2(x_d + 1)`), each value safely under `3^(d+1)`.

### 4.3 Bushes are doubly exponential in depth

We first record the depth and the recurrence of the bushy family.

**Theorem 4.4 (Bushy depth).** `depth(bushy(n)) = n`.

*Proof sketch.* Induction on `n`. Base `depth(base) = 0`. Step: `depth(bushy(n+1)) =
1 + max(depth(bushy n), depth(bushy n)) = 1 + depth(bushy n) = 1 + n`. ∎

**Theorem 4.5 (Bushy recurrence).**
`typeStateBound(bushy(n+1)) = (typeStateBound(bushy(n)) + 1)^2`.

*Proof sketch.* By definition `bushy(n+1) = bushy(n) → bushy(n)`, so the arrow rule gives
`(typeStateBound(bushy n) + 1)·(typeStateBound(bushy n) + 1) =
(typeStateBound(bushy n) + 1)^2`. ∎

The squaring recurrence drives double-exponential growth.

**Theorem 4.6 (Bushy lower bound).** `2^(2^n) ≤ typeStateBound(bushy(n)) + 1`.

*Proof sketch.* Induction on `n`. Base: `2^(2^0) = 2^1 = 2 ≤ typeStateBound(bushy 0) + 1
= 1 + 1 = 2`. Step: write `x_n := typeStateBound(bushy n)`. By Theorem 4.5,
`x_{n+1} + 1 = (x_n + 1)^2 + 1 − 0 ≥ (x_n + 1)^2`. By the inductive hypothesis
`x_n + 1 ≥ 2^(2^n)`, monotonicity of squaring gives
`(x_n + 1)^2 ≥ (2^(2^n))^2 = 2^(2·2^n) = 2^(2^{n+1})`. Hence
`x_{n+1} + 1 ≥ 2^(2^{n+1})`. ∎

The bushy sequence of type-state bounds is `1, 4, 25, 676, 458329, …`, with `x_n + 1`
dominating the tower `2^(2^n) = 2, 4, 16, 256, 65536, …`.

### 4.4 Impossibility: no uniform exponential-in-depth bound

**Theorem 4.7 (Impossibility).** There is no constant `c : ℕ` such that
`typeStateBound(A) ≤ c^(depth(A) + 1)` for all `A : Ty`.

*Proof sketch.* Suppose such a `c` existed. Instantiating at `bushy(n)` and using
`depth(bushy n) = n` (Theorem 4.4) gives `typeStateBound(bushy n) ≤ c^(n+1)` for all
`n`. Combining with the lower bound of Theorem 4.6,
```
2^(2^n) ≤ typeStateBound(bushy n) + 1 ≤ c^(n+1) + 1.
```
Now bound the right-hand side. Since `c ≤ 2^c` (Lemma 5.6), `c^(n+1) ≤ (2^c)^(n+1) =
2^(c(n+1))`, whence `c^(n+1) + 1 ≤ 2·2^(c(n+1)) = 2^(c(n+1) + 1)`. Therefore
`2^(2^n) ≤ 2^(c(n+1)+1)`, and strict monotonicity of `2^(·)` gives
`2^n ≤ c(n+1) + 1 ≤ (c+1)(n+1)`. But `2^n` eventually dominates any linear function of
`n` (Lemma 5.7): taking `n = 2(c+1)` already violates `2^n ≤ (c+1)(n+1)`. Contradiction.
∎

This is the crux: depth cannot be a controlling parameter for semantic complexity, not
even up to choice of exponential base. The single-exponential ceiling `c^(depth+1)` is
defeated by the double-exponential bushy family.

### 4.5 Sharpness: size is the controlling parameter

**Theorem 4.8 (Size-exponential bound).** For every `A : Ty`,
`typeStateBound(A) + 1 ≤ 2^(size(A))`.

*Proof sketch.* Induction on `A`. Base: `typeStateBound(base) + 1 = 2 = 2^1 =
2^(size(base))`. Arrow: let `u := typeStateBound(A)`, `v := typeStateBound(B)`. We must
show `(u+1)(v+1) + 1 ≤ 2^(1 + size A + size B)`. By the inductive hypotheses
`u + 1 ≤ 2^(size A)` and `v + 1 ≤ 2^(size B)`, so `(u+1)(v+1) ≤ 2^(size A + size B)`.
Since `2^(size A + size B) < 2^(1 + size A + size B)` (the exponent strictly increases),
we get `(u+1)(v+1) + 1 ≤ 2^(size A + size B) + 1 ≤ 2^(1 + size A + size B)`, the last
step because `m + 1 ≤ 2m` for `m = 2^(size A + size B) ≥ 1`. ∎

**Corollary 4.9 (Certified predicted bound).** `typeStateBound(A) ≤ predictedBound(A)
= 2^(size(A)) − 1`.

*Proof sketch.* Immediate from Theorem 4.8 via `x + 1 ≤ N ⟹ x ≤ N − 1` on naturals. ∎

The size bound is *universal*: it admits no exceptions, in stark contrast to the
nonexistent depth bound. Moreover it is *order-tight*: the bushy family attains
`log2(typeStateBound(bushy n)) = Θ(size(bushy n))` (Section 5), so no
sub-exponential-in-size bound is possible.

## 5. Structural anatomy: the width–depth tradeoff

The contrast between Sections 4.4 and 4.5 is explained by a single structural fact:
depth ignores branching, size does not.

**Theorem 5.1 (Width–size identity).** `2·arrowWidth(A) + 1 = size(A)`.

*Proof sketch.* Induction. Base: `2·0 + 1 = 1 = size(base)`. Arrow: `2(1 + arrowWidth A
+ arrowWidth B) + 1 = 1 + (2 arrowWidth A + 1) + (2 arrowWidth B + 1) = 1 + size A +
size B = size(A → B)` by the inductive hypotheses. ∎

**Corollary 5.2.** `arrowWidth(A) < size(A)`.

So size and arrow width carry the same information up to an affine transformation; the
size-exponential bound is equivalently a *width*-exponential bound.

**Theorem 5.3 (Chains: depth equals width).** If `ChainTy(A)` then `depth(A) =
arrowWidth(A)`.

*Proof sketch.* Induction on the chain. Base: `0 = 0`. For `base → B` with `ChainTy(B)`,
`depth(base → B) = 1 + depth(B)` and `arrowWidth(base → B) = 1 + 0 + arrowWidth(B)`; the
inductive hypothesis `depth(B) = arrowWidth(B)` closes the case. ∎

For chains, depth *is* width, which is why depth controls complexity there (Theorem 4.3
re-derives, via Theorem 4.1, `complexity(A) ≤ 3^(depth(A)+1)` for chains, through
Theorem 4.3). The
divergence appears only when width can exceed depth — exactly what the bushes do.

**Theorem 5.4 (Bushy invariants).**
`arrowWidth(bushy(n)) = 2^n − 1` and `size(bushy(n)) = 2^(n+1) − 1`.

*Proof sketch.* Both by induction using `bushy(n+1) = bushy(n) → bushy(n)`:
`arrowWidth(bushy(n+1)) = 1 + 2(2^n − 1) = 2^{n+1} − 1`, and likewise for size via
Theorem 5.1. ∎

This is the punchline: the bushy double-exponential-in-depth growth
`typeStateBound(bushy n) + 1 ≥ 2^(2^n)` is, through `size(bushy n) = 2^{n+1} − 1`,
exactly a *single* exponential in size — fully consistent with the universal bound of
Theorem 4.8, whose order it attains (`log2(typeStateBound(bushy n)) = Θ(size)`). What
looks like a depth explosion is an ordinary size exponential viewed through the wrong
lens.

**Theorem 5.5 (Depth-to-size bound).** `size(A) ≤ 2^(depth(A)+1) − 1`.

*Proof sketch.* Induction; the arrow case `size(A→B) = 1 + size A + size B` is bounded
using `size A, size B ≤ 2^(depth+1) − 1` for the larger of the two depths, giving the
full-binary-tree ceiling. ∎

**Corollary 5.6 (Worst-case depth bound, recovered).** `typeStateBound(A) + 1 ≤
2^(2^(depth(A)+1) − 1)`.

*Proof sketch.* Compose Theorem 4.8 with Theorem 5.5 and monotonicity of `2^(·)`. ∎

Corollary 5.6 shows the *best possible* depth-only upper bound is itself doubly
exponential — and the bushes show it cannot be improved to any single exponential
(Theorem 4.7). Depth bounds complexity, but only doubly exponentially, and only because
size is at most exponential in depth.

We also isolate two arithmetic facts used above.

**Lemma 5.7.** `c ≤ 2^c` for all `c : ℕ` (`le_two_pow`).

**Lemma 5.8.** For every `k : ℕ` there is `n` with `k·(n+1) < 2^n`
(`exp_eventually_dominates_linear`); explicitly `n = 2k + 3` suffices.

## 6. Algorithms

The theory is constructive: every invariant is a structurally recursive function, and
the certified bound is computable. Two algorithms make this concrete.

**Algorithm A — Certified bound computation.** Given a type `A`, compute
`typeStateBound(A)` and the certificate `predictedBound(A) = 2^(size A) − 1` by a single
post-order traversal, returning the pair together with the verified guarantee
`typeStateBound(A) ≤ predictedBound(A)` (Corollary 4.9). Complexity: `O(size(A))`
arithmetic operations (on big integers, since values can be doubly exponential).

**Algorithm B — Regime classifier.** Given a type, classify its growth regime by
comparing depth and arrow width. If `arrowWidth(A) = depth(A)` (a chain-like profile),
report *single-exponential-in-depth* with witness ceiling `3^(depth+1)` (Theorem 4.3);
if width grows toward the bushy maximum `2^depth − 1`, report *double-exponential-in-
depth* with witness `2^(2^depth)` (Theorem 4.6); otherwise report an intermediate regime
bounded by `2^(size)` (Theorem 4.8). Complexity: `O(size(A))`.

## 7. Applications

**Parameterized complexity / FPT.** The impossibility theorem is a sharp negative result
for parameter selection: arrow depth (equivalently, the "order" of a functional) is not
a viable parameter for fixed-parameter tractability of semantic-state problems, because
no `f(depth)` bound exists. Size (or width) is the correct parameter, and it gives a
clean single-exponential kernel.

**Automata and bisimulation minimization.** The multiplicative recurrence is the same
product blow-up that governs state explosion in compositional model checking. Theorems
4.3–4.8 quantify when minimization can rescue tractability (bounded width / size) and
when worst cases are unavoidable (bushy structure), with exact extremal witnesses.

**Descriptive and semantic complexity.** The results give a precise width–depth
tradeoff for the expressive cost of higher-order types, identifying size as the
descriptive invariant that aligns with semantic state count.

**Semantic compression.** Corollary 4.9 yields a certified, size-linear-bit-length
budget (`log2(predictedBound + 1) = size`) for encoding the canonical-quotient state
space — a compression guarantee that depth cannot provide.

## 8. Discussion

The take-home message is methodological as much as mathematical: an intuitively natural
structural parameter can be provably useless, while a humbler one is exactly sharp. Depth
"feels" like complexity but is blind to branching; size sees the whole tree and therefore
governs the multiplicative recurrence. The bushy family is the universal worst case that
both defeats every depth-only bound and attains the order of the size bound, so the two
main theorems are not merely complementary but jointly *optimal*: `2^Θ(size)` is the
right order, and no `c^(depth+1)` exists.

A subtlety worth emphasizing is the role of the `+1` increments in the arrow rule. They
encode the "untouched input" behavior class and are what make the recurrence
*multiplicative with offset* rather than purely multiplicative; without them the chain
bound would be trivial and the bushy squaring would not lift cleanly to the `2^(2^n)`
tower. The width–size identity `2·arrowWidth + 1 = size` shows the offsets accumulate to
exactly the `+1` separating size from twice the width.

## 9. Future work

- **Tight constants.** Determine the least base `b` such that chains satisfy
  `typeStateBound ≤ b^(depth+1)` (we use `b = 3`; the recurrence `x_{d+1} = 2(x_d+1)`
  suggests the asymptotic base is `2`).
- **Multi-base types.** Extend the theory to several base types and to product types,
  where width acquires finer structure.
- **Average-case profiles.** Use `depthProfile` to study the *distribution* of width
  across depth levels and obtain bounds parameterized by the profile rather than the
  scalar size.
- **Connection to generalization theory.** The companion development in
  `MachineLearning/CompressionGeneralization.lean` builds an analytic
  compression / minimum-description-length theory whose controlling quantity is, as here,
  *description length* (size / bits) rather than a naive count (parameters / depth). The
  two threads share the moral that the right capacity measure is the compressed size; see
  Section 10 for the concrete program inherited from that line of work.

## 11. Conclusion

We have settled which structural invariant controls semantic state complexity for simple
types. Arrow depth is insufficient — provably, no exponential-in-depth bound can hold
uniformly — while type size is sharp, with a universal `typeStateBound(A) + 1 ≤
2^(size(A))` bound whose order is attained by balanced bushy types. The chain/bush dichotomy, organized
by the width–size identity, exhibits the full width–depth tradeoff and pins down both the
single- and double-exponential regimes exactly. The same moral — compressed size, not a
naive count, is the right complexity measure — recurs in compression-based generalization
theory, suggesting a unified view of capacity across type theory and learning.
