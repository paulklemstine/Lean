# Computational Evidence — the Anti-Fibonacci Sequence

All numerical claims in this file are reproduced *inside Lean* as `#eval` blocks guarded
by `#guard_msgs`, so they are re-checked on every build of the corresponding file in
`Catalog/Computation/`.  Nothing below is an unchecked scratch computation.

## 0. Which sequence?

The literal rule in the brief ("`A(n+1)` = smallest positive integer not equal to
`A(n)+A(n-1)`") excludes a *single* value, so it returns `1` unless `A(n)+A(n-1) = 1`;
the resulting sequence is constant `1`.  This collapse is already recorded in the
catalog (`Catalog/Shared/AntiFibonacciConnector.lean`,
`Catalog/Bridges/AntiFibonacci.lean`).  The *data* given in the brief,
`1, 1, 2, 4, 7, 11, 16, 22, 29, 37, …`, is generated by

```
antiFib 0 = 1,   antiFib (n+1) = antiFib n + n,   2·antiFib n + n = n² + 2
```

(`Catalog/Novelty/Basic.lean`, OEIS **A000124** — the lazy-caterer / central polygonal
numbers, prefixed with an extra `1`; equivalently `antiFib n = 1 + T(n-1)` with `T`
triangular).  All new results below are proved for this sequence.

## 1. Growth constant (the brief's `n²/4` claim)

`antiFib n = (n² - n + 2)/2`, hence `antiFib n / n² → 1/2`, **not** `1/4`
(already proved in `Catalog/Novelty/Asymptotics.lean`).  For example
`antiFib 1000 = 499501`, and `499501 / 10⁶ = 0.4995…`.

## 2. Modular periods (`Catalog/Computation/AntiFibonacciModularPeriod.lean`)

Residue streams `antiFib n mod m`:

| m | first residues | observed period | `pisanoAnti m` |
|---|----------------|-----------------|----------------|
| 2 | 1,1,0,0,1,1,0,0 | 4  | 2·2 = 4 |
| 3 | 1,1,2,1,1,2      | 3  | 3 |
| 4 | 1,1,2,0,3,3,0,2  | 8  | 2·4 = 8 |
| 5 | 1,1,2,4,2,1,1,…  | 5  | 5 |
| 6 | 1,1,2,4,1,5,4,4,5,1,4,2 | 12 | 2·6 = 12 |
| 7 | 1,1,2,4,0,4,2,1  | 7  | 7 |

Proved: the minimal period is exactly `m` for odd `m` and `2m` for even `m`.

## 3. Counting function (`Catalog/Computation/AntiFibonacciCounting.lean`)

`C(N) = #{k : antiFib k ≤ N}`; the brute-force scan and the closed form
`C(N) = (⌊√(8N-7)⌋+1)/2 + 1` agree for every `1 ≤ N < 120` (checked in Lean).

| N | C(N) | √(2N) |
|---|------|-------|
| 1 | 2 | 1.41 |
| 4 | 4 | 2.83 |
| 10 | 5 | 4.47 |
| 10⁴ | 142 | 141.42 |
| 10⁶ | 1415 | 1414.21 |

Consistent with the proved envelope `√(2N) ≤ C(N) ≤ √(2N) + 3`, with
`C(N)/√N → √2` and `C(N)/N → 0` (density zero).

## 4. Three-term progressions (`Catalog/Computation/AntiFibonacciPythagoreanAP.lean`)

Brute force over `1 ≤ a < b < c < 30` gives index triples
`(1,3,4), (1,15,21), (2,8,11), (3,13,18), (4,7,9), …`, i.e. value triples
`1,4,7`; `1,106,211`; `2,29,56`; `4,79,154`; `7,22,37`, ….
Every one corresponds to a Pythagorean triple `(a+c-1, c-a, 2b-1)`
(e.g. `(1,3,4) ↔ (4,3,5)`, `(4,7,9) ↔ (12,5,13)`, `(2,8,11) ↔ (12,9,15)`).

## 5. Perfect squares (`Catalog/Computation/AntiFibonacciPellSquares.lean`)

Scanning `n < 2000`: `antiFib n` is a perfect square exactly at
`n = 0, 1, 3, 6, 16, 33, 91, 190, 528, 1105`, with values
`1, 1, 4, 16, 121, 529, 4096, 17956, 139129, 609961`.
The corresponding `x = 2n-1` values `1, 5, 11, 31, 65, 181, 379, 1055, 2209` are exactly
the two interleaved orbits of `(x,y) ↦ (3x+8y, x+3y)` from `(1,1)` and `(5,2)`:

```
(1,1) → (11,4) → (65,23) → (379,134) → …
(5,2) → (31,11) → (181,64) → (1055,373) → …
```

Proved: this orbit description is *complete* (Vieta descent), so the classification of
squares is exact — and there are infinitely many.

## 6. Sums of two terms (`Catalog/Computation/AntiFibonacciSumsetTwoSquares.lean`)

Brute force: the `2 ≤ m ≤ 40` that are **not** sums of two anti-Fibonacci numbers are
`7, 10, 16, 19, 21, 25, 28, 34, 35, 37`.
The Lean check also confirms, for all `m < 60`, that representability coincides with
`8m - 14` being a sum of two squares, and that no `m ≡ 1, 7 (mod 9)` is representable
(checked for the first 30 members of each class).

## 7. Residue spectrum mod primes (`Catalog/Computation/AntiFibonacciResidueSpectrum.lean`)

Attained residues (computed in Lean):

| p | spectrum | size | (p+1)/2 |
|---|----------|------|---------|
| 3 | {1,2} | 2 | 2 |
| 5 | {1,2,4} | 3 | 3 |
| 7 | {0,1,2,4} | 4 | 4 |
| 11 | {0,1,2,4,5,7} | 6 | 6 |
| 13 | {1,2,3,4,7,9,11} | 7 | 7 |

Proved: the spectrum is exactly `{m : 8m - 7 is a square mod p}`, of size `(p+1)/2`;
in particular some residue class is always omitted.

## 8. Consecutive gcds (`Catalog/Computation/AntiFibonacciConsecutiveGcd.lean`)

`gcd(antiFib n, antiFib (n+1))` for `n = 0..15`:
`1,1,2,1,1,1,2,1,1,1,2,1,1,1,2,1` — value `2` exactly at `n ≡ 2 (mod 4)`;
verified in Lean for all `n < 200` and then proved in general.

## 9. Counterexample hunt

* The brief's `A(n) = ⌊n²/4⌋ + O(1)` is **false**: `antiFib n − ⌊n²/4⌋ ~ n²/4 → ∞`.
* The brief's "ratio oscillates between 1 and 2" is **false**: the ratio converges to `1`.
* The brief's "the complement has density 0" is **false** in the strong reading: at least
  `2/9` of all integers are not even sums of two anti-Fibonacci numbers
  (`card_not_sum_two_ge`).  The *value set itself* does have density `0`
  (`antiFibCount_density_zero`), which is the correct salvage of that claim.

## 10. Additive basis order (`Catalog/Computation/AntiFibonacciLagrange.lean`)

Brute force over `m ≤ 120` (all checks run inside Lean with `#guard_msgs`-pinned output):

| summands allowed | integers `m ≤ 120` **not** representable |
|---|---|
| 4 | none with `m ≥ 4` (and `0,1,2,3` are impossible for size reasons) |
| 3 | only `0, 1, 2` |
| 2 | `0, 1, 7, 10, 16, 19, 21, 25, 28, 34, 35, 37, 42, 43, 46, 49, 52, 54, 55, 56, 61, 64, 65, 70, 73, 76, 77, 79, 82, 84, 87, 88, 91, 97, 98, 100, 105, 106, 109, 111, 115, 118, 119, 120` |

Proved from this data: `sum_four_iff` — `m` is a sum of four anti-Fibonacci numbers **iff**
`m ≥ 4` (unconditional, via Lagrange's four-squares theorem and the identity
`4(A²+B²+C²+D²) = (A+B+C+D)² + (A+B-C-D)² + (A-B+C-D)² + (A-B-C+D)²`, all of whose entries
are odd when `A²+B²+C²+D²` is odd).  The order-`3` column is explained by the proved
reduction `sum_three_iff_sq_add_sq_add_sq`: `m ≥ 3` is a sum of three terms iff `8m - 21`
(which is `≡ 3 mod 8`, hence never of the excluded shape `4^a(8b+7)`) is a sum of three
squares — i.e. exactly Gauss's three-squares theorem, which Mathlib does not yet contain.

## 11. Prime divisors (`Catalog/Computation/AntiFibonacciPrimeDivisors.lean`)

Primes `p < 100` dividing some anti-Fibonacci number (Lean brute force over the first
`p + 1` terms, which suffices because the period mod odd `p` is `p`):

`2, 7, 11, 23, 29, 37, 43, 53, 67, 71, 79` — residues mod 7: `2, 0, 4, 2, 1, 2, 1, 4, 4, 1, 2`.

Primes `p < 100` dividing **no** anti-Fibonacci number:
`3, 5, 13, 17, 19, 31, 41, 47, 59, 61, 73, 83, 89, 97` — residues mod 7 all in `{3, 5, 6}`.

Proved: `p ∣ antiFib n` for some `n` **iff** `p = 7` or `p ≡ 1, 2, 4 (mod 7)`
(`prime_dvd_antiFib_iff`), by quadratic reciprocity for the discriminant `-7`; and,
with Dirichlet's theorem, both the divisor primes and the non-divisor primes are infinite.
This is a strict *avoidance* phenomenon: every prime divides some Fibonacci number, but
infinitely many primes divide no anti-Fibonacci number.
