# Computational Evidence — The Anti-Fibonacci Sequence

## 1. Small-case calculations

The research brief fixes the concrete data `1, 1, 2, 4, 7, 11, 16, …`.
The literal greedy rule stated in the brief ("A(n+1) = smallest positive integer not
equal to A(n) + A(n-1)") does **not** reproduce this data: the smallest positive integer
`≠ v` is almost always `1`, giving `1,1,1,…`. So we take the concrete data as ground
truth and reverse-engineer its generating rule.

Successive differences of the data are `0, 1, 2, 3, 4, 5, …`, so the data is generated by

    A 0 = 1,    A (n+1) = A n + n.

`#eval (List.range 10).map antiFib` yields:

    [1, 1, 2, 4, 7, 11, 16, 22, 29, 37]

which matches the brief exactly. Closed form: `A n = 1 + n(n-1)/2`, equivalently
`2 * A n + n = n² + 2`.

| n  | A n | n²/2 | fib(2n+1) |
|----|-----|------|-----------|
| 0  | 1   | 0    | 1         |
| 1  | 1   | 0.5  | 2         |
| 3  | 4   | 4.5  | 13        |
| 6  | 16  | 18   | 233       |
| 10 | 46  | 50   | 10946     |

## 2. OEIS search

`1, 2, 4, 7, 11, 16, 22, 29, …` is **A000124** (central polygonal / "lazy caterer"
numbers, `n(n+1)/2 + 1`). The brief's sequence is A000124 prepended with a leading `1`;
equivalently `a(n) = 1 + C(n,2)` with 0-indexing. This is **not** the golden-ratio /
Fibonacci family.

## 3. Counterexample hunt against the brief's conjectures

- **Claim `A n ~ n²/4`.** FALSE. `A n = (n² - n + 2)/2 ~ n²/2`. Numerically
  `A(1000)/1000² = 0.4995 → 1/2`, not `1/4`.
- **Claim `A n = ⌊n²/4⌋ + O(1)`.** FALSE for every constant multiple of `n²`; the exact
  form is quadratic, and `A n - ⌊n²/2⌋` grows linearly, so only the *exact* identity
  `2·A n + n = n² + 2` survives.
- **Claim "ratio A(n+1)/A(n) oscillates between 1 and 2, never converging".** FALSE.
  `A(n+1)/A(n) = (n²+n+2)/(n²-n+2)`; numerically `1.24 (n=10)`, `1.02 (n=100)`,
  `1.002 (n=1000)` — monotonically converging to `1`.
- **Claim "the sequence avoids being the sum of the two previous terms".** FALSE at
  index 5: `A 5 = 11 = 7 + 4 = A 4 + A 3`. It holds *strictly* only for indices `≥ 6`:
  `A k < A(k-1) + A(k-2)`. This threshold is sharp.

## 4. What is actually true (and proved in the Lean files)

- `2 * antiFib n + n = n² + 2` (exact closed form, by induction).
- `antiFib (n+6) < antiFib (n+5) + antiFib (n+4)` (avoids addition from index 6), with
  `antiFib 5 = antiFib 4 + antiFib 3` witnessing sharpness.
- `antiFib n / n² → 1/2` (correct growth constant).
- `antiFib (n+1) / antiFib n → 1`, hence the ratio does **not** tend to the golden ratio.
- `antiFib n < fib(2n+1)` for `n ≥ 6` (exponential Fibonacci growth dominates), phrased
  via the catalog's Riordan row-sum identity `pascalRiordanA n = fib(2n+1)`.
