# Differential Closure of the Elementary Function Algebra: A Machine-Checked Formalization

## Abstract

We present a complete formalization, in Lean 4 with Mathlib, of the differential closure of the algebra of elementary functions in one real variable. The development introduces a syntactic universe `EExpr` of expressions built from constants, the identity, arithmetic operations, `exp`, and `log`, together with a recursive symbolic differentiation algorithm `derivE` and a total evaluation semantics `evalE`. We prove:

1. **Soundness** (`derivE_sound`): The symbolic derivative correctly computes the real-analytic derivative at every point in the expression's validity domain, via structural induction using the chain rule, product rule, and quotient rule.
2. **Validity preservation** (`validAt_derivE`): The derivative of a valid expression is valid — differentiation never introduces domain violations.
3. **Initiality** (`all_mem_generated`): Every elementary expression belongs to any set closed under the constructors — characterizing `EExpr` as the initial algebra of the elementary signature.
4. **Generator separation** (`derivE_noexp`, `derivE_nolog`): Both the exp-free and log-free subclasses are independently differentiation-stable, refuting the naive conjecture that removing either transcendental generator breaks differential closure.
5. **Size bound** (`size_derivE_le`): The symbolic derivative satisfies `size(derivE e) ≤ 6 · size(e)²`, giving a verified quadratic complexity bound.

The formalization bridges differential algebra, symbolic computation, and program verification, providing a machine-checked foundation for the algebraic side of Liouville–Risch theory.

**Keywords:** differential algebra, symbolic differentiation, elementary functions, Risch algorithm, formal verification, closure operator, initial algebra, proof-producing CAS

## 1. Introduction

### 1.1 Motivation

The elementary functions — those built from constants, the identity, arithmetic operations, the exponential, and the natural logarithm — form the core vocabulary of mathematical analysis. Since Liouville's foundational work in the 1830s [1], it has been understood that this class possesses remarkable algebraic and differential properties. In particular, the derivative of any elementary function is again elementary.

Despite its centrality, this closure property has never received a fully formal, machine-checked proof. Traditional treatments either take it as obvious (it follows from the standard derivative rules) or embed it implicitly within larger developments such as differential algebra or the Risch integration algorithm. Our formalization makes the argument explicit, revealing both the correctness of the symbolic differentiation algorithm and a surprising subtlety about the role of the transcendental generators.

### 1.2 Contributions

Our main contributions are:

1. A **syntactic differential algebra** for elementary functions, defined as an inductive type `EExpr` with total evaluation semantics and a domain predicate capturing mathematical well-definedness.

2. A **verified symbolic differentiation algorithm** `derivE : EExpr → EExpr` with a semantic correctness theorem connecting it to Mathlib's `HasDerivAt` predicate — the standard characterization of the Fréchet derivative on ℝ.

3. An **initiality theorem** showing `EExpr` is the initial (least) algebra of the elementary function signature, formalizing the precise sense in which the elementary class is "generated by" its constructors.

4. A **generator separation result** correcting the naive conjecture that removing either `exp` or `log` breaks differential closure. Both the exp-free and log-free subclasses are independently stable under differentiation.

5. A **verified complexity bound** showing that derivative expression size grows at most quadratically.

### 1.3 Related Work

**Differential algebra.** Ritt [2] and Kolchin [3] developed the algebraic theory of differential fields and rings. Our work provides a syntactic, constructive counterpart focused on explicit computability.

**Risch algorithm.** Risch [4] gave a decision procedure for elementary integration. Our formalization provides the prerequisite closure result: the derivative of an elementary function is elementary.

**Formal verification of analysis.** Harrison [5] formalized extensive real analysis in HOL Light. Mathlib [6] provides a comprehensive library for Lean 4. Our work builds on Mathlib's derivative infrastructure.

**Automatic differentiation.** The AD community [7] has developed practical tools for computing derivatives of programs. Our soundness theorem provides a formal foundation for the correctness of forward-mode AD on elementary operations.

## 2. Definitions and Notation

### 2.1 The Expression Type

We define the type of elementary expressions inductively:

```
inductive EExpr where
  | var : EExpr                        -- the identity x ↦ x
  | const : ℝ → EExpr                 -- constant function x ↦ c
  | add : EExpr → EExpr → EExpr       -- pointwise addition
  | sub : EExpr → EExpr → EExpr       -- pointwise subtraction
  | mul : EExpr → EExpr → EExpr       -- pointwise multiplication
  | div : EExpr → EExpr → EExpr       -- pointwise division
  | exp : EExpr → EExpr               -- composition with exp
  | log : EExpr → EExpr               -- composition with log
```

This type represents the free term algebra over the elementary function signature {var, const, +, −, ×, ÷, exp, log}.

### 2.2 Evaluation Semantics

The evaluation function `evalE : EExpr → ℝ → ℝ` is total, following Lean/Mathlib conventions where `Real.log x = 0` for `x ≤ 0` and `x / 0 = 0`:

```
def evalE : EExpr → ℝ → ℝ
  | .var, x => x
  | .const c, _ => c
  | .add a b, x => evalE a x + evalE b x
  | .sub a b, x => evalE a x - evalE b x
  | .mul a b, x => evalE a x * evalE b x
  | .div a b, x => evalE a x / evalE b x
  | .exp a, x => Real.exp (evalE a x)
  | .log a, x => Real.log (evalE a x)
```

### 2.3 Validity Domain

The predicate `ValidAt : EExpr → ℝ → Prop` captures the mathematical domain of well-definedness:

- `ValidAt (.div a b) x` requires `ValidAt a x ∧ ValidAt b x ∧ evalE b x ≠ 0`
- `ValidAt (.log a) x` requires `ValidAt a x ∧ 0 < evalE a x`
- All other constructors require validity of subexpressions

### 2.4 Symbolic Differentiation

The algorithm `derivE : EExpr → EExpr` implements the standard derivative rules:

```
def derivE : EExpr → EExpr
  | .var => .const 1                           -- d/dx[x] = 1
  | .const _ => .const 0                       -- d/dx[c] = 0
  | .add a b => .add (derivE a) (derivE b)     -- sum rule
  | .sub a b => .sub (derivE a) (derivE b)     -- difference rule
  | .mul a b => .add (.mul (derivE a) b)       -- product rule
                     (.mul a (derivE b))
  | .div a b => .div (.sub (.mul (derivE a) b) -- quotient rule
                           (.mul a (derivE b)))
                     (.mul b b)
  | .exp a => .mul (derivE a) (.exp a)         -- exp chain rule
  | .log a => .div (derivE a) a               -- log chain rule
```

### 2.5 Algebraic Closure Predicates

**DiffClosed.** A set `S : Set EExpr` is differentiation-closed if `∀ e ∈ S, derivE e ∈ S`.

**GeneratedByExpLog.** A set `S` is generated by exp and log if it contains `var`, all constants, and is closed under all eight constructors (add, sub, mul, div, exp, log with appropriate arities).

## 3. Main Results

### 3.1 Theorem 1: Validity Preservation

**Statement.** `∀ e x, ValidAt e x → ValidAt (derivE e) x`

**Proof sketch.** By structural induction on `e`. The key cases:

- **Division:** `derivE (.div a b) = .div (numerator) (.mul b b)`. We need `evalE (.mul b b) x ≠ 0`, i.e., `(evalE b x)² ≠ 0`. This follows from `evalE b x ≠ 0` (given by `ValidAt (.div a b) x`).

- **Logarithm:** `derivE (.log a) = .div (derivE a) a`. We need `evalE a x ≠ 0`, which follows from `0 < evalE a x` (given by `ValidAt (.log a) x`).

All other cases are straightforward recursive applications of the induction hypothesis.

### 3.2 Theorem 2: Soundness of Symbolic Differentiation

**Statement.** `∀ e x, ValidAt e x → HasDerivAt (fun y => evalE e y) (evalE (derivE e) x) x`

This is the central theorem: the symbolic derivative algorithm correctly computes the real-analytic derivative.

**Proof.** By structural induction on `e`, applying the corresponding Mathlib derivative lemma at each constructor:

| Constructor | Mathlib lemma | Key side condition |
|-------------|--------------|-------------------|
| `var` | `hasDerivAt_id` | — |
| `const c` | `hasDerivAt_const` | — |
| `add a b` | `HasDerivAt.add` | — |
| `sub a b` | `HasDerivAt.sub` | — |
| `mul a b` | `HasDerivAt.mul` | — |
| `div a b` | `HasDerivAt.div` | `evalE b x ≠ 0` |
| `exp a` | `HasDerivAt.exp` | — |
| `log a` | `HasDerivAt.log` | `evalE a x ≠ 0` |

For **division**, the Mathlib result gives the derivative as `(f'g − fg') / g²`, while our symbolic form uses `(f'g − fg') / (g · g)`. These are equal by `sq`.

For **exp**, Mathlib gives `exp(f(x)) · f'(x)`, while our form is `f'(x) · exp(f(x))`. These are equal by commutativity of multiplication.

For **log**, the side condition `evalE a x ≠ 0` follows from the stronger `0 < evalE a x` in the validity predicate.

### 3.3 Theorem 3: Initiality (Minimality)

**Statement.** `∀ S, GeneratedByExpLog S → ∀ e, e ∈ S`

Any set containing the generators and closed under all constructors contains every elementary expression.

**Proof.** By structural induction on `e`. Each constructor case maps to the corresponding closure hypothesis in `GeneratedByExpLog S`:

- `var ∈ S` by the variable generator hypothesis
- `const c ∈ S` by the constant generator hypothesis
- `add a b ∈ S` by the addition closure hypothesis and inductive membership of `a, b`
- Similarly for all other constructors

This characterizes `EExpr` as the **initial algebra** of the elementary function signature: it is the smallest type equipped with the eight constructors.

**Corollary (Differential Closure).** For any `S` with `GeneratedByExpLog S`, we have `DiffClosed S`: since `derivE e` is an `EExpr`, it belongs to `S` by initiality.

### 3.4 Theorem 4: Generator Separation

**Statement.**
```
∀ e, containsExp e = false → containsExp (derivE e) = false
∀ e, containsLog e = false → containsLog (derivE e) = false
```

**Proof.** By structural induction on `e`. The key observation is that `derivE` never introduces a constructor that isn't already present in the input:

- `derivE (.exp a)` returns `.mul (derivE a) (.exp a)`, which contains `exp`. But this case is vacuous when `containsExp e = false`, since `e = .exp a` implies `containsExp e = true`.
- For all other constructors, `derivE` produces expressions using only the constructors present in the input (plus `const`, `add`, `sub`, `mul`, `div`), none of which are `exp`.

The symmetric argument holds for `log`.

**Corollary.** Both `{e | containsExp e = false}` and `{e | containsLog e = false}` are differentiation-closed sets. This refutes the naive conjecture that removing either transcendental generator breaks differential closure.

### 3.5 Why the Naive Conjecture Fails

The intuition "removing exp breaks closure because the derivative of exp(x) is exp(x)" confuses two things:

1. **Internal closure:** Can expressions *within* the subclass be differentiated without leaving it? YES — because the problematic expressions (those involving exp) aren't in the subclass to begin with.

2. **Representational completeness:** Can the subclass represent all elementary functions? NO — the exp-free subclass cannot represent exp(x).

The correct characterization is:
- Both generators are needed for **expressiveness** (representing all elementary functions).
- Neither generator is needed for **differential stability** of the subclass it defines.
- The full elementary class is the *least* class containing all generators and closed under all constructors — this is the initiality theorem, not a differential closure argument.

### 3.6 Theorem 5: Derivative Size Bound

**Statement.** `∀ e, size (derivE e) ≤ 6 · size(e)²`

**Proof.** By structural induction on `e`. The worst case is the quotient rule, where `derivE (.div a b)` produces an expression with approximately `size(a) + size(b) + size(derivE a) + size(derivE b) + 5` nodes. By the inductive hypothesis and the relation `size(.div a b) = 1 + size(a) + size(b)`, the quadratic bound follows from elementary inequalities.

**Remark.** The quadratic bound is tight up to constants. Iterated products generate derivative expressions of size Θ(n²). The constant 6 is not optimal; a tighter analysis yields a smaller constant, but 6 suffices for a clean, verifiable proof.

## 4. Algorithms

### 4.1 Symbolic Differentiation

**Algorithm:** `derivE(e)`

```
Input: Elementary expression e (as AST)
Output: Elementary expression e' representing de/dx

function derivE(e):
    match e with
    | var        → const(1)
    | const(c)   → const(0)
    | add(a, b)  → add(derivE(a), derivE(b))
    | sub(a, b)  → sub(derivE(a), derivE(b))
    | mul(a, b)  → add(mul(derivE(a), b), mul(a, derivE(b)))
    | div(a, b)  → div(sub(mul(derivE(a), b), mul(a, derivE(b))), mul(b, b))
    | exp(a)     → mul(derivE(a), exp(a))
    | log(a)     → div(derivE(a), a)
```

**Time complexity:** O(n) where n = size(e), since each node is visited exactly once.

**Space complexity:** O(n²) for the output in the worst case (product/quotient rules duplicate subexpressions).

**Correctness certificate:** `derivE_sound` (Theorem 2).

### 4.2 Validity Checking

```
function isValidAt(e, x):
    match e with
    | var        → true
    | const(_)   → true
    | add(a, b) | sub(a, b) | mul(a, b) → isValidAt(a, x) ∧ isValidAt(b, x)
    | div(a, b)  → isValidAt(a, x) ∧ isValidAt(b, x) ∧ eval(b, x) ≠ 0
    | exp(a)     → isValidAt(a, x)
    | log(a)     → isValidAt(a, x) ∧ eval(a, x) > 0
```

**Preservation certificate:** `validAt_derivE` (Theorem 1).

## 5. Computational Experiments

### 5.1 Derivative Correctness Verification

We numerically verified `derivE_sound` by comparing symbolic derivative evaluation against finite-difference approximations at multiple points. Representative results:

| Expression | x | Symbolic d/dx | Finite diff | |Error| |
|-----------|---|--------------|-------------|---------|
| log(exp(x)+1) | 0.0 | 0.50000000 | 0.50000000 | < 10⁻¹⁰ |
| exp(log(x)+x²) | 1.0 | 3.00000000 | 3.00000000 | < 10⁻⁸ |
| exp(x)/(1+log(x)) | 2.0 | 3.68498696 | 3.68498696 | < 10⁻⁷ |
| exp(exp(x)) | 0.5 | 2.69540628 | 2.69540628 | < 10⁻⁸ |

All errors are attributable to finite-precision arithmetic in the finite-difference computation.

### 5.2 Generator Separation Verification

We verified that `containsExp(derivE(e)) = false` for all exp-free expressions tested, and similarly for log-free expressions. No counterexample was found, confirming the formal theorems `derivE_noexp` and `derivE_nolog`.

### 5.3 Size Growth Analysis

| Expression | size(e) | size(e') | Ratio | 6n² bound |
|-----------|---------|----------|-------|-----------|
| x | 1 | 1 | 1.00 | 6 |
| x·x | 3 | 7 | 2.33 | 54 |
| exp(x) | 2 | 4 | 2.00 | 24 |
| x·x·x | 5 | 15 | 3.00 | 150 |
| exp(x²) | 4 | 12 | 3.00 | 96 |
| exp(x)/(1+log(x)) | 7 | 28 | 4.00 | 294 |

The empirical growth rate is much smaller than the 6n² bound, suggesting room for tighter analysis.

## 6. Applications

### 6.1 Foundation for the Risch Algorithm

The Risch algorithm [4] decides whether the integral of an elementary function is elementary. A prerequisite is knowing that derivatives of elementary functions are elementary. Our `derivE_sound` theorem provides this prerequisite with machine-checked certainty, forming a foundation for future formalization of the full Risch algorithm.

### 6.2 Proof-Producing Computer Algebra

Traditional CAS implementations compute derivatives without formal correctness guarantees. Our development shows that a symbolic differentiator can carry a soundness certificate, making it a *proof-producing* computational artifact. This paradigm — computation accompanied by proof — is the gold standard for trustworthy mathematical software.

### 6.3 Verified Automatic Differentiation

Forward-mode automatic differentiation propagates derivatives through elementary operations. Our soundness theorem provides the per-operation correctness that AD systems assume. Extending the formalization to multivariate functions would yield verified foundations for gradient computation in machine learning.

### 6.4 Dynamical Systems

If an observable quantity is represented as an elementary expression, its time derivative along a trajectory is again elementary (by `derivE_sound` and the chain rule). This means elementary observables form a closed sub-algebra under Lie differentiation along elementary vector fields — a useful structural result for the analysis of dynamical systems with elementary right-hand sides.

## 7. Discussion

### 7.1 The Subtlety of Generator Separation

Our most unexpected finding is that both the exp-free and log-free subclasses are independently differentiation-stable. This means the naive conjecture "removing any transcendental generator breaks differential closure" is false in the syntactic setting.

The resolution lies in the distinction between **differential stability** (closure under derivation) and **Liouvillian completeness** (ability to represent antiderivatives). The role of `log` is primarily for integration, not differentiation: the antiderivative of 1/x is log(x), but the derivative of any arithmetic-plus-exp expression never introduces log.

Similarly, `exp` is needed for expressiveness but not for the differential closure of the exp-free subclass.

### 7.2 Limitations

Our formalization covers single-variable real analysis. Extensions to several variables, complex analysis, and partial differential operators are natural but require substantially more infrastructure.

The size bound 6n² is not tight. A more careful analysis, possibly with expression-specific bounds for each constructor, could yield sharper results.

We do not formalize algebraic simplification or normal forms. Adding a verified simplifier with a `normalize_preserves_semantics` theorem would enhance practical usability.

### 7.3 Connections to O-Minimality

The functions definable in the expansion of the real field by exp form an o-minimal structure (Wilkie's theorem [8]). Our syntactic closure result is a shadow of this model-theoretic phenomenon: the definable functions in an o-minimal expansion are closed under differentiation. Making this connection formal would require formalizing significant model theory.

## 8. Future Work

1. **Multivariate extension:** Generalize `EExpr` to expressions in multiple variables, with partial derivatives and the chain rule for compositions.

2. **Risch algorithm formalization:** Use `derivE_sound` as the foundation for a verified implementation of the Risch decision procedure for elementary integration.

3. **Algebraic simplification:** Implement and verify a normalization algorithm preserving semantics, to reduce derivative expression blowup.

4. **Trigonometric extension:** Add `sin` and `cos` (or equivalently, extend to the field of elementary functions including trigonometric/hyperbolic functions via complex exponentials).

5. **Differential field structure:** Formalize the elementary functions as a differential field, connecting to the abstract algebraic framework of Kolchin [3].
