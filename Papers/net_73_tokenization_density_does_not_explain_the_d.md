# Computational evidence — NET-73

Every number in this note is recomputed inside Lean (exact rational arithmetic)
in `Catalog/Applications/NET73*.lean`; nothing here rests on a scratch script.

## 1. The measured table

| domain    | TPW   | k*@512 |
|-----------|-------|--------|
| code      | 1.950 | 12     |
| prose-de  | 1.885 | 20     |
| prose-fr  | 1.246 | > 32 (censored) |
| math      | 1.214 | 16     |
| prose-en  | 1.173 | 16     |

French is *censored*: only a lower bound on its knee is reported, so the
regression statistics use the four uncensored domains, which is also the
population that reproduces the reported ρ and R².

## 2. Spearman ρ, all tie-breaking conventions

Ascending TPW ranks are `en 1 < math 2 < de 3 < code 4`.  The knee has a tie
(math and prose-en both 16), so the rank vector is convention-dependent:

| convention on the 16–16 tie | rank vector (code, de, math, en) | Σd² | ρ |
|---|---|---|---|
| math before en (as reported) | (1, 4, 2, 3) | 14 | **−2/5 = −0.40** |
| en before math | (1, 4, 3, 2) | 12 | −1/5 |
| midranks (2.5, 2.5) | (1, 4, 5/2, 5/2) | 12.5 | −1/4 |
| competition ranks | (1, 4, 2, 2) | 11 | −1/10 |

The reported value −0.40 is reproduced exactly by the first convention
(`Catalog.NET73.spearman_reported`), and the **sign is convention-independent**
(`spearman_negative_all_conventions`): every convention gives ρ < 0, so the
pre-registered threshold ρ ≥ 0.9 fails under all of them.

## 3. Least-squares fit of k* on TPW (four uncensored domains)

Exact rational arithmetic:

* mean TPW = 3111/2000 = 1.5555, mean k* = 16
* cov(TPW, k*) = −13/50 = −0.26
* var(TPW) = 527129/1000000, var(k*) = 32
* **R² = 4225/1054258 = 0.0040075…**

Reproducing the reported 0.004 exactly (`Catalog.NET73.rsq_value`).  Since a
genuine affine law forces R² = 1 (`rsq_eq_one_of_affine`, Cauchy–Schwarz
equality case), the fit rules out `k* = a·TPW + b` for every `a ≠ 0`.

## 4. Counterexample hunt on monotonicity

Two discordant pairs survive every convention:

* increasing law: `TPW(en) = 1.173 < 1.950 = TPW(code)` but
  `k*(en) = 16 > 12 = k*(code)`;
* decreasing law: `TPW(math) = 1.214 < 1.885 = TPW(de)` and
  `k*(math) = 16 < 20 = k*(de)`.

Both horns are therefore refuted using only uncensored data
(`tokenization_density_no_monotone_law`); the censored French point strengthens,
but is not needed for, the decreasing horn.

Note one numeric correction found while formalising: the informal claim "code
has 1.66× English's TPW" is correct, but "5/3×" is **false** —
`1.173 × 5/3 = 1.9550 > 1.9500`.  The Lean statement uses the true constant
`1.66`.

## 5. The decay-rate model (geometric capture curve `1 − r^k`)

At tolerance τ = 3/4 the knee is the least `k` with `r^k ≤ 1/4`:

| r | r^(k*−1) | r^(k*) | k* |
|---|---|---|---|
| 1/2  | 0.5000 | 0.2500 | 2 |
| 9/10 | (9/10)^13 = 0.254187… | (9/10)^14 = 0.228768… | 14 |

Two domains with *identical* tokens-per-word and knees 2 versus 14: a sevenfold
knee gap generated purely by attention decay
(`geometric_domain_shift_at_equal_density`).  This is the in-model analogue of
code (`k* = 12`) versus French (`k* > 32`) at nearly equal token density.

## 6. Participation bound, checked on a worked domain

For four equally weighted keys the collision index is `S = 4·(1/4)² = 1/4`, so
the Cauchy–Schwarz bound predicts `k* ≥ τ²/S = (3/4)²/(1/4) = 9/4`, and the true
knee at τ = 3/4 is `3` (`quadUniform_knee_three`): the bound is non-vacuous and
close to attained.

## 7. OEIS

No integer sequence is generated by this experiment (the data are five measured
pairs, and the model produces knees `⌈τ/m⌉`-style quantities depending on
continuous parameters), so no OEIS lookup applies.
