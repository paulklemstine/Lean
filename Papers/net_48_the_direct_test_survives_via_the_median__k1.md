# Computational evidence (Tropical / KneeMedian)

All numbers below were computed inside the Lean project (`#eval`, exact rational arithmetic)
before the corresponding theorems were formalised.  Every claim that survived is now a
machine-checked theorem in `Catalog/Tropical/KneeMedian/`; the ones that failed are recorded
here and appear in the files as explicit refutations.

| `k`   |  96   | 128   | 160   | 192   | 224   | 240   | 256   | 288   | 384   | 512   | 768   | 1024  |

| ratio | 0.963 | 0.973 | 0.981 | 0.984 | 0.986 | 0.987 | 0.990 | 0.993 | 0.999 | 1.000 | 1.003 | 1.003 |

## 2. Third-seed stability scan of the reported median

With the other two seeds pinned at `224` and `256`:

| third seed `x` | 160 | 192 | 224 | 240 | 256 | 300 |
|---|---|---|---|---|---|---|
| `tropMed3 x 224 256` | 224 | 224 | 224 | **240** | 256 | 256 |

The informal summary said "only a third seed `≥ 256` would shift the median".  The scan shows
`x = 240` already shifts it: the true stability set is the ray `x ≤ 224`.
Formalised: `net48_stability_interval`, `informal_stability_claim_false`.

## 3. Ratio and speed-up columns

* knees `{256, 224, 160}` / product point `256` → ratios `{1, 7/8, 5/8}`, median `7/8`;
* knees `{128, 112, 96}` / product point `128` → ratios `{1, 7/8, 3/4}`, median `7/8`;
* speed-ups `2048 / k` → `{8, 64/7, 64/5} = {8.0, 9.14…, 12.8}`, median `64/7`;
* at `ctx = 1024`: `1024 / k` → `{8, 64/7, 32/3} = {8.0, 9.14…, 10.67}`, median `64/7`.

Both columns are images of the knee column under a monotone (`÷P`) resp. an order-reversing
(`ctx/·`) map, and in both cases the median transports.
Formalised: `isMedian_ratios16`, `isMedian_ratios8`, `isMedian_speedups16`,
`guaranteed_speedup16`.

## 4. Counterexample hunt: which statistic obeys the law?

* **mean**: `(128+112+96)/3 = 112 = 7/8·128` but `(256+224+160)/3 = 640/3 ≈ 213.33 ≠ 224`.
  No constant `a` with `a·128 = 112` and `a·256 = 640/3`.  → `mean_has_no_ratio_law`.
* **min**: ratios `3/4` vs `5/8` — no constant ratio.
* **max**: ratio `1` at both contexts, but only because it is pinned by the product-law upper
  bound `k* ≤ P`; the informative constant is the median's `7/8`. → `upper_edge_pinned`.

## 5. Counterexample hunt: axioms for "the centre"

Conjecture tested: *monotone + symmetric + conservative + self-dual ⇒ median*.
Search over sign-switched aggregators produced the **sum-sign aggregator**

```
F(a,b,c) = max(a,b,c)  if a+b+c > 0
         = min(a,b,c)  if a+b+c < 0
         = med(a,b,c)  if a+b+c = 0
```

Spot checks: `F(0,0,1) = 1 ≠ 0 = med(0,0,1)`; monotone on all tested comparable pairs;
`F(-x) = -F(x)` on all tested triples.  All four axioms verified and the conjecture refuted;
adding translation equivariance restores it.
Formalised: `aggTrans_indispensable`, `median_characterisation`.

## 6. Counterexample hunt: knee of the aggregate curve

Three monotone step curves with knees `1, 2, 3` on grid `{1,2,3}`, bar `1`:

* mean curve values `1/3, 2/3, 1` → knee `3`, whereas the median of the knees is `2`;
* median curve values `0, 1, 1` → knee `2` ✓.

Dropping monotonicity (a curve that clears the bar at `1` and falls back at `2`) breaks the
median statement too: median curve value at `2` is `0 < 1`.
Formalised: `mean_curve_knee_ne_median_knee`, `knee_median_needs_monotone`,
`knee_of_median_curve`, `knee_of_median_curve_general`.

## Cycle-2 checks: breakdown behaviour of median vs mean (three seeds)

Clean 16× knee triple `K = (256, 224, 160)`, product point `P = 256`.  Replacing the third
entry by `t` and recomputing both aggregators:

| `t` | `med(256, 224, t)` | `mean(256, 224, t)` |
|---|---|---|
| `0` | 224 | 160 |
| `160` | 224 | 213.33 |
| `224` | 224 | 234.67 |
| `256` | 256 | 245.33 |
| `10^6` | 256 | 333493.33 |

The median column never leaves `[224, 256]` — the range of the two untouched seeds — which is
exactly `net48_one_seed_breakdown`; the mean column is unbounded, which is exactly
`mean_has_no_breakdown`.  The same contrast at the level of *curves* (two clean unit steps with
knee `1`, one corrupted step with knee `N`) gives median-curve knee `1` and mean-curve knee `N`
for every `N > 1`, formalised as `mean_curve_knee_has_no_breakdown`.
